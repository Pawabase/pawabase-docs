## Sessions

List calls return an object with the items under `data`, the same shape as `users.search`.

<CodeGroup>
```typescript TypeScript
const { data: sessions } = await a.sessions.list({ limit: 100 });      // active sessions across users
await a.sessions.revoke(sessions[0].family);                  // end one, including its refresh tokens
```

```python Python
sessions = pb.admin.sessions.list(limit=100)["data"]
pb.admin.sessions.revoke(sessions[0]["family"])
```
</CodeGroup>

To sign one person out everywhere, use `users.revokeSessions(userId)`.

## Devices and API keys

<CodeGroup>
```typescript TypeScript
const { data: devices } = await a.devices.list({ limit: 50 });   // devices people recently signed in from
const { data: keys } = await a.apiKeys.list({ limit: 50 });      // user API keys (never the secrets)
await a.apiKeys.revoke(keys[0].id);
```

```python Python
devices = pb.admin.devices.list(limit=50)["data"]
keys = pb.admin.api_keys.list(limit=50)["data"]
pb.admin.api_keys.revoke(keys[0]["id"])
```
</CodeGroup>

## Sign-in events

<CodeGroup>
```typescript TypeScript
const failures = await a.insight.events({ failed: true, limit: 100 });
const resets = await a.insight.events({ kind: "password_reset", limit: 50 });
```

```python Python
failures = pb.admin.insight.events(failed=True, limit=100)
resets = pb.admin.insight.events(kind="password_reset", limit=50)
```
</CodeGroup>

Events cover sign-ins, sign-ups, resets and second-factor use. Filter by `failed` to spot someone guessing passwords, or by `kind`.

## Numbers at a glance

```typescript
const stats = await a.insight.stats();    // users, sign-ins, second-factor use, failures
```

Put them on an internal dashboard, and alert when failures jump.

## Back up and restore

Export every identity (users, organizations, roles and factors) as one document, for safekeeping or to copy an environment:

<CodeGroup>
```typescript TypeScript
const backup = await a.insight.backup();

// Check what a restore would change, then do it
const preview = await a.insight.restore(backup, { dryRun: true });
await a.insight.restore(backup, { replace: false });
```

```python Python
backup = pb.admin.insight.backup()
preview = pb.admin.insight.restore(backup, dry_run=True)
pb.admin.insight.restore(backup, replace=False)
```
</CodeGroup>

Always do a dry run first. `replace: true` makes the environment match the backup exactly, which removes identities the backup lacks. Store backups encrypted; they describe real people.

## Preview a token

If your app puts custom claims in tokens, see what a user's token would contain before issuing one:

```typescript
const claims = await a.insight.previewTokenProfile(profile, userId, { org: "acme" });
```

## A weekly security routine

1. Review `insight.events({ failed: true })` for repeated failures against one account.
2. List users with `status: "no_mfa"` who have admin roles, and ask them to enrol.
3. Review user API keys and revoke ones you do not recognise.
4. Take a `backup()` and store it.
