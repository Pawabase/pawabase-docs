The [Auth](/auth/overview) guides cover what a person does for themselves: sign up, sign in, change their profile. **User administration** is what *you* do on their behalf from a server: create an account, disable one, assign a role, sign someone out everywhere, look at a sign-in history, reset a lost second factor.

It is a separate client because it is powerful. It needs your project's **secret key** and must only run in code you control.

<Warning>
The admin client can read and change every user. Never use it in a browser or mobile app, and never put the secret key in client code.
</Warning>

## Get started

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";
import { admin } from "@pawabase/client/admin";

const a = admin(
  createClient({
    url: process.env.PAWABASE_URL!,
    apiKey: process.env.PAWABASE_SECRET_KEY!,     // pb_sk_…
    environment: "production",
  }),
);

await a.users.create({ email: "ada@example.com", password: "a long passphrase", roles: ["editor"] });
const { data } = await a.users.search({ search: "ada" });
await a.users.update(userId, { disabled: true });
```

## Environments

Every environment (development, staging, production) has its own users. The client works on the environment you created it with. To act on another one with the same key:

```typescript
const staging = a.withEnvironment("staging");
```

Python: `pb.admin.environment("staging")`.

## Typical uses

- **Seed accounts:** create admin and test users when you set up an environment.
- **Back-office:** a support tool that finds a user, resets their second factor, or disables an account.
- **Onboarding by import:** create accounts for a list of people you already know, verified, with roles.
- **Compliance:** delete a user on request; export their sign-in history.
- **Role assignment:** set roles from your billing system when a plan changes, so access rules react at once.
