A **role** is a named bundle of **permissions**. You give people roles, and your [access rules](/policies/overview) check for a role or a permission. This keeps rules short and lets you change what "editor" means in one place.

## Permissions

A permission is a string of the form `resource:action`, where `*` is a wildcard.

| Permission | Means |
| --- | --- |
| `posts:read` | Read posts |
| `posts:write` | Write posts |
| `posts:*` | Anything on posts |
| `billing:*` | Anything on billing |
| `*` | Everything |

The names are yours. Pawabase only matches strings; your rules decide what they mean.

## Define a role

<CodeGroup>
```typescript TypeScript
await a.roles.define("editor", ["posts:read", "posts:write", "comments:*"], { description: "Can write posts" });
await a.roles.define("support", ["users:read", "orders:read"]);
await a.roles.define("org:billing", ["billing:*"]);
```

```python Python
pb.admin.roles.put("editor", ["posts:read", "posts:write", "comments:*"], description="Can write posts")
pb.admin.roles.put("support", ["users:read", "orders:read"])
```
</CodeGroup>

Names are lowercase, and may contain a colon to group them (`org:billing`). Defining a role that exists replaces it.

## List and remove

<CodeGroup>
```typescript TypeScript
const roles = await a.roles.list();
await a.roles.remove("support");
```

```python Python
roles = pb.admin.roles.list()
pb.admin.roles.remove("support")
```
</CodeGroup>

## Put people in roles

<CodeGroup>
```typescript TypeScript
await a.users.create({ email: "grace@example.com", roles: ["editor"] });
await a.users.update(userId, { roles: ["editor", "support"] });      // replaces the list
```

```python Python
pb.admin.users.create(email="grace@example.com", roles=["editor"])
pb.admin.users.update(user_id, roles=["editor", "support"])
```
</CodeGroup>

The roles and permissions appear on the person's session. After you change them, the new values arrive when the person's token refreshes (within minutes), or immediately after they sign in again. To force it, sign them out with `revokeSessions`.

## Use roles in rules

```json
"role:editor"
```

```json
{ "role": ["editor", "admin"] }
```

```json
"permission:posts.write"
```

```json
{ "contains": ["$auth.permissions", "posts:write"] }
```

Prefer checking a permission over a role in your rules: roles change names as the business grows, permissions describe what the person may do. See [recipes](/policies/recipes#roles).

## Roles in the client

The signed-in user's roles are on `user.roles`. Use them only to decide what to **show**; the rules on the server are what protect data.

```typescript
const user = await pawabase.auth.getUser();
const canEdit = user.roles.includes("editor");
```

## Change a plan, change access

A common pattern: when billing says a customer upgraded, update their roles or `appMetadata` from your server. Access rules that read them take effect at once on the next token refresh.

```typescript
async function onUpgrade(userId: string) {
  await a.users.update(userId, { roles: ["member", "pro"], appMetadata: { plan: "pro" } });
  await a.users.revokeSessions(userId);     // optional: apply immediately
}
```
