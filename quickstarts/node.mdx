On a server there are two ways to use the client. Pick based on whose permissions the code should have.

| You want | Use |
| --- | --- |
| Admin work, jobs, scripts that act for the whole project | A **secret key** (`pb_sk_…`) |
| Handle a request for one signed-in user | That user's **access token** |

## Install

```bash
npm install @pawabase/client
```

## Acting as the project

A secret key bypasses your access rules. Keep it in an environment variable and never send it to a browser.

```typescript
import { createClient } from "@pawabase/client";

const admin = createClient({
  url: process.env.PAWABASE_URL!,
  apiKey: process.env.PAWABASE_SECRET_KEY!,
  environment: "production",
});

const { data: overdue } = await admin.from("invoices").eq("status", "overdue");
```

## Acting for one user

When your server handles a request from a signed-in user, pass their token so your access rules apply to them exactly as they would in the browser.

```typescript
import express from "express";
import { createClient } from "@pawabase/client";

const app = express();

app.get("/my-tasks", async (req, res) => {
  const token = req.headers.authorization?.replace("Bearer ", "");
  const pawabase = createClient({
    url: process.env.PAWABASE_URL!,
    apiKey: process.env.PAWABASE_PUBLISHABLE_KEY!,
    accessToken: token,
  });
  const { data } = await pawabase.from("tasks");
  res.json(data);
});
```

With `accessToken` set, the client keeps no session of its own and does not refresh, so make one per request.

## A script that signs in

For a script that runs as a particular user, sign in once; the session stays in memory for the life of the process.

```typescript
const pawabase = createClient({ url, apiKey: publishableKey, auth: { persistSession: false } });
await pawabase.auth.signInWithPassword({ email, password });
```
