## 1. Get your keys

Open your project in the dashboard and copy two things:

- The **API URL**, like `https://api.example.com`.
- The **publishable key**, which starts with `pb_pk_`. It is safe to put in a web page. It identifies your project, and what people can do is decided by your access rules.

<Warning>
Never put a **secret key** (`pb_sk_…`) in a web page. It bypasses every rule. The client refuses to start with one in a browser.
</Warning>

## 2. Install

```bash
npm install @pawabase/client
```

## 3. Create the client

```typescript
import { createClient } from "@pawabase/client";

export const pawabase = createClient({
  url: "https://api.example.com",
  apiKey: "pb_pk_…",
});
```

Create it once and import it wherever you need it.

## 4. Create a table to read

In the dashboard, open **Database**, create a table called `tasks` with a `title` (text) and `done` (true or false) column, and add a row or two. Give signed-in users permission to read it.

## 5. Sign a user in

```typescript
const { user, session, verificationRequired } = await pawabase.auth.signUp({
  email: "ada@example.com",
  password: "a long passphrase",
});

if (verificationRequired) {
  // They must click the link in their email first.
} else {
  console.log("Signed in as", user.email);
}
```

Sign-in later is `signInWithPassword`. The client stores the session in the browser and refreshes it, so the user stays signed in across page loads.

## 6. Read data

```typescript
const { data: tasks } = await pawabase.from("tasks").eq("done", false).order("title");
console.log(tasks);
```

Because a user is signed in, the request carries their identity, and your access rules decide which rows come back.

## 7. Write data

```typescript
const task = await pawabase.from("tasks").create({ title: "Write the docs", done: false });
await pawabase.from("tasks").update(task.id, { done: true });
```
