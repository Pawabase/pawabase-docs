The **audit log** records changes to how your project is set up. Open **Activity → Audit log**. It answers questions like:

- Who deleted that table, or rotated that secret?
- What changed just before errors started?
- Which key or AI tool made a change, and when?
- Did someone restore a backup or release an API version?

It is a record of **changes**, not of every request. For requests, use [Requests and traces](/activity/requests). For people signing in to your app, use [Sign-in activity](/auth/sign-in-activity).

## What each entry contains

| Part | Meaning |
| --- | --- |
| **Actor** | Who or what made the change (for example `studio`, or the name of a key or tool). Some entries have none. |
| **Action** | What happened, in the form `area.what`, for example `secret.updated` or `snapshot.taken` |
| **Target** | The thing it was done to, for example a table, key, bucket or template name |
| **Environment** | Which environment it happened in |
| **When** | The time of the change |

**Values are never recorded.** The log says that a secret changed, not what it changed to. Arguments an AI tool passes are recorded by **name** only.

## What gets recorded

| Area | Actions |
| --- | --- |
| **Environments** | `environment.created`, `preview.deleted`, `version.retired` |
| **Data** | `database.write` (a change made in the SQL console), `database.table_dropped`, `database.query_saved`, `database.query_deleted`, `resource.purged` |
| **Files** | `storage.deleted`, `storage.moved`, `storage.shared`, `storage.unshared`, `storage.folder.created`, `storage.folder.deleted` |
| **Secrets and keys** | `secret.updated`, `key.revoked` |
| **Backups** | `snapshot.taken`, `snapshot.deleted` |
| **AI** | `ai.provider_added`, `ai.provider_updated`, `ai.provider_removed`, `ai.model_added`, `ai.model_updated`, `ai.model_removed` |
| **Monitoring** | `alarm.created`, `alarm.updated`, `alarm.deleted`, `incident.opened`, `incident.deleted`, dashboards created, changed and deleted |
| **Domains** | `domain.added`, `domain.removed` |
| **Mail** | `mail.kit.updated` |
| **Operations** | `job.retried`, `cache.invalidated`, `event.emitted`, `flow.run` (when run by hand) |
| **AI tools** | Every call an AI tool makes over MCP is recorded as `mcp.tool`, with the names of its arguments |

The table lists the most common actions; other configuration changes are recorded the same way.

## Use it

### After an incident

1. Note the time errors started in [Activity](/activity/overview).
2. Open the audit log and look at what changed in the minutes before.
3. If a change is the cause, undo it, or restore from a [backup](/backups/restore).

### Find who did something

Read down the **Action** and **Target** columns, newest first. Because each integration should have its own key, the actor tells you *which app or job* made a change, not only which person.

### Review AI tool activity

Everything an [AI tool](/ai/mcp) does shows up here as `mcp.tool` and on the **AI → AI tools** page. Review after you let a tool build with a **Build with me** key.

## How long it is kept

Audit history is kept for a time that depends on your plan:

| Free | Starter | Pro | Business | Scale |
| --- | --- | --- | --- | --- |
| 7 days | 30 days | 90 days | 365 days | 730 days |

If you need to keep it longer, copy what matters elsewhere on a schedule.

## Good practice

- **One key per integration**, so the actor means something.
- **Don't share a Studio login.** Invite each person to the organization ([Team](/cloud/team)).
- **Look at it after every release**, alongside errors.
- Pair it with [alarms](/activity/alarms) for the changes that must never happen unnoticed.

## What it does not show

- **Data changes made through your app's API** (a customer editing their own record). Those are your application's data, not configuration. Use [Requests](/activity/requests), or an [event subscription](/automation/events) if you want your own history of record changes.
- **The contents of anything secret.**
- **People signing in.** See [Sign-in activity](/auth/sign-in-activity).
