The gateway has two kinds of thing. A **provider** is a company or server that runs models, with the key to use it. A **model** is a name your app asks for (`chat`, `embed`) that points at one of a provider's models.

Splitting them means your app never changes when you do: swap `chat` from one provider's model to another's in Studio and every caller keeps working.

## Providers

**AI → Providers → Add provider.** A panel lists the providers; choose one, paste its key (or, for your own server, its address), and connect:

| Provider | Chat | Embeddings | Notes |
| --- | --- | --- | --- |
| OpenAI | yes | yes | |
| Anthropic | yes | no | Anthropic has no embedding models. Text conversations and tool calls are supported; images are not. |
| Google Gemini | yes | yes | Reached through Google's OpenAI-compatible endpoint. |
| Mistral | yes | yes | |
| Groq | yes | no | |
| OpenAI-compatible | yes | yes | Any server that speaks the OpenAI API: Ollama, vLLM, LM Studio, OpenRouter, Together, DeepSeek, xAI. You give its address. |

Right after connecting, Studio asks the provider which models your key can use and shows them to tick (see below). The key you paste is sealed for this environment on arrival. Studio and the API show only that a key is **stored**. To change it, paste a new one. Switching a provider **Off** refuses every model on it.

<Note>
For an OpenAI-compatible server, Pawabase refuses addresses that resolve to a private network (your own machines, cloud metadata) unless the host is on the operator's allow-list (`PAWABASE_OUTBOUND_ALLOW_HOSTS`), so a model definition cannot be used to reach internal services. A local development install allows them.
</Note>

## Models

**AI → Models → Add models** lists the models the provider itself reports for your key, split into **Chat** and **Embeddings**, with search. Tick one or more and add them. They get simple names (`chat`, `embed`, and `chat-2` if taken) that you can keep or change in code. A model the provider does not list (a fine-tune, a new release) can be added by name under **Use a model that is not listed**.

If the provider cannot be asked (a wrong key, or it is offline), Studio shows common models instead and says why.

Open a model to change it:

| Setting | Meaning |
| --- | --- |
| **Model** | Which of the provider's models answers. Your app keeps asking for the same name, so you can swap models without a deploy. |
| **Who can use it** | See below. |
| **Instructions** | A system prompt added to every conversation that has none of its own. |
| **Temperature** and other defaults | Used when a request does not set them. A request's own value always wins. |
| **Vector size** | For embedding models: how many numbers each vector has. Vector fields must match. |
| **Price in / out** | USD per million tokens, so usage can show a cost. Optional. |
| **If it fails, try** | Another model of the same kind, used when this one errors with a provider failure or rate limit. |

### Who can use a model

| Choice | Meaning |
| --- | --- |
| **Servers only** (default) | Only a secret key. Nothing in a browser or app can run it. |
| **Signed-in users** | Any signed-in user, and servers. |
| **Anyone** | Any caller with your public key. They spend your provider credit, so use it deliberately. |
| A named policy or rule | For example, only people with a `pro` role. Set it with the API (`policy`) or write the rule in [Policies](/policies/overview). |

A secret key always passes, as everywhere else in Pawabase.

<Warning>
A model that anyone can call is a way to spend your money. Prefer **Servers only**, and let your own server decide what a user may ask. If you must open a model to browsers, set a cap with your provider and keep an eye on **Usage & logs**.
</Warning>

## Playground

**AI → Playground** (or **Try** on a model) is a chat with the model, as your app would call it: the whole conversation is sent each time, so the model remembers it. Set instructions, temperature and the longest answer on the right. For an embedding model it shows the size of the vector and a preview. Every message shows its time and tokens, and counts in Usage & logs as coming from Studio.

## Usage and logs

**AI → Usage & logs** shows, over a day, week or month: calls, failures, tokens in and out, cost and average time, in all and per model, plus a list of recent calls with their result.

A record holds the model, provider, status, tokens, time, cost, who called (a user id or key id) and where from (`api`, `flow`, `studio`, `embed`). It holds a short reason for a failure and **never the prompt or the answer.**

## Limits

| | |
| --- | --- |
| Request body | 4 MB |
| Messages in one conversation | 500 |
| Texts in one embeddings request | 2,048 and 400,000 characters in all |
| A provider that does not answer | Gives up after 2 minutes |

## From code

<CodeGroup>
```typescript TypeScript
import { manage } from "@pawabase/client/manage";

const ai = manage(pawabase).ai;
await ai.connect({ name: "openai", kind: "openai", key: process.env.OPENAI_API_KEY! });
await ai.addModel({ alias: "chat", provider: "openai", upstream: "gpt-4o-mini", inputPrice: 0.15, outputPrice: 0.6,
  params: { system: "You are a helpful assistant for Acme." } });
await ai.addModel({ alias: "embed", provider: "openai", upstream: "text-embedding-3-small", kind: "embedding" });
const week = await ai.usage({ days: 7 });
```

```python Python
ai = pb.manage.ai
ai.connect(name="openai", kind="openai", key=os.environ["OPENAI_API_KEY"])
ai.add_model(alias="chat", provider="openai", upstream="gpt-4o-mini", input_price=0.15, output_price=0.6,
             params={"system": "You are a helpful assistant for Acme."})
ai.add_model(alias="embed", provider="openai", upstream="text-embedding-3-small", kind="embedding")
week = ai.usage(days=7)
```
</CodeGroup>

The settings a model may default are `system`, `temperature`, `top_p`, `max_tokens`, `max_completion_tokens`, `stop`, `presence_penalty`, `frequency_penalty`, `seed`, `reasoning_effort` and `response_format`. Anything else is refused, so a typo does not silently do nothing.
