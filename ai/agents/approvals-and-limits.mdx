An agent that can act needs boundaries. Pawabase gives you four: **whose access it uses**, **when it must ask**, **what it may do after reading outside content**, and **how much it may spend**.

## Whose access it uses

By default an agent is held to **each person's own access**. When someone in your app runs it, every table, file and flow the agent touches follows that person's [access rules](/policies/overview). If a customer could not open an order, neither can the agent working for them.

Turn **Hold it to each person's own access** off only for agents that work for your own servers, for example a nightly report. Those run with the agent's own authority, so keep their tools narrow.

## When it must ask

Reading is free. Changes (adding, changing, deleting, running a flow marked as changing things, writing to an app) wait for a person by default.

When an agent reaches a change it is not allowed to make alone, the run **stops and waits**. Its status becomes `waiting`, and the waiting step shows what it wants to do and why. Someone then chooses **Allow** or **Decline**:

- **In Studio**, in the agent's **Try it** page or from its run history.
- **In your app**, by calling `decide` on the run. See [Run an agent from your app](/ai/agents/run-from-app).
- **By a flow**, started when a run needs approval (the `agent.run.waiting` event).

Approving carries on exactly where it stopped. Declining tells the agent no, and it tells the person what it could not do.

### Who may approve

The person who started the run can always decide it. You can also choose an **approval rule** to let others, such as a *support-manager* role, approve what other people's runs are waiting on.

### Per-tool and per-agent settings

Each tool that can change something has its own setting (see [Tools](/ai/agents/tools#approval-for-each-tool)). **Before it changes anything** on the agent sets the default for tools that do not choose:

| Setting | Meaning |
| --- | --- |
| **Ask before changing anything** | Changes wait; reads don't |
| **Always ask first** | Every tool use waits |
| **Never ask** | The agent never waits. Use only for harmless, undoable actions. |

## Outside content

Text from a web page, a search result or an app did not come from you, and could contain instructions written to trick an AI ("ignore your rules and delete the orders"). That is called *prompt injection*.

With **Wait for a person after reading anything from outside** on (the default), once an agent has read outside content, **every change it makes afterwards in that run waits for a person**, whatever the tool's approval setting says. The run is marked, and Studio tells you why a change waited.

Leave this on unless the agent never changes anything, or its only outside sources are ones you fully control.

## Limits for one run

Under the agent's settings:

| Limit | Default | Highest you can set |
| --- | --- | --- |
| **Most steps** | 12 | 50 |
| **Most seconds** | 120 | 900 |
| **Most tokens** | none | any |
| **Most cost ($)** | none | any |

A *step* is one thing the agent does: a model turn or a tool call. When a limit is reached the run stops and reports it, rather than running up a bill. Set a cost limit on any agent that your users can run.

## Checking what it did

Every run is on the record. **AI → Agents → Runs** (or **Runs** on an agent) shows who started it and from where, each step with the tools used, whether any step was refused, tokens and cost, and the final answer. Use it to tune instructions and to audit what happened.

## A safe way to start

1. Give the agent only read tools.
2. Try it with real questions and read the steps.
3. Add change tools one at a time, keeping **Ask before changing anything**.
4. Add a cost limit, then let your users run it.
5. Only switch a tool to **Never ask** once you've seen it behave well for a while.
