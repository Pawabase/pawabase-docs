## A support assistant that knows your orders

**You want:** customers ask about their orders in your app, and an assistant answers, and can start a refund once a person approves.

1. **Models.** Add a chat model named `chat`.
2. **Knowledge.** Create a knowledge base `help` and add your shipping and returns articles.
3. **A flow.** Build a `request-refund` flow that creates a refund request and notifies your team.
4. **The agent.** Create `support`:
   - **Instructions:** *You help customers with their orders. Answer from the help articles. Be brief. If asked for a refund, use the refund flow and say a person will confirm it.*
   - **Tools:** the `orders` table with **Find** and **Open**; the `request-refund` flow ticked **This flow changes things**; the `help` knowledge base.
   - **Who may run it:** signed-in users.
   - **Limits:** most cost `$0.25`.
5. **Your app.**

<CodeGroup>
```typescript TypeScript
const reply = await pawabase.ai.agents.run("support", question, { thread });
```

```python Python
reply = pb.ai.agents.run("support", question, thread=thread)
```
</CodeGroup>

Because the agent is held to each person's access, a customer can only ever see their own orders, whatever they ask.

## Answers from your own documents

**You want:** a "Ask the docs" box that answers from your help centre and shows where the answer came from.

1. Add an embedding model `embed` and a chat model `chat`.
2. Create a knowledge base `docs` and add your pages (web page or Notion).
3. Search and answer:

<CodeGroup>
```typescript TypeScript
const hits = await pawabase.ai.knowledge.search("docs", question, { limit: 4 });
const context = hits.map((h) => h.text).join("\n\n");
const answer = await pawabase.ai.chat("chat", [
  { role: "system", content: "Answer using only the notes below. If they don't say, say you don't know.\n\n" + context },
  { role: "user", content: question },
]);
// show answer, and hits[].source as the references
```

```python Python
hits = pb.ai.knowledge.search("docs", question, limit=4)
context = "\n\n".join(h["text"] for h in hits)
answer = pb.ai.chat("chat", [
    {"role": "system", "content": "Answer using only the notes below. If they don't say, say you don't know.\n\n" + context},
    {"role": "user", "content": question},
])
```
</CodeGroup>

Or give the `docs` knowledge base to an agent and let it do both steps.

## Search your products by meaning

**You want:** "something to drink tea from" finds the mug.

Add a **Vector** field to `products` that fills itself in from `title` and `description`, then call `similar`. See [Vector search](/ai/vector-search).

## Classify or summarise every new record

**You want:** every support ticket gets a category and a one-line summary when it arrives.

Build a flow triggered by the ticket being created, add an **Ask a model** block with the **JSON** option on, and save the result back to the ticket. See [AI in flows](/ai/flows).

## A research helper that writes to Notion

**You want:** an assistant that searches the web and files a summary in Notion.

1. Connect **Notion** and **Tavily** under **AI → Connections**.
2. Create an agent with **Search the web** (Tavily) and **Notion** (create pages).
3. Keep **Wait for a person after reading anything from outside** on. The agent reads the web, then asks before it writes anything. You approve, and the page appears.

## An assistant you review before it acts

**You want:** an agent that proposes changes to orders, and a manager approves them.

Set the table's **Change** tool to **Always ask first**, and choose an **approval rule** for your managers. Start a flow on `agent.run.waiting` that notifies them. They approve in your app with `decide`. See [Approvals and limits](/ai/agents/approvals-and-limits).
