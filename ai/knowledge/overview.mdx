A **knowledge base** is a collection of documents that Pawabase reads, splits into passages and indexes by *meaning*. An agent (or your own code) can then ask it a question and get back the most relevant passages, with where each came from.

Use one when you want an assistant to answer from **your** material instead of from what a model happens to remember: your help centre, return policy, product manuals, onboarding guide, meeting notes.

## How it works

1. You add documents: a file, a pasted text, a web page or pages from Notion.
2. Pawabase reads each one, splits it into passages and turns each passage into a vector with your embedding model.
3. When someone searches, Pawabase finds the passages closest in meaning *and* those that match the words, and returns the best.
4. An agent given the knowledge base searches it as one of its tools, and answers using what it found.

Documents are ready to search a few seconds after they are added. Each shows its status: **pending**, **ready**, or **failed** with the reason.

## Create one

You need an **embedding model** first (see [Providers and models](/ai/gateway)). Then:

<Steps>
  <Step title="Open AI → Knowledge → Create a knowledge base">
    Give it a name such as *Help articles* and say what is in it.
  </Step>
  <Step title="Choose the embedding model">
    Under **Using which model?** pick the embedding model. Keep the same model for the life of the base: its documents are indexed with it.
  </Step>
  <Step title="Choose who can search it">
    Under **Who can search it?** pick an [access rule](/policies/overview). By default only your servers can.
  </Step>
  <Step title="Add your first document">
    See [Add documents](/ai/knowledge/documents).
  </Step>
</Steps>

## Use it

| Where | How |
| --- | --- |
| **An agent** | Add the knowledge base under **What it can use**. The agent searches it when it needs facts. |
| **Studio** | Open the base and use **Try a search** ("How long do refunds take?") to see what an agent would find. |
| **Your code** | `pawabase.ai.knowledge.search(...)`. See [Search from your app](/ai/knowledge/documents#search-from-your-app). |

## Private documents for each user

A signed-in user can add documents that **only they** can find, for example their own notes or uploads. Their documents are kept out of everyone else's searches and out of an agent's answers for other people. Your servers can also add a document *for* one user.

## Keep it good

- **One topic per document** retrieves better than one giant file.
- **Update, don't duplicate.** Give each document a `source` (such as its URL or file name). Adding the same source again replaces the old version.
- **Try real questions** in **Try a search** before giving the base to an agent, and fix gaps by adding or rewriting documents.
- **Write documents as answers.** "Refunds take 5–7 business days" retrieves better than a vague paragraph.
