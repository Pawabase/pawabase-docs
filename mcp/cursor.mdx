Cursor connects to Pawabase using a remote HTTP MCP server. The project configuration lives in `.cursor/mcp.json`; you can also configure a user-level server in Cursor. A project file is useful when different repositories use different Pawabase environments.

## Prepare the environment

Open Studio, select the environment, and go to **MCP**. Copy the full URL and create a dedicated secret key. Choose **Look only** to inspect, or **Build with me** when the agent should create resources.

## Add the server

Create `.cursor/mcp.json` at the root of the project:

```json
{
  "mcpServers": {
    "pawabase": {
      "url": "https://YOUR-API-ADDRESS/mcp/v1",
      "headers": {
        "apikey": "YOUR_SECRET_KEY"
      }
    }
  }
}
```

Replace both placeholders with values from the **same** environment. Keep a file containing a real key out of version control. Add `.cursor/mcp.json` to `.gitignore` if your team has not already done so; commit a separate example file with placeholders if you want to document the project setup.

Open Cursor's MCP settings and confirm `pawabase` connects. In Agent chat, ask: “List Pawabase tables and describe the fields of `orders`.” Check the Studio **MCP** call history. When Cursor asks permission to run a tool, review the operation and its target environment.

## Team and production use

Each teammate should create their own key; sharing one key makes audit and revocation harder. For production, create a second entry with an explicit name such as `pawabase-prod-read` and a **Look only** key. When the key changes, update the local config and revoke the old key under **Settings → API keys**.

See [Cursor's MCP documentation](https://cursor.com/docs/mcp) for its settings and configuration options, and [troubleshooting](/mcp/troubleshooting) for Pawabase errors.
