---
title: "Troubleshoot MCP connections"
description: "Diagnose missing tools, HTTP errors, key problems, and client configuration."
icon: "circle-help"
---

Start with the exact MCP URL and a dedicated secret key from the same **Studio → MCP** environment. Verify the client supports **remote Streamable HTTP**, sends `apikey` on every request, and can reach the endpoint. Then use the symptoms below.

| Symptom | Likely cause | What to check |
| --- | --- | --- |
| 401 Unauthorized | Missing, revoked, malformed, or publishable key | Create a new secret key in the selected environment; check the `apikey` header |
| 403 Forbidden | Valid key lacks required scope, or request origin is rejected | Choose the right access preset; check server origin/network policy |
| 404 Not Found | Wrong API address or path | Copy the full URL from Studio; path must end in `/mcp/v1` |
| 405 Method Not Allowed | Client sent `GET` or `DELETE` | Use a Streamable HTTP client that sends JSON-RPC with `POST` |
| 400 protocol error | Unsupported MCP version or request shape | Negotiate a supported version and send valid JSON-RPC |
| Connection timeout | Server is unreachable from the client's network | Check DNS, HTTPS, firewall, proxy, and whether remote cloud connectors can reach it |
| Tool is missing | Scope does not permit it, or client has stale discovery | Inspect key preset, restart the client, and call `tools/list` again |
| Tool result has `isError: true` | The tool ran but its operation failed | Read the result text and inspect the operation's arguments and project state |

## Check the endpoint independently

Use the [initialize request](/mcp/custom-client) with `curl -i`. This separates Pawabase connectivity from editor or AI-client configuration. If the raw request succeeds, compare its URL and headers with the client config. Do not paste a real key into support tickets or screenshots.

## URL and environment mismatches

The URL displayed in Studio already ends in `/mcp/v1`; do not add the suffix again. A key is scoped to one environment. If you switch from development to production in the client, create a production key and use the production environment's MCP URL. A similarly named project is not enough to identify the right endpoint.

## Client-specific checks

- **Claude Code:** Run `claude mcp list`; confirm the server uses HTTP and the expected header. Re-add it after key rotation.
- **Claude Desktop:** A custom remote connector connects from Anthropic's infrastructure. Check the fixed request header and public reachability; a private VPN URL may work in your browser but fail in Claude.
- **Codex:** Confirm `PAWABASE_API_KEY` is in the environment that launched Codex. In `env_http_headers`, the value is the variable name, not the key.
- **Cursor and VS Code:** Ensure the config file uses the editor's expected schema and that the agent has enabled the server. A project config file containing a placeholder key will connect only after you replace it locally.
- **Self-hosted stdio:** Check the command path, working directory, and `PAWABASE_*` process settings. Remember that remote key scope presets do not govern the local stdio process.

## After it connects

Ask the client to list tables before making changes. Review the Studio **MCP** page or [audit log](/activity/audit-log) to see calls. If a write fails despite **Build with me**, inspect the tool's required arguments and whether it needs a broader scope. Do not jump to **Everything** just to clear an unexplained error.

If you suspect a key was exposed, revoke it immediately under **Settings → API keys**, create a replacement, and update only the affected client.
