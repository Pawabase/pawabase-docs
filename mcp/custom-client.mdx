Use this guide when you have your own AI application or an MCP-capable framework. Pawabase's remote endpoint implements **Streamable HTTP** with JSON responses. Send JSON-RPC 2.0 messages as `POST` requests to the environment URL ending in `/mcp/v1`. It is stateless: each request can be made independently. This endpoint does not use the older SSE transport.

## Connection inputs

| Input | Value |
| --- | --- |
| Endpoint | Full MCP URL copied from **Studio → MCP**, ending in `/mcp/v1` |
| Authentication | `apikey: pb_sk_...` header; `Authorization: Bearer pb_sk_...` also works on this endpoint |
| Request format | `Content-Type: application/json`, JSON-RPC 2.0 body |
| Response | JSON result or JSON-RPC error |
| Protocol version | Use a supported MCP version, such as `2025-06-18` |

Create a dedicated [scoped key](/mcp/keys) for the application. Keep it on your server or in a secret manager. A browser client must never receive a Pawabase secret key.

## Initialize

Use your HTTP library or an MCP SDK. The raw request below is useful for diagnosing a connection:

```bash
curl -i "https://YOUR-API-ADDRESS/mcp/v1" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "apikey: YOUR_SECRET_KEY" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"my-pawabase-client","version":"1.0.0"}}}'
```

Read the returned server capabilities and protocol version. Send the MCP `notifications/initialized` notification if your SDK requires it, then discover what this key can use. The endpoint also supports MCP versions `2024-11-05` and `2025-03-26`; negotiate the version your client supports.

## Discover tools, resources, and prompts

```bash
curl "https://YOUR-API-ADDRESS/mcp/v1" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "apikey: YOUR_SECRET_KEY" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}'
```

Read each tool's name, description, and input schema before calling it. Pawabase filters the list according to the key's scopes. Repeat the request with `resources/list` or `prompts/list` to inspect published resources and reusable prompts. A client should not assume every environment or key sees the same tools.

## Call a tool

After discovery, send `tools/call` with a tool name and arguments matching its schema:

```json
{
  "jsonrpc": "2.0",
  "id": 3,
  "method": "tools/call",
  "params": {
    "name": "TOOL_NAME_FROM_TOOLS_LIST",
    "arguments": {}
  }
}
```

Inspect the tool result. A JSON-RPC success can still contain `isError: true` for an application-level failure. Show the error to the user and do not treat it as a successful change. Some destructive operations have a `confirm` argument; an automated client can set it, so the key's scope must already reflect acceptable authority.

## Operational behavior

- `POST /mcp/v1` is the MCP endpoint. `GET` and `DELETE` return 405.
- A publishable key is rejected. A secret key for a different environment will not authorize this endpoint.
- Requests can be stateless; do not depend on a session ID unless your MCP SDK requires one for its own bookkeeping.
- Back off on repeated failures and do not send the key in logs, model prompts, or client-side code.
- Review calls in Studio **MCP** and the [audit log](/activity/audit-log), where tool calls are recorded as `mcp.tool`.

For a self-hosted local process, see [stdio and remote deployment](/mcp/self-hosted). For error responses, see [troubleshooting](/mcp/troubleshooting).
