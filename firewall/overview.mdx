The firewall decides what to do with a request **before** it reaches Auth, data or storage. Use it to block bad addresses and countries, rate-limit expensive paths like sign-in, and watch what it blocks.

## In Studio

**Access → Networking → Firewall.**

### How rules work

*Tried in order. The first allow or block that matches decides; log and rate-limit rules record or count and go on. A simulated rule only records what it would have done.*

**Rules** have: an **Action** (allow, block, log, rate limit), **conditions** on the request (path, method, header, country, address…), **Enabled**, and optionally **Simulate** ("record what it would do, without doing it") so you can try a rule safely.

Rule **templates** fill the form for you: *Rate-limit sign-in*, *Rate-limit the API*, *Block bad bots*, *Block countries*, *Block large uploads*, *Allow office addresses*. *Choose a template to fill in the form, then adjust it before creating your rule.*

Rate-limit rules also have **Limit**, **Counted by** (address, user, key…) and a window; **0 only refuses the excess.**

### Bans

*Addresses and ranges refused before any rule runs. Rate-limit rules and automatic bans add to this list; an allow rule still lets an address through.* Add a ban with **Address or range**, **Why** and **Expires**.

### Test

*Describe a request and see, step by step, what the firewall would do with it. Nothing is sent and nothing is counted.* Always test a new rule here first.

### Events

*Every request the firewall blocked, limited or logged, newest first.* Filter by action, source, address, path or rule.

## In code

<CodeGroup>
```typescript TypeScript
await m.firewall.addRule({
  name: "Burst on sign-in",
  action: "rate_limit",
  conditions: [{ field: "path", op: "starts_with", value: "/auth" }],
  rateLimit: { requests: 5, window_seconds: 60 },
});

await m.firewall.ban("203.0.113.7", { seconds: 3600, reason: "credential stuffing" });
const bans = await m.firewall.bans();
await m.firewall.liftBan(bans.data[0].id);

const verdict = await m.firewall.test("198.51.100.4", { path: "/auth/v1/token", method: "POST" });
const blocked = await m.firewall.events({ action: "block", limit: 50 });
const stats = await m.firewall.stats({ hours: 24 });
```

```python Python
pb.manage.firewall.add_rule({
    "name": "Burst on sign-in", "action": "rate_limit",
    "conditions": [{"field": "path", "op": "starts_with", "value": "/auth"}],
    "rate_limit": {"requests": 5, "window_seconds": 60},
})
pb.manage.firewall.ban("203.0.113.7", seconds=3600, reason="credential stuffing")
```
</CodeGroup>

Reorder with `m.firewall.order([ids])` (rules run in order); edit with `updateRule`; remove with `removeRule`.

## Recommended starting rules

1. Rate-limit `/auth` to a handful of requests a minute per address.
2. Rate-limit the API per key or user to protect your plan limits.
3. Allow your office addresses first, so a mistake can't lock you out.
4. Block known-bad bots and, if your market is local, countries you never serve.

Use [Attack protection](/auth/attack-protection) for account lockouts; the firewall works at the request level.
