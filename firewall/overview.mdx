The firewall decides what to do with a request **before** it reaches Auth, data or storage. Use it to block bad addresses and countries, rate-limit expensive paths like sign-in, and watch what it blocks.

## Where

**Access → Networking → Firewall.** It has a summary and pages for **Rules**, **Bans**, **Test** and **Events**.

## Rules

*Tried in order. The first allow or block that matches decides; log and rate-limit rules record or count and go on. A simulated rule only records what it would have done.*

**New rule:**

| Field | Meaning |
| --- | --- |
| **Name** | `Rate-limit sign-in` |
| **Action** | Allow, block, log, or rate limit |
| **Conditions** | Match on the request: path, method, header, country, address, role of the key |
| **Limit** and **Counted by** | For rate limits: how many in what window, and per what (address, user…). *0 only refuses the excess* |
| **Simulate** | *Record what it would do, without doing it* |
| **Enabled** | Pause without deleting |

**Templates** fill the form: *Rate-limit sign-in*, *Rate-limit the API*, *Block bad bots*, *Block countries*, *Block large uploads*, *Allow office addresses*. *Choose a template to fill in the form, then adjust it before creating your rule.* Drag rules to reorder: order matters.

## Bans

*Addresses and ranges refused before any rule runs. Rate-limit rules and automatic bans add to this list; an allow rule still lets an address through.* **Add a ban:** **Address or range**, **Why**, **Expires**.

## Test

*Describe a request and see, step by step, what the firewall would do with it. Nothing is sent and nothing is counted.* Always test a new rule here before enabling it.

## Events

*Every request the firewall blocked, limited or logged, newest first. Refreshes every few seconds.* Filter by action, source, address, path or rule.

## Recommended starting rules

1. Allow your office addresses first, so a mistake can't lock you out.
2. Rate-limit `/auth` to a handful of requests a minute per address.
3. Rate-limit the API per key or user to protect your plan limits.
4. Block known-bad bots; block countries you never serve.

Use [Attack protection](/auth/attack-protection) for account lockouts; the firewall works at the request level.
