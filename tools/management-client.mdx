The management client is the SDK's way of doing what Studio does, from a script. Use it for custom tooling, seeding and one-off migrations. For a whole backend kept in version control, use [infrastructure as code](/tools/iac/overview) instead.

<Warning>
It needs a **secret key** and must only run on a server or a developer machine. Never ship it to a browser.
</Warning>

## Get started

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";
import { manage } from "@pawabase/client/manage";

const m = manage(
  createClient({ url: process.env.PAWABASE_URL!, project: process.env.PAWABASE_PROJECT!, apiKey: process.env.PAWABASE_SECRET_KEY!, environment: "development" }),
);

const tables = await m.resources.list();
```

```python Python
import os
from pawabase import Pawabase

pb = Pawabase(os.environ["PAWABASE_URL"], os.environ["PAWABASE_SECRET_KEY"], project=os.environ["PAWABASE_PROJECT"], environment="development")

tables = pb.manage.resources.list()
```
</CodeGroup>

To act on another environment with the same key: `manage(pawabase, "staging")` in TypeScript, `pb.manage.environment("staging")` in Python.

## Every method

Every service, with the TypeScript name, the Python name and what it does, as of `@pawabase/client` 0.6.0 and `pawabase` 0.8.0. Python methods take the same arguments, with keyword arguments in snake_case (`dryRun` is `dry_run`). Answers are the server's JSON; list calls return `{ data: [...] }`.

Services marked **definitions** (`resources`, `policies`, `schemas`, `routes`, `flows`, `schedules`, `subscriptions`, `webhooks`, `inboundHooks`, `buckets`, `mailTemplates`, `agents`, `knowledgeBases`, `connections`) also have `list()`, `getOne(key)` (`get_one`), `create(body)`, `replace(key, body)` and `remove(key)`, which work on the definition as Studio saves it. The bodies are documented with each product, and in [infrastructure as code](/tools/iac/overview).

| `list(), getOne(key), create(body), replace(key, body), remove(key)` | `list(), get_one(key), create(body), replace(key, body), remove(key)` | The definitions themselves, as Studio saves them |
| `test(name)` | `test` | Call the service with the stored key and say what was found, or why it could not be reached. |

### Lifecycle

#### `environments`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list()` | `list` | Everything of this kind |
| `create(name, options)` | `create` | A new environment, optionally with another's definitions copied in. |
| `getOne(name)` | `get_one` | One environment |
| `update(name, changes)` | `update` | Change an environment's infrastructure, sign-in settings or settings; each is merged in. |
| `deleteEnvironment(name)` | `delete_environment` | Delete an environment and everything in it |
| `createPreview(ref, options)` | `create_preview` | A short-lived copy for a branch or pull request (`ref`: lowercase letters, digits and hyphens); it expires by itself. |
| `deletePreview(preview)` | `delete_preview` | Delete a preview now |
| `promote(to, options)` | `promote` | Copy this environment's definitions (never secrets or keys) to `to`. `include` limits the kinds; `dryRun` only reports what would change. |
| `blueprint()` | `blueprint` | Export definitions, roles and settings as a document another project can apply. |
| `applyBlueprint(blueprint, environments, "production"])` | `apply_blueprint` | Build new environments from a blueprint; each must not exist yet. |
| `reloadCode()` | `reload_code` | Re-read the deployed function code now. |

#### `versions`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list()` | `list` | The live API first, then every released version. |
| `check(fromEnv)` | `check` | Whether `fromEnv`'s definitions can be served here as a version, and what would be added or left out. |
| `release(name, fromEnv, options)` | `release` | Serve `fromEnv`'s definitions as `/rest/<name>` (`v2`, `v3`…). A name is never reused. |
| `retire(name)` | `retire` | Stop serving a version. |

#### `backups`

| TypeScript | Python | Does |
| --- | --- | --- |
| `download(options)` | `download` | A backup document: `definitions`, `settings`, `users` and, with `data`, rows (up to `maxRows` per table). |
| `restore(backup, options)` | `restore` | Put a downloaded backup back. |
| `setSchedule(options)` | `set_schedule` | Automatic snapshots: `frequency` hourly, daily (at `hour` UTC) or weekly (on `weekday`, 0 = Monday); older ones are pruned past `keepLast` and `keepDays`. |
| `snapshots()` | `snapshots` | Saved backups and the schedule |
| `snapshot(name, options)` | `snapshot` | Take a snapshot now and keep it. |
| `updateSnapshot(snapshotId, changes)` | `update_snapshot` | Rename it, annotate it, or pin it so pruning keeps it. |
| `removeSnapshot(snapshotId)` | `remove_snapshot` | Delete a saved backup |
| `downloadSnapshot(snapshotId)` | `download_snapshot` | A saved backup's contents |
| `verifySnapshot(snapshotId)` | `verify_snapshot` | Check the stored snapshot is intact. |
| `restoreSnapshot(snapshotId, options)` | `restore_snapshot` | Restore a snapshot; a snapshot of the current state is taken first unless `safetySnapshot` is `false`. |
## Common recipes

### Create a table and its table

<CodeGroup>
```typescript TypeScript
await m.resources.create({
  name: "tasks",
  owner_field: "owner_id",
  fields: [
    { name: "title", type: "string", required: true },
    { name: "done", type: "boolean", default: false },
  ],
  operations: { list: { enabled: true, policy: "owner" }, create: { enabled: true, policy: "authenticated" } },
});
await m.resources.migrate("tasks");            // create the database table
```

```python Python
pb.manage.resources.create({
    "name": "tasks",
    "owner_field": "owner_id",
    "fields": [{"name": "title", "type": "string", "required": True}, {"name": "done", "type": "boolean", "default": False}],
    "operations": {"list": {"enabled": True, "policy": "owner"}, "create": {"enabled": True, "policy": "authenticated"}},
})
pb.manage.resources.migrate("tasks")
```
</CodeGroup>

### Change sign-in settings

<CodeGroup>
```typescript TypeScript
await m.environments.update("production", { auth: { signup_enabled: true, require_email_verification: true } });
```

```python Python
pb.manage.environments.update("production", auth={"signup_enabled": True, "require_email_verification": True})
```

## Good practice

- Prefer **IaC** for anything you want reviewed and repeated; use this client for scripts that act on *data* or *operations*.
- Always do `dryRun` first for bulk operations (`replay`, `redeliver_many`, `restore`).
- Keep the key in an environment variable; rotate it if it leaks.
- Treat results as `{ data: [...] }` for list calls.
