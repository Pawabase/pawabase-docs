Errors come from four places, each with its own shape:

| Where | Shape | Read |
| --- | --- | --- |
| `/oauth/authorize` | A redirect to your callback with `?error=…&error_description=…&state=…`, or (bad client or callback) a `400` JSON page | [Authorize](#authorize) |
| `/oauth/token`, `/oauth/revoke` | `{"error": "…", "error_description": "…"}` (RFC 6749) | [Token endpoint](#token-endpoint) |
| `/v1/…` | `{"error": "…", "message": "…", "details": …}` | [Management API](#management-api) |
| `/v1/projects/{ref}/studio/…` (from the project) | The project server's own body, usually `{"detail": "…"}` | [Inside a project](#inside-a-project) |

## Authorize

### Shown on Pawabase (no redirect)

| `error` | Cause | Fix |
| --- | --- | --- |
| `invalid_client` "No app has that client_id." | Wrong or deleted client id | Copy the client id from **Your apps** again. If the app was deleted, register a new one |
| `invalid_redirect_uri` "That redirect_uri is not registered for this app." | `redirect_uri` doesn't exactly match a registered one | Compare character by character: `http` vs `https`, `localhost` vs `127.0.0.1`, a trailing `/`, the port, the query. Add the exact URL in **Edit** |
| `invalid_redirect_uri` with no `redirect_uri` sent | The app has several callback URLs | Send `redirect_uri` |

### Sent to your callback

| `error` | Cause | Fix |
| --- | --- | --- |
| `access_denied` | The person clicked **Cancel** | Show a friendly message and the button again |
| `invalid_scope` "Unknown scope: …" | A typo, or a scope name from another platform | Use only the five [scopes](/tools/integrations/scopes-and-roles), space-separated |
| `invalid_scope` "This app may not ask for: …" | The scope is switched off in the app's settings | Switch it on in **Your apps → Edit**, or stop asking for it |
| `invalid_scope` "Ask for at least one scope." | `scope` was empty and the app allows none | Allow at least one scope in the app's settings |
| `unsupported_response_type` | `response_type` isn't `code` | Send `response_type=code`. Implicit flow (`token`) isn't supported |
| `invalid_request` "code_challenge must be an S256 challenge…" | `code_challenge_method=plain`, or a challenge that isn't 43–128 base64url characters | Send `S256` and the base64url SHA-256 of the verifier, **without** `=` padding |

### On the consent screen

| What the person sees | Cause | Fix |
| --- | --- | --- |
| "You need to be an admin or owner of an organization to connect this app." | Write scopes, and they're not an admin anywhere | Ask for read scopes only, or ask an admin of their organization to connect |
| An organization missing from the picker | Their role there is too low for the scopes | The same |
| "This connection can't go ahead" | The request is malformed in a way Pawabase can't send back | Check the parameters against [the reference](/tools/integrations/oauth-flow#parameters) |
| The sign-in page appears every time | Normal for a signed-out person | — |

## Token endpoint

| Status | `error` | `error_description` | Fix |
| --- | --- | --- | --- |
| 401 | `invalid_client` | "Unknown client." | Wrong client id |
| 401 | `invalid_client` | "The client secret is wrong." | Wrong or rotated secret. Basic auth needs `base64(client_id:client_secret)`; URL-encode both first if they contain `:` (they don't, but your library may expect it) |
| 401 | `invalid_client` | "Send the client secret, or use PKCE." | A code issued without a `code_challenge` needs the secret |
| 401 | `invalid_client` | "client_credentials needs the client secret." | Platform tokens always need the secret |
| 400 | `invalid_grant` | "The code is not valid." | Wrong code, a code for another app, or a typo when copying |
| 400 | `invalid_grant` | "The code was used already." | You exchanged it twice (a retry, a double-click, a page reload of the callback). The connection was ended; sign in again. Never retry an exchange |
| 400 | `invalid_grant` | "The code has expired." | More than 10 minutes between redirect and exchange |
| 400 | `invalid_grant` | "redirect_uri differs from the one the code was given for." | Send the same `redirect_uri` as at authorize, or leave it out |
| 400 | `invalid_grant` | "code_verifier does not match the code_challenge." | The verifier was lost or replaced: the session didn't survive the round trip (see [Common mistakes](#the-session-is-lost-between-login-and-callback)) |
| 400 | `invalid_grant` | "The refresh token is not valid." | Wrong token, or one from another app |
| 400 | `invalid_grant` | "The refresh token was revoked." | Already used (rotated), or disconnected. Connect again |
| 400 | `invalid_grant` | "The refresh token has expired." | Unused for 30 days. Connect again |
| 400 | `invalid_grant` | "The connection was removed." | An admin disconnected you. Connect again |
| 400 | `unauthorized_client` | "Only platform apps can act on their own organization…" | `client_credentials` on an OAuth app. Register a platform app |
| 400 | `invalid_scope` | … | A `client_credentials` scope the app may not ask for |
| 400 | `unsupported_grant_type` | "grant_type is authorization_code, refresh_token or client_credentials." | Typo in `grant_type`, or `password` (not supported) |

## Management API

| Status | `error` | Message | Cause and fix |
| --- | --- | --- | --- |
| 401 | `unauthorized` | "Send a token: Authorization: Bearer &lt;token&gt;." | No `Authorization` header, or not `Bearer` |
| 401 | `unauthorized` | "That token is not valid." | Garbled, unknown or revoked token; an expired personal token |
| 401 | `unauthorized` | "The access token has expired. Refresh it." | Refresh, then retry once |
| 401 | `unauthorized` | "That connection was removed." | Disconnected in Pawabase. Connect again |
| 401 | `unauthorized` | "That app no longer exists." | A platform token for a deleted app |
| 401 | `unauthorized` | "The person this token acts for no longer has an account." | The account was deleted or disabled |
| 403 | `forbidden` | "The person this token acts for is no longer a member of the organization." | They left. Someone else connects |
| 403 | `forbidden` | "This needs the \{role\} role or higher in \{org\}." | Their role is too low for this endpoint ([table](/tools/integrations/scopes-and-roles#role-needed-on-each-request)) |
| 403 | `forbidden` | "Only a platform app, with its client credentials, can hand its projects over." | `claim` with a person's token |
| 403 | `insufficient_scope` | "This token does not have the \{scope\} scope." | Ask for the scope in `details.needed` |
| 404 | `not_found` | "That project in this organization was not found." | Wrong `ref`, a deleted project, a project claimed away, or a project in another organization |
| 404 | `not_found` | "That organization was not found." | `GET /v1/organizations/{slug}` with another organization's slug |
| 409 | `not_ready` | "The project is not running…" | Wait for `state: "running"` before calling inside it; restore a paused project |
| 409 | `not_ready` | "This project cannot be paused or restored right now." | Pausing or restoring while creating or failed |
| 409 | `protected` | "This project is protected…" | Deletion protection is on; a person must switch it off |
| 409 | `has_app` | "That project already has an app…" | Deploy into a new project |
| 409 | `not_running` | "That project isn't running…" | Restore it first |
| 402 | `plan_limit` | "The \{plan\} plan allows \{n\} projects…" | `details.limit`, `details.used`. The organization upgrades or deletes a project |
| 402 | `plan_feature` | … | The marketplace app needs a plan feature |
| 415 | `unsupported_media_type` | "Send JSON." | A Studio API call with a non-JSON body |
| 422 | `invalid` | … | `details` maps each bad field to a message |
| 422 | `missing_values` | "\{App\} needs \{names\}." | Pass `values` for `details.missing` |
| 502 | `unreachable` | "The project's server could not be reached…" | Retry with backoff |

### Retrying

| Status | Retry? |
| --- | --- |
| 401 "expired" | After refreshing, once |
| Other 401, 403, 404, 422 | No: the request won't succeed unchanged |
| 409 `not_ready` | Yes, after the project is running |
| 402 | No: needs a person to act |
| 502, network errors | Yes, with exponential backoff (1 s, 2 s, 4 s, …, up to a minute) |
| `POST /v1/projects` after a network error | Check `GET /v1/projects` for it first: the first attempt may have succeeded |

## Inside a project

Calls through `/v1/projects/{ref}/studio/…` can fail in Cloud (with the shapes above) or in the project. The project's answers pass through unchanged:

| Status | Typical body | Cause |
| --- | --- | --- |
| 403 | `{"detail": "…"}` | The path isn't allowed for a project-confined session (another environment, `promote`, `previews`, `infra`, an unknown path). See [What is refused](/tools/integrations/project-api#what-is-refused) |
| 404 | `{"detail": "Not Found"}` or `{"status": 404, "error": "Not Found", …}` | No such route (check the target and path) or no such definition |
| 409 | `{"detail": "…"}` | A definition with that name exists; a blueprint into a non-empty environment |
| 422 | `{"detail": [...]}` | The definition doesn't validate. The list says which field and why |

A `404` with `"The page you are looking for does not exist."` almost always means a wrong path shape: `platform/envs/{env}/…` and `auth/envs/{env}/…` have `envs/`; `object/{env}/…` and the other targets don't.

## Common mistakes

### The session is lost between login and callback

**Symptom:** "state mismatch" in your own check, or `invalid_grant` "code_verifier does not match".

**Causes:**
- The session cookie is `SameSite=Strict`. Use `Lax`: the callback is a cross-site navigation.
- You started on `localhost` and the callback is `127.0.0.1` (or the reverse). Cookies are per host. Use the same host everywhere.
- The session lives in memory and the server restarted, or the callback hit another server instance. Store sessions in a shared store.
- The cookie is `Secure` on an `http://` development address. Browsers drop it.

### The code is used twice

**Symptom:** the first sign-in works, then the connection immediately stops; or `invalid_grant` "used already".

**Causes:** a framework that runs the callback handler twice (React strict mode in a client-side callback, a prefetch, a browser that retries), or a retry on a timeout. Exchange codes on the server, once, and redirect away from the callback URL straight after so a reload doesn't repeat it.

### Connections end at random

**Symptom:** `invalid_grant` "The refresh token was revoked." for people who didn't disconnect.

**Cause:** concurrent refreshes (two workers, two tabs, a background job and a request). The second refresh used a spent token and Pawabase ended the connection. Serialise refreshes; see [Reuse detection](/tools/integrations/oauth-flow#reuse-detection).

### Everything is 403 for one customer

**Cause:** the person who connected left the organization or was demoted. `GET /v1/token` still works (it needs no scope) and shows the role; if it's `403 forbidden` "no longer a member", ask an admin of that organization to connect again.

### `POST /v1/projects` works but building inside fails

**Causes:**
- Calling inside before `state` is `running`: `409 not_ready`. Poll first.
- Using `environment` from a project that wasn't running yet: use `default_environment` from a running project.
- A token with `projects:write` but not `project:write`.
- The person is a member: creating needs member, changing inside needs admin.

### The consent screen shows no organizations

**Cause:** the scopes need admin (any write scope) and the person isn't an admin anywhere. Ask for fewer scopes, or let them know an admin needs to connect.

### Works locally, fails in production

**Causes:** the production callback URL isn't registered (or is `http`); the production secret is from another app; `PAWABASE_URL` still points at a development Cloud.

## Getting help

When asking for help, include:

- the client id (never the secret),
- the endpoint, method and time of the failing request,
- the full error body,
- for `/v1`, what `GET /v1/token` answers with the same token.

Never include secrets, access tokens, refresh tokens or personal tokens.
