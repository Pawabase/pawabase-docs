`/v1/projects/{ref}/studio/{path}` is the door into a project. It reaches the same API that Pawabase Studio uses, so anything a person does in Studio, a connected product can do through it: define tables, write access rules, build flows, manage users, edit mail templates, create buckets, set secrets, make keys, install blueprints.

Pawabase Cloud stands in the middle. For each call it checks the token, the scope and the person's role, then signs a short-lived request for **that one project** and forwards it to the project's server. The project's server only accepts paths that stay inside the project.

## The shape of a call

```
{METHOD} https://dashboard.pawabase.cloud/v1/projects/{ref}/studio/{target}/{path}?{query}
Authorization: Bearer <token>
Content-Type: application/json
```

| Part | Meaning |
| --- | --- |
| `{ref}` | The project's `ref` (its slug) or its `id` |
| `{target}` | Which part of the project's server: `platform`, `auth`, `realtime`, `telemetry`, `gateway`, `object`, `avatar`, `document` |
| `{path}` | The path under that target. Most start with `envs/{env}/…` (`platform`, `auth`) or `{env}/…` (the others) |
| `{env}` | The environment's **full name**, as in `default_environment` or `environments[].key` from [`GET /v1/projects/{ref}`](/tools/integrations/management-api#projects) |
| `{query}` | Passed on unchanged |
| Body | JSON only. Passed on unchanged |

| Method | Scope | Least role |
| --- | --- | --- |
| `GET` | `project:read` | member |
| `POST`, `PUT`, `PATCH`, `DELETE` | `project:write` | admin |

The answer is the project server's answer, **unchanged**: same status, same JSON. Errors from inside the project have the project server's shape (usually `{"detail": "..."}`, or `{"error", "message"}`), not the Management API's.

## Targets

| Target | Reaches | Example path |
| --- | --- | --- |
| `platform` | Definitions and settings of an environment: tables, rules, flows, routes, buckets, mail templates, webhooks, schedules, secrets, keys, blueprints, the API description | `platform/envs/{env}/resources` |
| `auth` | The environment's users and organizations: list, create, update, disable, reset two-step verification, sessions | `auth/envs/{env}/users` |
| `realtime` | The environment's realtime channels: publish, look at presence | `realtime/{env}/…` |
| `telemetry` | Logs, traces and metrics Studio's Activity pages read | `telemetry/{env}/…` |
| `gateway` | Request logs and usage | `gateway/{env}/…` |
| `object` | Files in the environment's buckets | `object/{env}/{bucket}/{key}` |
| `avatar` | Users' profile pictures | `avatar/{env}/…` |
| `document` | Knowledge-base documents | `document/{env}/…` |

Plus a few paths with no environment: `platform/blocks` (the flow-block catalogue), `platform/runtime` (filtered to this project) and `platform/key-scopes` (the scopes an API key can hold), all `GET`.

## Find the environment first

Every useful path names an environment, so start with the project:

<CodeGroup>
```typescript TypeScript
const project = await pawabase(token, "GET", `/projects/${ref}`);
const env = project.default_environment; // e.g. "acme-shop-x7k2-development"
const studio = (method: string, path: string, body?: unknown) =>
  pawabase(token, method, `/projects/${ref}/studio/${path}`, body);
```

```python Python
project = pawabase(token, "GET", f"/projects/{ref}")
env = project["default_environment"]  # e.g. "acme-shop-x7k2-development"


def studio(method: str, path: str, body=None):
    return pawabase(token, method, f"/projects/{ref}/studio/{path}", body)
```
</CodeGroup>

The examples below use `studio(...)` and `env` from here.

## Definitions

Every kind of definition has the same five routes under `platform/envs/{env}/{kind}`:

| Method | Path | Does |
| --- | --- | --- |
| `GET` | `platform/envs/{env}/{kind}` | List them |
| `POST` | `platform/envs/{env}/{kind}` | Create one |
| `GET` | `platform/envs/{env}/{kind}/{name}` | Read one |
| `PUT` | `platform/envs/{env}/{kind}/{name}` | Replace one (send the whole definition) |
| `DELETE` | `platform/envs/{env}/{kind}/{name}` | Delete one |

The kinds:

| `{kind}` | What it is | Docs |
| --- | --- | --- |
| `resources` | Tables and their API | [Tables and resources](/database/tables-and-resources) |
| `schemas` | Validation schemas | [Schemas](/database/schemas) |
| `policies` | Named access rules | [Access rules](/policies/overview) |
| `routes` | Custom API routes | [Routes](/logic/routes) |
| `flows` | Server logic | [Flows](/logic/flows) |
| `subscriptions` | Event subscriptions | [Events](/automation/events) |
| `webhooks` | Outgoing webhooks | [Webhooks](/automation/webhooks) |
| `inbound-hooks` | Incoming webhooks | [Inbound hooks](/automation/inbound-hooks) |
| `schedules` | Timed jobs | [Schedules](/automation/schedules) |
| `buckets` | File storage buckets | [Buckets](/storage/buckets) |
| `mail-templates` | Email templates | [Templates](/mail/templates) |
| `connections` | Connected apps for agents | [AI agents](/ai/agents/overview) |
| `knowledge-bases` | Documents agents search | [AI agents](/ai/agents/overview) |
| `agents` | AI agents | [AI agents](/ai/agents/overview) |

Each definition is validated before it is stored. A rule that doesn't parse, a flow that names a missing block or a schedule whose cron expression is wrong is refused with `422` and a message saying why, so your product can show the person what to fix.

### Create a table

Creating a resource defines it; `migrate` then creates its table in the database.

<CodeGroup>
```typescript TypeScript
await studio("POST", `platform/envs/${env}/resources`, {
  name: "tasks",
  fields: [
    { name: "title", type: "string", required: true },
    { name: "done", type: "boolean" },
    { name: "rank", type: "integer" },
  ],
  owner_field: "owner_id",
  realtime: true,
  operations: {
    list: { enabled: true, policy: "owner" },
    get: { enabled: true, policy: "owner" },
    create: { enabled: true, policy: "authenticated" },
    update: { enabled: true, policy: "owner" },
    delete: { enabled: true, policy: "owner" },
  },
});
await studio("POST", `platform/envs/${env}/resources/tasks/migrate`);
```

```python Python
studio("POST", f"platform/envs/{env}/resources", {
    "name": "tasks",
    "fields": [
        {"name": "title", "type": "string", "required": True},
        {"name": "done", "type": "boolean"},
        {"name": "rank", "type": "integer"},
    ],
    "owner_field": "owner_id",
    "realtime": True,
    "operations": {
        "list": {"enabled": True, "policy": "owner"},
        "get": {"enabled": True, "policy": "owner"},
        "create": {"enabled": True, "policy": "authenticated"},
        "update": {"enabled": True, "policy": "owner"},
        "delete": {"enabled": True, "policy": "owner"},
    },
})
studio("POST", f"platform/envs/{env}/resources/tasks/migrate")
```
</CodeGroup>

The resource body's fields:

| Field | Value |
| --- | --- |
| `name` | Lowercase letters, digits and `_`, starting with a letter, up to 63 characters. Becomes `/rest/v1/{name}` |
| `fields` | `[{name, type, required?, unique?, default?, write_only?, ...}]` |
| `operations` | Which of `list`, `get`, `create`, `update`, `delete` are on, and the rule each uses |
| `owner_field` | A field Pawabase fills with the signed-in user's id on create |
| `id_type` | `ulid` (default), `uuid` or `integer` |
| `relations` | Links to other resources |
| `realtime` | Announce changes to subscribed clients |
| `events` | Emit `created`, `updated`, `deleted` events for flows (default on) |
| `timestamps` | Add `created_at` and `updated_at` (default on) |
| `cache_ttl` | Seconds to cache list and get answers (0–86400) |
| `rate_limit` | Per-operation limits |
| `indexes` | `[{name, columns, unique?, where?, method?}]` |

The full reference, with every field type and option, is in [Tables and resources](/database/tables-and-resources) and [Columns and types](/database/columns-and-types).

### Read what exists

<CodeGroup>

```typescript TypeScript
const tables = await studio("GET", `platform/envs/${env}/resources`);
const flows = await studio("GET", `platform/envs/${env}/flows`);
const one = await studio("GET", `platform/envs/${env}/flows/order_paid`);
```

```python Python
tables = studio("GET", f"platform/envs/{env}/resources")
flows = studio("GET", f"platform/envs/{env}/flows")
one = studio("GET", f"platform/envs/{env}/flows/order_paid")
```
</CodeGroup>

Lists answer `{"data": [...]}`.

### Change or remove one

`PUT` replaces the whole definition: read it, change what you need, send it all back. `DELETE` removes it.

<CodeGroup>
```typescript TypeScript
const current = await studio("GET", `platform/envs/${env}/schedules/nightly_report`);
await studio("PUT", `platform/envs/${env}/schedules/nightly_report`, { ...current, cron: "0 3 * * *" });
await studio("DELETE", `platform/envs/${env}/webhooks/old_hook`);
```

```python Python
current = studio("GET", f"platform/envs/{env}/schedules/nightly_report")
studio("PUT", f"platform/envs/{env}/schedules/nightly_report", {**current, "cron": "0 3 * * *"})
studio("DELETE", f"platform/envs/{env}/webhooks/old_hook")
```
</CodeGroup>

## The API description

`GET platform/envs/{env}/openapi` answers the environment's OpenAPI 3 document: every table, route and flow the project serves, with their request and response shapes. An IDE can use it to generate a typed client for the person's app, or give it to an AI model as context.

## Users

User administration is under the `auth` target:

| Method | Path | Does |
| --- | --- | --- |
| `GET` | `auth/envs/{env}/users` | List users (`{"data": [...]}`), with search and paging in the query |
| `POST` | `auth/envs/{env}/users` | Create a user |
| `GET` | `auth/envs/{env}/users/{user_id}` | Read one |
| `PATCH` | `auth/envs/{env}/users/{user_id}` | Change one (name, metadata, disabled, …) |
| `DELETE` | `auth/envs/{env}/users/{user_id}` | Delete one |
| `POST` | `auth/envs/{env}/users/{user_id}/sessions/revoke` | Sign them out everywhere |
| `DELETE` | `auth/envs/{env}/users/{user_id}/sessions/{session_id}` | End one session |
| `POST` | `auth/envs/{env}/users/{user_id}/mfa/reset` | Remove their two-step verification |
| `GET` | `auth/envs/{env}/users/{user_id}/history` | Their sign-in history |

The sign-in settings themselves (methods, password policy, providers, redirect URLs) are under `platform/envs/{env}/auth`.

These are the **project's** users — the people who use the app the person is building — not Pawabase accounts.

## Secrets

| Method | Path | Does |
| --- | --- | --- |
| `GET` | `platform/envs/{env}/secrets` | List secrets: names and versions, never values |
| `POST` | `platform/envs/{env}/secrets` | Set one: `{"name", "value"}` |
| `POST` | `platform/envs/{env}/secrets/{name}/rotate` | New value |
| `POST` | `platform/envs/{env}/secrets/{name}/rollback` | Back to the previous value |
| `DELETE` | `platform/envs/{env}/secrets/{name}` | Delete |

A product that connects a person's Stripe or OpenAI account to their project stores the key here, where flows read it, instead of in its own database.

## API keys

The [Management API's key endpoints](/tools/integrations/management-api#api-keys) cover listing and creating. Through the Studio API you can also:

| Method | Path | Does |
| --- | --- | --- |
| `POST` | `platform/envs/{env}/keys/{key_id}/rotate` | New secret value for the key; the old one stops |
| `POST` | `platform/envs/{env}/keys/{key_id}/revoke` | Stop the key |

Revoke the keys your product made when a person disconnects it.

## Blueprints

A blueprint is a whole backend in one file: tables, rules, flows, templates, sample data. See [Blueprints](/tools/blueprints).

| Method | Path | Does |
| --- | --- | --- |
| `GET` | `platform/envs/{env}/blueprint` | Export the environment as a JSON blueprint (the older format) |
| `POST` | `platform/envs/{env}/blueprint/install` | Install a blueprint into an **empty** environment: `{"bundle": "<base64 zip>", "variables": {...}}` |

The install is rehearsed in a scratch environment first; if any part would fail, nothing is installed and the answer says why. An environment that already has definitions is refused with `409`.

<Note>
The Studio API relays JSON only. The zip export (`blueprint.zip`) and other binary downloads don't pass through it. To read files, create an API key and use the project's own [storage API](/storage/download) at `endpoints.api`.
</Note>

## Environment versions

`GET platform/envs/{env}/versions` lists the environment's saved API versions (see [API versions](/environments/api-versions)).

## What is refused

The project's server checks every path against an allow-list and refuses, with `403`, anything that isn't known to stay inside the project:

| Refused | Why |
| --- | --- |
| Another project's environment | `{env}` must be one of this project's environments |
| `…/promote` and `…/previews` under an environment | They create or change **another** environment |
| `DELETE platform/envs/{env}` | Deleting an environment is done by deleting the project |
| Writes to an environment's `infra` | It could point the environment at someone else's database or storage |
| `platform/usage` beyond this project, the runtime's audit log | They cover every project on the server |
| Any path that isn't on the list | Fails closed: unknown means refused |

`POST platform/envs` (a new environment) is allowed: the new environment is filed under this project.

## Who did it

Each request Cloud signs for the project names who is calling: `ada@acme.com via Lumen` for a person's connection, `app:Lumen` for a platform app's own token, and the person's email for a personal token. The project's server records changes under that name, so the people working in the project can tell which changes came from your product.

In the organization, Cloud's own activity log also records the project-level actions (`project.created`, `project.deleted`, `integration.key_created`, …) by the person (or `app:<client id>` for a platform token); `integration.key_created` also notes the full `… via …` name.

## Timeouts and size

- A call waits up to **120 seconds** for the project's server. Blueprint installs of large apps take tens of seconds; give your HTTP client a timeout above 120 s.
- If the project's server can't be reached, the answer is `502 unreachable` from Cloud. Retry with backoff.
- If the project isn't `running` (creating, paused, failed), the answer is `409 not_ready` from Cloud.

## A worked example: build a todo backend

An AI app builder asked to "make me a todo app backend" might do this, end to end:

<CodeGroup>
```typescript TypeScript
// 1. A new project, ready to use.
let project = await pawabase(token, "POST", "/projects", { name: "Todos" });
while (project.state === "creating") {
  await new Promise((r) => setTimeout(r, 2000));
  project = await pawabase(token, "GET", `/projects/${project.ref}`);
}
const ref = project.ref, env = project.default_environment;
const studio = (m: string, p: string, b?: unknown) => pawabase(token, m, `/projects/${ref}/studio/${p}`, b);

// 2. A table each person owns.
await studio("POST", `platform/envs/${env}/resources`, {
  name: "todos",
  fields: [{ name: "title", type: "string", required: true }, { name: "done", type: "boolean" }],
  owner_field: "owner_id",
  operations: Object.fromEntries(["list", "get", "update", "delete"].map((op) => [op, { enabled: true, policy: "owner" }])
    .concat([["create", { enabled: true, policy: "authenticated" }]])),
});
await studio("POST", `platform/envs/${env}/resources/todos/migrate`);

// 3. A key for the app's browser code.
const key = await pawabase(token, "POST", `/projects/${ref}/api-keys`, { name: "Todos web", role: "publishable" });

// 4. Hand the app what it needs.
console.log({ PAWABASE_URL: project.endpoints.api, PAWABASE_ENV: env, PAWABASE_KEY: key.key });
```

```python Python
import time

# 1. A new project, ready to use.
project = pawabase(token, "POST", "/projects", {"name": "Todos"})
while project["state"] == "creating":
    time.sleep(2)
    project = pawabase(token, "GET", f"/projects/{project['ref']}")
ref, env = project["ref"], project["default_environment"]


def studio(method, path, body=None):
    return pawabase(token, method, f"/projects/{ref}/studio/{path}", body)


# 2. A table each person owns.
owner_only = {"enabled": True, "policy": "owner"}
studio("POST", f"platform/envs/{env}/resources", {
    "name": "todos",
    "fields": [{"name": "title", "type": "string", "required": True}, {"name": "done", "type": "boolean"}],
    "owner_field": "owner_id",
    "operations": {"list": owner_only, "get": owner_only, "update": owner_only, "delete": owner_only,
                   "create": {"enabled": True, "policy": "authenticated"}},
})
studio("POST", f"platform/envs/{env}/resources/todos/migrate")

# 3. A key for the app's browser code.
key = pawabase(token, "POST", f"/projects/{ref}/api-keys", {"name": "Todos web", "role": "publishable"})

# 4. Hand the app what it needs.
print({"PAWABASE_URL": project["endpoints"]["api"], "PAWABASE_ENV": env, "PAWABASE_KEY": key["key"]})
```
</CodeGroup>

The person's app then uses the Pawabase client SDK with those three values, and signed-in users each see only their own todos.
