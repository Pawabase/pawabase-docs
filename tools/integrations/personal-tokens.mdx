A **personal access token** lets your own code call the [Management API](/tools/integrations/management-api) as you, without the OAuth flow. Use one for:

- a CI job that creates a preview project for each pull request and deletes it after,
- a script that installs a blueprint into every project of the organization,
- a deploy pipeline that sets secrets and updates flows from your repository,
- trying the API by hand while building an integration.

For a product other people use, register an [OAuth app](/tools/integrations/register-an-app) instead: a personal token always acts as **you**.

## How it differs from an OAuth connection

| | Personal access token | OAuth connection |
| --- | --- | --- |
| Made by | You, in the dashboard | A person approving a product |
| Acts as | You | The person who approved |
| Lifetime | Your choice: 7, 30, 90 or 365 days, or never expires | Access 1 hour, refresh 30 days (rotating) |
| Refresh | Not needed | Required |
| Organization | The one you create it in | The one picked on the consent screen |
| Format | `pbp_` + 43 characters | A signed JWT |
| Listed in | **Your** tokens, on the Integrations page | **Connected apps**, for every admin |

Both are limited by the same [scopes and roles](/tools/integrations/scopes-and-roles), and checked against your current role on every request.

## Create one

<Steps>
  <Step title="Open Integrations">
    In the organization the token is for, open **Settings → Integrations**.
  </Step>
  <Step title="New token">
    In **Personal access tokens**, click **New token**.
  </Step>
  <Step title="Name it">
    Name it after where it will be used: "GitHub Actions: preview projects", "Laptop CLI". The name is how you'll recognise it later.
  </Step>
  <Step title="Choose when it expires">
    7, 30, 90 days, a year, or never. Shorter is safer. A token for CI should expire, with a reminder to replace it.
  </Step>
  <Step title="Choose scopes">
    Switch off everything the job doesn't need. A job that only reads logs needs `projects:read` and `project:read`.
  </Step>
  <Step title="Copy it">
    **Create token** shows the token once. Copy it into your CI's secret store or your password manager. Pawabase keeps only a hash.
  </Step>
</Steps>

Any member of the organization can create personal tokens, including viewers: the token can't do more than your role allows anyway. There is no role check when it's created, only on each use.

## Use it

Send it as a bearer token, exactly like an OAuth access token:

<CodeGroup>
```typescript TypeScript
const token = process.env.PAWABASE_TOKEN!; // pbp_…

const response = await fetch("https://dashboard.pawabase.com/v1/projects", {
  headers: { authorization: `Bearer ${token}` },
});
console.log(await response.json());
```

```python Python
import os
import httpx

token = os.environ["PAWABASE_TOKEN"]  # pbp_…

response = httpx.get("https://dashboard.pawabase.com/v1/projects", headers={"authorization": f"Bearer {token}"})
print(response.json())
```
</CodeGroup>

`GET /v1/token` answers `"kind": "personal"`, your user, and `"app": null`.

## A CI example: a project per pull request

<CodeGroup>
```typescript TypeScript
// preview.ts — run on pull request open and close
const PAWABASE = "https://dashboard.pawabase.com";
const token = process.env.PAWABASE_TOKEN!;
const pr = process.env.PR_NUMBER!;
const call = async (method: string, path: string, body?: unknown) => {
  const r = await fetch(`${PAWABASE}/v1${path}`, {
    method,
    headers: { authorization: `Bearer ${token}`, "content-type": "application/json" },
    body: body ? JSON.stringify(body) : undefined,
  });
  if (!r.ok) throw new Error(`${r.status} ${await r.text()}`);
  return r.json();
};

const name = `PR #${pr}`;
const existing = (await call("GET", "/projects")).find((p: any) => p.name === name);

if (process.env.PR_ACTION === "closed") {
  if (existing) await call("DELETE", `/projects/${existing.ref}`);
} else if (!existing) {
  let project = await call("POST", "/projects", { name, description: `Preview for pull request ${pr}` });
  while (project.state === "creating") {
    await new Promise((r) => setTimeout(r, 2000));
    project = await call("GET", `/projects/${project.ref}`);
  }
  const bundle = (await import("node:fs")).readFileSync("backend.zip").toString("base64");
  await call("POST", `/projects/${project.ref}/studio/platform/envs/${project.default_environment}/blueprint/install`, { bundle, variables: {} });
  console.log(`::notice::Preview backend at ${project.endpoints.api}`);
}
```

```python Python
# preview.py — run on pull request open and close
import base64, os, time
import httpx

PAWABASE = "https://dashboard.pawabase.com"
token = os.environ["PAWABASE_TOKEN"]
pr = os.environ["PR_NUMBER"]


def call(method, path, body=None):
    r = httpx.request(method, f"{PAWABASE}/v1{path}", headers={"authorization": f"Bearer {token}"}, json=body, timeout=130)
    r.raise_for_status()
    return r.json()


name = f"PR #{pr}"
existing = next((p for p in call("GET", "/projects") if p["name"] == name), None)

if os.environ.get("PR_ACTION") == "closed":
    if existing:
        call("DELETE", f"/projects/{existing['ref']}")
elif not existing:
    project = call("POST", "/projects", {"name": name, "description": f"Preview for pull request {pr}"})
    while project["state"] == "creating":
        time.sleep(2)
        project = call("GET", f"/projects/{project['ref']}")
    bundle = base64.b64encode(open("backend.zip", "rb").read()).decode()
    env = project["default_environment"]
    call("POST", f"/projects/{project['ref']}/studio/platform/envs/{env}/blueprint/install", {"bundle": bundle, "variables": {}})
    print(f"::notice::Preview backend at {project['endpoints']['api']}")
```
</CodeGroup>

The token needs `projects:read projects:write project:write`, and you need to be an admin (deleting projects and writing inside them need admin).

## See and revoke

**Personal access tokens** on the Integrations page lists **your own** tokens for this organization:

| Column | Meaning |
| --- | --- |
| **Name** | What you called it, and `pbp_…` with its last six characters |
| **Can** | Its scopes |
| **Expires** | When it stops working, or **Never** |
| **Last used** | The last request made with it |

**Revoke** stops it at once and removes it from the list. An expired token is greyed out, tagged **expired** and listed after the live ones; **Remove** clears it. Expired tokens are deleted automatically a month after they ran out.

You only see your own tokens: an admin can't see or revoke yours. If you leave the organization, your tokens for it stop working at once (they act as you, and you're no longer a member). If your account is disabled, all of them stop.

## Lifetime

- A token with an expiry stops at that moment, answering `401 unauthorized` "That token is not valid."
- A token that never expires lasts until you revoke it or leave the organization. Prefer an expiry, and calendar a reminder to replace it.
- There's no way to extend a token: make a new one, switch your job to it, revoke the old one.

## From code

The dashboard uses these actions with your dashboard session:

| Action | Body | Answer |
| --- | --- | --- |
| `POST /rest/v1/x/cloud/integrations.tokens.list` | `{}` | `{"data": {"tokens": [...]}}` |
| `POST /rest/v1/x/cloud/integrations.tokens.create` | `{"name", "scopes"?: [...], "days"?: 1–365}` | The token, with `token` once. Leave `days` out for a token that never expires |
| `POST /rest/v1/x/cloud/integrations.tokens.revoke` | `{"token": "<id>"}` | `{"data": {"revoked": "<id>"}}` |

A personal token can't create other personal tokens: these are dashboard actions, and integration tokens are refused there.

## Activity

`integration.token_created` and `integration.token_revoked` are recorded in the organization's activity, with your email and the token's name (never the token).

## Keep it safe

- Store it in a secret store: your CI's encrypted secrets, a password manager, a vault. Never commit it, never paste it in an issue or a chat.
- One token per place it's used, so revoking one doesn't break the others.
- If a token may have leaked, revoke it first, then work out what happened.
- `pbp_` is a fixed prefix so secret scanners can recognise Pawabase tokens. Add it to your scanner's patterns: `pbp_[A-Za-z0-9_-]{43}`.
