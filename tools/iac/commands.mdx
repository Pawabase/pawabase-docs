| Command | What it does |
| --- | --- |
| `pawabase init` | Start a project here: `pawabase.toml`, `infra/app.py`, `.env.example` |
| `pawabase validate` | Check every definition and reference. Contacts nothing |
| `pawabase plan` | Compare your code with the environment. Writes nothing |
| `pawabase deploy` | Apply the plan |
| `pawabase emulate` | Rehearse a deploy against a simulated environment |
| `pawabase whoami` | Show the effective settings and test the API key |

## Shared options

| Option | Meaning |
| --- | --- |
| `-e`, `--env` | The environment (overrides `pawabase.toml`; `PAWABASE_ENV`) |
| `--url` | The gateway (overrides `pawabase.toml`; `PAWABASE_URL`) |
| `--entry` | The file or folder of definitions |
| `--json` | Machine-readable output |

## `deploy` options

| Option | Meaning |
| --- | --- |
| `--dry-run` | Show the plan and stop (like `plan`) |
| `--yes` | Don't ask |
| `--mode merge\|override` | Leave extras (default) or delete them |
| `--force-secrets` | Resend secrets that haven't changed |
| `--no-migrate` | Don't create or extend database tables |

## `emulate` options

| Option | Meaning |
| --- | --- |
| `--reset` | Start the simulation from empty |

## Environment variables

| Variable | Meaning |
| --- | --- |
| `PAWABASE_API_KEY` | The deploy key (a secret key with the Deploy and configure preset) |
| `PAWABASE_URL` | The gateway |
| `PAWABASE_ENV` | The environment |

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | A failure or a refusal |
| `2` | `--yes` was needed (for example in CI) but not given |

## `whoami`

Run it first when something doesn't connect: it prints the URL, environment and entry in effect, and tests that the key works.
