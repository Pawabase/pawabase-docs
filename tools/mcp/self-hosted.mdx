Self-hosted Pawabase offers two MCP transports. Choose **remote HTTP** when your Pawabase API is reachable by the AI client. Choose **local stdio** when the client can start a Pawabase process on a trusted machine with access to your installation.

| Transport | Server | Authentication and boundary | Good fit |
| --- | --- | --- | --- |
| Remote HTTP | `https://YOUR-API/mcp/v1` | Environment secret key and its scopes | Hosted API, multiple clients, auditable per-client keys |
| Local stdio | `pawabase-server mcp` | Local process configuration and installation authority | Private development installation or a client on the server host |

## Remote HTTP

Run the Pawabase API server with MCP enabled and expose its endpoint over HTTPS. Create a secret key in the target environment, then give the client the full `/mcp/v1` URL and an `apikey` header. The HTTP endpoint can be disabled with `PAWABASE_MCP_ENABLED=false`; if you intend to use remote MCP, leave it enabled.

Test from the **same network** that will run the client. A Claude custom remote connector makes requests from Anthropic's cloud, even when you use Claude Desktop; a private localhost or VPN address will not be reachable by that connector. Other local clients, such as Claude Code, can reach a private address if their own machine can.

Use HTTPS for a public endpoint. Give each client its own key and scope. [Create keys in Studio](/tools/mcp/keys) and check [custom-client requests](/tools/mcp/custom-client) if your integration does not provide a UI.

## Local stdio

On the machine where the client runs, install Pawabase and make sure its normal `PAWABASE_*` configuration points to the intended installation. Launch the MCP server with `pawabase-server mcp`. For clients that accept an `mcpServers` command configuration, the shape is:

```json
{
  "mcpServers": {
    "pawabase-local": {
      "command": "/absolute/path/to/pawabase/.venv/bin/pawabase-server",
      "args": ["mcp"],
      "cwd": "/absolute/path/to/pawabase"
    }
  }
}
```

Replace both paths with your installation paths. The client starts the process and speaks MCP over its standard input and output. Local stdio has the authority of the Pawabase installation and its process environment; it is **not** restricted by a remote MCP API key preset. Give the process only the access you intend the AI client to have.

Do not put diagnostic output on the process's stdout, because stdout carries MCP messages. Use stderr or server logs for diagnostics. The `PAWABASE_MCP_ENABLED` switch controls the HTTP endpoint, not the local stdio command.

## Which path should I choose?

For a team or production environment, remote HTTP gives you one secret key per client, scope presets, and immediate revocation. For a private local developer setup, stdio avoids exposing an HTTP endpoint, but the local process's authority is broader. If a remote client cannot reach your self-hosted server, solve the network path before debugging keys.

See [troubleshooting](/tools/mcp/troubleshooting) for connectivity and authentication errors.
