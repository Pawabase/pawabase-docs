An MCP connection authenticates with a **secret API key** for one Pawabase environment. Studio creates keys with the permissions you choose. The MCP URL identifies the environment; the key determines which operations are allowed inside it. Both must point to the same environment.

## Get the URL and key in Studio

<Steps>
  <Step title="Open the environment">
    In Studio, open your project, select the environment you want the assistant to use, then open **MCP** in the environment navigation. Copy the full MCP URL shown there.
  </Step>
  <Step title="Create a dedicated key">
    Name it for its client, such as `Claude Code development` or `Codex production read`. One key per client makes rotation and audit easier.
  </Step>
  <Step title="Choose its access">
    Use **Look only** for inspection. Use **Build with me** for development work. Use **Everything** only when the assistant must administer users, keys, or secrets.
  </Step>
  <Step title="Copy and store the key">
    Studio displays the secret once. Store it in your password manager or machine's secret store. If you lose it, create a replacement and revoke the old key under **Settings → API keys**.
  </Step>
</Steps>

| Studio choice | Scope preset | Appropriate use |
| --- | --- | --- |
| Look only | `ai-read` | Inspect tables, flows, runs, logs, and usage |
| Build with me | `ai-build` | Build resources and change data, excluding users, keys, and secrets |
| Everything | `full` | Administer the whole environment, including sensitive operations |

Start production on **Look only**. Keep a separate **Build with me** key for development. The server hides tools that the key cannot use and checks authorization on each request. Asking the assistant to ignore a restriction does not change the key's scope.

## Which key type works?

MCP accepts a secret key, usually beginning with `pb_sk_`. A publishable key is for application clients and is rejected by the MCP endpoint. Supply the secret as either the `apikey` header or, for this MCP endpoint, `Authorization: Bearer YOUR_KEY`. The client guides use `apikey` because that is what Studio generates.

The URL is **not** the key. Copy both from the same environment. The API address in **Project Settings** is useful when constructing URLs, but the MCP page already shows the final endpoint.

## Store it according to the client

| Client | Preferred storage |
| --- | --- |
| Codex | Environment variable referenced by `env_http_headers` in `config.toml` |
| Claude Code | A dedicated key entered in the CLI command; protect local CLI configuration and shell history |
| Cursor or VS Code | Local, ignored editor configuration or a supported secret substitution mechanism |
| Claude custom connector | Fixed request header in connector settings; review who can use a shared organization connector |
| Custom application | Server-side secret manager, never frontend JavaScript |

Do not commit a real key to Git, paste it into a public issue, or put it in a browser app. If a key is exposed, revoke it under **Settings → API keys**, create a new one, and update the affected client. A revoked key stops authorizing new calls.

## Access checklist

1. Start with **Look only** and verify the client connects.
2. If it must build, create a second **Build with me** key for development.
3. Give production its own **Look only** key unless a specific task needs more access.
4. Review the **MCP** call history and [audit log](/activity/audit-log) after changes.
5. Revoke keys you no longer use.

<Warning>
An AI client's approval prompt and a tool's `confirm` argument are review steps. They do not reduce the authority of a leaked or over-scoped key. Choose scopes based on what the key may do without your supervision.
</Warning>

## Create a key through the management API

For automation, an authorized secret key can create an environment key through `POST /platform/v1/envs/development/keys` on the environment API address:

```bash
curl -X POST "https://YOUR-API-ADDRESS/platform/v1/envs/development/keys" \
  -H "apikey: EXISTING_AUTHORIZED_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name":"Codex MCP","role":"secret"}'
```

This creates a secret key; use Studio's MCP page for its guided AI access presets. See [keys and security](/reference/keys-and-security) for general API key behavior.
