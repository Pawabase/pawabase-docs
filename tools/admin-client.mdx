The admin client manages the people who sign in to **your** app (not your Pawabase team): create accounts, disable them, assign roles, end sessions, read sign-in history. It mirrors Studio's **Users & auth → People** pages.

<Warning>
It can read and change every user. It needs a **secret key**; never use it in a browser or app.
</Warning>

## Get started

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";
import { admin } from "@pawabase/client/admin";

const a = admin(createClient({ url: process.env.PAWABASE_URL!, project: process.env.PAWABASE_PROJECT!, apiKey: process.env.PAWABASE_SECRET_KEY!, environment: "production" }));

await a.users.create({ email: "ada@example.com", password: "a long passphrase", roles: ["editor"] });
const { data } = await a.users.search({ search: "ada" });
await a.users.update(data[0].id, { disabled: true });
```

```python Python
import os
from pawabase import Pawabase

pb = Pawabase(os.environ["PAWABASE_URL"], os.environ["PAWABASE_SECRET_KEY"], project=os.environ["PAWABASE_PROJECT"], environment="production")

pb.admin.users.create(email="ada@example.com", password="a long passphrase", roles=["editor"])
found = pb.admin.users.search(search="ada")["data"]
pb.admin.users.update(found[0]["id"], disabled=True)
```
</CodeGroup>

Another environment: `a.withEnvironment("staging")` / `pb.admin.environment("staging")`.

## Users

| Call | Does |
| --- | --- |
| `users.search({ search, status, limit, offset })` | Find people. `status`: `disabled`, `unverified`, `locked`, `mfa`, `no_mfa` |
| `users.getUser(id)` | One person |
| `users.create({...})` | Create an account without sign-up restrictions (`email`, `password`, `username`, `name`, `emailVerified` (default true), `userMetadata`, `appMetadata`, `roles`) |
| `users.update(id, {...})` | `name`, `emailVerified`, `disabled`, `password`, `userMetadata`, `appMetadata`, `roles` (replaces), `unlock` |
| `users.deleteUser(id)` | Remove the account |
| `users.history(id)` | Recent sign-ins and security events |
| `users.activity(id, { weeks })` | What they did over the last `weeks` weeks (max 53): counts per day by kind (`signin`, `account`, `request`), totals, and a summary (last seen, failures, busiest hour, top routes) |
| `users.timeline(id, { type, limit, before })` | Sign-ins, account changes and requests in one feed, newest first. `type`: `signin`, `account`, `request`. Pass `next_before` from the answer as `before` for the next page |
| `users.exportData(id)` | A data-access request: everything the sign-in service holds about them, as JSON. See [Data requests](/auth/data-requests) |
| `users.eraseData(id, confirm)` | An erasure request. **Final.** `confirm` is their email address |
| `privacy.requests({ limit })` | The exports and erasures handled so far (records hold no personal data) |
| `users.resetMfa(id)` | Remove their second factors |
| `users.grant(id, perms)` / `revoke` | Direct permissions |
| `users.revokeSessions(id)` / `revokeSession(id, sessionId)` | Sign out |
| `users.devices(id)` / `forgetDevice` | Trusted devices |
| `users.apiKeys(id)` | Their personal API keys (never the secrets) |

Python uses snake_case (`get_user`, `reset_mfa`, `revoke_sessions`, `delete_user`, `api_keys`, `export_data`, `erase_data(user_id, confirm=…)`).

## Roles, organizations, invitations

<CodeGroup>
```typescript TypeScript
await a.roles.define("editor", ["posts:read", "posts:write"], { description: "Can write posts" });
await a.orgs.create("acme", "Acme Inc", { ownerEmail: "ada@example.com" });
await a.orgs.addMember("acme", { email: "grace@example.com", role: "admin" });
await a.orgs.invite("acme", { email: "new@example.com", role: "member", redirectTo: "https://myapp.com/invite" });
const { data: pending } = await a.invitations.list();
```

```python Python
pb.admin.roles.put("editor", ["posts:read", "posts:write"], description="Can write posts")
pb.admin.orgs.create("acme", "Acme Inc", owner_email="ada@example.com")
pb.admin.orgs.add_member("acme", email="grace@example.com", role="admin")
pb.admin.orgs.invite("acme", email="new@example.com", role="member", redirect_to="https://myapp.com/invite")
```
</CodeGroup>

## Sessions, devices, keys, insight

| Call | Does |
| --- | --- |
| `sessions.list({ limit })`, `sessions.revoke(family)` | Active sessions across users |
| `devices.list`, `apiKeys.list`, `apiKeys.revoke(id)` | Devices and user API keys |
| `insight.events({ kind, failed, limit })` | Sign-in and security events |
| `insight.stats()` | Counts of users, sign-ins, MFA use, failures |
| `insight.backup()` / `insight.restore(doc, { replace, dryRun })` | Export and import identities |
| `insight.previewTokenProfile(profile, userId, { org })` | See what a token profile would contain |

See [Users](/auth/users), [Roles](/auth/roles), [Organizations](/auth/organizations), [Import and export](/auth/import-and-export) for the Studio side.

## Every method

Every service of the admin client, with the TypeScript name, the Python name and what it does. Python takes the same arguments as keyword arguments in snake_case. Two names differ: `roles.define` is `roles.put` in Python, and `machines.delete` is `machines.delete_machine`.

### `users`

| TypeScript | Python | Does |
| --- | --- | --- |
| `search(options)` | `search` | Find people: `search` matches email, username and name; `status` is `disabled`, `unverified`, `locked`, `mfa` or `no_mfa`; `limit`, `offset` |
| `getUser(userId)` | `get_user` | One person |
| `create(user)` | `create` | Create an account without the sign-up restrictions (allow-lists). The password policy still applies. `app_metadata` is for your server only |
| `update(userId, changes)` | `update` | Change profile fields, `user_metadata`, `app_metadata`, roles, disable or enable, unlock |
| `deleteUser(userId)` | `delete_user` | Delete the account |
| `history(userId)` | `history` | Recent sign-ins and security events |
| `activity(userId, { weeks })` | `activity` | What they did over up to 53 weeks: counts per day by kind, totals, last seen, busiest hour, most used routes |
| `timeline(userId, { type, limit, before })` | `timeline` | Sign-ins, account changes and requests in one feed, newest first; pass `next_before` as `before` for the next page |
| `exportData(userId)` | `export_data` | Everything the auth service holds about them, as JSON (a data-access request). Your own tables aren't included |
| `eraseData(userId, confirm)` | `erase_data` | Delete the account and clear what could identify them (an erasure request). Final; `confirm` is their email |
| `resetMfa(userId)` | `reset_mfa` | Remove their second factors so they can enrol again |
| `grant(userId, permissions)` | `grant` | Give permissions directly, beyond their roles' (`posts:write`, `billing:*`) |
| `revoke(userId, permissions)` | `revoke` | Take directly granted permissions away |
| `revokeSessions(userId)` | `revoke_sessions` | Sign them out everywhere |
| `revokeSession(userId, sessionId)` | `revoke_session` | End one of their sessions |
| `devices(userId)` | `devices` | Their devices |
| `forgetDevice(userId, deviceId)` | `forget_device` | Forget one device |
| `apiKeys(userId)` | `api_keys` | Their own API keys (never the secrets) |

### `roles`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list()` | `list` | Roles with their permissions |
| `define(name, permissions, { description })` | `put` | Create or replace a role. Names are lowercase (`editor`, `org:billing`); permissions are `resource:action` patterns with `*` |
| `remove(name)` | `remove` | Delete a role |

### `orgs`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list()` | `list` | Every organization |
| `getOrg(slug)` | `get_org` | One organization |
| `create(slug, name, { ownerEmail, metadata })` | `create` | Create one, optionally with an owner |
| `update(slug, { name, metadata, appMetadata, maxMembers, requireMfa, suspended })` | `update` | Rename it, replace its `metadata` or `app_metadata` (server-only data), set its seats (`null` removes the limit), require a second factor, or suspend it (from `@pawabase/client` 0.6.0, `pawabase` 0.8.0) |
| `remove(slug)` | `remove` | Delete it |
| `addMember(slug, { email, role })` | `add_member` | Add an existing user straight in |
| `setMemberRole(slug, userId, role)` | `set_member_role` | Change a member's role |
| `removeMember(slug, userId)` | `remove_member` | Remove a member |
| `invite(slug, { email, role, redirectTo })` | `invite` | Mail an invitation; `redirectTo` must be an allowed redirect URL |

### `ssoConnections / sso_connections`

An organization's [company login](/auth/enterprise-sign-in). From `@pawabase/client` 0.7.0 and `pawabase` 0.9.0.

| TypeScript | Python | Does |
| --- | --- | --- |
| `list()` | `list` | Every connection, with its organization, verified domains and state |
| `getConnection(name)` | `get_connection` | One connection |
| `create({ name, type, organization, settings, defaultRole, groupsAttribute, roleMapping, enabled, required })` | `create(name, type=, organization=, …)` | Give an organization its company login (one per organization) |
| `update(name, { settings, enabled, trustEmail, defaultRole, groupsAttribute, roleMapping, required })` | `update` | Change it; `settings` are merged |
| `test(name)` | `test` | Reach the provider (OIDC) or read the certificate (SAML) |
| `remove(name)` | `remove` | Delete it; members and accounts stay |

See [Manage connections from code](/auth/enterprise-connections#manage-connections-from-code) for the fields and refusals.

### `invitations`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list()` | `list` | Pending and past invitations across organizations |
| `resend(invitationId, { redirectTo })` | `resend` | Send the email again |
| `revoke(invitationId)` | `revoke` | Cancel an invitation |

### `sessions`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list({ limit })` | `list` | Active sessions across people |
| `revoke(family)` | `revoke` | End one session and all its refresh tokens |

### `apiKeys / api_keys`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list({ limit })` | `list` | People's own API keys across the environment |
| `revoke(keyId)` | `revoke` | Stop one |

### `machines`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list()` | `list` | Every machine |
| `getMachine(machineId)` | `get_machine` | One machine with its keys (never the secrets) |
| `create(input)` | `create` | Create one: `name`, `kind` (`service` or `agent`), `roles`, `permissions`, `org` |
| `update(machineId, input)` | `update` | `roles` and `permissions` replace the lists; `org: null` removes the organization |
| `disable(machineId)` | `disable` | Stop every key at once |
| `enable(machineId)` | `enable` | Turn it back on |
| `delete(machineId)` | `delete_machine` | Delete it |
| `createKey(machineId, { name, scopes, expiresInDays })` | `create_key` | Make a key. The secret (`key`) is in the answer once; `client_id` is the machine's id |
| `revokeKey(machineId, keyId)` | `revoke_key` | Stop one key |

### `devices`

| TypeScript | Python | Does |
| --- | --- | --- |
| `list({ limit })` | `list` | Recent devices people signed in from |

### `insight`

| TypeScript | Python | Does |
| --- | --- | --- |
| `events({ kind, failed, limit })` | `events` | Authentication events (sign-ins, sign-ups, resets, second steps); `failed` for failures only |
| `stats()` | `stats` | Counts of users, sign-ins, second-step use and failures |
| `backup()` | `backup` | Every identity (users, organizations, roles, factors) as a document |
| `restore(identities, { replace, dryRun })` | `restore` | Apply a backup's identities; `dryRun` reports what would change |
| `previewTokenProfile(profile, userId, { org })` | `preview_token_profile` | The claims a [token profile](/auth/token-profiles) would put in a token for this person, without issuing one |
| `hostedSource(page, { branding, form })` | `hosted_source` | The HTML a hosted sign-in page is served as, for branding you're editing |

### `privacy`

| TypeScript | Python | Does |
| --- | --- | --- |
| `requests({ limit })` | `requests` | Data requests handled so far (exports and erasures), without personal data |

## Examples

### Onboard a customer

<CodeGroup>
```typescript TypeScript
await a.orgs.create(customer.slug, customer.name, { ownerEmail: customer.ownerEmail, metadata: { plan: customer.plan } });
```

```python Python
pb.admin.orgs.create(customer["slug"], customer["name"], owner_email=customer["owner_email"], metadata={"plan": customer["plan"]})
```
</CodeGroup>

### React to a plan change

<CodeGroup>
```typescript TypeScript
await a.users.update(userId, { roles: ["member", "pro"], appMetadata: { plan: "pro" } });
await a.users.revokeSessions(userId);        // optional: apply it immediately
```

```python Python
pb.admin.users.update(user_id, roles=["member", "pro"], app_metadata={"plan": "pro"})
pb.admin.users.revoke_sessions(user_id)
```
</CodeGroup>
