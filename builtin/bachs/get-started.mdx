[Bachs](https://bachs.io) takes the payment. Pawabase's Bachs integration is everything between your app and Bachs: starting a checkout, remembering the payment, receiving Bachs's webhook, checking that it is genuine, and marking the payment paid only when Bachs agrees. This page takes you from nothing to a sandbox payment.

## Before you start

You need a Bachs account and a **secret key**. In the Bachs Developer Portal, create the key with these scopes:

| Scope | Why |
| --- | --- |
| **View payments** | Pawabase checks a checkout with Bachs before marking it paid |
| **Create & charge** | Pawabase starts checkouts |
| **Webhooks** | Optional. Lets Pawabase create the webhook endpoint at Bachs for you |

Use a sandbox key, `sk_sandbox_…`, while you build. A live key is `sk_live_…`. Pawabase works out which Bachs to talk to from the key itself, so a sandbox key can only ever reach the sandbox.

## Install it

<Steps>
  <Step title="Open Integrations">
    In Studio, choose **Integrations** in the sidebar and open **Bachs**.
  </Step>
  <Step title="Paste the key">
    Paste the secret key and choose **Install Bachs**. Pawabase asks Bachs about the key first. If Bachs refuses it, or it lacks the payments scopes, nothing is installed and you are told why.
  </Step>
  <Step title="Look at what it did">
    Two tables appear under **Data → Tables**: `bachs_payments` and `bachs_events`. The workspace opens.
  </Step>
  <Step title="Connect the webhook">
    If your server is reachable over https from the internet, Pawabase creates the webhook endpoint at Bachs and keeps its signing secret. Otherwise the **Webhook** tab shows the address to give Bachs, and you paste back the signing secret.
  </Step>
</Steps>

Installing never overwrites anything. If `bachs_payments` or `bachs_events` already exists and fits, it is reused with its data; if it does not fit, installing stops and says why. See [How integrations work](/builtin/how-they-work#tables-you-already-have).

## Try a payment from Studio

On the **Overview** tab, choose **Start** and enter an amount and currency. Studio runs the same path your app will, through the same checks, and gives you a real sandbox checkout link. Pay it with a test card from the Bachs sandbox, then open the **Payments** tab: the payment is `paid` once Bachs confirms it.

## Take a payment from your app

Call it from your app with the SDK. The buyer signs in to your app as usual; the Bachs key never reaches the browser.

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";

const pawabase = createClient({ url, project, apiKey: "pb_pk_…" });
await pawabase.auth.signInWithPassword({ email, password });

const { checkoutUrl, reference } = await pawabase.bachs.payments.create({
  amount: "5000.00",
  currency: "NGN",
  successUrl: "https://shop.example.com/thanks",
  email: "ada@example.com",
});

window.location.href = checkoutUrl!;
```

```python Python
from pawabase import Pawabase

pb = Pawabase(url, "pb_pk_…", project=project)
pb.auth.sign_in_with_password(email="ada@example.com", password="…")

started = pb.bachs.payments.create(
    amount="5000.00",
    currency="NGN",
    success_url="https://shop.example.com/thanks",
    email="ada@example.com",
)
redirect(started["checkout_url"])
```
</CodeGroup>

When the buyer returns to `successUrl`, find out how it went:

<CodeGroup>
```typescript TypeScript
const payment = await pawabase.bachs.payments.waitFor(reference);
if (payment.status === "paid") unlockOrder(payment.metadata);
```

```python Python
payment = pb.bachs.payments.wait_for(reference)
if payment["status"] == "paid":
    unlock_order(payment["metadata"])
```
</CodeGroup>

That is the whole integration from your side. [The SDK page](/builtin/bachs/sdk) covers every method, and [REST API](/builtin/bachs/rest-api) the same calls without the SDK.

## The Bachs workspace

Once installed, the Bachs page has seven tabs.

| Tab | What it is for |
| --- | --- |
| **Overview** | What needs attention (payments to review, a webhook that is not connected), the numbers, the latest payments, and a way to try one |
| **Payments** | Every payment, searchable by reference, email or description and filterable by status. Open one to see it in full and to **Check with Bachs**, which settles it now exactly as the webhook would |
| **Events** | Each delivery from Bachs that was handled and what was done about it. Open one to see its payload |
| **Webhook** | The address Bachs delivers to, how many genuine deliveries have arrived and when, and how to create the endpoint again or paste a new signing secret |
| **Settings** | The [rules you can set](/builtin/bachs/react#settings) and your before-start flow |
| **Connection** | Which key is in use, replacing it, and disconnecting |
| **Build** | Code to call it from your app, the events to build flows on, and what is built in versus yours |
