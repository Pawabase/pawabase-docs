## One backend, one request path

Every request moves through the same clear system. Authentication establishes identity, policies decide access, the operation changes data, and the surrounding services handle everything that follows.

```text
Application
    ↓
Authentication → Policy → Data operation
                              ↓
                  Event · Queue · Function
                              ↓
                   Realtime · Webhook · Log
```

<Info>
Pawabase is more than a database endpoint. Its services share the same project, environment, identity, and policy context, so you can build the backend as one system.
</Info>

## Follow a deliberate path

### Build the foundation

Start with the [mental model](/concepts/mental-model), create a [project and environment](/concepts/projects-and-environments), then define your first [resource](/data/resources). Add [authentication](/auth/overview) and [policies](/policies/overview) before connecting application data.

### Add behavior

Use [flows](/flows/overview) for visible multi-step automation, [events](/events/overview) to react to changes, [queues](/jobs/queues) for durable background work, and [functions](/code/functions) when the behavior belongs in code.

### Prepare for production

Review [environments and promotion](/operate/environments-and-promotion), [observability](/operate/observability), [backup and restore](/operate/backup-and-restore), and the [production checklist](/self-hosting/production-checklist) before exposing an environment to real traffic.
