Pawabase is a backend made of products that share one project, one identity and one set of access rules: a data API, authentication, storage, realtime, automation, mail and more. Each product has its own section in these docs, written for the developer who calls it from an app or a server.

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";

const pawabase = createClient({ url: "https://api.example.com", apiKey: "pb_pk_…" });

await pawabase.auth.signInWithPassword({ email: "ada@example.com", password: "…" });
const { data: tasks } = await pawabase.from("tasks");
```

```python Python
from pawabase import Pawabase

pb = Pawabase("https://api.example.com", "pb_pk_…")

pb.auth.sign_in_with_password(email="ada@example.com", password="…")
tasks = pb.from_("tasks").execute()
```
</CodeGroup>

## How the products fit together

Every request passes through the same path, so the products behave like one system rather than separate services.

```text
Your app
   ↓
Authentication → Policies → Data operation
                               ↓
                  Events · Jobs · Flows
                               ↓
                Realtime · Webhooks · Mail
```

Authentication establishes who is calling. Policies decide whether they may. The operation changes data, and what follows (an event, a flow, a push to subscribers) runs in the same project with the same identity. The [mental model](/concepts/mental-model) walks through one request end to end.
