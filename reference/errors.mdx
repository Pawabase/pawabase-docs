All errors from the server extend one base type. Catch the specific ones you care about and let the rest bubble up.

| TypeScript | Python | Status | Meaning |
| --- | --- | --- | --- |
| `AuthenticationError` | `AuthenticationError` | 401 | Not signed in, token expired, or wrong API key |
| `PermissionError` | `ForbiddenError` | 403 | Signed in, but a rule refuses this |
| `NotFoundError` | `NotFoundError` | 404 | No such record or file, or a rule hides it |
| `ConflictError` | `ConflictError` | 409 | A unique value is already used |
| `ValidationError` | `ValidationError` | 400, 422 | Invalid or missing input |
| `PayloadTooLargeError` | | 413 | Body larger than allowed |
| `RateLimitError` | `RateLimitedError` | 429 | Too many requests |
| `ServerError` | `ServerError` | 5xx | A problem on the server |
| `NetworkError` | `NetworkError` | none | The request never got an answer |
| `RealtimeError` | `RealtimeError` | none | A live channel was refused or closed |
| `ConfigError` | `ConfigError` | none | The client was set up wrongly |

In Python, `QuotaExceededError` (a kind of `ForbiddenError`) means the plan's limit is reached.

## What an error carries (TypeScript)

| Property | Meaning |
| --- | --- |
| `status` | The HTTP status |
| `code` | A stable machine-readable code, such as `not_found` or `rate_limited` |
| `message` | A readable description |
| `requestId` | Quote this when asking for help |
| `retryAfter` | Seconds to wait, on 429 and 503 |
| `policy` | The rule that refused, on 403, when known |
| `details` | Extra structured data |

`ValidationError` also has `issues`, `fieldError(field)` and `byField()` for form messages.

```typescript
try {
  await pawabase.from("profiles").create({ email: "nope" });
} catch (e) {
  if (e instanceof ValidationError) console.log(e.byField());   // { email: ["must be a valid email"] }
  else if (e instanceof ApiError && e.is("rate_limited")) console.log(e.retryAfter);
}
```

## Retries

The client already retries rate limits (`429`), `502`, `503`, `504` and network failures, with short delays. You see an error only if it keeps failing. Tune it with the `retry` option, or pass `retry: false`.
