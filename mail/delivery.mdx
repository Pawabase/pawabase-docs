Pawabase doesn't send email by itself: it hands every message to **your email provider** over SMTP, the standard way mail servers talk. You choose the provider, so mail comes from your domain, counts against your provider account, and benefits from the reputation you build there.

Open **Mail → Delivery**. It has three parts: **Providers**, **Senders**, and **Pause delivery**.

<Note>
Until a provider is connected, messages are **recorded, not delivered**: they appear in [Mail activity](/mail/activity) but nobody receives them. That includes sign-in emails, so people can't verify their address or reset a password. Set up delivery before you launch.
</Note>

## Pawabase mail

An environment with no provider of its own sends through **Pawabase mail**, our free sender, so email works from the first day.

- Messages go out from Pawabase's address with **your sender's name** ("Sell4me &lt;team@pawabase.com&gt;"), and **replies go to your sender's own address**.
- Your plan sets how many it may send a month (**Pawabase mail / month** in [Plans and limits](/cloud/plans-and-limits)). Each one also counts toward the plan's total emails.
- When the month's allowance is used up, sending is refused until the next month, or until you add your own provider.

Add your own provider below to send from your own domain, at your plan's higher total. Studio's **Mail → Delivery** says which one an environment uses.

## Providers

A **provider** is an SMTP server with credentials. Choose **Add provider** and pick a **Service**. Presets fill in the address for you:

| Service | Host | Port | Username |
| --- | --- | --- | --- |
| **Resend** | `smtp.resend.com` | 465 | `resend` |
| **SendGrid** | `smtp.sendgrid.net` | 587 | `apikey` |
| **Mailgun** | `smtp.mailgun.org` | 587 | your Mailgun SMTP login |
| **Gmail** | `smtp.gmail.com` | 587 | your Google address |
| **Amazon SES** | `email-smtp.us-east-1.amazonaws.com` | 587 | your SES SMTP username |
| **Postmark** | `smtp.postmarkapp.com` | 587 | your server token |
| **Custom SMTP** | any | any | any |

| Field | Meaning |
| --- | --- |
| **Name** | What you call it, for example *Transactional* |
| **Host** | The provider's SMTP server |
| **Port** | **465** for SSL from the start, **587** for STARTTLS (the connection is upgraded to encrypted). Use what your provider says. |
| **Username** | Your SMTP username. Several providers use a fixed word (`apikey`, `resend`). |
| **Password or API key** | Your SMTP password or API key. It's saved as an encrypted [secret](/secrets/overview) and never shown again. |

For Amazon SES, change the host to your region's address (for example `email-smtp.eu-west-1.amazonaws.com`). For Gmail, use an **app password**, not your normal password.

### Test the connection

**Test connection** connects to the server and signs in with your credentials **without sending anything**. It tells you whether it worked, or what went wrong:

| Result | What it usually means |
| --- | --- |
| Connected | Host, port and credentials are right |
| Could not connect / timed out | Wrong host or port, or the provider blocks that port |
| Authentication failed | Wrong username, password or API key, or the key lacks SMTP permission |
| TLS or SSL error | The port and the encryption don't match: try 465 for SSL or 587 for STARTTLS |

The time and result of the last test are shown on the provider.

### More than one provider

You can keep several providers saved, for example a primary and a backup, or a test inbox service for development. **One is the default** and sends everything. To switch, make another the default; nothing else changes.

<Tip>
Keep a second provider set up and tested. If your main provider has an outage or suspends your account, you can switch in seconds.
</Tip>

## Senders

**Senders** are the addresses mail comes from. Each has a display **name** and an **email**:

| Name | Email | Shown as |
| --- | --- | --- |
| *Northwind* | `orders@northwind.com` | Northwind &lt;orders@northwind.com&gt; |
| *Northwind Support* | `support@northwind.com` | Northwind Support &lt;support@northwind.com&gt; |

One sender is the **default**. Templates and Compose can pick a different sender; everything else, including sign-in emails, uses the default.

Your provider must allow the address: most require you to verify the sending domain (or the single address) before they'll send from it. A message from an address your provider doesn't accept fails with the provider's reason in [Activity](/mail/activity).

### Reply-to

**Reply to** is where replies go when it isn't the sender, for example `support@yourdomain.com`. If you don't set one, replies go to the **Support email** in [Settings → App details](/environments/settings#app-details). A message can set its own reply-to.

## Pause delivery

**Pause delivery** keeps your settings but stops sending. While paused, messages are recorded as **suppressed** and shown under [Activity](/mail/activity), with what they would have said. Use it:

- In `development` and preview environments, so a test never emails a real person.
- While you're testing templates against real data.
- During an incident, for example if a bug is sending the wrong email.

Turn it off to send again. Suppressed messages aren't sent later; send them again from Activity if you need to.

## Per environment

Delivery is set **per environment**. A common setup:

| Environment | Delivery |
| --- | --- |
| `development` | Paused, or a test inbox service so you can read what was sent |
| `staging` | A test inbox, or your real provider with a separate sending domain |
| `production` | Your real provider, verified domain, SPF, DKIM and DMARC set |

[Promote](/environments/promote) does not copy delivery settings or passwords, so you set production up deliberately.

## Before you launch

1. Verify your sending domain with your provider.
2. Add the **SPF**, **DKIM** and **DMARC** records it gives you. See [Deliverability](/mail/deliverability).
3. Send a test from **Mail → Delivery** or [Compose](/mail/sending#compose) to a Gmail, an Outlook and an Apple address, and check the inbox and spam folder.
4. Make sure **Pause delivery** is off in production.
5. Set an [alarm](/activity/alarms) on mail failures.

## Troubleshooting

| Problem | Check |
| --- | --- |
| Studio says delivery is not set up | No provider is connected. Add one. |
| Everything is *suppressed* | **Pause delivery** is on. |
| Everything is *failed* with an authentication error | The password or API key changed. Edit the provider and paste the new one. |
| *Failed* with "sender not verified" or similar | Verify the sending address or domain with your provider. |
| *Sent* but nobody receives it | The provider accepted it but it bounced or went to spam. Check the provider's dashboard and [Deliverability](/mail/deliverability). |

More in [Mail troubleshooting](/mail/troubleshooting).
