A **template** is an email you design once and send many times, with values filled in each time: a welcome email with the person's name, a receipt with the line items, a reset link. Your flows, your server, Compose and the sign-in system all send a template **by its name**.

## The template library

Open **Mail → Templates**. The library lists every template with its status and category.

| Feature | What it does |
| --- | --- |
| **Search** | Matches names, subjects and tags |
| **Filters** | *All*, *Drafts*, *Published*, *Archived*, and **Every category** |
| **Sort** | By name or last change |
| **Folders** | Group templates (folders are managed in the [brand kit](/mail/brand-kit#folders)) |
| **Favourites** | Star the ones you use most |
| **Template actions** | Open, rename, duplicate, move to a folder, archive or restore, delete |

The library also shows **how often each template was sent** recently and **which flows send it**, so you can see what would be affected before you change or delete one.

### Statuses

| Status | Meaning |
| --- | --- |
| **Draft** | Never published. It can't be sent yet. |
| **Published** | Has a published version that every sender uses. |
| **Unpublished changes** | Published, and the draft has been edited since. Senders still get the last published version until you publish again. |
| **Archived** | Put away; restore it from the archive. |

## Create a template

1. **Mail → Templates → New template.**
2. Start from **Blank** or from a prebuilt design:

| Category | Prebuilt designs |
| --- | --- |
| Onboarding | Welcome |
| Authentication | Email verification, Password reset, Magic link, One-time code |
| Teams | Team invitation |
| Security | Security alert |
| Billing | Payment receipt, Invoice, Subscription update |
| Lifecycle | Trial reminder |
| Commerce | Order confirmation |
| Product | Notification |
| Marketing | Announcement |

3. Give it a **name**. The name is how code and flows send it, so choose something stable such as `order-confirmation` (letters, digits, dashes and underscores).

Each prebuilt design comes with its values already listed (for example `order.number`, `order.items`), each with a sample, so the preview looks real straight away.

## Design it

The editor is visual. Type `/` anywhere, or use **Insert**, to add a block:

| Block | Use it for |
| --- | --- |
| **Text**, **Heading**, **Smaller heading** | Paragraphs and titles |
| **Bulleted list**, **Numbered list** | Lists and steps in order |
| **Quote** | A quotation or callout |
| **Button** | A call to action, with its own colour, corners and padding |
| **Image** | Upload or link an image, with alt text and an optional link |
| **Divider**, **Spacer** | A line between sections, or empty room |
| **Section** | A coloured panel that holds other blocks |
| **Two columns**, **Three columns** | Side-by-side content |
| **Variable** | A value filled in when sent |
| **Condition** | Content only shown when a condition is true (see [Template language](/mail/template-language#conditions)) |
| **Repeat** | One copy per item in a list, for line items or results |
| **HTML** | Your own markup, when a block isn't enough |
| **Saved block** | A reusable header, footer, signature or block from the [brand kit](/mail/brand-kit) |

Select any block to style it. Select a block and choose **Save as a reusable block** to use it in other templates.

Above the body:

- **Subject**: what the inbox shows first. It can contain values: `Your order {{ order.number }} has shipped`.
- **Preheader**: the line most inboxes show after the subject. Use it; otherwise the inbox shows the first words of the body.

**Undo** (⌘Z) and **Redo** (⌘⇧Z) work throughout. **Keyboard shortcuts** lists the rest.

### Bring an existing design

**Import HTML** pastes in a design you already have. Choose **Convert to editable blocks** to edit it in the editor, or keep it as HTML.

### Plain text

Every email should have a plain-text version: some people and some mail clients read only that, and spam filters look for it. Studio keeps one beside the design.

## Values

The **Values** tab lists what the template reads when it is sent, each with a description and a **sample**:

| Value | Description | Sample |
| --- | --- | --- |
| `user.first_name` | Their first name | Ada |
| `order.number` | | #34383F22 |
| `order.items` | The lines of the order (a list) | `[{"name": "Mug", "qty": 2}]` |

Samples fill the preview and test sends. Your code or flow passes the real values when it sends. For a list or object, write the sample as JSON.

Three values are always available from [Settings → App details](/environments/settings#app-details), so you never pass them yourself:

| Value | Holds |
| --- | --- |
| `app.name` | Your product's name |
| `app.support_email` | Where people get help |
| `app.address` | Your postal address, for footers |

The full syntax (conditions, loops, filters, escaping) is on [Template language](/mail/template-language).

## Check, preview and test

- **Preview** shows the email exactly as it will be sent, with your sample values.
- **Checks** flag problems before you publish. *Nothing to fix* means you're good. They look for:

| Area | What is checked |
| --- | --- |
| **Subject and preview** | A missing subject; a subject long enough to be cut off (phones show about 40 characters, desktop inboxes about 70); missing preview text |
| **Values** | A value with no sample; a value name that isn't valid (use letters, digits and underscores with dots between parts: `user.first_name`) |
| **Buttons and links** | A button with no link; links over `http` instead of `https`; button or link text such as "click here" that doesn't say where it goes; low-contrast buttons (aim for 4.5:1) |
| **Images** | An image with no address, or served over `http` (Gmail and others block or warn about insecure images) |
| **Readability** | Low-contrast body text or links; body text under 14px; headings that skip levels; more than one main heading |
| **Deliverability** | An email that's mostly images (spam filters weigh the text-to-image ratio); HTML larger than 102 KB, which Gmail cuts behind *View entire message* |
| **Mail clients** | Notes on what differs: rounded corners show square in Outlook for Windows, web fonts fall back in Gmail and Outlook for Windows, columns stack on phones |
| **Your own HTML** | A reminder to send a test to each client you care about, because custom markup isn't checked |

- **Send a test email** sends it to your address with the sample values. The subject starts with **[Test]** so you can tell it apart.

## Details

The template's details panel holds:

| Detail | Meaning |
| --- | --- |
| **Name** | How it's sent. Renaming it means updating anything that sends it by the old name. |
| **Description** | What it is, for your team |
| **Category** | One of the categories above, used for filtering |
| **Tags** | Free words for search |
| **Folder** | Where it lives in the library |
| **Favourite** | Starred in the library |

## Publish

Drafts are **never sent**. Choose **Publish this template**, optionally with a note about **what changed** ("New footer, clearer button"). From that moment everything that sends this template (your code, flows and sign-in) uses the new version.

Sending a template that has never been published fails with *has not been published yet*.

## Versions

Each publish keeps a **version**, with its note, who published it and when. Open **Versions** to read any of them. **Restore** puts an older version back as the **draft**; publish it to send it again. Nothing changes for senders until you publish.

## Rename, duplicate, archive and delete

- **Rename** keeps the template's versions. Code and flows that send it by the old name will fail until you update them. The library shows which flows send it.
- **Duplicate** makes a copy with a new name, to start a variation.
- **Archive** hides a template you no longer use but might want back.
- **Delete** removes it and its versions. Anything still sending it will fail.

## Templates in other environments

Templates are definitions, so [promote](/environments/promote) copies them between environments, and [infrastructure as code](/tools/iac/mail-templates) can define them in your repository.

## Good practice

- **Name templates for what they are** (`order-confirmation`), not when you made them.
- **Give every value a sample** so tests show real-looking output.
- **Send yourself a test** and open it on a phone before publishing.
- **Write a note on every publish**, so the version history tells a story.
- **Keep transactional and marketing templates apart** using categories, so you can find and review them easily.
