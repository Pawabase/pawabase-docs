**Mail → Activity** lists every message this environment sent, or would have sent, newest first. It's where you answer "did they get the email?"

## Statuses

| Status | Meaning | What you can do |
| --- | --- | --- |
| **sent** | Your provider accepted the message | Send a copy |
| **failed** | Your provider refused it or couldn't be reached. The reason is shown. | Retry, send a copy |
| **suppressed** | Deliberately not sent, because [delivery is paused](/mail/delivery#pause-delivery) | Retry once delivery is on |
| **scheduled** | Waiting for its send time | Cancel |
| **canceled** | A scheduled message you canceled | Nothing; it won't be sent |

<Note>
**Sent** means the provider *accepted* it. The provider then delivers it, and it can still bounce, be rejected by the recipient's server, or land in spam later. Your provider's dashboard shows bounces and complaints; see [Deliverability](/mail/deliverability).
</Note>

## Find a message

- **Search** recipients and subjects: type part of an address or a subject.
- **Filter** by status (*all*, *sent*, *failed*, *suppressed*, *scheduled*) and by template.
- Messages from a template show its name, so you can see every receipt or every reset email at once.

## Read a message

Open a message to see everything it carried:

| Part | Meaning |
| --- | --- |
| **To**, **Cc**, **Bcc** | Who it was addressed to |
| **From**, **Reply to** | The sender and reply address used |
| **Subject**, **HTML**, **Text** | Exactly what was sent, after the template was filled in |
| **Template** and **template values** | Which template and the data it was given |
| **Attachments** | The files it carried |
| **Source** | What sent it: a flow or API call, Compose or Studio, or the sign-in system (*identity*) |
| **What the mail server answered** | The provider's reply when it accepted or refused the message, and the message id it assigned |
| **Error** | Why it failed, for a failed message |
| **Retry of an earlier message** | A link to the original, when this was a retry |
| **Created**, **scheduled for**, **sent at** | When it happened |

The provider's **message id** is what to quote when you contact your provider about a specific message.

## Retry a failed message

**Retry** sends the message again exactly as it was, with the same recipients, content and attachments, as a **new** entry that links back to the original. Use it once you've fixed the cause, for example after replacing an expired API key.

A retry counts against your monthly emails like any send.

## Send a copy

**Send a copy** sends the same subject and body to another address, for example to yourself to see what a customer received, or to a customer who says they lost it. It goes out now, as a new message.

## Cancel a scheduled message

Open a **scheduled** message and **Cancel** it. It becomes *canceled* and is never sent. You can only cancel before it goes; once its time has come and it's been sent, it's too late.

A scheduled message was rendered when it was scheduled, so changing the template afterwards doesn't change it. To send a corrected version, cancel it and schedule again.

## The overview numbers

**Mail → Overview** shows totals for the last 7, 30 or 90 days: **sent**, **failed**, **suppressed** and **scheduled**, a day-by-day chart, and the **most recent errors**. A sudden rise in failures usually means a provider problem (expired key, suspended account, rate limit). [Activity → Mail](/activity/background-work#mail) shows sends and failures by template.

## From code

The management client reads the log:

<CodeGroup>
```typescript TypeScript
import { manage } from "@pawabase/client/manage";

const m = manage(pawabase);                       // a secret key
const failed = await m.mail.log({ status: "failed", limit: 50 });
const config = await m.mail.config();             // is delivery set up? is it paused?
```

```python Python
failed = pb.manage.mail.log(status="failed", limit=50)
config = pb.manage.mail.config()
```
</CodeGroup>

Retrying, cancelling, one message, totals and template use (`@pawabase/client` 0.6.0, `pawabase` 0.8.0):

<CodeGroup>
```typescript TypeScript
const m = manage(pawabase);                       // a client with the secret key
const one = await m.mail.message(messageId);      // everything it carried
await m.mail.retry(messageId);                    // send again as a new message
await m.mail.cancel(messageId);                   // a scheduled one
const stats = await m.mail.stats({ days: 30 });   // totals, a daily series, recent errors
const usage = await m.mail.templateUsage();       // sends per template, and which flows send it
const found = await m.mail.log({ q: "ada@example.com", template: "receipt" });
```

```python Python
m = pb.manage
m.mail.message(message_id)
m.mail.retry(message_id)
m.mail.cancel(message_id)
m.mail.stats(days=30)
m.mail.template_usage()
m.mail.log(q="ada@example.com", template="receipt")
```
</CodeGroup>

| Endpoint | Does |
| --- | --- |
| `GET …/mail/log` | List messages. Query: `status`, `template`, `q` (search), and paging |
| `GET …/mail/log/{id}` | One message with everything it carried |
| `POST …/mail/log/{id}/retry` | Send it again as a new message |
| `POST …/mail/log/{id}/cancel` | Cancel a scheduled message |
| `GET …/mail/stats?days=30` | Totals by status, a daily series and recent errors (1 to 365 days) |
| `GET …/mail/templates/usage` | How often each template was sent and which flows send it |

## Privacy

The log keeps what each message said, including the values passed to its template. Treat it as personal data:

- Don't put secrets (passwords, full card numbers) in emails or their values.
- Limit who can open Studio in production, and use scoped keys so integrations can't read the mail log unless they need to (`mail:read`).

## Troubleshooting

| You see | It means |
| --- | --- |
| Nothing at all for a message you expected | It was never sent. Check the flow run or job that should have sent it ([Activity](/activity/background-work)). |
| Several *failed* entries for one message | A queued send was retried; each attempt is logged. |
| *Suppressed* | Delivery is paused for this environment. |
| *Sent*, but they didn't get it | Look in spam; check the provider dashboard for a bounce; see [Deliverability](/mail/deliverability). |

More in [Mail troubleshooting](/mail/troubleshooting).
