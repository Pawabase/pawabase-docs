A **delivery** is one event being sent to one [webhook endpoint](/automation/webhooks). Every delivery is recorded from the moment it is queued, so you can always answer "did the partner receive it, and what did they say?"

## How a delivery works

1. Something emits an event (a record is created, a flow's **Send webhook** block runs, you press **Send test event**).
2. Pawabase finds every **enabled** endpoint whose **events** pattern matches the event name. A pattern can use `*` as a wildcard: `orders.*` matches `orders.created` and `orders.paid`; `*` matches everything.
3. A delivery is created for each matching endpoint with status **pending**, and sent in the background. Your app is never slowed by a slow partner.
4. Pawabase `POST`s a JSON body to the endpoint's URL.
5. If the endpoint answers with a **2xx** status, the delivery is **delivered**. Anything else (a 4xx or 5xx, a timeout, a connection error) is a failed attempt and is retried.

An event is delivered to an endpoint **at most once per event id**. If an event is processed twice (for example after a restart), the second pass does not create a second delivery for the same endpoint.

### What the endpoint receives

```http
POST /hooks/pawabase HTTP/1.1
content-type: application/json
Pawabase-Event: orders.created
Pawabase-Delivery: 01JD8Z6Q4G2X…
Pawabase-Signature: t=1731000000,v1=9f2c…
```

```json
{
  "id": "01JD8Z6Q0000EVENT",
  "event": "orders.created",
  "env": "production",
  "data": { "id": "01JD8Z…", "total": 42.5, "status": "pending" },
  "sent_at": 1731000000
}
```

| Part | Meaning |
| --- | --- |
| `id` | The event id. The same id is sent again on retries and redeliveries, so use it to ignore duplicates. |
| `event` | The event name. |
| `env` | The environment that emitted it. |
| `data` | The event's payload. |
| `sent_at` | When this attempt was sent (Unix seconds). |
| `Pawabase-Signature` | `t=<time>,v1=<signature>` for verifying the request. See [Verify webhook signatures](/automation/webhook-signatures). |
| `Pawabase-Delivery` | The id of this delivery, shown in Studio. |
| Your extra headers | Any headers you added to the endpoint are sent too. |

Each attempt waits at most **15 seconds** for an answer.

## Retries

A failed attempt is retried on a growing schedule:

| Attempt | Waits before it |
| --- | --- |
| 2 | about 10 seconds |
| 3 | about 1 minute |
| 4 | about 5 minutes |
| 5 | about 30 minutes |
| 6 | about 2 hours |
| 7 | about 6 hours |
| 8 | about 12 hours |
| 9 and 10 | about a day |

The waits vary slightly so that many failing deliveries don't all retry at the same instant. How many attempts an endpoint gets is its **Max attempts**: from 1 to 10, **5 by default**. An endpoint that is down for an afternoon still receives its events; with 10 attempts a delivery keeps trying for about two and a half days.

While waiting for the next attempt the delivery is **retrying**, with the time of the next attempt shown. After the last attempt it becomes **failed**.

<Note>
An endpoint address that points at a private network or your own machines is refused as **failed** straight away, without retries, so a webhook can't be used to reach internal services. Use a public address (or a tunnel while developing).
</Note>

## Read the deliveries

Open **Activity → Webhooks** (or the endpoint itself) to see deliveries, newest first.

| Column | Meaning |
| --- | --- |
| **Status** | `pending`, `retrying`, `delivered` or `failed` |
| **Event** | The event name |
| **URL** | Where it was sent |
| **Attempts** | How many times it has been tried |
| **Duration** | How long the last attempt took |
| **Response** | The status your endpoint answered with, and the first 2,000 characters of its body |
| **Error** | Why the last attempt failed (`HTTP 500`, a timeout, a connection error) |

Filter by endpoint, event, status or time. This is the first place to look when a partner says they received nothing.

### Reading a failure

| What you see | Usual cause |
| --- | --- |
| `HTTP 401` or `403` | The receiver rejected the request. It may be checking the signature wrongly, or needs an extra header. |
| `HTTP 404` | The URL is wrong or the route was removed. |
| `HTTP 5xx` | The receiver has a bug or is down. It will be retried. |
| A timeout | The receiver takes longer than 15 seconds. Answer quickly and do the work afterwards. |
| A connection error | DNS, firewall or certificate problem on the receiver. |
| A refused-address message | The URL points to a private network. |

## Redeliver

- **One delivery:** open it and choose **Redeliver**.
- **Many, after an outage:** filter to the failed deliveries (by endpoint, event, status, or **since** a number of minutes), choose **Redeliver**, and use **Dry run** first to see how many would be sent. Up to 500 are sent at once, and the filter can look back up to 90 days.

Each redelivery creates a **new** delivery with the **same payload and event id**. Your receiver must treat a repeated `id` as a duplicate.

## Make your receiver safe to retry

Because the same event can arrive more than once (retries, redeliveries), receivers should be **idempotent**:

1. Verify the signature first.
2. Look up `id`. If you've already processed it, answer `200` and do nothing.
3. Otherwise record it and do the work.
4. Answer with a **2xx quickly**. Queue slow work.

## Send from a flow

To send an event to every subscribed endpoint from a flow, add the **Send webhook** block. See [Flows](/logic/flows).

## Alert on failures

A rising number of failed deliveries is worth an [alarm](/activity/alarms). The **Webhooks** view in [Activity](/activity/background-work#webhooks) shows deliveries by endpoint and the busiest events.

## Troubleshooting

| Problem | What to check |
| --- | --- |
| Nothing was delivered | Is the endpoint **Enabled**? Does its **Events** pattern match the event name exactly (`orders.created`, not `order.created`)? |
| It was delivered twice | Normal after a retry or redelivery. Deduplicate on `id`. |
| Everything is stuck in *retrying* | Your endpoint is answering non-2xx. Open a delivery and read the response. |
| Signature check fails in your receiver | Verify against the **raw** body, with the endpoint's signing secret. See [signatures](/automation/webhook-signatures). |
| A partner needs a copy after an outage | Filter failed deliveries and **Redeliver**. |
