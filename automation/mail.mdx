Pawabase sends transactional email: sign-in codes, receipts, invitations, notifications. Messages are queued as background jobs, so a slow mail provider never slows your app, and every message is logged.

**Setup (once per environment):** connect your email provider (SMTP host, port, username and password, and the "from" address) in the dashboard under **Mail**. Passwords are never returned afterwards.

## Templates

A template holds the subject and body, with `{{ placeholders }}` filled in at send time.

<CodeGroup>
```typescript TypeScript
await m.mailTemplates.create({
  name: "receipt",
  subject: "Your receipt for order {{ order.id }}",
  preheader: "Thanks for your order",
  html: "<h1>Thanks, {{ customer.name }}</h1><p>Total: {{ order.total }}</p>",
  text: "Thanks, {{ customer.name }}. Total: {{ order.total }}",
  variables: [
    { name: "customer.name", description: "Customer's name", sample: "Ada" },
    { name: "order.total", description: "Order total", sample: "$19.99" },
  ],
});

const all = await m.mailTemplates.list();
await m.mailTemplates.replace("receipt", { /* the whole definition */ name: "receipt", subject: "Receipt {{ order.id }}", html: "…", text: "…" });
await m.mailTemplates.remove("receipt");
```

```python Python
pb.manage.mail_templates.create({
    "name": "receipt",
    "subject": "Your receipt for order {{ order.id }}",
    "html": "<h1>Thanks, {{ customer.name }}</h1><p>Total: {{ order.total }}</p>",
    "text": "Thanks, {{ customer.name }}. Total: {{ order.total }}",
})
```
</CodeGroup>

| Field | Meaning |
| --- | --- |
| `name` | The name flows use to send it |
| `subject`, `preheader` | The subject line and the preview text (255 characters at most) |
| `html`, `text` | The body. Always provide both: `text` is shown by clients that don't render HTML |
| `status` | `draft`, `published` (default) or `archived` |
| `category`, `tags`, `folder` | For organising many templates |
| `variables` | `{ name, description, sample }` for each value the template reads, used for previews |

Templates use `{{ value }}` for substitution, `{% if … %}` and `{% for … %}` for logic, and filters like `{{ name | upper }}`. Unknown values render as empty, so preview with sample data.

## Send

From a flow, use the mail block with the template name and the data:

```json
{ "id": "send_receipt", "data": { "block": "mail.send", "config": { "to": "{{ steps.load.output.email }}", "template": "receipt", "data": { "customer": { "name": "{{ steps.load.output.name }}" }, "order": { "id": "{{ input.order_id }}", "total": "{{ steps.load.output.total }}" } } } } }
```

Build the flow in the dashboard (the mail block lists its own fields) and trigger it from an [event](/automation/events), so sending mail is decoupled from the code that causes it.

## Test

<CodeGroup>
```typescript TypeScript
await m.mail.sendTest(["you@example.com"]);          // a test message through the configured provider
const config = await m.mail.config();                // settings in effect (password never shown) and whether mail is being delivered
const log = await m.mail.log({ status: "failed", limit: 20 });
```

```python Python
pb.manage.mail.send_test(["you@example.com"])
config = pb.manage.mail.config()
log = pb.manage.mail.log(status="failed", limit=20)
```
</CodeGroup>

The log shows messages with status `sent`, `failed` or `suppressed`. In development environments, mail may be suppressed on purpose so you do not email real people; the log says so.

## Good practice

- Send from a domain you control, with SPF and DKIM set up at your provider, or messages land in spam.
- One template per message type; put variable parts in `data`, not in code.
- Keep the plain-text body readable; some people only see that.
- Never put secrets or full tokens in an email; links with short-lived tokens are the standard.
- Check `mail.log({ status: "failed" })` after a deploy. A wrong password or from-address shows up there first.
