The Management API is what a connected product calls once it has a token. It lives at:

```
https://dashboard.pawabase.com/v1
```

Every request carries the token:

```
Authorization: Bearer <access token, personal token, or platform token>
```

Bodies are JSON (`Content-Type: application/json`). Answers are JSON. Each token is for **one organization**, so no endpoint takes an organization in its path except `GET /v1/organizations/{slug}`, which must name the token's own.

## Calling it

The Management API is JSON over HTTPS. Every call carries `Authorization: Bearer <token>`; bodies are JSON with `Content-Type: application/json`; each endpoint below shows the request as `curl` first, then the same call with the [client libraries](/integrations/sdk), which send identical requests and turn an error answer into an exception carrying the status, the `code` and the `details`.

<CodeGroup>
```bash cURL
curl https://dashboard.pawabase.com/v1/projects \
  -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```typescript TypeScript (SDK)
import { PawabaseCloud } from "@pawabase/client/cloud";

// `token` is an access token, a personal pbp_… token, or a platform app's token, or a function giving one (oauth.tokenSource).
const pawabase = new PawabaseCloud({ token });
```

```python Python (SDK)
from pawabase.cloud import Cloud

pawabase = Cloud(token=token)  # an access token, a pbp_… token, a platform app's token, or oauth.token_source(...)
```
</CodeGroup>

## Errors

Every error from `/v1` has one shape:

```json
{"error": "not_found", "message": "That project in this organization was not found.", "details": null}
```

| Status | `error` | When |
| --- | --- | --- |
| 401 | `unauthorized` | No token, an unknown or expired token, a revoked connection, a deleted app, or the person's account is gone |
| 403 | `insufficient_scope` | The token lacks the scope (`details.needed` names it) |
| 403 | `forbidden` | The person's role is too low, or they left the organization |
| 404 | `not_found` | The project (or organization, or marketplace app) isn't in this organization |
| 409 | `not_ready` | The project isn't running yet (or its region can't serve the call) |
| 409 | `protected` | The project has deletion protection on |
| 402 | `plan_limit` | The organization's plan allows no more projects (`details.limit`, `details.used`) |
| 402 | `plan_feature` | A marketplace app needs a plan feature the organization doesn't have |
| 415 | `unsupported_media_type` | A Studio API call sent a body that isn't JSON |
| 422 | `invalid` | A field is missing or wrong (`details` maps field names to problems) |
| 502 | `unreachable` | The project's server could not be reached; try again in a minute |

The full list, with what to do for each: [Errors and troubleshooting](/integrations/errors).

## Who am I

### `GET /v1/token`

What the token is: which organization, which role, which scopes, and who or what it acts for. Needs no scope. Call it right after the token exchange to learn who the person is.

<CodeGroup>
```bash cURL
curl https://dashboard.pawabase.com/v1/token -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```typescript TypeScript (SDK)
const me = await pawabase.whoami();
console.log(`${me.user?.email} connected ${me.organization} as ${me.role}`);
```

```python Python (SDK)
me = pawabase.whoami()
print(f"{me['user']['email']} connected {me['organization']} as {me['role']}")
```
</CodeGroup>

```json
{
  "organization": "acme",
  "role": "owner",
  "scopes": ["organizations:read", "projects:read", "projects:write", "project:read", "project:write"],
  "kind": "grant",
  "user": {"id": "01M7PX72DDFTCPN6APAWK0NBFS", "email": "ada@acme.com", "name": "Ada Lovelace"},
  "app": {"name": "Acme Builder", "client_id": "pbc_YnlsTGxjACaabxvklZNh"}
}
```

| Field | Meaning |
| --- | --- |
| `organization` | The organization's slug |
| `role` | The role used for this request: the person's current role, or `admin` for a platform token |
| `scopes` | What the token may do |
| `kind` | `grant` (OAuth connection), `client` (platform app's own token), `personal` (personal access token), or `session` (a dashboard session) |
| `user` | The person: `id`, `email`, `name`. `null` for a platform app's own token |
| `app` | The app: `name`, `client_id`. `null` for personal tokens and sessions |

Use `user.id` (not the email, which can change) to link the connection to your own account record.

## Organizations

### `GET /v1/organizations`

Scope `organizations:read`. A list with the token's one organization, so code written for several organizations works unchanged.

```bash cURL
curl -s https://dashboard.pawabase.com/v1/organizations -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```json
[
  {"id": "01M7PX73ZYYPN2V0PWH1PX6BWS", "slug": "acme", "name": "Acme", "created_at": "2026-11-18T08:43:47.582521+00:00", "role": "owner"}
]
```

### `GET /v1/organizations/{slug}`

Scope `organizations:read`. The organization with its plan and usage. `{slug}` must be the token's organization; any other is `404`.

```bash cURL
curl -s https://dashboard.pawabase.com/v1/organizations/acme -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```json
{
  "id": "01M7PX73ZYYPN2V0PWH1PX6BWS",
  "slug": "acme",
  "name": "Acme",
  "created_at": "2026-11-18T08:43:47.582521+00:00",
  "role": "owner",
  "plan": "scale",
  "status": "active",
  "usage": {"projects": 3}
}
```

| Field | Meaning |
| --- | --- |
| `plan` | The plan's code: `free`, `pro`, `scale`, … |
| `status` | The subscription's status, `active` when in good standing |
| `usage.projects` | Projects the organization has now (not counting ones being deleted) |

Use `plan` and `usage` to warn people before `POST /v1/projects` would hit `plan_limit`.

## Projects

### The project object

```json
{
  "id": "01M7QBC1C7F9BGWBE1P6F58TDK",
  "ref": "mellow-dingo-swrz",
  "slug": "mellow-dingo-swrz",
  "org": "acme",
  "organization": "acme",
  "name": "Made in Acme Builder",
  "description": null,
  "state": "running",
  "endpoints": {"api": "https://acme-mellow-dingo-swrz.eu-1.pawabase.cloud"},
  "studio": true,
  "environment": "acme-mellow-dingo-swrz-development",
  "default_environment": "acme-mellow-dingo-swrz-development",
  "app": null,
  "integration": {"name": "Acme Builder", "client_id": "pbc_YnlsTGxjACaabxvklZNh"},
  "created_by_email": "ada@acme.com",
  "created_at": "2026-11-18T12:51:08.807490+00:00",
  "updated_at": "2026-11-18T12:51:09.610615+00:00"
}
```

| Field | Meaning |
| --- | --- |
| `ref` | How you name the project in `/v1/projects/{ref}`. The same as `slug`. The project's `id` is accepted there too |
| `id` | The project's permanent id |
| `slug` | The project's address name, generated when it is created; never changes |
| `organization`, `org` | The organization's slug |
| `name`, `description` | What people call it |
| `state` | `creating`, `running`, `paused` or `failed` |
| `endpoints.api` | Where the project's API answers, once `running`. Your product's own app uses this address with an [API key](#api-keys) |
| `studio` | Whether the project can be opened in Studio (and reached through the [Studio API](/integrations/project-api)) |
| `environment`, `default_environment` | The full name of the project's first environment. Clients send it as `PAWABASE_ENV` or the `x-environment` header; Studio API paths use it as `{env}`. `default_environment` is `null` until the project is `running` |
| `app` | The marketplace app on the project, if any: `{slug, state, error}` where `state` is `waiting`, `installing`, `installed` or `failed` |
| `integration` | Which app created the project through the API, if one did: `{name, client_id}` |
| `created_by_email` | Who created it: the person, or `app:<client id>` for a platform token |

### `GET /v1/projects`

Scope `projects:read`. The organization's projects, newest first. Projects being deleted are left out.

<CodeGroup>
```bash cURL
curl https://dashboard.pawabase.com/v1/projects -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```typescript TypeScript (SDK)
const projects = await pawabase.projects.list();
for (const p of projects) console.log(p.name, p.state, p.endpoints.api ?? "—");
```

```python Python (SDK)
for p in pawabase.projects.list():
    print(p["name"], p["state"], p["endpoints"].get("api", "—"))
```
</CodeGroup>

The answer is a JSON array of [project objects](#the-project-object). There is no paging: organizations have at most as many projects as their plan allows.

### `POST /v1/projects`

Scope `projects:write`, role member. Creates a project. Answers `201` at once with the project in state `creating`; setting it up takes a few seconds to a minute.

| Field | Required | Value |
| --- | --- | --- |
| `name` | Yes | Up to 80 characters |
| `description` | No | Up to 300 characters |
| `region` | No | A region code, where the Cloud offers a choice. Ignored where it doesn't |
| `app` | No | A [marketplace app](#marketplace)'s slug: the app is installed into the project as soon as it is running |
| `values` | No | With `app`: values for the app's variables, `{"SITE_URL": "https://…"}` |

<CodeGroup>
```bash cURL
curl https://dashboard.pawabase.com/v1/projects \
  -H "Authorization: Bearer $PAWABASE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Customer portal"}'
```

```typescript TypeScript (SDK)
const created = await pawabase.projects.create({ name: "Customer portal" });

// Polls every 2 s, up to 2 minutes. Throws if the project ends up failed.
const project = await pawabase.projects.waitUntilRunning(created.ref);
console.log("API at", project.endpoints.api, "environment", project.default_environment);
```

```python Python (SDK)
created = pawabase.projects.create("Customer portal")

# Polls every 2 s, up to 2 minutes. Raises if the project ends up failed.
project = pawabase.projects.wait_until_running(created["ref"])
print("API at", project["endpoints"]["api"], "environment", project["default_environment"])
```
</CodeGroup>

Pawabase generates the project's address (`slug`) from the name, with a few random characters to keep it unique. You can't choose it.

When the token belongs to an app, the project records it in `integration`, and the organization's activity shows `project.created` by the person (or `app:<client id>`).

Errors: `402 plan_limit` when the plan's project allowance is used up; `402 plan_feature` when `app` needs a feature the plan lacks; `404` for an unknown `app`; `422 missing_values` when `app` has variables without defaults that you didn't give (`details.missing` lists them); `422 invalid` for a missing name.

With `app` and no `description`, the project is described by the app's tagline.

### `GET /v1/projects/{ref}`

Scope `projects:read`. One [project](#the-project-object), plus its environments as the project's server reports them:

```bash cURL
curl -s https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```json
{
  "...": "every field of the project object",
  "environments": [
    {
      "id": "01M7QBC20Z7RQ92R8B0N58…",
      "slug": "development",
      "key": "acme-mellow-dingo-swrz-development",
      "schema": "development",
      "status": "ready",
      "is_default": true
    }
  ]
}
```

| Field | Meaning |
| --- | --- |
| `environments[].slug` | The environment's short name inside the project |
| `environments[].key` | Its full name: what Studio API paths and clients use as `{env}` |
| `environments[].status` | `ready` once it can serve requests |
| `environments[].is_default` | The project's first environment |

`environments` is `null` when the project's server didn't answer in time (the rest of the answer is still current), and absent when the project isn't `running`.

### `PATCH /v1/projects/{ref}`

Scope `projects:write`, role admin. Rename a project or change its description. The address never changes.

```bash cURL
curl -s -X PATCH https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz \
  -H "Authorization: Bearer $PAWABASE_TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Customer portal v2", "description": "Where customers log in"}'
```

| Field | Value |
| --- | --- |
| `name` | Up to 80 characters, not empty |
| `description` | Up to 300 characters. An empty string clears it |

Answers the updated project.

### `DELETE /v1/projects/{ref}`

Scope `projects:write`, role admin. Deletes the project **and all its data**: every environment, database, file and key. Answers at once with `{"deleted": "<slug>"}`; the project leaves lists immediately and is taken down in the background.

```bash cURL
curl -s -X DELETE https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz -H "Authorization: Bearer $PAWABASE_TOKEN"
# → {"deleted": "mellow-dingo-swrz"}
```

A project with **deletion protection** on (set in its settings in the dashboard) is refused with `409 protected`. Integrations can't switch protection off: a person has to.

<Warning>
Deleting can't be undone. If your product deletes projects, make the person confirm in your interface first, and say which project by name.
</Warning>

### `POST /v1/projects/{ref}/pause`

Scope `projects:write`, role admin. Pauses a running project: its data and settings stay, its API and Studio close. Answers the project with `state: "paused"`. Pausing a paused project changes nothing. Pausing one that isn't running or paused is `409 not_ready`.

```bash cURL
curl -s -X POST https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz/pause -H "Authorization: Bearer $PAWABASE_TOKEN"
```

### `POST /v1/projects/{ref}/restore`

Scope `projects:write`, role admin. Restores a paused project. Answers the project with `state: "running"`.

```bash cURL
curl -s -X POST https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz/restore -H "Authorization: Bearer $PAWABASE_TOKEN"
```

### `POST /v1/projects/{ref}/claim`

Scope `projects:write`. Only a **platform app's own token** (from `client_credentials`) may call it. Makes a claim link. See [Platform apps and claim links](/integrations/platform-apps#claim-links).

```bash cURL
curl -s -X POST https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz/claim -H "Authorization: Bearer $PAWABASE_TOKEN"   # a platform app's own token
```

## Marketplace

Pawabase's ready-made apps (helpdesk, storefront, CRM, bookings, …) can be deployed into projects.

### `GET /v1/marketplace`

Scope `projects:read`. Every app:

```bash cURL
curl -s https://dashboard.pawabase.com/v1/marketplace -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```json
[
  {
    "slug": "bookings",
    "name": "Bookings",
    "tagline": "A complete appointments system: live availability, deposits, packages, reschedules, no-show protection and reminders",
    "category": "Scheduling",
    "accent": "#0D9488",
    "icon": "calendar",
    "version": "2.0.0",
    "publisher": "Pawabase",
    "counts": {"tables": 11, "flows": 19, "routes": 9, "policies": 5, "roles": 3, "mail_templates": 8, "buckets": 1},
    "preview": ["bookings", "services", "staff", "clients"],
    "requires": []
  }
]
```

`requires` lists plan features the app needs (for example `["ai"]`); deploying it on a plan without them is `402 plan_feature`.

### `GET /v1/marketplace/{app}`

Scope `projects:read`. One app in full: its tables, flows, routes, and the **variables** it asks for, each with a name, description and default. Pass values for them as `values` when deploying.

```bash cURL
curl -s https://dashboard.pawabase.com/v1/marketplace/bookings -H "Authorization: Bearer $PAWABASE_TOKEN"
```

### Deploy into a new project

`POST /v1/projects` with `app` (above). One call: the project is created, and the app is installed the moment it is running.

### `POST /v1/projects/{ref}/apps`

Scope `projects:write`, role admin. Installs an app into an **existing, empty** project.

```bash cURL
curl -s -X POST https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz/apps \
  -H "Authorization: Bearer $PAWABASE_TOKEN" -H "Content-Type: application/json" \
  -d '{"app": "storefront", "values": {"SITE_URL": "https://shop.example.com"}}'
# → 202 {"project": {…}, "app": {"slug": "storefront", "state": "waiting"}}
```

| Field | Required | Value |
| --- | --- | --- |
| `app` | Yes | The app's slug |
| `values` | No | Values for its variables |

Answers `202` with `{"project": {...}, "app": {"slug", "state": "waiting", ...}}`. Poll `GET /v1/projects/{ref}` and read `app.state` until it is `installed` or `failed` (`app.error` says why). Pawabase rehearses the install in a scratch environment first, so a failed install leaves the project as it was, not half-built.

Refused at once: `409 has_app` when the project already has an app (waiting, installing or installed); `409 not_running` when the project is paused or failed; `422 missing_values` for variables without defaults. A project that already has its own tables or flows is accepted, but the install then fails (`app.state: "failed"`): apps go into empty projects only.

## API keys

Your product may want to call the project's own API (records, files, flows) as an app would, not through the Management API. For that it needs a project **API key**.

### `GET /v1/projects/{ref}/api-keys`

Scope `project:read`, role member. Every key of the project (never their secret values):

```bash cURL
curl -s https://dashboard.pawabase.com/v1/projects/mellow-dingo-swrz/api-keys -H "Authorization: Bearer $PAWABASE_TOKEN"
```

```json
{
  "data": [
    {
      "id": "b7e4443e-2b3f-4ded-8e86-88bc7ecb6bf8",
      "name": "web",
      "role": "publishable",
      "prefix": "pb_pk_VMh3Uf1m",
      "scopes": [],
      "allowed_ips": [],
      "allowed_routes": [],
      "environments": ["development"],
      "expires_at": null,
      "revoked_at": null,
      "last_used_at": null,
      "use_count": 0,
      "created_by": "studio",
      "project_id": "01M7Q53BATRHTZMWG6EQ6H2RCT",
      "active": true,
      "created_at": "2026-11-18T11:38:48.510474+00:00",
      "updated_at": "2026-11-18T11:38:48.510496+00:00"
    }
  ]
}
```

### `POST /v1/projects/{ref}/api-keys`

Scope `project:write`, role admin. Creates a key in the project's first environment (or the one named by `?environment=<full name>`). **The key is in the answer once**, as `key`.

| Field | Required | Value |
| --- | --- | --- |
| `name` | Yes | Up to 200 characters. Name it after your product, so people recognise it in Studio |
| `role` | No | `publishable` (default): safe in browsers, access rules apply. `secret`: server-only, bypasses access rules |
| `environments` | No | `"all"`, or a list of environment names. Left out: only the one in the path |
| `scopes` | No | Limit what the key may do (the list is in Studio's API keys page) |
| `expires_at` | No | ISO date-time after which the key stops working |
| `allowed_ips` | No | IPs or CIDR ranges the key may be used from |
| `allowed_routes` | No | Route rules such as `GET /rest/v1/orders` or `/flows/v1/*` |

<CodeGroup>
```bash cURL
curl https://dashboard.pawabase.com/v1/projects/$REF/api-keys \
  -H "Authorization: Bearer $PAWABASE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name": "Acme Builder (server)", "role": "secret"}'
```

```typescript TypeScript (SDK)
const made = await pawabase.projects.createKey(ref, { name: "Acme Builder (server)", role: "secret" });
await secrets.put(`pawabase:${ref}`, made.key); // store it now; it is never shown again
```

```python Python (SDK)
made = pawabase.projects.create_key(ref, "Acme Builder (server)", role="secret")
secrets.put(f"pawabase:{ref}", made["key"])  # store it now; it is never shown again
```
</CodeGroup>

The organization's activity records `integration.key_created` with who did it (for example `ada@acme.com via Acme Builder`).

<Note>
A key made this way belongs to the **project**, not to the connection. Disconnecting your app in Pawabase does not revoke keys it made. Revoke them yourself when a person disconnects (through the [Studio API](/integrations/project-api#api-keys)), or tell people they can in Studio.
</Note>

## Rate of requests and timeouts

- Management calls answer quickly; calls through the Studio API wait for the project's server, up to **120 seconds**.
- Access tokens last an hour: refresh before they run out rather than on the first `401`, and [serialise refreshes](/integrations/oauth-flow#reuse-detection).
- Each `GET /v1/projects/{ref}` asks the project's server for its environments. Don't poll it faster than every two seconds.

## Versioning

The API is versioned in its path. Within `/v1`, fields may be **added** to answers and new endpoints may appear; nothing is removed or renamed. Ignore fields you don't know. A breaking change would come as `/v2`, with `/v1` kept alongside.
