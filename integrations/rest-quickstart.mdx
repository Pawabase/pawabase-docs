Everything the [integration SDK](/integrations/sdk) does is plain HTTP, and this page walks the whole thing with `curl` so you can use any language, or none. The **REST reference** group in the sidebar (under Connect apps) lists every endpoint, parameter, status and response, and you can try calls from it. The [OAuth flow](/integrations/oauth-flow) page explains each step's rules in depth.

<Note>
Examples use `https://dashboard.pawabase.com`. A self-hosted Pawabase Cloud uses its own address; `GET /.well-known/oauth-authorization-server` reports the right endpoints for the server you are talking to.
</Note>

## What you need

From [Register an app](/integrations/register-an-app): the **client id** (`pbc_…`), the **client secret** (`pbs_…`) and a registered **callback URL**.

```bash
export CLIENT_ID=pbc_YnlsTGxjACaabxvklZNh
export CLIENT_SECRET=pbs_…
export REDIRECT_URI=http://127.0.0.1:4400/callback
export PAWABASE=https://dashboard.pawabase.com
```

## Conventions

| | |
| --- | --- |
| **Base address** | `$PAWABASE/oauth/*` for OAuth, `$PAWABASE/v1/*` for the Management API |
| **Auth** | OAuth endpoints: your client id and secret (HTTP Basic, or in the form body). `/v1`: `Authorization: Bearer <token>` |
| **Bodies** | `/oauth/token` and `/oauth/revoke` take `application/x-www-form-urlencoded` (JSON is accepted too). `/v1` takes and answers JSON |
| **Errors** | OAuth: `{"error", "error_description"}`. `/v1`: `{"error", "message", "details"}`. See [Errors](/integrations/errors) |
| **Caching** | `/oauth/*` answers carry `Cache-Control: no-store` |
| **Rate limits** | `/oauth/token` and `/oauth/revoke`: 300 a minute per client id and address, 1,200 a minute per address. Over it: `429 slow_down` with `Retry-After` |
| **Timeouts** | `/v1` calls into a project wait for the project's server up to 120 seconds. Set your client's timeout above that |
| **Versioning** | In the path (`/v1`). Fields may be added to answers; nothing is removed or renamed. Ignore fields you don't know |

## 1. Make the PKCE pair and a state

A `code_verifier` is a random string of 43–128 characters (`A–Z a–z 0–9 - . _ ~`). The `code_challenge` is its SHA-256, base64url-encoded without padding. The `state` is at least 16 random bytes you compare when the person comes back.

```bash
VERIFIER=$(openssl rand -base64 48 | tr '+/' '-_' | tr -d '=\n')
CHALLENGE=$(printf '%s' "$VERIFIER" | openssl dgst -sha256 -binary | openssl base64 -A | tr '+/' '-_' | tr -d '=')
STATE=$(openssl rand -hex 16)
```

Keep `VERIFIER` and `STATE` in the person's session on your server. Only `CHALLENGE` goes into the address.

## 2. Send the person to authorize

Redirect the **browser** (a 302) to:

```bash
echo "$PAWABASE/oauth/authorize?client_id=$CLIENT_ID&redirect_uri=$(printf '%s' "$REDIRECT_URI" | jq -sRr @uri)&response_type=code&scope=organizations:read%20projects:read%20projects:write&state=$STATE&code_challenge=$CHALLENGE&code_challenge_method=S256"
```

The person signs in if needed, picks an organization on the consent screen and clicks **Connect**. Pawabase redirects to your callback:

```text
http://127.0.0.1:4400/callback?code=pbo_Qm7…&state=<the state you sent>
```

If they cancel it is `?error=access_denied&state=…` instead. **Check that `state` equals the one you saved** before doing anything else. If the client id or callback address is wrong, Pawabase never redirects: it answers `400` in the browser.

## 3. Trade the code for tokens

On your server (never the browser: it carries the secret). A code works once and for 10 minutes.

```bash
curl -s $PAWABASE/oauth/token \
  -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d grant_type=authorization_code \
  -d code=pbo_Qm7… \
  --data-urlencode redirect_uri="$REDIRECT_URI" \
  -d code_verifier="$VERIFIER"
```

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs…",
  "token_type": "bearer",
  "expires_in": 3600,
  "refresh_token": "pbr_4vQ9…",
  "scope": "organizations:read projects:read projects:write",
  "organization": "acme"
}
```

Store both tokens on your server with your user record and the `organization`. **Do not retry this call on a network error**: a second use of a code ends the whole connection. Start the sign-in again instead.

<Tip>
A **public client** (a CLI or desktop app) has no secret: drop `-u …` and send `-d client_id=$CLIENT_ID` instead. The verifier then proves the sign-in.
</Tip>

## 4. Call the API

```bash
export TOKEN=eyJhbGciOiJIUzI1NiIs…

curl -s $PAWABASE/v1/token -H "Authorization: Bearer $TOKEN"
curl -s $PAWABASE/v1/projects -H "Authorization: Bearer $TOKEN"
```

```bash
# Create a project, then poll until it is running (no faster than every 2 seconds)
curl -s $PAWABASE/v1/projects \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Customer portal"}'
# → 201 {"ref": "mellow-dingo-swrz", "state": "creating", …}

curl -s $PAWABASE/v1/projects/mellow-dingo-swrz -H "Authorization: Bearer $TOKEN"
# → {"state": "running", "endpoints": {"api": "…"}, "default_environment": "acme-mellow-dingo-swrz-development", …}
```

```bash
# Anything Studio can do inside the project, with the default environment name
ENV=acme-mellow-dingo-swrz-development
curl -s -X POST $PAWABASE/v1/projects/mellow-dingo-swrz/studio/platform/envs/$ENV/resources \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "orders", "fields": [{"name": "total", "type": "number"}]}'
```

An error looks like this, with the status as the HTTP status:

```json
{"error": "insufficient_scope", "message": "This token cannot do that.", "details": {"needed": "projects:write"}}
```

## 5. Refresh before it runs out

The access token lasts an hour. A minute before, trade the refresh token for a new pair. **The old refresh token stops working at once**, so save the new one before you use the new access token.

```bash
curl -s $PAWABASE/oauth/token \
  -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d grant_type=refresh_token \
  -d refresh_token=pbr_4vQ9…
```

<Warning>
A refresh token that is used twice ends the whole connection, because only a copy could be used twice. If two workers can refresh the same connection, take a lock (a row lock or a Redis lock) around the stored tokens and re-read them inside it before you refresh. See [Reuse detection](/integrations/oauth-flow#reuse-detection).
</Warning>

When the answer is `400 invalid_grant`, the connection is over (an admin disconnected it, it went 30 days unused, or a copy was used). Ask the person to connect again. `401 invalid_client` means your secret is wrong; the connection is fine.

## 6. Disconnect

```bash
curl -s $PAWABASE/oauth/revoke \
  -u "$CLIENT_ID:$CLIENT_SECRET" \
  -d token=pbr_4vQ9…
# → 200 {}
```

Send the refresh token to end the whole connection (it disappears from the organization's **Connected apps** list). The answer is `200 {}` even for a token Pawabase doesn't know.

## The other two ways in

<Tabs>
  <Tab title="Platform app">
    A platform app gets its own token with no person involved. It acts as an admin of the organization that registered it:

    ```bash
    curl -s $PAWABASE/oauth/token \
      -u "$CLIENT_ID:$CLIENT_SECRET" \
      -d grant_type=client_credentials \
      -d "scope=projects:write project:write"
    ```

    There is no refresh token: ask again when `expires_in` runs out. Then make a project and a claim link for your user:

    ```bash
    curl -s -X POST $PAWABASE/v1/projects/$REF/claim -H "Authorization: Bearer $PLATFORM_TOKEN"
    # → 201 {"claim_url": "https://dashboard.pawabase.com/claim?token=pbk_…", "expires_at": "…"}
    ```

    See [Platform apps and claim links](/integrations/platform-apps).
  </Tab>
  <Tab title="Personal token">
    For your own scripts and CI there is no OAuth at all. Create a `pbp_…` token in **Settings → Integrations → New token** and send it as the bearer:

    ```bash
    curl -s $PAWABASE/v1/projects -H "Authorization: Bearer pbp_…"
    ```

    See [Personal access tokens](/integrations/personal-tokens).
  </Tab>
</Tabs>

## The same thing in code, without the SDK

<CodeGroup>
```typescript TypeScript
const basic = "Basic " + Buffer.from(`${CLIENT_ID}:${CLIENT_SECRET}`).toString("base64");

async function token(form: Record<string, string>) {
  const response = await fetch(`${PAWABASE}/oauth/token`, {
    method: "POST",
    headers: { "content-type": "application/x-www-form-urlencoded", authorization: basic },
    body: new URLSearchParams(form),
  });
  const body = await response.json();
  if (!response.ok) throw Object.assign(new Error(body.error_description), { code: body.error, status: response.status });
  return body; // access_token, refresh_token, expires_in, scope, organization
}

const tokens = await token({ grant_type: "authorization_code", code, redirect_uri: REDIRECT_URI, code_verifier: verifier });

const api = (path: string, init: RequestInit = {}) =>
  fetch(`${PAWABASE}/v1${path}`, { ...init, headers: { authorization: `Bearer ${tokens.access_token}`, "content-type": "application/json" } });
const projects = await (await api("/projects")).json();
```

```python Python
import httpx

auth = (CLIENT_ID, CLIENT_SECRET)  # HTTP Basic


def token(**form):
    response = httpx.post(f"{PAWABASE}/oauth/token", auth=auth, data=form)
    body = response.json()
    if response.status_code != 200:
        raise RuntimeError(f"{body['error']}: {body.get('error_description')}")
    return body  # access_token, refresh_token, expires_in, scope, organization


tokens = token(grant_type="authorization_code", code=code, redirect_uri=REDIRECT_URI, code_verifier=verifier)
projects = httpx.get(f"{PAWABASE}/v1/projects", headers={"authorization": f"Bearer {tokens['access_token']}"}, timeout=130).json()
```
</CodeGroup>

That is all the SDK adds on top: PKCE and state generation, the return check, one-at-a-time refresh, typed errors and the project helpers. Prefer it where you can; this page is for when you can't.
