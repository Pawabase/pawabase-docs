An integration is plain HTTP: the [OAuth flow](/integrations/oauth-flow) and the [Management API](/integrations/management-api), which the [REST quickstart](/integrations/rest-quickstart) walks with curl. These libraries are **just a client** for it. They send exactly those requests; they add no behaviour the HTTP API doesn't have. Use them to skip writing the PKCE, state-check and refresh plumbing yourself, or ignore them and call the API from any language.

Each method below lists the HTTP request it makes, so you can always see what is really sent.

| | TypeScript | Python |
| --- | --- | --- |
| **Package** | `@pawabase/client` 0.10 or later (0.12 for `regions`, `retry` and `idempotencyKey`) | `pawabase` 0.12 or later (0.14 for `regions`, `retry` and `idempotency_key`) |
| **Import** | `import { PawabaseOAuth, PawabaseCloud } from "@pawabase/client/cloud"` | `from pawabase.cloud import OAuth, Cloud` |
| **Async** | Every method returns a promise | `AsyncOAuth` and `AsyncCloud` are the same, awaited |
| **Runs on** | Node 20+, Bun, Deno, Workers, browsers | Python 3.11+ |

```bash
npm install @pawabase/client
pip install pawabase
```

<Note>
This is not the SDK your *own app* uses to read and write its data (`createClient`, with an API key). That one talks to a project. This one talks to **Pawabase Cloud**, on behalf of the people who connect your product. See [Apps, clients and connections](/integrations/clients) for the difference.
</Note>

## Quickstart

Register an app first ([Register an app](/integrations/register-an-app)) to get a client id and secret, and add your callback address.

<CodeGroup>
```typescript TypeScript (SDK)
import { PawabaseOAuth, PawabaseCloud } from "@pawabase/client/cloud";

const oauth = new PawabaseOAuth({
  clientId: process.env.PAWABASE_CLIENT_ID!,
  clientSecret: process.env.PAWABASE_CLIENT_SECRET!,
  redirectUri: "https://app.example.com/oauth/pawabase/callback",
});

// 1. "Connect Pawabase" button: make the address, keep state + codeVerifier in the person's session, redirect.
app.get("/connect", async (req, res) => {
  const pending = await oauth.authorize({ scopes: ["organizations:read", "projects:read", "projects:write"] });
  req.session.pawabase = { state: pending.state, codeVerifier: pending.codeVerifier };
  res.redirect(pending.url);
});

// 2. They come back: the SDK checks the state, trades the code (with PKCE), and returns the tokens.
app.get("/oauth/pawabase/callback", async (req, res) => {
  const { state, codeVerifier } = req.session.pawabase;
  const tokens = await oauth.callback(req.originalUrl, { state, codeVerifier });
  const pawabase = new PawabaseCloud({ token: tokens.accessToken });
  const me = await pawabase.whoami();
  await db.connections.upsert({ user: req.user.id, organization: tokens.organization, pawabaseUser: me.user?.id, tokens });
  res.redirect("/projects");
});

// 3. Later, for that customer: tokens refresh themselves, and each new pair is handed to you to save.
const stored = await db.connections.find({ user: req.user.id });
const pawabase = new PawabaseCloud({ token: oauth.tokenSource(stored.tokens, { onRefresh: (next) => db.connections.save(stored.id, next) }) });
const project = await pawabase.projects.create({ name: "Customer portal" });
await pawabase.projects.waitUntilRunning(project.ref);
```

```python Python (SDK)
import os
from pawabase.cloud import OAuth, OAuthTokens, Cloud

oauth = OAuth(
    client_id=os.environ["PAWABASE_CLIENT_ID"],
    client_secret=os.environ["PAWABASE_CLIENT_SECRET"],
    redirect_uri="https://app.example.com/oauth/pawabase/callback",
)

# 1. "Connect Pawabase" button: make the address, keep state + code_verifier in the person's session, redirect.
@app.get("/connect")
def connect(request):
    pending = oauth.authorize(scopes=["organizations:read", "projects:read", "projects:write"])
    request.session["pawabase"] = {"state": pending.state, "code_verifier": pending.code_verifier}
    return redirect(pending.url)

# 2. They come back: the SDK checks the state, trades the code (with PKCE), and returns the tokens.
@app.get("/oauth/pawabase/callback")
def callback(request):
    saved = request.session["pawabase"]
    tokens = oauth.callback(str(request.url), state=saved["state"], code_verifier=saved["code_verifier"])
    with Cloud(token=tokens.access_token) as pawabase:
        me = pawabase.whoami()
    db.connections.upsert(user=request.user.id, organization=tokens.organization, pawabase_user=me["user"]["id"], tokens=tokens.to_dict())
    return redirect("/projects")

# 3. Later, for that customer: tokens refresh themselves, and each new pair is handed to you to save.
stored = db.connections.find(user=request.user.id)
source = oauth.token_source(OAuthTokens.from_dict(stored.tokens), on_refresh=lambda t: db.connections.save(stored.id, t.to_dict()))
with Cloud(token=source) as pawabase:
    project = pawabase.projects.create("Customer portal")
    pawabase.projects.wait_until_running(project["ref"])
```
</CodeGroup>

## PawabaseOAuth

Your registered app. One per product.

```ts
new PawabaseOAuth({ clientId, clientSecret?, redirectUri?, baseUrl?, fetch? })
```

| Option | Meaning |
| --- | --- |
| `clientId` | Your app's `pbc_…` id |
| `clientSecret` | Your `pbs_…` secret. **Leave it out for a public client** (a desktop app or CLI): PKCE alone proves the sign-in |
| `redirectUri` | One of the app's registered callback addresses. Can be given per call instead |
| `baseUrl` | Pawabase Cloud's address. Default `https://dashboard.pawabase.com`. A self-hosted Cloud passes its own |
| `fetch` | Your own `fetch`, for tests or a proxy. Python: `transport=`, an `httpx` transport |

| Method | Calls | Returns |
| --- | --- | --- |
| `authorize({ scopes?, state?, redirectUri? })` | nothing: builds the address | `{ url, state, codeVerifier }`. Keep `state` and `codeVerifier` in the person's session, redirect the browser to `url` |
| `callback(returned, { state, codeVerifier })` | `POST /oauth/token` | `OAuthTokens`. Reads the return address (a full URL, or its query), refuses a declined or forged return, and trades the code |
| `exchangeCode({ code, codeVerifier?, redirectUri? })` | `POST /oauth/token` | `OAuthTokens`. The lower-level step: prefer `callback` |
| `refresh(refreshToken)` | `POST /oauth/token` | A new `OAuthTokens`. The old refresh token stops working |
| `clientCredentials(scopes?)` | `POST /oauth/token` | A platform app's own token (no refresh token) |
| `revoke(token)` | `POST /oauth/revoke` | Nothing. A refresh token ends the whole connection; an access token ends only itself |
| `tokenSource(tokens, { onRefresh })` | `/oauth/token`, when needed | A function that always returns a working access token |
| `metadata()` | `GET /.well-known/oauth-authorization-server` | The server's own description of its endpoints |

In Python the names are snake_case (`code_verifier`, `exchange_code`, `client_credentials`, `token_source`, `on_refresh`).

### The tokens object

```ts
interface OAuthTokens {
  accessToken: string;
  refreshToken?: string;      // absent for client credentials
  expiresAt: number;          // ms since the epoch, already 30 s early
  scope: string[];
  organization?: string;      // the organization the person picked
}
```

In Python it is `OAuthTokens(access_token, refresh_token, expires_at, scope, organization)`, with `to_dict()` and `OAuthTokens.from_dict()` to store it as JSON. Store the whole object per connection, keyed by your user and the `organization`.

### Keeping tokens fresh

`tokenSource` is how you should hand tokens to `PawabaseCloud`. It returns the current access token while it is good, and refreshes 30 seconds before `expiresAt`. Since `expiresAt` is itself set 30 seconds before the token really expires, that is a minute before Pawabase would refuse it:

```ts
const token = oauth.tokenSource(stored.tokens, {
  onRefresh: async (next) => { await db.connections.save(stored.id, next); },
});
const pawabase = new PawabaseCloud({ token });
```

Three rules it follows for you, which matter because refresh tokens are single-use:

1. **One refresh at a time.** Many calls at once share one refresh (a single-flight promise in TypeScript, a lock in Python).
2. **Saved before used.** `onRefresh` runs with the new pair *before* the new access token is returned to your call, so a crash right after can't lose the new refresh token.
3. **Replaces the old.** The source holds the new pair from then on.

<Warning>
One `tokenSource` covers one process. If several workers or servers can refresh the **same** connection, two of them can send the same refresh token and Pawabase will end the connection (see [reuse detection](/integrations/oauth-flow#reuse-detection)). Hold a lock across processes around the row `onRefresh` writes, such as a row lock or a Redis lock, and re-read the stored tokens inside it before refreshing.
</Warning>

When refreshing fails with `invalid_grant`, the connection is over. Catch it, mark the connection as disconnected in your database, and ask the person to connect again:

```ts
try {
  await pawabase.projects.list();
} catch (error) {
  if (error instanceof OAuthError && error.needsReconnect) await db.connections.markDisconnected(stored.id);
  else throw error;
}
```

## PawabaseCloud

One connection: the Management API for one organization.

```ts
new PawabaseCloud({ token, baseUrl?, fetch?, timeout? })
```

`token` is one of:

- a string: an access token, a personal `pbp_…` token, or a platform app's token;
- a function returning one (sync or async): [`tokenSource`](#keeping-tokens-fresh) is exactly that.

`timeout` is in milliseconds (seconds in Python) and defaults to 130 000, because calls into a project wait for its server for up to two minutes.

### Who and what

| Method | Endpoint | Scope |
| --- | --- | --- |
| `whoami()` | `GET /v1/token` | none |
| `organizations.list()` | `GET /v1/organizations` | `organizations:read` |
| `organizations.get(slug)` | `GET /v1/organizations/{slug}` | `organizations:read` |

`whoami()` answers the organization, the role used, the scopes, the `kind` of token and the person's `user.id`, email and name. Call it right after connecting, and link the connection to your own account by `user.id` (the email can change).

### Projects

| Method | Endpoint | Scope, role |
| --- | --- | --- |
| `projects.list()` | `GET /v1/projects` | `projects:read` |
| `projects.get(ref)` | `GET /v1/projects/{ref}` | `projects:read` |
| `projects.create({ name, description?, type?, region?, size?, app?, values? }, { idempotencyKey? })` | `POST /v1/projects` | `projects:write`, member |
| `projects.retry(ref)` | `POST /v1/projects/{ref}/retry` | `projects:write`, admin |
| `regions()` | `GET /v1/regions` | `projects:read` |
| `projects.update(ref, { name?, description? })` | `PATCH /v1/projects/{ref}` | `projects:write`, admin |
| `projects.delete(ref)` | `DELETE /v1/projects/{ref}` | `projects:write`, admin |
| `projects.pause(ref)` / `projects.restore(ref)` | `POST /v1/projects/{ref}/pause` / `restore` | `projects:write`, admin |
| `projects.claimLink(ref)` | `POST /v1/projects/{ref}/claim` | `projects:write`, platform app only |
| `projects.installApp(ref, app, values?)` | `POST /v1/projects/{ref}/apps` | `projects:write`, admin |
| `projects.listKeys(ref)` | `GET /v1/projects/{ref}/api-keys` | `project:read`, member |
| `projects.createKey(ref, { name, role?, environments?, scopes?, expiresAt?, allowedIps?, allowedRoutes?, environment? })` | `POST /v1/projects/{ref}/api-keys` | `project:write`, admin |
| `marketplace.list()` / `marketplace.get(slug)` | `GET /v1/marketplace[/{app}]` | `projects:read` |

Python: `projects.create("Customer portal", app="bookings", values={...}, idempotency_key=key)` takes the name first; `create_key(ref, "name", role="secret", allowed_ips=[...])`; `claim_link`, `install_app`, `list_keys`. Answers are the API's own JSON (snake_case fields in both languages), documented in the [Management API](/integrations/management-api).

#### Waiting for a project

Creating a project answers at once with `state: "creating"`; setting it up takes a few seconds to a minute. Two helpers wait for you:

```ts
const created = await pawabase.projects.create({ name: "Customer portal", app: "storefront" });
const ready = await pawabase.projects.waitUntilRunning(created.ref);   // polls every 2 s, up to 2 minutes
await pawabase.projects.waitForApp(created.ref);                       // when you also asked for an app
console.log(ready.endpoints.api, ready.default_environment);
```

They throw (an `Error`, in Python a `RuntimeError`) if the project ends up `failed`, if the app fails to install (the message carries Pawabase's reason), or if the wait runs out. Options: `{ interval, timeout, signal }` in milliseconds; in Python `interval=` and `timeout=` in seconds. Don't poll faster than every two seconds.

#### Keys

```ts
const made = await pawabase.projects.createKey(ref, { name: "My product (server)", role: "secret" });
await vault.put(`pawabase:${ref}`, made.key); // in the answer once, and never again
```

A key belongs to the project, not the connection: disconnecting your app does not revoke keys it made.

### Inside a project

`studio(ref)` reaches everything Studio can do in that one project: tables, records, access rules, flows, users, mail, buckets, secrets, blueprints. See [Inside a project](/integrations/project-api) for every target and path.

```ts
const project = await pawabase.projects.get(ref);
const env = project.default_environment!;
const studio = pawabase.studio(ref);

await studio.post("platform", `envs/${env}/resources`, {
  name: "orders",
  fields: [{ name: "total", type: "number", required: true }],
});
const tables = await studio.get("platform", `envs/${env}/resources`);
```

| Method | Needs |
| --- | --- |
| `studio.get(target, path, query?)` | `project:read`, member |
| `studio.post / put / patch / delete(target, path, body?)` | `project:write`, admin |
| `studio.request(method, target, path, { body, query })` | as above |

`target` is `platform`, `auth`, `realtime`, `telemetry`, `gateway`, `object`, `avatar` or `document`. The answer is the project server's own, unchanged.

### Anything else

`pawabase.request(method, path, { body, query })` makes any `/v1` call and returns the parsed JSON. Use it for an endpoint the class has no method for yet; errors are the same.

## Platform apps

A platform app gets its own token with no person involved:

```ts
const tokens = await oauth.clientCredentials(["projects:write", "project:write"]);
const platform = new PawabaseCloud({ token: tokens.accessToken });

const project = await platform.projects.create({ name: `${user.name}'s shop`, app: "storefront" });
await platform.projects.waitForApp(project.ref);
const { claim_url } = await platform.projects.claimLink(project.ref);   // email this to the user
```

The token lasts an hour and has no refresh token: ask for a new one when it expires. Cache it, or give `PawabaseCloud` a function that asks when needed. See [Platform apps and claim links](/integrations/platform-apps).

## Personal access tokens

For your own scripts and CI, skip OAuth entirely:

```ts
const pawabase = new PawabaseCloud({ token: process.env.PAWABASE_TOKEN! }); // pbp_…
```

## Errors

Two error classes, one for each half. Both carry the HTTP `status`.

| Class | From | Fields |
| --- | --- | --- |
| `OAuthError` | `/oauth/*`, and a bad return | `code` (the standard OAuth error), `message`, `status` (`0` if the person was sent back with an error), `retryAfter`, `needsReconnect` |
| `CloudError` | `/v1/*` | `code` (Pawabase's error), `message`, `status`, `details` |

**`OAuthError` codes you will meet:**

| `code` | Meaning | What to do |
| --- | --- | --- |
| `access_denied` | The person clicked Cancel | Tell them nothing was connected |
| `invalid_state` | The return was not for the sign-in you started | Refuse it. Start again |
| `invalid_grant` | The code or refresh token is expired, used, revoked, or the connection was removed | `needsReconnect` is true: ask the person to connect again. Never retry |
| `invalid_client` | Wrong client id or secret | Fix your configuration. The connection is fine |
| `slow_down` | Rate limited | Wait `retryAfter` seconds |

**`CloudError` codes you will meet:** `unauthorized` (token unknown or expired: refresh, or reconnect), `insufficient_scope` (`details.needed` names the scope), `forbidden` (the person's role is too low), `not_found`, `not_ready` (project still starting), `plan_limit`, `plan_feature`, `invalid` (`details` maps fields to problems). The full list, with what to do for each, is in [Errors and troubleshooting](/integrations/errors).

```ts
try {
  await pawabase.projects.create({ name: "Customer portal" });
} catch (error) {
  if (error instanceof CloudError && error.code === "plan_limit") {
    showUpgradePrompt(error.details); // { limit, used }
  } else throw error;
}
```

## What the SDK does not do

- **It never stores anything.** Tokens are returned to you and handed back to `onRefresh`. Where they live, and how they are encrypted at rest, is yours to decide.
- **It does not retry the code exchange.** A code works once; a second use ends the connection. A network error there means: start the sign-in again.
- **It does not hold a secret for a browser.** Never put `clientSecret` in code that ships to a browser. A single-page app or a desktop app is a public client: construct `PawabaseOAuth` without a secret and rely on PKCE.
- **It does not verify the access token.** Treat it as opaque. Call `whoami()` to know what it is.

## Without the SDK

Everything above is plain HTTP, and the [REST quickstart](/integrations/rest-quickstart) walks it with curl. The sidebar's **REST reference** lists every endpoint. Also: [the OAuth flow](/integrations/oauth-flow) and the [Management API](/integrations/management-api) document every request and response, and `GET /.well-known/oauth-authorization-server` lets any standard OAuth library discover the endpoints.
