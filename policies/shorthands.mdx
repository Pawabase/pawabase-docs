Most rules are made from a handful of ready-made checks. They read better than building the same thing with **Compare values**, and they are the forms Pawabase understands best.

## The checks

| In the builder | Fill in | Passes when |
| --- | --- | --- |
| **Is signed in** | yes / no | The caller is signed in. *no* means "must be anonymous" |
| **Has role** | one or more roles | The caller has any of those roles |
| **Has permission** | one or more permissions | The caller has that permission, or the wildcard `*` |
| **Owns the record (field)** | a column; default `owner_id` | That column equals the caller's id |
| **Uses a secret key** | nothing | A secret key (or Studio) made the request |
| **Signed in with 2FA** | nothing | The session completed a second step |
| **Key has scope** | a scope | The API key carries it |
| **Caller kind is** | a kind, such as `user` | The kind of caller matches |

## The same checks in the rule picker

| In the picker | Equivalent |
| --- | --- |
| **Signed-in users** | Is signed in |
| **Record owner (owner_id)** | Owns the record (`owner_id`) |
| **Signed in with 2FA** | Signed-in users **and** Signed in with 2FA |
| **Secret keys & Studio** | Uses a secret key |
| **Users with role…** | Has role |
| **Users with permission…** | Has permission |
| **Owner via field…** | Owns the record (that column) |
| **Keys with scope…** | Key has scope |
| **Anyone (public)** / **Nobody** | Always / never |

## Organization checks

Four more checks look at the [organization](/auth/organizations) the session is signed in to (`switchOrg`, or `org` at sign-in). They aren't in the builder's list; write them in the condition's **JSON** view, in a named rule, in [infrastructure as code](/tools/iac/policies), or as a reference such as `org_role:billing` wherever a rule is asked for.

| JSON | Reference | Passes when |
| --- | --- | --- |
| `{"org": "org_id"}` | `org:org_id` | The session is in an organization **and** the record's column (default `org_id`) holds that organization's id. On lists it becomes a database filter, so each organization sees only its rows |
| `{"org_role": ["admin", "billing"]}` | `org_role:billing` | The session is in an organization and the caller's role there is one of these |
| `{"org_permission": "invoices.write"}` | `org_permission:invoices.write` | The session is in an organization and the caller's role there grants this permission (or `*`). A list must have all |
| `{"team": ["finance"]}` | `team:finance` | The caller is in one of these teams of the current organization |

Two ready-made rules go with them:

| Rule | Passes when |
| --- | --- |
| `org_member` | The session is signed in to any organization |
| `org` | Rows of the organization the caller is signed in to (the record's `org_id`) |

The record's column must hold the organization's **id** (`$auth.org_id`), not its slug.

## Every check in JSON

What each builder check is, written out. Use these in a rule's JSON view, a named rule, or code:

| Builder | JSON |
| --- | --- |
| **Is signed in** | `{"authenticated": true}` |
| **Has role** | `{"role": ["admin", "editor"]}`: any of them |
| **Has permission** | `{"permission": ["posts:write"]}`: all of them, or `*` |
| **Owns the record (field)** | `{"owner": "author_id"}`: signed in, and the column equals `$auth.user_id` |
| **Uses a secret key** | `{"service": true}` |
| **Signed in with 2FA** | `{"aal": "aal2"}` |
| **Key has scope** | `{"scope": "resource:write"}` |
| **Caller kind is** | `{"kind": "user"}`: `user` for people and machines, `service` for Pawabase's own services. To tell a machine from a person, compare `$auth.actor_type` with `machine` |

And the ready-made rules: `public` (anyone), `deny` (nobody but secret keys and Studio), `authenticated`, `service`, `owner` (`owner_id`), `mfa` (signed in with a second step), `org_member`, `org`. A reference can also carry an argument: `role:admin`, `permission:posts:write`, `owner:author_id`, `scope:resource:write`.

## Permission names must match

**Has permission** compares text. If a role grants `posts:write`, type `posts:write`, not `posts.write`. Pick one separator for your project and use it everywhere ([Roles](/auth/roles)).

## Why prefer them

- **Database filters.** An **Owns the record** rule on a list becomes "only the caller's rows" in the database query, so only they are read and pages and counts are exact.
- **Clarity.** *Has role admin* explains itself.
- **Fewer mistakes.** The builder makes them correctly.

## Custom owner columns

Not every table's owner is called `owner_id`. Use **Owner via field…** (or **Owns the record (field)**) and type `author_id`, `customer_id` or whichever column holds the person.

Where several people may act (the author **or** an editor), combine: **Any of:** Owns the record (`author_id`); Has role `editor`.
