A shorthand is a one-key object (or a `name:value` string) that stands for a longer condition. They read better and they are the forms Pawabase understands best.

## The shorthands

| Shorthand | Expands to | Passes when |
| --- | --- | --- |
| `{ "authenticated": true }` | `{ "eq": ["$auth.authenticated", true] }` | The caller is signed in. `false` means "must be anonymous" |
| `{ "role": "admin" }` | `{ "contains": ["$auth.roles", "admin"] }` | The caller has that role |
| `{ "role": ["admin", "editor"] }` | `any` of the above | The caller has **any** of the roles |
| `{ "permission": "posts.write" }` | `contains` on `$auth.permissions`, or `*` | The caller has that permission, or the wildcard `*` |
| `{ "permission": ["a", "b"] }` | `all` of the above | The caller has **all** of the permissions |
| `{ "owner": "owner_id" }` | `authenticated` and `eq ["$record.owner_id", "$auth.user_id"]` | The record's column equals the caller's id. Column defaults to `owner_id` |
| `{ "service": true }` | `eq ["$credential.is_service", true]` | A secret key (or Studio) |
| `{ "kind": "user" }` | `eq ["$auth.kind", "user"]` | The caller is that kind |
| `{ "scope": "resource:write" }` | `contains ["$credential.scopes", "resource:write"]` | The API key has that scope |
| `{ "aal": "aal2" }` | `eq ["$auth.aal", "aal2"]` | The session's assurance level |

## String forms

Where a rule *reference* is accepted, a shorthand can be a string:

| String | Same as |
| --- | --- |
| `"role:admin"` | `{ "role": "admin" }` |
| `"permission:posts.write"` | `{ "permission": "posts.write" }` |
| `"owner:author_id"` | `{ "owner": "author_id" }` |
| `"scope:resource:write"` | `{ "scope": "resource:write" }` |

(Inside `all`/`any`/`not`, use the object forms.)

## Permission strings must match exactly

The `permission` shorthand compares text. If you grant `posts:write` to a role, the rule must say `posts:write`, not `posts.write`. Pick one separator for your project and use it everywhere ([Roles](/auth/roles)).

## Built-in names

| Name | Equals |
| --- | --- |
| `public` | `true` |
| `deny` | `false` (service callers still pass) |
| `authenticated` | `{ "authenticated": true }` |
| `service` | `{ "service": true }` |
| `owner` | `{ "owner": "owner_id" }` |
| `mfa` | `{ "all": [{ "authenticated": true }, { "aal": "aal2" }] }` |

## Why prefer them

- **Database filters.** An `owner` rule on a list becomes `WHERE owner_id = <caller>`, so only the caller's rows are read and pages and counts are exact. A hand-written equivalent also works, but shorthands are always recognised.
- **Clarity.** `role:admin` explains itself.
- **Fewer mistakes.** The builder produces them correctly.

## Custom owner columns

Not every table's owner is called `owner_id`:

```json
{ "owner": "author_id" }
{ "owner": "customer_id" }
```

The same works as `"owner:author_id"` in a reference. For tables where *several* people may act (author or editor), combine: `{ "any": [{ "owner": "author_id" }, { "role": "editor" }] }`.
