A rule is a JSON value. It is either a name, a shorthand with a parameter, or a **condition**.

## Conditions

A condition is an object with one operator:

```json
{ "eq": ["$record.owner_id", "$auth.user_id"] }
```

Read it as: *the record's owner equals the caller's id.* The operands are in a list. Operands starting with `$` are looked up in the situation; everything else is a literal.

### Comparing

| Operator | Meaning | Example |
| --- | --- | --- |
| `eq` | Equal | `{ "eq": ["$record.status", "draft"] }` |
| `ne` | Not equal | `{ "ne": ["$record.status", "archived"] }` |
| `gt`, `gte` | Greater than (or equal) | `{ "gte": ["$input.quantity", 1] }` |
| `lt`, `lte` | Less than (or equal) | `{ "lte": ["$input.quantity", 100] }` |
| `in` | The first value is in the list | `{ "in": ["$record.status", ["open", "pending"]] }` |
| `not_in` | The first value is not in the list | `{ "not_in": ["$auth.user_id", "$record.blocked_ids"] }` |

### Strings and lists

| Operator | Meaning | Example |
| --- | --- | --- |
| `contains` | A list contains a value, or a string contains text | `{ "contains": ["$auth.roles", "admin"] }` |
| `starts_with` | A string starts with text | `{ "starts_with": ["$object.key", "public/"] }` |
| `ends_with` | A string ends with text | `{ "ends_with": ["$auth.email", "@acme.com"] }` |
| `matches` | A string matches a pattern | `{ "matches": ["$input.slug", "^[a-z0-9-]+$"] }` |

### Testing a value

| Operator | Meaning | Example |
| --- | --- | --- |
| `exists` | The value is present and not null | `{ "exists": "$auth.user_id" }` |
| `truthy` | The value is non-empty and not false | `{ "truthy": "$auth.org" }` |
| `empty` | The value is missing, null or empty | `{ "empty": "$record.deleted_at" }` |

### Combining

| Operator | Meaning |
| --- | --- |
| `all` | Every condition in the list must pass (and) |
| `any` | At least one must pass (or) |
| `not` | Negates one condition |

```json
{
  "all": [
    { "authenticated": true },
    { "any": [
      { "eq": ["$record.owner_id", "$auth.user_id"] },
      { "contains": ["$auth.roles", "admin"] }
    ] }
  ]
}
```

<Warning>
The names are `all`, `any`, `not`, `ne` and `not_in`. Using `and`, `or`, `neq` or `nin` is rejected when you save the rule.
</Warning>

### Plain true and false

`true` always passes and `false` never does. `{ "authenticated": true }` passes for signed-in users.

## Shorthands

Common conditions have short forms you can use as a whole rule or inside `all` and `any`:

| Shorthand | Passes when |
| --- | --- |
| `"public"` | Always |
| `"authenticated"` | The caller is signed in |
| `"owner"` or `{ "owner": "author_id" }` | The record's owner column (default `owner_id`) equals the caller's id |
| `"service"` or `{ "service": true }` | The caller uses a secret key |
| `"mfa"` | Signed in with a second factor (`aal2`) |
| `"deny"` | Never, except for service callers |
| `"role:admin"` | The caller has that role |
| `{ "role": ["admin", "support"] }` | The caller has any of those roles |
| `"permission:posts.write"` | The caller has that permission |
| `{ "kind": "user" }` | The kind of caller |
| `{ "scope": "resource:write" }` | The API key has that scope |
| `{ "aal": "aal2" }` | The assurance level of the session |

A list of references means **all must pass**: `["authenticated", "role:editor"]`.

## What is in `$auth`

| Path | Meaning |
| --- | --- |
| `$auth.authenticated` | True when signed in |
| `$auth.user_id` | The caller's id |
| `$auth.roles` | A list of the caller's roles |
| `$auth.permissions` | A list of the caller's permissions |
| `$auth.org`, `$auth.org_role` | The active organization and the caller's role in it |
| `$auth.kind` | What kind of caller this is |
| `$auth.aal` | `aal1` (password) or `aal2` (second factor) |

Trust `roles`, `permissions` and `app_metadata`. Do **not** base a rule on `user_metadata`, which people can edit themselves.

## Save a rule under a name

Reuse a rule by saving it and referring to it by name:

<CodeGroup>
```typescript TypeScript
await m.policies.create({
  name: "team-member",
  description: "Callers in the record's organization",
  condition: { eq: ["$record.org", "$auth.org"] },
});

await m.resources.create({ name: "projects", operations: { list: { enabled: true, policy: "team-member" } } /* … */ });
```

```python Python
pb.manage.policies.create({
    "name": "team-member",
    "description": "Callers in the record's organization",
    "condition": {"eq": ["$record.org", "$auth.org"]},
})
```
</CodeGroup>

Change the saved rule once and every place that names it changes. List and edit with `m.policies.list()` and `m.policies.replace(name, {...})`.

When a rule needs real code that this language cannot express, your team can register a code rule on the server and refer to it by name exactly like a saved one.

## How lists are protected

For a **list** request, Pawabase works out the rule before reading any rows. If the rule is an equality between a column and a value it already knows (`owner_id = this user`), it becomes a database filter, so pages and counts stay correct. A rule it cannot reduce to a filter is checked row by row, which is why `total` can be `null` in that case. Prefer simple equality rules on large tables.
