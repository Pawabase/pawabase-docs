## Published public, drafts private

Readers see published posts; authors also see their drafts.

```json
{ "any": [
  { "eq": ["$record.status", "published"] },
  { "owner": "author_id" }
] }
```

Use for `list` and `get`. (Per-row, so totals can be `null`; see [evaluation](/policies/how-rules-are-evaluated).)

## Hide deleted records

With a nullable `deleted_at` column ([soft delete](/database/patterns#soft-delete)):

```json
{ "all": [{ "owner": "owner_id" }, { "empty": "$record.deleted_at" }] }
```

## Scheduled publishing

Visible once `publish_at` has passed:

```json
{ "any": [
  { "empty": "$record.publish_at" },
  { "lte": ["$record.publish_at", "$now"] }
] }
```

A null `publish_at` means "publish immediately". Without the `empty` branch, those rows would never be visible (`lte` with a missing side is false).

## Expiring content

```json
{ "any": [
  { "empty": "$record.expires_at" },
  { "gt": ["$record.expires_at", "$now"] }
] }
```

## Locked records

No edits once locked:

```json
{ "all": [{ "owner": "owner_id" }, { "ne": ["$record.locked", true] }] }
```

as `update` and `delete`. A rule can't *unlock*; do that from a service or a role: `{ "any": [{ "role": "admin" }, <the rule above>] }`.

## Only forward state changes

Let the owner move a record from `draft` to `submitted`, but not edit approved ones:

```json
{ "all": [
  { "owner": "owner_id" },
  { "in": ["$record.status", ["draft", "submitted"]] },
  { "in": ["$input.status", ["draft", "submitted"]] }
] }
```

as `update`. Approval is a separate step done by `role:reviewer` through another route.

## Limit values

```json
{ "all": [{ "authenticated": true }, { "lte": ["$input.quantity", 10] }, { "gte": ["$input.quantity", 1] }] }
```

as `create`. For hard limits that must hold however the record is written, also set the column's `minimum`/`maximum` ([Columns](/database/columns-and-types)).

## Rate-limited by state

"At most 3 open orders" can't be a JSON rule: it needs a count of other rows. Do it in a [route](/logic/routes), or a unique partial [index](/database/indexes#partial-indexes), such as one open cart per customer.

## Honour the visibility of related records

A comment is visible if its post is. Comments can't look at the post in a JSON rule. Either copy the post's `visibility` onto the comment on create, or give comments the rule `public` and only expose them through the post with `expand`, which reads comments under the *comments* table's rule.
