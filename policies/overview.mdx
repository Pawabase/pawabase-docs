An **access rule** (also called a policy) answers one question: *may this caller do this, here, now?* Every table action, bucket, channel, route and function is protected by one. Because the answer is decided on the server, on every request, you can call Pawabase straight from a browser without a backend in the middle.

A rule is a small piece of JSON. You write it once, give it a name if you want to reuse it, and attach it wherever it is needed.

## Get started

The simplest rules are plain words:

| Rule | Who passes |
| --- | --- |
| `"public"` | Everyone, even signed-out visitors |
| `"authenticated"` | Any signed-in user |
| `"owner"` | The user whose id is stored in the record's `owner_id` column |
| `"service"` | Server code using a secret key, and the dashboard |
| `"mfa"` | Signed-in users who completed a second factor |
| `"deny"` | Nobody except service callers |

Attach them when you define a table. Here, anyone signed in may create a note, and people may read and change only their own:

<CodeGroup>
```typescript TypeScript
import { manage } from "@pawabase/client/manage";
const m = manage(serverClient);           // a secret-key client, on your server

await m.resources.create({
  name: "notes",
  owner_field: "owner_id",
  fields: [{ name: "text", type: "string", required: true }],
  operations: {
    list:   { enabled: true, policy: "owner" },
    get:    { enabled: true, policy: "owner" },
    create: { enabled: true, policy: "authenticated" },
    update: { enabled: true, policy: "owner" },
    delete: { enabled: true, policy: "owner" },
  },
});
```

```python Python
pb.manage.resources.create({
    "name": "notes",
    "owner_field": "owner_id",
    "fields": [{"name": "text", "type": "string", "required": True}],
    "operations": {
        "list":   {"enabled": True, "policy": "owner"},
        "get":    {"enabled": True, "policy": "owner"},
        "create": {"enabled": True, "policy": "authenticated"},
        "update": {"enabled": True, "policy": "owner"},
        "delete": {"enabled": True, "policy": "owner"},
    },
})
```
</CodeGroup>

From then on, the client code does not change: `pawabase.from("notes")` returns each person only their own notes.

## Where rules are attached

| Protects | Written as | Learn more |
| --- | --- | --- |
| Table actions (list, get, create, update, delete) | `operations.<action>.policy` | [Database access](/database/access-and-errors) |
| Storage buckets | `read_policy`, `write_policy`, `list_policy`, `update_policy`, `delete_policy` | [Storage access](/storage/access) |
| Realtime channels | `subscribe`, `publish` | [Channels](/realtime/channels) |
| Routes | `policy` | [Routes](/logic/routes) |

The same rule means the same thing everywhere.

## What a rule can look at

A rule is evaluated against the situation, which has these parts:

| Part | Contains |
| --- | --- |
| `$auth` | Who is calling: `user_id`, `authenticated`, `roles`, `permissions`, `org`, `kind`, `aal` |
| `$record` | The row being read, changed or deleted (table rules) |
| `$input` | The data being submitted (create and update) |
| `$object` | The file being touched: `key`, `segments`, `action` (storage rules) |
| `$request` | The request itself |
| `$credential` | The API key used: `is_service`, `scopes` |

Anything starting with `$` is looked up there. Anything else is a literal value. Write `$$` for a literal dollar sign.
