For B2B apps, data belongs to an **organization**. People belong to several; each session acts in one ([Organizations](/auth/organizations)). The session carries `org` and `org_role`.

## Setup

1. Add an `org` column (text, **indexed**) to every team table.
2. Set it on create from the session: `org: session.org`.
3. Apply a team rule to every action.

## Members see their organization's records

```json
{ "all": [
  { "truthy": "$auth.org" },
  { "eq": ["$record.org", "$auth.org"] }
] }
```

**The `truthy` line is essential.** If the caller has no active organization and a record has none either, `eq` of two nulls is true, and everyone sees everything. Always require the caller's side.

Save it as a named rule `team_member`, and use it on list, get, update and delete.

## Create inside your organization

```json
{ "all": [
  { "truthy": "$auth.org" },
  { "eq": ["$input.org", "$auth.org"] }
] }
```

so nobody can create a record in a different organization by sending a different `org`.

## By organization role

Members read; admins and owners change and delete:

```json
{ "list": "team_member",
  "get": "team_member",
  "create": "team_member",
  "update": { "all": [ { "eq": ["$record.org", "$auth.org"] }, { "in": ["$auth.org_role", ["admin", "owner"]] } ] },
  "delete": { "all": [ { "eq": ["$record.org", "$auth.org"] }, { "in": ["$auth.org_role", ["owner"]] } ] } }
```

(Use named rules for `update` and `delete` too: `team_admin`, `team_owner`.)

## Personal and team records on one table

A record is either personal (`owner_id`) or team (`org`):

```json
{ "any": [
  { "owner": "owner_id" },
  { "all": [{ "truthy": "$auth.org" }, { "eq": ["$record.org", "$auth.org"] }] }
] }
```

## Platform staff across organizations

Your own support team needs to see all organizations:

```json
{ "any": [{ "role": "platform_support" }, <the team rule>] }
```

Prefer a separate staff tool with a secret key behind your own login, rather than a global role in customer-facing rules.

## Files and channels per organization

- **Storage:** key `<org>/…`, and `{ "eq": ["$object.segments.0", "$auth.org"] }` ([Storage](/policies/storage)).
- **Channels:** name `org:<slug>:…` and require `truthy $auth.org` ([Realtime](/policies/realtime)).

## Switching organizations

`switchOrg(slug)` refreshes the token with the new `org`. All the rules above follow. Don't cache lists across a switch: reload on `TOKEN_REFRESHED`.

## Invitations and access

New members get access the moment they accept an invitation and switch to the organization ([Invitations](/auth/invitations)). Removing a member removes their role; their existing sessions lose the organization at the next refresh.

## Test the boundary

```typescript
const adaAcme = await signedIn("ada@acme.com", { org: "acme" });
const bobGlobex = await signedIn("bob@globex.com", { org: "globex" });
const noOrg = await signedIn("ada@acme.com");         // no active organization

const doc = await adaAcme.from("documents").create({ org: "acme", title: "Plan" });
await expect(bobGlobex.from("documents").get(doc.id)).rejects.toBeInstanceOf(NotFoundError);
expect((await noOrg.from("documents")).data).toHaveLength(0);       // the null-equals-null trap
```

The last assertion is the one people forget.
