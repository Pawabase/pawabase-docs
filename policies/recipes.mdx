Each recipe shows the rule and what it means for the client code.

## Private to the owner

Every person sees and changes only their own records.

```json
{ "operations": {
  "list":   { "enabled": true, "policy": "owner" },
  "get":    { "enabled": true, "policy": "owner" },
  "create": { "enabled": true, "policy": "authenticated" },
  "update": { "enabled": true, "policy": "owner" },
  "delete": { "enabled": true, "policy": "owner" }
}, "owner_field": "owner_id" }
```

On create, set `owner_id` to the caller's id (`owner_id: user.id`). A person cannot create a record owned by someone else if the create rule also checks it:

```json
{ "all": [{ "authenticated": true }, { "eq": ["$input.owner_id", "$auth.user_id"] }] }
```

## Public to read, owner to write

A blog: anyone reads, only the author writes.

```json
{ "list": "public", "get": "public", "create": "authenticated", "update": "owner", "delete": "owner" }
```

## Published posts public, drafts private

```json
{ "any": [
  { "eq": ["$record.status", "published"] },
  { "eq": ["$record.author_id", "$auth.user_id"] }
] }
```

Use it on `list` and `get`. Readers see published posts; authors also see their drafts.

## Organization members

All records carry an `org` column set from the caller's active organization. Members see their organization's records:

```json
{ "all": [{ "truthy": "$auth.org" }, { "eq": ["$record.org", "$auth.org"] }] }
```

Only admins of the organization may delete:

```json
{ "all": [
  { "eq": ["$record.org", "$auth.org"] },
  { "in": ["$auth.org_role", ["admin", "owner"]] }
] }
```

## Roles

```json
"role:admin"
```

```json
{ "role": ["editor", "admin"] }
```

Give people roles from your server with the [admin client](/admin/roles).

## Staff only, with a second factor

```json
["role:staff", "mfa"]
```

All entries must pass: the caller is staff *and* signed in with a second factor.

## Only your server

For tables the browser must never touch (billing, audit logs):

```json
"service"
```

Reads and writes then work only with a secret key. Expose what users need through a [route](/logic/routes).

## Read-only for users, write for the server

```json
{ "list": "authenticated", "get": "authenticated", "create": "service", "update": "service", "delete": "service" }
```

## Prevent editing locked records

```json
{ "all": [
  { "eq": ["$record.owner_id", "$auth.user_id"] },
  { "ne": ["$record.locked", true] }
] }
```

## Validate what is being written

Rules can look at `$input`. Only allow a status that moves forward:

```json
{ "all": [
  { "eq": ["$record.owner_id", "$auth.user_id"] },
  { "in": ["$input.status", ["draft", "submitted"]] }
] }
```

## Limit by quantity or size

```json
{ "all": [{ "authenticated": true }, { "lte": ["$input.quantity", 10] }] }
```

## Files under your own folder

For a bucket, with keys like `<user id>/file.png`:

```json
{ "all": [{ "truthy": "$auth.user_id" }, { "eq": ["$object.segments.0", "$auth.user_id"] }] }
```

Use it as `write_policy` and `read_policy`. For organizations, compare `$object.segments.0` with `$auth.org`.

## Chat rooms

Scope channels by organization, naming them `org:<slug>:…`, and let the channel rule require an active organization:

```json
{ "truthy": "$auth.org" }
```

For rooms with their own member lists, ask your team to register a code rule that looks up membership, and refer to it by name.

## Admin override

Add `any` with a role so admins bypass an ownership rule:

```json
{ "any": ["role:admin", { "eq": ["$record.owner_id", "$auth.user_id"] }] }
```
