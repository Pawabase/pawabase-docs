Each recipe shows the rule, the table setup, what the client does, and what to test.

## Private to the owner

Every person sees and changes only their own records.

**Table:** `owner_field: "owner_id"`. **Rules:**

```json
{ "list": "owner", "get": "owner", "create": "authenticated", "update": "owner", "delete": "owner" }
```

**Client:** `from("notes").create({ text })`, `from("notes")`. The owner is filled in for you.
**Test:** Bob lists, gets, updates and deletes Ada's note: empty list, then `NotFoundError`.

## Authored content, public to read

A blog where anyone reads and only the author writes.

```json
{ "list": "public", "get": "public", "create": "role:author", "update": "owner:author_id", "delete": "owner:author_id" }
```

Set `owner_field: "author_id"` so it fills on create.

## Authors and editors

Authors edit their own; editors edit anything.

```json
{ "any": [{ "owner": "author_id" }, { "role": "editor" }] }
```

Use for `update` and `delete`. Note that on **list** this `any` is per-row, so totals are `null`. If lists are large, give editors a separate route or table for review.

## Shared with specific people

A document shared with a list of user ids (`shared_with`, a list column):

```json
{ "any": [
  { "owner": "owner_id" },
  { "contains": ["$record.shared_with", "$auth.user_id"] }
] }
```

Use for `list` and `get`. Make `update` stricter: owner only, or those with `"editor"` in a separate `editors` list.

For larger sharing models (per-person permissions, groups), use a `shares` table (`document_id`, `user_id`, `role`) and check membership in a [code rule](/policies/code-rules); JSON can't query another table.

## Can't forge the owner

Ensure nobody creates a record owned by someone else, even if they send an `owner_id`:

```json
{ "all": [{ "authenticated": true }, { "eq": ["$input.owner_id", "$auth.user_id"] }] }
```

as the `create` rule. Because the owner field is filled automatically, this is a belt-and-braces check; you need it if your clients ever send `owner_id` themselves.

## Prevent changing the owner

Only a service may reassign:

```json
{ "all": [{ "owner": "owner_id" }, { "empty": "$input.owner_id" }] }
```

as `update`: the owner may edit, but not send an `owner_id` at all. Mark the owner column **read only** for the same effect, enforced by the column.

## Transfer ownership

Never let the client set `owner_id` directly. Expose a [route](/logic/routes) `POST /documents/{id}/transfer` that checks the caller owns it and the target exists, then updates as a service.

## Records created by the server for a person

When your server (secret key) creates a record on someone's behalf, **set the owner explicitly**, or the `owner` rule never matches and the person can't see it:

```typescript
await admin.from("invoices").create({ customer_id: userId, total: 1999 });
```

## A person's profile

One row per user whose id equals the user's id:

```json
{ "eq": ["$record.id", "$auth.user_id"] }
```

Create it with `id` set to the user's id from a [sign-up flow](/auth/auth-webhooks) (`user.created`).
