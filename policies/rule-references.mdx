Wherever a rule is needed (a table's five actions, a bucket's five rules, a channel's subscribe and publish, a route, a subscription), Studio shows the same **rule picker**.

## The choices

| Choice in the picker | What it is |
| --- | --- |
| **Default (signed-in users)** | No rule of its own |
| **Anyone (public)** | Everyone, signed in or not |
| **Signed-in users** | Anyone who is signed in |
| **Record owner (owner_id)** | The person whose id is in the record's `owner_id` |
| **Signed in with 2FA** | Completed a second step |
| **Secret keys & Studio** | Your servers and team only |
| **Nobody** | No one (secret keys and Studio still pass) |
| **Users with role…** | Type a role, such as `admin` |
| **Users with permission…** | Type a permission, such as `posts.write` |
| **Owner via field…** | Type a column, such as `author_id` |
| **Keys with scope…** | Type a scope, such as `resource:write` |
| **This environment** | Pick one of your [named rules](/policies/named-rules) |
| **Custom condition** | Build one with the [condition builder](/policies/condition-builder) |
| **List** | Add several of the above; **all** must pass |

## Lists mean "all"

Choose **List** and add rules: *Signed-in users*, *Users with role `editor`*, *Signed in with 2FA*. The request passes only for a signed-in editor who completed a second step.

For "any of" (an owner **or** an admin), use a **Custom condition** with **Any of**, containing **Owns the record** and **Has role**.

## Mixing named rules and conditions

A list can mix: *This environment → `team_member`* and *Users with role `editor`* together means "a team member who is an editor".

## Unknown names

A rule that names something that doesn't exist is refused when you save. Studio warns first: *"x" is not a policy in this environment, so this action will be refused when you save.* Named rules belong to an **environment**: a rule created in `development` must exist in `production` too ([promote it](/environments/overview)).

## Choosing well

- Use **built-ins** for most cases.
- Use **named rules** for anything used more than once, or that a teammate should be able to read and change in one place.
- Use **custom conditions** for one-offs.
- Use **List** to add a requirement ("and also 2FA").
