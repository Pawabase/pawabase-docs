The condition builder is how you make custom rules in Studio. You add **rules** (single checks) and **groups** (sets of checks), and choose how they combine. You never type a rule's structure.

<Frame caption="The builder in the New policy sheet.">
  <img src="/images/studio/policy-builder.jpg" alt="Condition builder with All of these rules pass, Is signed in yes, and Owns the record user_id" />
</Frame>

## Where

It appears in **Access → Policies → New policy** (under **Who passes**), and inline wherever you choose **Custom condition** in a rule picker (a table's **Access** tab, a bucket, a channel, a route, a subscription's **Only when…**).

## Groups: how checks combine

At the top of a group, pick one:

| Choice | Means |
| --- | --- |
| **All of** | Every check below must pass (AND). Studio shows **AND** between rows |
| **Any of** | At least one must pass (OR) |
| **None of** | None may pass |

Click **+ Group** to nest: "signed in **and** (the owner **or** an admin)" is an **All of** containing an **Any of**. An empty **All of** says *No rules: everyone passes*; an empty **Any of** says *No rules: nobody passes*.

## Kinds of check

Click **+ Rule**, then open the first menu:

<Frame caption="The kinds of check.">
  <img src="/images/studio/policy-rule-types.jpg" alt="Menu listing Is signed in, Has role, Has permission, Owns the record (field), Uses a secret key, Signed in with 2FA, Key has scope, Caller kind is, Compare values, Check a value, Nobody" />
</Frame>

| Kind | Fill in | Passes when |
| --- | --- | --- |
| **Is signed in** | yes / no | The caller is (or isn't) signed in |
| **Has role** | one or more roles, such as `admin, editor` | The caller has any of those roles |
| **Has permission** | such as `posts.write` | The caller has that permission (or all, if you list several) |
| **Owns the record (field)** | the column, such as `owner_id` | That column on the record equals the caller's id |
| **Uses a secret key** | nothing | The request used a secret key (or came from Studio) |
| **Signed in with 2FA** | nothing | The person completed a second step this session |
| **Key has scope** | such as `resource:write` | The API key carries that scope |
| **Caller kind is** | such as `user` | The kind of caller matches |
| **Compare values…** | a left value, an operator, a right value | The comparison is true |
| **Check a value…** | a value and a check | The value passes the check |
| **Anyone (always allow)** / **Nobody (always deny)** | nothing | Always / never |

### Compare values

Choose the **Comparison operator**:

| Studio says | Meaning |
| --- | --- |
| equals / does not equal | Same / different |
| greater than / at least | Numbers, dates, text |
| less than / at most | Numbers, dates, text |
| is one of / is not one of | In a list of values |
| contains | A list contains a value, or text contains text |
| starts with / ends with | Text |
| matches regex | Text matches a pattern |

### Check a value

**exists** (it is present), **is set / true** (present and not empty or false), **is empty** (missing or empty).

## The values you type

Each side of a comparison is either a **path** (it starts with `$` and reads a fact about the request) or a plain value:

- `$auth.user_id` is the caller's id; `$record.owner_id` is a column on the record; `$input.status` is something being submitted.
- `draft`, `3`, `yes` are plain values. Write `$$` for a literal dollar sign.

The box suggests the common paths as you type. See [Facts a rule can check](/policies/context).

## Build one: "the owner or an admin, but only while not locked"

1. Open **New policy**. Leave **All of** selected.
2. Click **+ Group**, switch it to **Any of**.
   - In the group, **+ Rule** → **Owns the record (field)** → `owner_id`.
   - **+ Rule** → **Has role** → `admin`.
3. Back in the outer **All of**, **+ Rule** → **Compare values…**: `$record.locked` **does not equal** `true`.
4. Name it `owner_or_admin_unlocked`. **Create policy.**

Read back as a sentence: *All of these pass: (any of: owns the record, has role admin) and locked is not true.*

## Tips

- Prefer the dedicated kinds (**Has role**, **Owns the record**) to comparisons you make yourself: they read better and Pawabase can turn them into database filters.
- Keep groups shallow. More than three levels? Split into named rules ([Named rules](/policies/named-rules)).
- Use **Use example** on the New policy sheet to see a working rule.
