Roles and permissions come from [Auth → Roles](/auth/roles) and travel in the session token. Rules read them from `$auth.roles` and `$auth.permissions`.

## Admin only

```json
"role:admin"
```

## Any of several roles

```json
{ "role": ["editor", "admin"] }
```

## By permission

Give roles permissions, then check the permission:

```json
"permission:posts.write"
```

with roles such as `editor` granted `posts.write`. Add a new role later without touching any rule.

## All of several permissions

```json
{ "permission": ["billing.read", "billing.export"] }
```

## Roles or ownership

Admins override ownership:

```json
{ "any": [{ "role": "admin" }, { "owner": "owner_id" }] }
```

## Staff with a second factor

```json
["role:staff", "mfa"]
```

All entries must pass. A staff member who signed in with just a password is refused until they complete the second step.

## A hierarchy

Roles are not ordered by themselves. For "manager or above", list them:

```json
{ "role": ["manager", "director", "admin"] }
```

or grant lower permissions to higher roles and check the permission. The second scales better.

## Read-only role

A `viewer` who can list and get but never write:

```json
{ "list": { "role": ["viewer", "editor", "admin"] },
  "get":  { "role": ["viewer", "editor", "admin"] },
  "create": { "role": ["editor", "admin"] },
  "update": { "role": ["editor", "admin"] },
  "delete": "role:admin" }
```

## Roles that depend on the organization

A person may be an admin in one organization and a member in another. Use the organization role, not the global one:

```json
{ "all": [{ "eq": ["$record.org", "$auth.org"] }, { "in": ["$auth.org_role", ["admin", "owner"]] }] }
```

## Service-only operations

For things only your servers do:

```json
"service"
```

Reads and writes then work only with a secret key. Offer users what they need through a [route](/logic/routes).

## Show UI by role, protect by rule

```typescript
const user = await pawabase.auth.getUser();
const canEdit = user.roles.includes("editor");        // show the button
```

The rule still decides. Never make a decision in the browser that a rule should make.

## When roles change

A new role arrives with the next token refresh (minutes) or the next sign-in; end sessions to force it ([Roles](/auth/roles#when-changes-take-effect)).
