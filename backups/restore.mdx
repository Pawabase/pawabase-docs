You can restore from a **saved backup** or from a **file you downloaded**, into the same environment or a different one.

## Restore step by step

<Steps>
  <Step title="Open Project → Backups → Restore from a backup">
    Choose a saved backup, or upload a file.
  </Step>
  <Step title="Choose what to restore">
    Tick the parts: **Definitions**, **Settings**, **Users & access**, **Data**. Studio shows what the file holds, so you only pick what is there.
  </Step>
  <Step title="Choose how">
    - **Merge** adds and updates. Existing things not in the backup stay.
    - **Replace** first removes what is in the chosen parts, then restores. The environment ends up matching the backup.
  </Step>
  <Step title="Review, then confirm">
    For **Replace** you type the environment's name to confirm. A dry run shows what would change before anything does.
  </Step>
</Steps>

## The safety net

Leave **Save the current state first** on. Before **Replace**, Pawabase saves what is there now as a backup called *Before restore*, so a restore that was a mistake can be undone by restoring that.

<Warning>
**Replace** deletes the current rows, users and definitions in the parts you chose. Be sure you picked the right environment before you confirm.
</Warning>

## What a restore does not bring back

Backups never contain **API keys, secret values, stored files, sessions, logs or jobs**. After a restore into a fresh environment:

- Create new [API keys](/environments/api-keys).
- Add your [secrets](/secrets/overview) again.
- Reconnect AI providers, and re-add connection keys.
- Files in buckets stay where they are; they aren't part of a backup.

People keep their passwords: a backup holds each person's password hash, so they sign in as before. Because of that, keep backup files private.

## From code

<CodeGroup>
```typescript TypeScript
const m = manage(pawabase);   // a client with the secret key

// try it first: what would change, nothing written
const preview = await m.backups.restoreSnapshot(snapshotId, { include: ["data"], strategy: "merge", dryRun: true });

// restore for real, replacing the data; a "Before restore" backup is taken first
await m.backups.restoreSnapshot(snapshotId, {
  include: ["data"],
  strategy: "replace",
  confirm: "my-org-shop-a1b2-production",   // the environment's name, typed out
});

// a backup file you downloaded, into this environment
const file = JSON.parse(await readFile("backup.json", "utf8"));
await m.backups.restore(file, { include: ["definitions", "settings"], strategy: "merge" });

// a fresh download of the whole environment, without storing a snapshot
const now = await m.backups.download({ data: true, maxRows: 100_000 });
```

```python Python
b = pb.manage.backups

b.restore_snapshot(snapshot_id, include=["data"], strategy="merge", dry_run=True)
b.restore_snapshot(snapshot_id, include=["data"], strategy="replace", confirm="my-org-shop-a1b2-production")

b.restore(json.load(open("backup.json")), include=["definitions", "settings"], strategy="merge")
now = b.download(data=True, max_rows=100_000)
```
</CodeGroup>

| Option | Meaning |
| --- | --- |
| `include` | Parts to restore: `definitions`, `settings`, `users`, `data`. Default: every part the backup holds |
| `strategy` | `merge` adds and updates; `replace` first removes what the chosen parts hold |
| `confirm` | Needed for `replace`: the environment's full name |
| `dryRun` / `dry_run` | Report what would change, write nothing |
| `safetySnapshot` / `safety_snapshot` | On a saved backup's restore: take a *Before restore* backup first (default on) |

## Move to another environment

1. **Download a backup** from the source (tick the parts).
2. In the target, **Restore from a backup**, upload the file and choose **Merge**.

For moving people alone, use [Import and export](/auth/import-and-export).

## After restoring

1. Open [Activity](/activity/overview) and check for errors.
2. Check a few rows and sign in as a test user.
3. If something is wrong, restore *Before restore* to go back.
