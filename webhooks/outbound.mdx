An outbound webhook sends events to a URL you control, such as your own server, a partner or an automation tool. Pawabase signs each request, retries failures and keeps a history you can search and replay.

## Get started

<CodeGroup>
```typescript TypeScript
import { manage } from "@pawabase/client/manage";
const m = manage(serverClient);   // a secret-key client

await m.webhooks.create({
  name: "partner-orders",
  url: "https://partner.example.com/hooks/pawabase",
  events: ["orders.created", "orders.updated"],
  secret: process.env.WEBHOOK_SECRET,       // at least 16 characters
});

await m.webhooks.test("partner-orders");    // sends one test event, one attempt, no retries
```

```python Python
import os

pb.manage.webhooks.create({
    "name": "partner-orders",
    "url": "https://partner.example.com/hooks/pawabase",
    "events": ["orders.created", "orders.updated"],
    "secret": os.environ["WEBHOOK_SECRET"],
})

pb.manage.webhooks.test("partner-orders")
```
</CodeGroup>

Your endpoint must [verify the signature](/webhooks/verifying) and answer `2xx` quickly.

## Settings

| Field | Meaning |
| --- | --- |
| `name` | Letters, digits and dashes. Used to find the webhook |
| `url` | Where to send. Use HTTPS. Private and loopback addresses are refused outside development |
| `events` | Event names or patterns. Default `["*"]` (everything) |
| `headers` | Extra headers to send with every request |
| `secret` | Signs each request. At least 16 characters. Keep it in an environment variable |
| `max_attempts` | Tries before a delivery is marked failed, 1 to 10. Default 5 |
| `enabled` | `false` pauses the webhook |
| `description` | A note for your team |

Patterns work as they do for [subscriptions](/events/subscribing#match-with-wildcards): `orders.*` matches every order event.

## What your endpoint receives

A `POST` with a JSON body:

```json
{
  "id": "evt_abc123",
  "event": "orders.created",
  "project": "acme",
  "env": "production",
  "data": { "id": "ord_001", "total": 2999, "status": "pending" },
  "sent_at": 1727520000
}
```

| Field | Meaning |
| --- | --- |
| `id` | The event id. Use it to ignore a repeat |
| `event` | The event name |
| `project`, `env` | Where it came from |
| `data` | The event's payload, for example the record |
| `sent_at` | Unix time the delivery was queued |

The `Pawabase-Signature` header carries the signature.

## Retries

Your endpoint must answer `2xx` within 30 seconds. Anything else (a `4xx`/`5xx`, a timeout, a refused connection) counts as a failed attempt and is retried later, up to `max_attempts`:

| Attempt | Waits before it |
| --- | --- |
| 1 | Immediately |
| 2 | About 10 seconds |
| 3 | About 1 minute |
| 4 | About 5 minutes |
| 5 | About 30 minutes |
| 6 | About 2 hours |
| 7 | About 6 hours |
| 8 | About 12 hours |
| 9 and 10 | About 24 hours |

Waits vary by up to 20% so many failures to one endpoint do not return together. With the default of 5 attempts a delivery keeps trying for about 36 minutes; with 10, about 3 days.

<Warning>
If your endpoint needs to do slow work, answer `200` at once and process in the background. A response slower than 30 seconds is a failed attempt, and the retry would repeat the work.
</Warning>

Only one delivery is created per event and endpoint, even if an event is processed again, so a retry never produces a second copy under a new id.

## Delivery history

<CodeGroup>
```typescript TypeScript
const failed = await m.webhooks.deliveries({ status: "failed", endpoint: "partner-orders", limit: 50 });
```

```python Python
failed = pb.manage.webhooks.deliveries(status="failed", endpoint="partner-orders", limit=50)
```
</CodeGroup>

A delivery's status is `pending`, `retrying`, `delivered` or `failed`. It includes the attempts made, how long the last took, the response status and trimmed body, and the error. Look here first when a partner says they received nothing.

## Send failed deliveries again

After your endpoint was down, redeliver. Always count with a dry run first.

<CodeGroup>
```typescript TypeScript
await m.webhooks.redeliver("dlv_123");                     // one

const preview = await m.webhooks.redeliverMany({ endpoint: "partner-orders", status: "failed", sinceMinutes: 480, dryRun: true });
await m.webhooks.redeliverMany({ endpoint: "partner-orders", status: "failed", sinceMinutes: 480 });
```

```python Python
pb.manage.webhooks.redeliver("dlv_123")

preview = pb.manage.webhooks.redeliver_many(endpoint="partner-orders", status="failed", since_minutes=480, dry_run=True)
pb.manage.webhooks.redeliver_many(endpoint="partner-orders", status="failed", since_minutes=480)
```
</CodeGroup>

| Option | Meaning |
| --- | --- |
| `ids` | Exact deliveries (up to 500). Other filters are ignored when given |
| `status` | `failed` (default), `retrying` or `delivered` |
| `endpoint`, `event` | Narrow by webhook name or event |
| `sinceMinutes` | Only deliveries from the last N minutes |
| `limit` | Most to resend in one call. Default 100, up to 500 |
| `dryRun` | Count without sending |

Each resend creates a new delivery with the same payload, so your endpoint should treat a repeated `id` as a duplicate.

## Send on demand from a flow

The `webhook.send` block sends an event to every webhook subscribed to its name, as if it had been emitted:

```json
{ "id": "export_done", "data": { "block": "webhook.send", "config": { "event": "order.exported", "payload": { "order_id": "{{ input.order_id }}" } } } }
```

It returns `{ "deliveries": 3 }`, the number queued.

## Change or remove

<CodeGroup>
```typescript TypeScript
await m.webhooks.replace("partner-orders", { name: "partner-orders", url, events: ["orders.*"], enabled: false });
await m.webhooks.remove("partner-orders");
```

```python Python
pb.manage.webhooks.remove("partner-orders")
```
</CodeGroup>
