An **inbound hook** gives an outside service a URL to call. Pawabase verifies the request, then starts a flow or emits an event. You do not run a server for it.

## Get started

<CodeGroup>
```typescript TypeScript
await m.inboundHooks.create({
  name: "stripe",
  slug: "stripe",
  verification: "hmac-sha256",
  signature_header: "stripe-signature",
  secret: process.env.STRIPE_WEBHOOK_SECRET,   // at least 16 characters
  target_type: "flow",
  target: "handle-stripe",
});

const { url } = await m.inboundHooks.url("stripe");   // give this to the other service
```

```python Python
pb.manage.inbound_hooks.create({
    "name": "stripe",
    "slug": "stripe",
    "verification": "hmac-sha256",
    "signature_header": "stripe-signature",
    "secret": os.environ["STRIPE_WEBHOOK_SECRET"],
    "target_type": "flow",
    "target": "handle-stripe",
})

url = pb.manage.inbound_hooks.url("stripe")["url"]
```
</CodeGroup>

The URL has the form `https://<your api host>/hooks/v1/<environment>/<slug>`, so each environment has its own address. It needs no API key, since the signature is the credential.

## Settings

| Field | Meaning |
| --- | --- |
| `slug` | The last part of the URL. Lowercase letters, digits and dashes |
| `name`, `description` | Labels for your team |
| `verification` | How requests are checked: `hmac-sha256` (default), `hmac-sha512`, `hmac-sha256-ts` (HMAC over timestamp and body), `pawabase` (Pawabase's own `t=…,v1=…` header), `token` (a shared token), or `none` |
| `signature_header` | The header that carries the signature. Default `x-signature` |
| `secret` | The shared secret, at least 16 characters |
| `target_type` | `flow` to run a flow, or `event` to emit an event |
| `target` | The flow name, or the event name to emit |
| `enabled` | Pause without deleting |

Match `verification` and `signature_header` to what the sender does. GitHub signs with HMAC-SHA256 in `x-hub-signature-256`; Stripe signs a timestamp and body in `stripe-signature`. Check the sender's documentation.

<Warning>
Avoid `verification: "none"`. Without a check, anyone who finds the URL can start your flow.
</Warning>

## What the flow receives

The request's JSON body is the flow's `input`:

```text
input.action                  "opened"          (GitHub)
input.issue.title             "Bug report"
input.repository.full_name    "acme/project"
```

For an event target, the body is the event's payload, and subscribers react as to any [event](/events/subscribing).

## Answer codes

| Case | Response |
| --- | --- |
| Signature or timestamp invalid | `403` |
| Verified | `202`, and the flow starts in the background |
| Verified but the target fails | `202`; the error is in the delivery record and the [job log](/jobs/failures-and-replay) |

Senders retry on non-2xx, so a `202` for a failing flow stops them hammering you. Retry from your side instead.

## Examples

<Tabs>
  <Tab title="GitHub">
    ```typescript
    await m.inboundHooks.create({
      name: "github", slug: "github", verification: "hmac-sha256",
      signature_header: "x-hub-signature-256", secret: process.env.GITHUB_SECRET,
      target_type: "flow", target: "on-github",
    });
    ```
    Set the payload URL in the repository's webhook settings to the URL above, with the same secret.
  </Tab>
  <Tab title="Stripe">
    ```typescript
    await m.inboundHooks.create({
      name: "stripe", slug: "stripe", verification: "hmac-sha256-ts",
      signature_header: "stripe-signature", secret: process.env.STRIPE_SECRET,
      target_type: "event", target: "stripe.received",
    });
    ```
    Emitting an event lets several flows react to Stripe's calls. Confirm the verification mode against Stripe's current signature format.
  </Tab>
</Tabs>

## Test it

Send a request from the other service's "send test" button and check the flow's run:

<CodeGroup>
```typescript TypeScript
const runs = await m.flows.runs({ flow: "handle-stripe", limit: 5 });
```

```python Python
runs = pb.manage.flows.runs(flow="handle-stripe", limit=5)
```
</CodeGroup>
