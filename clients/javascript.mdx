`@pawabase/client` is the official TypeScript client for applications that call Pawabase.

The useful mental model is one configured client with several capability-specific entry points.
The client owns the gateway URL, API key, user-session source, retry policy, and request hooks.
Its child clients use that shared context rather than asking the application to rebuild headers for every request.

```text
PawabaseClient
├── from("resource")      records and queries
├── auth                  identities, sessions, MFA, and application organizations
├── storage               buckets and objects
├── functions             deployed function invocation
├── flows                 pathless HTTP-triggered flows
├── routes                custom REST routes
├── realtime              channels, presence, history, and publishing
└── request()             public endpoints without a dedicated method
```

This is application integration documentation.
It describes the package's public exports and observable behavior, not Pawabase's internal services.

<Note>
  A normal Pawabase installation is already one project.
  The SDK's optional `project` value is not a project picker.
  It is a scope hint required by social sign-in URLs.
  Each installation can have multiple environments, and every API key belongs to one environment.
</Note>

## What the SDK takes responsibility for

Using `fetch` directly is valid, but it makes the application responsible for several rules that are easy to implement inconsistently.
The SDK centralizes those rules.

| Concern | SDK behavior | Why the application cares |
| --- | --- | --- |
| API-key authentication | Sends `apikey` on gateway requests | The gateway must identify the installation and environment before it can route the call |
| User authentication | Sends `Authorization: Bearer …` when a session exists | Policies can evaluate the signed-in user without each call rebuilding headers |
| Session refresh | Refreshes shortly before expiry and after one eligible `401` | A normal token expiry does not force an avoidable sign-in |
| Refresh concurrency | Shares one refresh across concurrent calls and coordinates browser tabs where Web Locks exists | Refresh tokens rotate; racing exchanges can invalidate a legitimate session |
| Errors | Maps response and transport failures to typed error classes | UI and server code can branch on class, status, and stable code |
| Retries | Retries rate limits and selected transient failures under method-safety rules | A failed connection does not silently duplicate an unsafe write |
| Record filters | Serializes Pawabase's filter grammar and refuses ambiguous cases | A query cannot silently discard a repeated filter or split a comma-containing value |
| Realtime | Maintains one socket, reconnects, rejoins channels, and can replay recent messages | Channel consumers do not each need a connection state machine |
| Generated types | Turns an environment's OpenAPI document into a `Database` interface | Resource names, fields, create bodies, and update bodies can be checked before runtime |

## Runtime and package formats

The package ships type declarations plus ESM and CommonJS builds.
It has no runtime dependencies.
HTTP calls use a standards-compatible `fetch` implementation.
Realtime uses a standards-compatible `WebSocket` implementation.

| Runtime | HTTP | Realtime | Session storage |
| --- | --- | --- | --- |
| Modern browser | Global `fetch` | Global `WebSocket` | `localStorage` when available |
| Node.js 22 or newer | Global `fetch` | Global `WebSocket` | Memory unless a custom store is supplied |
| Node.js 20 | Global `fetch` | Supply a WebSocket constructor | Memory unless a custom store is supplied |
| React Native | Supply compatible globals or adapters as required by the runtime | Supply the runtime's compatible socket | Supply an async storage adapter |
| Edge runtime | Usually global `fetch` | Runtime-dependent | Prefer a request-scoped token rather than persisted process state |
| Test process | Real or fake `fetch` | Optional fake socket | `MemoryStorage` or a test double |

The package declares Node.js 20 or newer for its distributed command-line type generator.
An application bundle only uses the browser-compatible surfaces it imports.

## Installation

Install the client from the npm registry.

```bash
npm install @pawabase/client
```

The package name is the same for JavaScript and TypeScript applications.
TypeScript applications receive its declarations automatically.
JavaScript applications can use the same runtime methods without supplying generic types.

## The smallest useful client

A browser client normally uses the public gateway origin and a publishable key.

```typescript
import { createClient } from "@pawabase/client";

export const pawabase = createClient({
  url: "https://api.example.com",
  apiKey: "pb_pk_…",
});
```

`createClient()` returns a `PawabaseClient`.
Creating it does not make a network request.
The first operation that needs the network uses the configured transport.
Auth initialization may read the configured session store first.

<Warning>
  Never place a secret key in browser code, a mobile bundle, a desktop bundle distributed to users, or a public environment variable.
  Secret keys bypass policies.
  The SDK rejects a secret key in a detected browser unless `dangerouslyAllowBrowser` is set, but that override does not make exposure safe.
</Warning>

## Find the values in Studio

The gateway URL and key are environment-specific integration values.
In Studio, open the environment that the application should call.
Use **Build → Settings → API keys** to create or inspect key metadata.
New key material is shown when the key is created and cannot be revealed again later.
Use **API Explorer** to confirm the environment's public operations before blaming the SDK for a route or schema mismatch.

| Value | Studio context | Application decision |
| --- | --- | --- |
| Gateway URL | The installation's public API origin | Keep it configurable so local, staging, and production builds do not share a hard-coded origin |
| Publishable key | **Build → Settings → API keys** | Use in untrusted clients; policies remain the authorization boundary |
| Secret key | **Build → Settings → API keys** | Use only in trusted server code; narrow scopes and deployment access |
| Environment | The active environment in Studio | Match the key and the generated types to the same environment |
| Project reference | Installation or Cloud project reference | Supply only where an API, notably social sign-in URL construction, requires the reference |

An API key is not the signed-in user.
The API key selects an environment and carries its own role and scopes.
A user access token adds application identity to the request.
Policies can then evaluate both the credential and the user context.

## One client, two credentials

Every normal SDK request can carry two different credentials.

| Credential | Wire location | Purpose | Safe location |
| --- | --- | --- | --- |
| Project key | `apikey` header | Selects the environment and establishes the key role and scopes | Publishable key in any client; secret key only on trusted servers |
| User access token | `Authorization: Bearer <token>` | Identifies the application user and current auth context | Managed by the client or supplied per server request |

The distinction explains several common outcomes.
A request with a valid publishable key can still receive `401` when an operation requires a signed-in user.
A signed-in user can still receive `403` when a policy rejects the user or the key lacks a required scope.
A secret key can bypass record policies, which is why moving it into a browser is a security failure rather than a convenience.

## A first request

The records client begins at `from(resourceName)`.
A list call returns a page object rather than an array by itself.

```typescript
const page = await pawabase
  .from("posts")
  .eq("status", "live")
  .order("created_at", "desc")
  .perPage(20);

for (const post of page.data) {
  console.log(post.title);
}

console.log(page.page);
console.log(page.per_page);
console.log(page.total);
```

`total` can be `null`.
That is not a parse error.
It means a per-row policy prevents Pawabase from knowing the complete visible count safely.
The [records and queries guide](/clients/typescript/records) explains how that affects pagination and iteration.

## Capability map

Each entry point expresses a different product concept.
Choosing the right one keeps policy, error, and response behavior predictable.

| Need | Entry point | Typical result |
| --- | --- | --- |
| List or mutate a resource | `client.from("posts")` | `Page<Row>`, one `Row`, `null`, or `void` |
| Use a manually declared row type | `client.resource<Row>("posts")` | A typed `ResourceClient` |
| Sign in or inspect a session | `client.auth` | `Session`, `User`, or a discriminated sign-in result |
| Work with one bucket | `client.storage.from("avatars")` | Object metadata, bytes, listings, or signed URLs |
| Invoke a deployed function | `client.functions.invoke()` | The function's public response body |
| Run a pathless HTTP flow | `client.flows.run()` | The flow's response body |
| Call a custom route | `client.routes.get()` and siblings | The route's public response body |
| Subscribe to a channel | `client.realtime.channel()` | A reusable `RealtimeChannel` |
| Call another public gateway path | `client.request()` | The requested parsed JSON body |
| Read platform service health | `client.status()` | `{ ok, services? }` |
| Act with a request's user token | `client.asUser(token)` | A stateless child client |
| Release timers and sockets | `client.dispose()` | No return value |

## The child clients share transport policy

The capability clients are not isolated network clients.
They share the configured HTTP behavior.
That includes the base URL, key, common headers, timeout, retry policy, hooks, and token provider.

This matters when troubleshooting.
If record reads and storage calls both fail with `AuthenticationError`, inspect the shared key and environment before inspecting two unrelated feature configurations.
If only realtime fails, inspect WebSocket support and **Settings → Realtime**, because the socket has additional channel authorization and connection requirements.

## Authentication is optional, authorization is not

The SDK works before a user signs in.
Anonymous record reads, public storage downloads, functions, flows, routes, and channel operations depend on their configured policies and the key's scopes.
Signing in adds a user token; it does not automatically grant access.

```typescript
const result = await pawabase.auth.signInWithPassword({
  email: "ada@example.com",
  password,
});

if (result.status === "mfa_required") {
  const session = await result.verify(code);
  console.log(session.user.email);
} else {
  console.log(result.session.user.email);
}
```

The result is a union because password verification is not always the end of sign-in.
An application that assumes every successful password response contains a final session will mishandle MFA-enabled accounts.

## Queries are immutable and awaitable

Calling a query method returns a new builder.
It does not alter the previous builder and does not immediately send a request.
Awaiting the builder, calling `execute()`, or using a terminal method sends the request.

```typescript
const visible = pawabase
  .from("posts")
  .eq("status", "live");

const newest = visible.order("created_at", "desc").perPage(10);
const popular = visible.order("views", "desc").perPage(10);

const [newestPage, popularPage] = await Promise.all([
  newest,
  popular,
]);
```

Reusing `visible` is safe because `order()` and `perPage()` return new builders.
This model is useful for UI filters where several views share a fixed authorization-relevant predicate.

## Realtime channels are reusable objects

`realtime.channel(name)` returns the same channel object when called again with the same name.
Listeners are therefore shared.
Treat channel ownership deliberately: a component that calls `unsubscribe()` affects every listener using that channel object.

```typescript
const room = pawabase.realtime.channel("chat:lobby", {
  presence: { display_name: "Ada" },
  replay: 50,
});

const stop = room.on("message", (message) => {
  console.log(message.event, message.payload);
});

await room.subscribe();

// Later, remove only this listener.
stop();
```

Use `unsubscribe()` when the application no longer wants the channel joined.
Use `realtime.forget(name)` after unsubscribing when a future request for the name should create a new channel object.

## Browser, server, and request-scoped clients

The same constructor can represent three materially different trust models.

| Model | API key | User token source | Session behavior | Policy effect |
| --- | --- | --- | --- | --- |
| Browser application | Publishable | Managed auth session | Persisted and refreshed by default | Policies apply |
| Long-running trusted server | Secret or publishable | None, managed session, or provider | Depends on options | Secret key bypasses policies; publishable key does not |
| Request-scoped server acting for a user | Publishable | `accessToken` or `asUser()` | No persistence and no refresh | User policies apply to that request's identity |

Do not share a mutable, persisted end-user session across server requests.
One user's token can leak into another user's work when a process-wide singleton owns the session.
Use a request-scoped client with `accessToken`, or derive one with `asUser()`.

```typescript
const base = createClient({
  url: process.env.PAWABASE_URL,
  apiKey: process.env.PAWABASE_PUBLISHABLE_KEY,
});

export async function loadTasks(accessToken) {
  const userClient = base.asUser(accessToken);
  return userClient.from("tasks").all({ maxRecords: 500 });
}
```

An `accessToken` client is intentionally stateless.
It does not load a stored session, persist tokens, refresh tokens, or detect a browser redirect fragment.
The framework or request handler remains responsible for the token source.

## Type generation changes the developer experience, not runtime authorization

Without a generated database type, record rows are `Record<string, unknown>`.
The server still validates the request.
With a generated `Database` type, TypeScript can also reject misspelled resources and invalid create bodies locally.

```typescript
import { createClient } from "@pawabase/client";
import type { Database } from "./pawabase.types";

export const pawabase = createClient<Database>({
  url: import.meta.env.PUBLIC_PAWABASE_URL,
  apiKey: import.meta.env.PUBLIC_PAWABASE_KEY,
});
```

Generated types are a snapshot of one environment's OpenAPI document.
They do not grant access, and they can become stale.
Run the generator after resource changes and check drift in continuous integration.

## Failure handling belongs at the call boundary

Every SDK-thrown failure extends `PawabaseError`.
Server responses extend `ApiError` and expose normalized fields such as `status`, `code`, `requestId`, and `body`.
Transport failures have separate classes because no server response exists.

```typescript
import {
  PermissionError,
  ValidationError,
} from "@pawabase/client";

try {
  await pawabase.from("posts").create(input);
} catch (error) {
  if (error instanceof ValidationError) {
    renderFieldErrors(error.byField());
  } else if (error instanceof PermissionError) {
    showAccessDenied(error.policy);
  } else {
    throw error;
  }
}
```

Do not convert every failure into “not found” or “try again.”
A validation failure needs field feedback.
A permission failure needs an authorization decision.
A rate limit may need a delayed retry.
An abort often needs no user-facing error at all.

## Retries are intentionally conservative

The client retries selected transient failures, but method semantics limit what can be repeated safely.

| Failure | Default behavior |
| --- | --- |
| `429` with an acceptable wait | Retry any method because rate limiting occurs before the operation runs |
| Network failure, timeout, `502`, `503`, or `504` on `GET`, `PUT`, or `DELETE` | Retry within the configured budget |
| Network failure, timeout, `502`, `503`, or `504` on `POST` or `PATCH` | Surface unless the call explicitly declares `idempotent: true` |
| `500` | Surface |
| Other `4xx` | Surface |
| Refresh-token exchange network failure | Surface rather than replaying a rotating refresh token |

The default budget is two retry attempts after the original call.
Backoff uses full jitter with a 300 ms initial ceiling and an 8 second maximum.
Each attempt has a 30 second timeout unless configured otherwise.

## Lifecycle and disposal

An SDK client can own an auth refresh timer, browser storage listeners, and a realtime socket.
Call `dispose()` when a long-lived client is truly being discarded, especially in tests, hot-reload boundaries, worker shutdown, or short-lived tools.

```typescript
const client = createClient({ url, apiKey });

try {
  return await runImport(client);
} finally {
  client.dispose();
}
```

Disposal is not sign-out.
It stops client-side activity and closes realtime.
Use `auth.signOut()` when the user's server-side session should end and local credentials should be cleared.

## Package exports

The root package exports runtime classes, constructor helpers, error classes, the installed version, and public TypeScript types.
Applications normally need a small subset.

| Export family | Runtime exports | Type-only exports |
| --- | --- | --- |
| Root client | `createClient`, `PawabaseClient` | `ClientOptions`, `DatabaseShape` |
| Auth | `AuthClient`, `MemoryStorage` | Auth results, listeners, options, storage, user/session wire types |
| Records | `ResourceClient`, `QueryBuilder` | Row, resource, condition, filter, page, read, query, and iteration types |
| Invocation | `FunctionsClient`, `FlowsClient`, `RoutesClient` | `CallOptions`, `RouteOptions` |
| Storage | `StorageClient`, `BucketClient` | Upload and transfer option/body types |
| Realtime | `RealtimeClient`, `RealtimeChannel` | Status, socket, options, channel event, and presence types |
| Transport | `HttpClient` | Fetch, hooks, request/response, retry, and token-provider types |
| Errors | Every error class plus guards | Error initialization and validation-issue types |
| Type generation | `generateTypes` | `TypegenOptions` |
| Package metadata | `VERSION` | None |

Use `import type` for types so transpilers can erase them cleanly.

```typescript
import {
  createClient,
  PermissionError,
  VERSION,
} from "@pawabase/client";

import type {
  ClientOptions,
  DatabaseShape,
  Page,
} from "@pawabase/client";
```

## ESM and CommonJS

The package export map provides both module formats.

```typescript
import { createClient } from "@pawabase/client";
```

```typescript
const { createClient } = require("@pawabase/client");
```

The package is marked side-effect free.
Bundlers can remove unused exports when their normal tree-shaking requirements are met.

## Wire names remain `snake_case`

The client preserves public JSON names.

```typescript
const session = await client.auth.getSession();

console.log(session?.access_token);
console.log(session?.expires_at);
console.log(session?.user.avatar_url);
```

There is no automatic camel-case transformation.
This keeps TypeScript values aligned with API Explorer, JSON examples, webhooks, and non-TypeScript clients.

## Client information on requests

Normal HTTP calls include a client-information header containing the SDK version.
This supports request diagnostics without exposing user identity.
The API key and user bearer are attached separately and masked in SDK hook observations.

The exported `VERSION` can be recorded with application release metadata.

```typescript
import { VERSION } from "@pawabase/client";

telemetry.setAttribute("pawabase.sdk.version", VERSION);
```

## Choosing high-level and low-level APIs

Prefer the highest-level client that accurately represents the operation.

| Operation | Preferred surface | Why |
| --- | --- | --- |
| Resource list/create/update/delete | `from()` | Query grammar, typing, pagination, and result semantics |
| User sign-in and refresh | `auth` | Rotating-token coordination and state events |
| Object transfer | `storage` | Correct body parsing, content type, and signed-URL credentials |
| Named function or flow | `functions` or `flows` | Correct path and response convention |
| Domain REST operation | `routes` | Method, query, body, and route prefix |
| Unsupported documented JSON endpoint | Root `request()` | Shared auth, errors, timeout, and retry behavior |
| Custom transport infrastructure | `HttpClient` | Full parser/auth/retry ownership, with more configuration burden |

The exported `HttpClient` is an advanced surface.
Ordinary applications should not construct it to reproduce behavior already configured on `PawabaseClient`.

## What “zero dependencies” means

The runtime package does not install a fetch, WebSocket, storage, schema validator, state manager, or UI framework.
It uses runtime standards and adapters supplied in client options.

This keeps framework choices in the application, but it also means Node.js 20 applications must add their own WebSocket package for realtime and React Native applications must supply persistent storage.

## Boundaries the SDK does not remove

The SDK cannot make a disabled resource operation available.
It cannot override a policy when used with a publishable key.
It cannot infer that retrying an arbitrary `POST` is safe.
It cannot make stale generated types match a changed environment.
It cannot make a private bucket public.
It cannot enable presence or history on a channel rule.
It cannot make one environment's key valid in another environment.

Those boundaries are deliberate.
The package makes public operations easier to call while leaving Pawabase's environment, credential, policy, and schema boundaries intact.
