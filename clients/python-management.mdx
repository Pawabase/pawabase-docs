With a secret key the same client reaches the management plane, so anything you can do in Studio can be a script, a CI job or part of your own back office.
Both entry points are scoped to **one environment** (the client's `environment=`), and a key manages only its own environment.

```python
from pawabase import Pawabase

pb = Pawabase("https://api.example.com", "pb_sk_…", environment="production")

pb.admin.users.create(email="ada@example.com", password="…", roles=["editor"])
pb.admin.users.update(user_id, disabled=True)
pb.admin.orgs.add_member("acme", email="ada@example.com", role="admin")

pb.manage.secrets.set("STRIPE_KEY", "sk_live_…")
pb.manage.firewall.ban("203.0.113.7", seconds=3600)
pb.manage.jobs.replay(job="send_mail", since_minutes=60, dry_run=True)
pb.manage.backups.snapshot("before-launch")
pb.manage.environment("staging").flows.list()      # the same API for another environment the key may manage
```

A publishable key is refused with `ForbiddenError`. `AsyncPawabase` offers the same methods, awaited.

## `pb.manage`

| Family | Services |
| --- | --- |
| Data | `resources`, `schema`, `policies`, `schemas`, `transformers`, `routes`, `database`, `runtime` |
| Automation | `flows`, `schedules`, `subscriptions`, `events`, `webhooks`, `inbound_hooks`, `jobs`, `functions` |
| Files and mail | `buckets`, `cache`, `mail`, `mail_templates` |
| Access | `keys`, `secrets`, `domains`, `firewall` |
| Observe | `observability`, `alarms`, `status_page`, `health` (service health, plan usage, audit) |
| Lifecycle | `environments` (previews, promote, blueprints), `releases` (branches, revisions, API versions), `backups` (backups, snapshots, restore) |

Definitions (`flows`, `policies`, `webhooks`, `resources`…) share `list`, `get_one`, `create`, `replace` and `remove`, and take `branch=` to work on a feature
branch's draft instead of the live environment (see [releases](/operate/releases-and-api-versions)).

```python
pb.manage.resources.create({"name": "posts", "fields": [{"name": "title", "type": "string", "required": True}],
                            "operations": {"list": {"enabled": True, "policy": "public"}}})
pb.manage.resources.migrate("posts")

pb.manage.flows.run("welcome", {"email": "ada@example.com"})
pb.manage.webhooks.deliveries(status="failed")
pb.manage.webhooks.redeliver_many(status="failed", since_minutes=60, dry_run=True)   # count first, then send

pb.manage.keys.create("ci", role="secret", scopes=["functions:invoke"], allowed_ips=["10.0.0.0/8"])
pb.manage.keys.rotate(key_id, grace_hours=24)         # the old key keeps working while clients switch

pb.manage.firewall.add_rule(name="Burst", action="rate_limit",
                            conditions=[{"field": "path", "op": "starts_with", "value": "/auth/v1/token"}],
                            rate_limit={"requests": 10, "window_seconds": 60, "by": "ip", "ban_seconds": 900})
pb.manage.firewall.test("203.0.113.7", path="/rest/v1/orders")     # what would happen, step by step; nothing is sent

pb.manage.observability.logs(q="timeout", minutes=15)
pb.manage.alarms.create(name="5xx", metric="errors", threshold=10, recipients=["ops@example.com"])
pb.manage.health.usage()                                # each plan limit and how much is used

pb.manage.backups.set_schedule(frequency="daily", hour=3, keep_last=7)
pb.manage.backups.restore_snapshot(snapshot_id, strategy="replace", confirm="production")
```

Calls that are about the project, not one environment (`environments.list()`, `flows.validate()`, `jobs.workers()`, the audit trail), say so in their
docstring and do not use the client's environment.

## `pb.admin`

`users`, `roles`, `orgs`, `invitations`, `sessions`, `api_keys`, `devices` and `insight` administer the people who sign in to *your* application, not the project's
own team. A user of one environment is never visible in another.

```python
pb.admin.users.search(status="locked")                   # search="ada", status: disabled, unverified, locked, mfa, no_mfa
pb.admin.users.update(user_id, unlock=True, roles=["support"])
pb.admin.users.reset_mfa(user_id)
pb.admin.users.grant(user_id, ["billing:*"])
pb.admin.users.revoke_sessions(user_id)
pb.admin.roles.put("editor", ["posts:*"])
pb.admin.orgs.invite("acme", email="grace@example.com", role="member")
pb.admin.insight.events(failed=True)
pb.admin.insight.backup()                                # every identity, as a document
```

These routes are served under `/platform/v1/envs/{env}/auth/…` with the same secret-key gate as the rest of the management plane. They are not part of the
internal admin API, which is not reachable through the gateway.
