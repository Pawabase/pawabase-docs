Every method in the client goes through one transport, `pawabase.http`.
Knowing its rules lets you predict how any call behaves, including raw calls you make yourself.

### Which token a request carries

For each request, the transport picks a user token in this order:

| Situation | Token sent |
| --- | --- |
| The request goes to an absolute URL (a signed URL) | None, and no API key either |
| The call passed an explicit `accessToken` | That token |
| The call passed `auth: "none"` | None; the API key alone |
| The client is stateless (`accessToken` option) | The value of that option |
| Otherwise | The stored session's access token, refreshed first if it is expiring |

Auth endpoints that must work for signed-out users, such as sign-in, sign-up and password recovery, are sent with `auth: "none"`.
That is why signing in works even when a stale session is stored.

### How the body is encoded

| You pass | Sent as | `content-type` |
| --- | --- | --- |
| A plain object or array | JSON text | `application/json`, unless you set one |
| A `string` | As is | Whatever you set; none by default |
| `Blob` or `File` | As is | The blob's type, if the method sets it |
| `ArrayBuffer` or a typed array | As is | Whatever you set |
| `FormData` | As is | Set by the runtime, with a boundary |
| `URLSearchParams` | As is | Set by the runtime |
| `ReadableStream` | Streamed, with `duplex: "half"` | Whatever you set |
| `undefined` or `null` | No body | none |

### How the answer is read

By default the answer is parsed as JSON.
An empty body, a `204` or a `205` gives `undefined`.
A body that is not valid JSON is returned as text rather than failing, because some endpoints answer with plain text.

Other parse modes exist for downloads and raw access:

| `parse` | Returns |
| --- | --- |
| `"json"` (default) | Parsed JSON, text if it is not JSON, or `undefined` if empty |
| `"text"` | The body as a string |
| `"blob"` | A `Blob` |
| `"arrayBuffer"` | An `ArrayBuffer` |
| `"stream"` | The body's `ReadableStream` |
| `"response"` | The `Response` object itself |

An error status throws before parsing, after retries are exhausted, unless the request asked for `throwOnError: false`.


## Raw requests

`pawabase.request(method, path, options)` calls any path on the gateway with the same credentials, retries and errors as the rest of the client.
Use it for endpoints the client has no method for, and to explore the API while you develop.

<CodeGroup>
```typescript TypeScript
const settings = await pawabase.request<{ signup_enabled: boolean }>("GET", "/auth/v1/settings");

const created = await pawabase.request("POST", "/rest/v1/orders", {
  body: { customer_id: "c_1", total_minor: 1200 },
});

const filtered = await pawabase.request("GET", "/rest/v1/orders", {
  query: { "filter[status]": "eq.open", per_page: 5 },
});
```

```python Python
settings = pb.request("GET", "/auth/v1/settings")

created = pb.request("POST", "/rest/v1/orders", json={"customer_id": "c_1", "total_minor": 1200})

filtered = pb.request("GET", "/rest/v1/orders", params={"filter[status]": "eq.open", "per_page": 5})
```

```bash cURL
curl "$PAWABASE_URL/auth/v1/settings" -H "apikey: $PAWABASE_KEY"

curl -X POST "$PAWABASE_URL/rest/v1/orders" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"customer_id": "c_1", "total_minor": 1200}'

curl -G "$PAWABASE_URL/rest/v1/orders" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "filter[status]=eq.open" --data-urlencode "per_page=5"
```
</CodeGroup>

| Option | Meaning |
| --- | --- |
| `body` | An object is sent as JSON; other bodies are sent as they are |
| `query` | Query parameters; `undefined` and `null` values are left out |
| `headers` | Extra headers for this call |
| `signal` | An `AbortSignal` to cancel the call |

The path is relative to the gateway origin and should start with `/`.
Query values are encoded for you; arrays repeat the parameter.

`request()` is deliberately small.
When you need the transport's advanced options, call `pawabase.http.request()` or `pawabase.http.send()` directly.

| Option on `http.request` | Purpose |
| --- | --- |
| `parse` | Choose `text`, `blob`, `arrayBuffer`, `stream` or `response` |
| `timeoutMs` | A timeout for this call |
| `retry` | A retry policy for this call, or `false` |
| `idempotent` | Allow retrying a `POST` or `PATCH` after a network failure or gateway error |
| `auth` | `"none"` to send the API key without the user's token |
| `accessToken` | A specific user token for this call |
| `absoluteUrl` | Call a full URL as it is, with no key, token or extra headers |
| `throwOnError` | `false` to get an error `Response` back instead of an exception |

<CodeGroup>
```typescript TypeScript
const csv = await pawabase.http.request<string>({
  path: "/rest/v1/x/reports/monthly.csv",
  query: { month: "2026-09" },
  parse: "text",
  timeoutMs: 60_000,
});
```

```python Python
# A body that is not JSON comes back as text
csv = pb.request("GET", "/rest/v1/x/reports/monthly.csv", params={"month": "2026-09"})

# or streamed, for large answers
with pb.stream("GET", "/rest/v1/x/reports/monthly.csv", params={"month": "2026-09"}) as response:
    for chunk in response.iter_bytes():
        sink.write(chunk)
```

```bash cURL
curl -G "$PAWABASE_URL/rest/v1/x/reports/monthly.csv" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "month=2026-09" -o monthly.csv
```
</CodeGroup>

```typescript
const response = await pawabase.http.send({
  method: "GET",
  path: "/rest/v1/orders/42",
  throwOnError: false,
});
if (response.status === 404) console.log("gone or hidden");
```

`http.send()` returns the `Response`; `http.request()` reads and parses it.
Both apply the same retry and refresh rules.


## Health checks

`pawabase.status()` asks the gateway for the health of the services behind it.
It sends the API key without a user token, and it needs no particular policy.

<CodeGroup>
```typescript TypeScript
const status = await pawabase.status();
// { ok: true, services: { api: { ok: true }, auth: { ok: true }, realtime: { ok: true } } }
```

```python Python
status = pb.status()   # GET /health/v1
```

```bash cURL
curl "$PAWABASE_URL/v1/status" -H "apikey: $PAWABASE_KEY"
```
</CodeGroup>

Use it in readiness probes for services that depend on Pawabase, and as the first step when diagnosing "nothing works".
It answers the question "is the installation up and is my key accepted" without involving your resources or policies.

| Result | Meaning |
| --- | --- |
| `ok: true` | The gateway and its services answered. |
| `ok: false` with a service `ok: false` | That service is down or unreachable from the gateway. |
| `AuthenticationError` | The key is not accepted by this gateway. |
| `NetworkError` | The gateway itself could not be reached. |


## The client's lifecycle

A client has a short lifecycle, and three moments in it matter.

### Construction

`createClient` validates the options, builds the transport, and starts reading the stored session.
Reading the session is asynchronous, so construction returns before it finishes.
In a browser, if the URL fragment carries tokens from a social sign-in, the client adopts them during this step.

Nothing is sent to the network during construction, except the user lookup that adopting tokens from a URL requires.
Creating a client is cheap.

### Ready

`pawabase.auth.initialized()` resolves once the stored session has been read.
You rarely need to await it: every method that depends on the session waits for it internally, and `onAuthStateChange` delivers `INITIAL_SESSION` once it is done.

```typescript
await pawabase.auth.initialized();
const user = await pawabase.auth.getCachedUser();
```

### Disposal

`pawabase.dispose()` stops the refresh timer, removes cross-tab listeners, removes auth listeners, and closes the realtime connection.
After disposal the client can still send HTTP requests, but it no longer refreshes sessions or keeps a socket.

Dispose a client when you discard it:

| Situation | Why dispose |
| --- | --- |
| Tests | Timers and sockets keep the test runner alive or leak into the next test. |
| Hot module reload | Each reload would otherwise add a refresh timer and listeners. |
| Short-lived clients in long-running processes | A secret-key client per job, for example. |
| A user switching accounts in a multi-account app that uses separate clients | The old client's timers would keep refreshing a session nobody uses. |

A hot-reload-safe module in Vite looks like this:

```typescript
import { createClient } from "@pawabase/client";

export const pawabase = createClient({
  url: import.meta.env.VITE_PAWABASE_URL,
  apiKey: import.meta.env.VITE_PAWABASE_KEY,
});

if (import.meta.hot) {
  import.meta.hot.dispose(() => pawabase.dispose());
}
```
