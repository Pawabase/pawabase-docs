The options above combine differently in each runtime.
This section gives a complete, working configuration for the runtimes TypeScript developers use most, with the reasoning for each choice.

### A Vite single-page application

A browser app needs a publishable key, the environment name for social sign-in and realtime, and the default session storage.

```typescript
// src/lib/pawabase.ts
import { createClient } from "@pawabase/client";
import type { Database } from "./database";

export const pawabase = createClient<Database>({
  url: import.meta.env.VITE_PAWABASE_URL,
  apiKey: import.meta.env.VITE_PAWABASE_KEY,
  environment: import.meta.env.VITE_PAWABASE_ENV,
});

if (import.meta.hot) import.meta.hot.dispose(() => pawabase.dispose());
```

Nothing else is needed.
The session is kept in `localStorage`, refreshed automatically, shared across tabs, and picked up from the URL after a social sign-in.

### Next.js with the App Router

A Next.js application usually needs three clients, each in its own module so that the bundler cannot mix them up.

```typescript
// lib/pawabase/browser.ts — imported by client components
"use client";
import { createClient } from "@pawabase/client";
import type { Database } from "./types";

export const pawabase = createClient<Database>({
  url: process.env.NEXT_PUBLIC_PAWABASE_URL!,
  apiKey: process.env.NEXT_PUBLIC_PAWABASE_KEY!,
  environment: process.env.NEXT_PUBLIC_PAWABASE_ENV,
  auth: { persistSession: false },
});
```

```typescript
// lib/pawabase/server.ts — imported by server components, actions and route handlers
import "server-only";
import { cookies } from "next/headers";
import { createClient } from "@pawabase/client";
import type { Database } from "./types";

const base = createClient<Database>({
  url: process.env.PAWABASE_URL!,
  apiKey: process.env.PAWABASE_PUBLISHABLE_KEY!,
  environment: process.env.PAWABASE_ENV,
});

export async function pawabaseForRequest() {
  const token = (await cookies()).get("pb-access")?.value ?? null;
  return token ? base.asUser(token) : base;
}
```

```typescript
// lib/pawabase/service.ts — privileged server work only
import "server-only";
import { createClient } from "@pawabase/client";
import type { Database } from "./types";

export const pawabaseService = createClient<Database>({
  url: process.env.PAWABASE_URL!,
  apiKey: process.env.PAWABASE_SECRET_KEY!,
  environment: process.env.PAWABASE_ENV,
});
```

The browser client here uses `persistSession: false` because the server owns the session in an HTTP-only cookie.
If your Next.js app keeps the session in the browser instead, drop that line and do not use the cookie-based server module for user data.
Pick one owner for the session; two owners refresh the same refresh token and end the session.

### SvelteKit

SvelteKit's `hooks.server.ts` runs for every request, which makes it the natural place to build the per-request client.

```typescript
// src/hooks.server.ts
import type { Handle } from "@sveltejs/kit";
import { createClient } from "@pawabase/client";
import { PUBLIC_PAWABASE_URL, PUBLIC_PAWABASE_KEY, PUBLIC_PAWABASE_ENV } from "$env/static/public";

const base = createClient({ url: PUBLIC_PAWABASE_URL, apiKey: PUBLIC_PAWABASE_KEY, environment: PUBLIC_PAWABASE_ENV });

export const handle: Handle = async ({ event, resolve }) => {
  const token = event.cookies.get("pb-access") ?? null;
  event.locals.pawabase = token ? base.asUser(token) : base;
  return resolve(event);
};
```

Load functions then read `locals.pawabase` and never create clients themselves.

### Remix and React Router

Loaders and actions run on the server and receive the request, so they build the per-request client from the cookie header.

```typescript
// app/pawabase.server.ts
import { createClient } from "@pawabase/client";

const base = createClient({
  url: process.env.PAWABASE_URL!,
  apiKey: process.env.PAWABASE_PUBLISHABLE_KEY!,
  environment: process.env.PAWABASE_ENV,
});

export function pawabaseFor(request: Request) {
  const cookie = request.headers.get("cookie") ?? "";
  const token = /(?:^|;\s*)pb-access=([^;]+)/.exec(cookie)?.[1] ?? null;
  return token ? base.asUser(decodeURIComponent(token)) : base;
}
```

The `.server.ts` suffix keeps the module out of the browser bundle.

### A Node command-line tool

A command-line tool that users sign in to should remember the session between runs, in a file only the user can read.

<CodeGroup>
```typescript TypeScript
import { homedir } from "node:os";
import { join } from "node:path";
import { createClient } from "@pawabase/client";
import { fileStorage } from "./file-storage";

export const pawabase = createClient({
  url: process.env.PAWABASE_URL ?? "https://api.example.com",
  apiKey: process.env.PAWABASE_KEY ?? "pb_pk_live_…",
  environment: process.env.PAWABASE_ENV ?? "production",
  auth: {
    storage: fileStorage(join(homedir(), ".config", "mytool", "session.json")),
    detectSessionInUrl: false,
  },
  retry: { retries: 1 },
});
```

```python Python
import os
from pathlib import Path

from pawabase import FileSessionStore, Pawabase

pb = Pawabase(
    os.environ.get("PAWABASE_URL", "https://api.example.com"),
    os.environ.get("PAWABASE_KEY", "pb_pk_live_…"),
    environment=os.environ.get("PAWABASE_ENV", "production"),
    session_store=FileSessionStore(Path.home() / ".config" / "mytool" / "session.json"),
    retries=1,
)
```
</CodeGroup>

A publishable key is correct here even though the tool runs on a developer's machine.
The tool acts for the person who signed in, and their policies should apply.

### Deno and Bun

Both have `fetch` and `WebSocket` globally, so no adapters are needed.
Import the package through npm specifiers in Deno.

```typescript
// Deno
import { createClient } from "npm:@pawabase/client";

const pawabase = createClient({
  url: Deno.env.get("PAWABASE_URL")!,
  apiKey: Deno.env.get("PAWABASE_SECRET_KEY")!,
  environment: Deno.env.get("PAWABASE_ENV"),
});
```

```typescript
// Bun
import { createClient } from "@pawabase/client";

const pawabase = createClient({
  url: Bun.env.PAWABASE_URL!,
  apiKey: Bun.env.PAWABASE_SECRET_KEY!,
  environment: Bun.env.PAWABASE_ENV,
});
```

### Cloudflare Workers and other edge runtimes

Edge runtimes give you configuration per request, through the handler's `env` argument, and may reuse an isolate across many requests.
Create a base client once per isolate, lazily, and `asUser` per request.

```typescript
import { createClient, type PawabaseClient } from "@pawabase/client";

interface Env {
  PAWABASE_URL: string;
  PAWABASE_PUBLISHABLE_KEY: string;
  PAWABASE_ENV: string;
}

let base: PawabaseClient | null = null;

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    base ??= createClient({
      url: env.PAWABASE_URL,
      apiKey: env.PAWABASE_PUBLISHABLE_KEY,
      environment: env.PAWABASE_ENV,
      timeoutMs: 10_000,
    });
    const token = request.headers.get("authorization")?.replace(/^Bearer /, "") ?? null;
    const pawabase = token ? base.asUser(token) : base;
    return Response.json(await pawabase.from("articles").eq("status", "live").perPage(10));
  },
};
```

Edge runtimes limit how long a request may run, so a shorter timeout gives a clearer error than the platform killing the request.

### React Native and Expo

Mobile apps need secure session storage and no URL detection.

```typescript
import * as SecureStore from "expo-secure-store";
import { createClient } from "@pawabase/client";

export const pawabase = createClient({
  url: process.env.EXPO_PUBLIC_PAWABASE_URL!,
  apiKey: process.env.EXPO_PUBLIC_PAWABASE_KEY!,
  environment: process.env.EXPO_PUBLIC_PAWABASE_ENV,
  auth: {
    storage: {
      getItem: (key) => SecureStore.getItemAsync(key.replace(/[^A-Za-z0-9._-]/g, "_")),
      setItem: (key, value) => SecureStore.setItemAsync(key.replace(/[^A-Za-z0-9._-]/g, "_"), value),
      removeItem: (key) => SecureStore.deleteItemAsync(key.replace(/[^A-Za-z0-9._-]/g, "_")),
    },
    detectSessionInUrl: false,
  },
});
```

`expo-secure-store` accepts only some characters in keys, and the default storage key contains the gateway host.
The adapter above replaces other characters so the key is always valid.

### Electron

In Electron, keep the client in the renderer if your app is a web app in a window, and give it a storage adapter that calls the main process, where `safeStorage` encrypts the session at rest.
Never give the renderer a secret key: a renderer can be inspected like any browser page.
