`pawabase.asUser(token)` returns a new client with the same options and a fixed user token.
It is the configuration you use on servers that act for one user per request.

<CodeGroup>
```typescript TypeScript
const base = createClient({ url, apiKey: publishableKey, environment: "production" });

export async function handler(request: Request) {
  const token = readAccessTokenCookie(request);
  const pawabase = token ? base.asUser(token) : base;
  const orders = await pawabase.from("orders").perPage(20);
  return Response.json(orders);
}

declare function readAccessTokenCookie(request: Request): string | null;
```

```python Python
base = AsyncPawabase(url, publishable_key, environment="production")


async def handler(request):
    token = read_access_token_cookie(request)
    pb = base.as_user(token) if token else base
    page = await pb.from_("orders").per_page(20).execute()
    return JSONResponse(dict(page.raw))
```

```bash cURL
curl "$PAWABASE_URL/rest/v1/orders?per_page=20" -H "apikey: $PAWABASE_PUBLISHABLE_KEY" -H "Authorization: Bearer $ACCESS_TOKEN"
```
</CodeGroup>

The returned client is stateless: no stored session, no refresh timer, no URL detection.
It is cheap to create, so create one per request and let it go when the request ends.
The token may also be a function, which is read before every call.

Do not share an `asUser` client between requests.
It holds one user's token, and sharing it would let one user's request run with another user's identity.

| Value | Where in Studio |

| Environment names | The environment switcher at the top of Studio; also **Project → Settings** |

| Key scopes and restrictions | The **Permissions** and **Limits** sections of the **New API key** sheet |

The keys table shows each key's **Name**, **Role** (publishable or secret), **Prefix**, **Scopes**, **Restrictions**, **Last used** and **State**.
The **Last used** column is a quick way to find keys that no deployed client uses any more, so you can revoke them.


## Recipes

### A client per environment, chosen at runtime

Some applications choose the environment at runtime, for example an internal tool with an environment picker.
Create clients lazily and keep one per environment.

```typescript
import { createClient, type PawabaseClient } from "@pawabase/client";

const keys: Record<string, string> = {
  development: import.meta.env.VITE_PAWABASE_KEY_DEVELOPMENT,
  staging: import.meta.env.VITE_PAWABASE_KEY_STAGING,
};

const clients = new Map<string, PawabaseClient>();

export function clientFor(environment: string): PawabaseClient {
  let client = clients.get(environment);
  if (!client) {
    const apiKey = keys[environment];
    if (!apiKey) throw new Error(`No key configured for ${environment}`);
    client = createClient({ url: import.meta.env.VITE_PAWABASE_URL, apiKey, environment });
    clients.set(environment, client);
  }
  return client;
}
```

Each client has its own stored session, because the storage key includes the API key.
A user signs in separately to each environment, which is correct: users are per environment.

### No retries for one sensitive route

A route that charges a card should never be repeated by the transport, even on a gateway error.
`POST` is not retried after a gateway error by default, but making the intent explicit protects against a later refactor:

<CodeGroup>
```typescript TypeScript
await pawabase.http.request({
  method: "POST",
  path: "/rest/v1/payments/charge",
  body: { order_id: orderId },
  retry: false,
});
```

```python Python
# The Python client never repeats a POST after a network failure or a 502/503/504.
# A client with retries=0 also stops repeating reads.
pb.request("POST", "/rest/v1/payments/charge", json={"order_id": order_id})
```

```bash cURL
curl -X POST "$PAWABASE_URL/rest/v1/payments/charge" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"order_id": "o_42"}'
```
</CodeGroup>

### A strict client for scripts

A script that changes data should fail fast and loudly.

```typescript
const pawabase = createClient({
  url: process.env.PAWABASE_URL!,
  apiKey: process.env.PAWABASE_SECRET_KEY!,
  environment: process.env.PAWABASE_ENV!,
  retry: { retries: 1, maxRetryAfterMs: 5000 },
  timeoutMs: 15_000,
  hooks: {
    onRetry: ({ method, url, reason }) => console.error(`retrying ${method} ${url}: ${reason}`),
  },
});
```

### A client behind a corporate proxy on Node

Node's built-in `fetch` does not read `HTTPS_PROXY` by itself.
Use undici's proxy agent and pass a `fetch` that uses it.

```typescript
import { ProxyAgent, fetch as undiciFetch } from "undici";
import { createClient } from "@pawabase/client";

const agent = new ProxyAgent(process.env.HTTPS_PROXY!);

const pawabase = createClient({
  url,
  apiKey,
  fetch: (input, init) => undiciFetch(input, { ...init, dispatcher: agent } as never) as unknown as Promise<Response>,
});
```

### Separate sessions for two people in one browser

A support console where a staff member signs in to an admin environment and also signs in as a test customer needs two sessions:

```typescript
const staff = createClient({ url, apiKey: staffKey, auth: { storageKey: "support.staff" } });
const customer = createClient({ url, apiKey: customerKey, auth: { storageKey: "support.customer" } });
```
