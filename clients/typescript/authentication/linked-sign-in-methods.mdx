A person can link several providers to one account, so they can sign in with any of them.

<CodeGroup>
```typescript TypeScript
const url = await pawabase.auth.linkIdentityUrl("github", { redirectTo: `${location.origin}/settings/security` });
location.assign(url);
```

```python Python
url = pb.auth.link_identity_url("github", redirect_to="https://app.example.com/settings/security")
```

```bash cURL
curl -X POST "$PAWABASE_URL/auth/v1/identities/link?provider=github&redirect_to=https%3A%2F%2Fapp.example.com%2Fsettings" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

After the provider, the browser returns with `#linked=github`, which `getSessionFromUrl` reports as `{ status: "linked", provider: "github" }`.

<CodeGroup>
```typescript TypeScript
const identities = await pawabase.auth.identities();
await pawabase.auth.unlinkIdentity(identities[0].id);
```

```python Python
identities = pb.auth.identities()
pb.auth.unlink_identity(identities[0]["id"])
```

```bash cURL
curl -X DELETE "$PAWABASE_URL/auth/v1/identities/$IDENTITY_ID" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

`identities()` lists the linked providers with their email and last sign-in.
`unlinkIdentity(id)` removes one.


## Second factors

`pawabase.auth.mfa` manages the signed-in person's second factors.

| Method | Purpose |
| --- | --- |
| `status()` | `{ enabled, aal, recovery_codes_remaining }` |
| `enroll()` | Start enrolling an authenticator app: `{ factor_id, secret, otpauth_uri }` |
| `verifyEnrollment(code)` | Confirm with a first code; returns one-time `recovery_codes` |
| `enrollEmail()` | Start using emailed codes as a factor |
| `challenge(mfaToken)` | Send the emailed code during a sign-in |
| `disable(code)` | Turn MFA off, with a current code |
| `regenerateRecoveryCodes(code)` | Replace the recovery codes, with a current code |

Enrolling an authenticator is two calls with a QR code in between:

<CodeGroup>
```typescript TypeScript
const enrollment = await pawabase.auth.mfa.enroll();
renderQrCode(enrollment.otpauth_uri);
showSecretForManualEntry(enrollment.secret);

const { recovery_codes } = await pawabase.auth.mfa.verifyEnrollment(codeFromApp);
showRecoveryCodesOnce(recovery_codes);
```

```python Python
enrollment = pb.auth.mfa.enroll()
render_qr_code(enrollment["otpauth_uri"])

codes = pb.auth.mfa.verify_enrollment(code_from_app)["recovery_codes"]
show_recovery_codes_once(codes)
```

```bash cURL
curl -X POST "$PAWABASE_URL/auth/v1/mfa/totp/enroll" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
curl -X POST "$PAWABASE_URL/auth/v1/mfa/totp/verify" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" -d '{"code": "123456"}'
```
</CodeGroup>

After `verifyEnrollment`, the client refreshes the session so it carries `aal2`, the assurance level of a session that has passed a second factor.
Policies that require `aal2` then admit the session without a new sign-in.

Recovery codes are shown once, at enrolment and when regenerated.
They are stored hashed and cannot be displayed again.
Make the person save them before leaving the screen.


## Sessions and sign-in history

`pawabase.auth.sessions` lets a person see and end their own sessions on other devices.

<CodeGroup>
```typescript TypeScript
const sessions = await pawabase.auth.sessions.list();
for (const s of sessions) {
  console.log(s.current ? "this device" : s.user_agent, s.ip, s.last_refreshed_at);
}

await pawabase.auth.sessions.revoke(lostPhoneSessionId);
const history = await pawabase.auth.sessions.history();
```

```python Python
for s in pb.auth.sessions.list():
    print("this device" if s["current"] else s["user_agent"], s["ip"], s["last_refreshed_at"])

pb.auth.sessions.revoke(lost_phone_session_id)
history = pb.auth.sessions.history()
```

```bash cURL
curl "$PAWABASE_URL/auth/v1/sessions" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
curl -X DELETE "$PAWABASE_URL/auth/v1/sessions/$SESSION_ID" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
curl "$PAWABASE_URL/auth/v1/history" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

| Field of a session | Meaning |
| --- | --- |
| `id` | The session's id |
| `method` | How it was started: password, magic link, a provider |
| `aal` | Its assurance level |
| `ip`, `user_agent` | Where it was started |
| `created_at`, `last_refreshed_at` | When it started and last refreshed |
| `current` | Whether it is the session making the request |

`history()` lists recent sign-in events with their outcome, method and reason, which is the data behind a "recent activity" screen.

### Signing out

`signOut({ scope })` ends sessions.

| `scope` | Ends | This client's session |
| --- | --- | --- |
| `local` (default) | This session | Cleared |
| `others` | Every other session of the account | Kept |
| `global` | Every session of the account | Cleared |

The local session is cleared even if the server cannot be reached, so "sign out" always works from the person's point of view.
A network failure is still thrown after clearing, so you can tell the person that other devices may still be signed in.


## Devices

`pawabase.auth.devices` lists browsers and apps the person has signed in from, and forgets one.

<CodeGroup>
```typescript TypeScript
const devices = await pawabase.auth.devices.list();
await pawabase.auth.devices.forget(deviceId);
```

```python Python
devices = pb.auth.devices.list()
pb.auth.devices.forget(device_id)
```

```bash cURL
curl "$PAWABASE_URL/auth/v1/user/devices" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
curl -X DELETE "$PAWABASE_URL/auth/v1/user/devices/$DEVICE_ID" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>


## Personal API keys

A person can create API keys that act as themselves, for scripts and integrations.
These are different from the environment's project keys: they carry the person's identity, so the person's policies apply.

<CodeGroup>
```typescript TypeScript
const key = await pawabase.auth.apiKeys.create({
  name: "Spreadsheet sync",
  scopes: ["resource:read"],
  expiresInDays: 90,
});
showSecretOnce(key.secret);
```

```python Python
key = pb.auth.api_keys.create(name="Spreadsheet sync", scopes=["resource:read"], expires_in_days=90)
show_secret_once(key["secret"])
```

```bash cURL
curl -X POST "$PAWABASE_URL/auth/v1/user/api-keys" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" -d '{"name": "Spreadsheet sync", "scopes": ["resource:read"], "expires_in_days": 90}'
```
</CodeGroup>

| Input | Meaning |
| --- | --- |
| `name` | A label the person recognizes |
| `scopes` | What the key may do; empty means everything the person may do |
| `expiresInDays` | When it stops working |
| `org` | The organization the key acts in |

The secret is in the response once and never again.
`apiKeys.list()` shows the person's keys without secrets, and `apiKeys.revoke(id)` ends one.
