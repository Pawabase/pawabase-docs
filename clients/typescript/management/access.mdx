### Keys

`m.keys` manages the environment's API keys.

| Method | Purpose |
| --- | --- |
| `list()` | Keys with their prefixes, never their secrets |
| `create(name, { role, scopes, expiresAt, allowedIps, allowedRoutes })` | A new key; the secret is in the answer once |
| `revoke(keyId)` | End a key now |
| `rotate(keyId, { graceHours })` | Issue a replacement; the old key keeps working for the grace period, 24 hours by default |

<CodeGroup>
```typescript TypeScript
const key = await m.keys.create("reporting-service", {
  role: "secret",
  scopes: ["resource:read"],
  allowedIps: ["203.0.113.0/24"],
  expiresAt: new Date(Date.now() + 90 * 24 * 3600 * 1000),
});
await storeInSecretManager("PAWABASE_REPORTING_KEY", key.key);
```

```python Python
from datetime import datetime, timedelta, timezone

key = m.keys.create(
    "reporting-service",
    role="secret",
    scopes=["resource:read"],
    allowed_ips=["203.0.113.0/24"],
    expires_at=datetime.now(timezone.utc) + timedelta(days=90),
)
store_in_secret_manager("PAWABASE_REPORTING_KEY", key["key"])
```

```bash cURL
curl -X POST "$PAWABASE_URL/platform/v1/envs/production/keys" -H "apikey: $PAWABASE_SECRET_KEY" -H "content-type: application/json" \
  -d '{"name": "reporting-service", "role": "secret", "scopes": ["resource:read"], "allowed_ips": ["203.0.113.0/24"], "allowed_routes": []}'
```
</CodeGroup>

A key with only `resource:read` cannot change data even through bugs, and an IP restriction makes a leaked key useless elsewhere.
Build keys for services this way, with the least they need.

Rotation with a grace period lets deployed services switch to the new key without downtime.
Rotate, deploy with the new key, and let the old one expire.

### Secrets

`m.secrets` manages the secrets flows read.
Values are written but never returned.

| Method | Purpose |
| --- | --- |
| `list()` | Names, descriptions and rotation reminders |
| `set(name, value, { description, rotateEveryDays })` | Create or replace |
| `update(name, { description, rotateEveryDays })` | Change the description or reminder; `0` clears the reminder |
| `rotate(name, value?)` | Replace the value, keeping the previous one for `rollback` |
| `rollback(name)` | Put back the value a rotation replaced |
| `remove(name)` | Delete |

<CodeGroup>
```typescript TypeScript
await m.secrets.rotate("PAYSTACK_SECRET", newValue);
// a flow starts failing with the new value?
await m.secrets.rollback("PAYSTACK_SECRET");
```

```python Python
m.secrets.rotate("PAYSTACK_SECRET", new_value)
# a flow starts failing with the new value?
m.secrets.rollback("PAYSTACK_SECRET")
```

```bash cURL
curl -X POST "$PAWABASE_URL/platform/v1/envs/production/secrets/PAYSTACK_SECRET/rotate" -H "apikey: $PAWABASE_SECRET_KEY" -H "content-type: application/json" -d '{"value": "sk_live_new…"}'
curl -X POST "$PAWABASE_URL/platform/v1/envs/production/secrets/PAYSTACK_SECRET/rollback" -H "apikey: $PAWABASE_SECRET_KEY"
```
</CodeGroup>

Setting secrets from CI keeps them out of Studio forms and out of people's clipboards.
Secrets are per environment; set each environment's own values.

### Firewall

`m.firewall` manages the gateway's firewall: ordered rules, managed signatures, bans, and what the firewall did.

| Method | Purpose |
| --- | --- |
| `rules()` | Rules in the order they are tried |
| `addRule(rule)` | Add a rule at the end |
| `updateRule(ruleId, changes)` | Change fields, using the server's field names |
| `removeRule(ruleId)` | Remove one |
| `order(ruleIds)` | Set the order; every rule exactly once |
| `config()`, `setConfig({ managed, autoBan })` | Managed rule sets and automatic bans |
| `bans({ includeExpired })`, `ban(ip, { seconds, reason })`, `liftBan(banId)` | Bans by address or range |
| `events({ action, source, ip, path, ruleId, limit })` | What the firewall did |
| `stats({ hours })` | Totals, a timeline, top addresses, paths, rules and countries |
| `test(ip, { path, method, userAgent, query, headers, country, role })` | What the firewall would do with a request, without sending it |

A rule has an `action` (`allow`, `block`, `log` or `rate_limit`), conditions on request fields, and a mode: `enforce`, or `simulate`, which only records what it would have done.

<CodeGroup>
```typescript TypeScript
await m.firewall.addRule({
  name: "Slow down token guessing",
  action: "rate_limit",
  conditions: [{ field: "path", op: "starts_with", value: "/auth/v1/token" }],
  rateLimit: { requests: 10, window_seconds: 60, by: "ip", ban_seconds: 900 },
  mode: "simulate",
});
```

```python Python
m.firewall.add_rule(
    name="Slow down token guessing",
    action="rate_limit",
    conditions=[{"field": "path", "op": "starts_with", "value": "/auth/v1/token"}],
    rate_limit={"requests": 10, "window_seconds": 60, "by": "ip", "ban_seconds": 900},
    mode="simulate",
)
```

```bash cURL
curl -X POST "$PAWABASE_URL/platform/v1/envs/production/firewall" -H "apikey: $PAWABASE_SECRET_KEY" -H "content-type: application/json" -d '{
  "name": "Slow down token guessing", "action": "rate_limit", "logic": "all", "match": {}, "mode": "simulate",
  "conditions": [{"field": "path", "op": "starts_with", "value": "/auth/v1/token"}],
  "rate_limit": {"requests": 10, "window_seconds": 60, "by": "ip", "ban_seconds": 900}, "enabled": true, "note": ""
}'
```
</CodeGroup>

Start new rules in `simulate`, read `events` for a day, then switch to `enforce`.
`test` answers "would this request be blocked?" before you find out from a customer.

Condition fields include `ip`, `country`, `method`, `path`, `host`, `query`, `header:<name>`, `query:<name>`, `user_agent`, `origin`, `referer`, `role`, `key_id` and `content_length`.
Managed rule sets cover `sqli`, `xss`, `traversal`, `scanners`, `sensitive_files`, `no_user_agent` and `methods`, each `off`, `log` or `block`.


## Observation

### Observability

`m.observability` reads the environment's traffic, logs and performance.

| Method | Returns |
| --- | --- |
| `overview({ range })` | The environment at a glance: traffic, errors, latency, workers, storage |
| `analytics({ range, from, to })` | Traffic over a range such as `1h`, `24h` or `7d` |
| `requests({ status, method, search, requestId, limit })` | Recent requests; `status` may be a class such as `5xx` |
| `request(requestId)` | One request: logs, database calls, spans, traceback |
| `logs({ q, minutes, limit, after })` | Application and access logs |
| `errors({ minutes })` | Recent errors |
| `routes({ minutes, limit, sort })`, `route(method, route, { minutes })` | Per-route traffic, latency and errors |
| `system({ minutes })` | CPU, memory and connections |
| `advisor({ minutes })` | Findings: slow routes, missing indexes, noisy errors |
| `metrics`, `metricCatalog`, `metricSeries` | Counters and series to chart or alarm on |
| `workers()`, `configuration()`, `capacity()` | What the environment runs with |

`request(requestId)` is the programmatic form of searching **Project → Activity**: given the `requestId` from a client error, it returns everything the platform recorded about that request.
Support tooling can fetch it directly when a customer quotes a reference.

<CodeGroup>
```typescript TypeScript
const detail = await m.observability.request(error.requestId!);
```

```python Python
detail = m.observability.request(error.request_id)
```

```bash cURL
curl "$PAWABASE_URL/platform/v1/envs/production/requests/$REQUEST_ID" -H "apikey: $PAWABASE_SECRET_KEY"
```
</CodeGroup>

`advisor()` is worth running before a release; it reports routes that are slow and fields that are filtered without an index.

### Alarms

`m.alarms` manages alarms on metrics: when a metric crosses a threshold for a number of checks, recipients are mailed.

| Method | Purpose |
| --- | --- |
| `list()`, `create(alarm)`, `update(id, changes)`, `remove(id)` | Alarm definitions |
| `check(id)` | Evaluate now |
| `test(id)` | Send the notification now |
| `history(id?)` | When alarms fired and recovered |

```typescript
const catalog = await m.observability.metricCatalog();
console.log(catalog); // the metric names this installation can alarm on

await m.alarms.create({
  name: "Server errors",
  metric: serverErrorMetric, // a name taken from the catalog
  threshold: 10,
  comparison: "gt",
  windowMinutes: 5,
  breachesNeeded: 2,
  recipients: ["oncall@example.com"],
});

declare const serverErrorMetric: string;
```

Metric names differ between installations and versions, so take them from `m.observability.metricCatalog()` rather than writing them from memory.
`update(id, { mute_minutes: 60 })` silences an alarm for an hour during planned work.

### Status page

`m.statusPage` manages the environment's public status page and its incidents.

| Method | Purpose |
| --- | --- |
| `page()`, `configure({ enabled, title, description, contactUrl, components })` | The page and its components |
| `incidents()`, `openIncident(title, …)`, `updateIncident(id, message, { status, impact })`, `removeIncident(id)` | Incidents and their updates |

Components can be measured automatically from the platform's services (`gateway`, `api`, `auth`, `realtime`, `workers`) or set by hand (`manual`).
Incident status moves through `investigating`, `identified`, `monitoring` and `resolved`; impact is `none`, `minor`, `major` or `critical`.

### Health

`m.health` reports service health, plan usage and the platform's audit trail.

| Method | Returns |
| --- | --- |
| `services()` | Each service with its state, latency and error rate |
| `usage()` | Each plan limit and how much is used |
| `retryPolicies()` | How background work is retried |
| `audit({ action, actor, target, since, until, env })` | Management changes: who did what, to what, when |
| `exportAudit({ format, … })` | The audit trail as `jsonl` or `csv` text |

The audit trail records changes made through Studio and through this module alike.
Exporting it on a schedule into your own storage keeps a record beyond the platform's retention.
