### Environments

`m.environments` manages the project's environments, previews, promotion and blueprints.
Most of its calls are about the project, not only the client's environment.

| Method | Purpose |
| --- | --- |
| `list()`, `getOne(name?)` | Environments |
| `create(name, { copyFrom })` | A new environment, optionally with another's definitions |
| `update(name, { infra, auth, settings, isDefault })` | Change infrastructure, sign-in settings or settings; each is merged |
| `deleteEnvironment(name)` | Delete one |
| `createPreview(ref, { name, expiresInHours, infra, auth, settings })` | A short-lived copy for a branch or pull request; it expires by itself |
| `deletePreview(preview)` | Delete a preview |
| `promote(to, { include })` | Copy this environment's definitions to another; never secrets or keys |
| `blueprint()` | Export definitions, roles and settings as a document |
| `applyBlueprint(blueprint, environments)` | Build new environments from a blueprint |
| `reloadCode()` | Re-read mounted code now |

Promotion is how definitions move from development to production:

<CodeGroup>
```typescript TypeScript
const development = manage(service, "development");
await development.environments.promote("staging");
// after testing staging:
await development.withEnvironment("staging").environments.promote("production", { include: ["resources", "policies", "flows"] });
```

```python Python
development = service.manage.environment("development")
development.environments.promote("staging")
# after testing staging:
service.manage.environment("staging").environments.promote("production", include=["resources", "policies", "flows"])
```

```bash cURL
curl -X POST "$PAWABASE_URL/platform/v1/envs/development/promote" -H "apikey: $PAWABASE_SECRET_KEY" \
  -H "content-type: application/json" -d '{"to": "staging"}'
```
</CodeGroup>

`include` limits promotion to kinds of definition, which is useful when one part is ready and another is not.
Secrets and keys are never promoted; each environment keeps its own.

A blueprint is a portable copy of a project's design.
Applying it creates new environments from it, which suits creating an identical project for a new customer or region.

### Releases, branches and API versions

`m.releases` manages definition branches, immutable revisions, API versions and releases.

| Method | Purpose |
| --- | --- |
| `branches()`, `createBranch(name, { fromBranch, fromRevision, protected })` | Branches of the definitions |
| `draft(branch)` | A branch's definitions as they stand |
| `merge(branch, { target, force })` | Merge a branch, into `main` by default |
| `revisions()`, `revision(id)`, `commit(branch, message)` | Immutable snapshots of a branch |
| `apiVersions()`, `createApiVersion(name, { isDefault })`, `updateApiVersion(name, changes)`, `rollbackApiVersion(name)` | Stable public API versions such as `v2` |
| `releases()`, `release(revisionId, apiVersion, name, { notes, allowBreaking })`, `activate(releaseId)` | Make a revision the live definitions of an API version |
| `deployments()` | What was deployed when |

The workflow for a reviewed change: create a branch, change definitions on it with the `branch` option of the definition services, commit a revision, then merge or release it.

<CodeGroup>
```typescript TypeScript
const m = manage(service, "development");
await m.releases.createBranch("add-tickets");
await m.resources.create(ticketsDefinition, { branch: "add-tickets" });
await m.policies.create(ticketPolicy, { branch: "add-tickets" });
const revision = await m.releases.commit("add-tickets", "Add tickets resource");
await m.releases.merge("add-tickets");
```

```python Python
m = service.manage.environment("development")
m.releases.create_branch("add-tickets")
m.resources.create(tickets_definition, branch="add-tickets")
m.policies.create(ticket_policy, branch="add-tickets")
revision = m.releases.commit("add-tickets", "Add tickets resource")
m.releases.merge("add-tickets")
```

```bash cURL
curl -X POST "$PAWABASE_URL/platform/v1/envs/development/branches" -H "apikey: $PAWABASE_SECRET_KEY" \
  -H "content-type: application/json" -d '{"name": "add-tickets", "protected": false}'
curl -X POST "$PAWABASE_URL/platform/v1/envs/development/resources?branch=add-tickets" -H "apikey: $PAWABASE_SECRET_KEY" \
  -H "content-type: application/json" -d @tickets.json
```
</CodeGroup>

API versions let you change the API while clients that depend on the old contract keep working.
A release pins a revision to a version such as `v2`, served at `/rest/v2`, and refuses breaking changes unless `allowBreaking` is set.
See [Releases and API versions](/studio/environments-and-promotion).

### Backups

`m.backups` downloads backups, schedules snapshots and restores them.

| Method | Purpose |
| --- | --- |
| `download({ include, data, maxRows })` | A backup document: definitions, settings, users, and with `data`, rows |
| `restore(backup, { include, strategy, dryRun, confirm })` | Put a downloaded backup back |
| `setSchedule({ enabled, frequency, hour, weekday, keepLast, keepDays, include })` | Automatic snapshots |
| `snapshots()`, `snapshot(name, { note, include })` | List and take snapshots |
| `updateSnapshot(id, { name, note, pinned })`, `removeSnapshot(id)` | Rename, annotate, pin, delete |
| `downloadSnapshot(id)`, `verifySnapshot(id)` | Download, and check integrity |
| `restoreSnapshot(id, { include, strategy, dryRun, confirm, safetySnapshot })` | Restore; a snapshot of the current state is taken first unless `safetySnapshot` is `false` |

| Restore strategy | Effect | Safety |
| --- | --- | --- |
| `merge` (default) | Adds and updates what the backup holds | Leaves other data in place |
| `replace` | Removes what the chosen parts hold, then restores | Requires `confirm` set to the environment's name |

<CodeGroup>
```typescript TypeScript
const before = await m.backups.snapshot("before-pricing-change", { note: "Taken by the release script" });
await m.backups.updateSnapshot(before.id, { pinned: true });
```

```python Python
before = m.backups.snapshot("before-pricing-change", note="Taken by the release script")
m.backups.update_snapshot(before["id"], pinned=True)
```

```bash cURL
curl -X POST "$PAWABASE_URL/platform/v1/envs/production/snapshots" -H "apikey: $PAWABASE_SECRET_KEY" -H "content-type: application/json" -d '{"name": "before-pricing-change", "note": "Taken by the release script"}'
```
</CodeGroup>

Take a pinned snapshot before risky changes; pinned snapshots survive pruning.
Practise restores on a test environment, with `dryRun` first, so the steps are familiar before they are needed.
