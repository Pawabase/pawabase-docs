`pawabase.realtime` connects your application to the environment's realtime service.
Through it, clients exchange messages on named channels, see who else is present, catch up on recent messages, and receive live changes to resources.

This page explains the connection and the channel model, how channel rules decide what each person may do, every method of the client's realtime module, how the connection survives network drops and token changes, and the limits that apply.

## The mental model

Realtime has three layers, and each answers a different question.

| Layer | What it is | Question it answers |
| --- | --- | --- |
| Connection | One WebSocket from a client to the gateway | Is this client connected, and as whom? |
| Channel | A named topic, such as `chat:lobby` or `resource:orders` | Which messages does this client receive? |
| Rule | A pattern with policies, configured per environment | Who may join, send and be present on which channels? |

A client opens **one** connection and joins any number of channels over it.
Channels are not created in advance: a channel exists while someone is on it.
What a client may do on a channel is decided by the first rule whose pattern matches the channel's name, or by the environment's default policy when none matches.

```text
client ── one WebSocket ──▶ gateway ──▶ realtime service
            │                                │
            ├─ subscribe "chat:lobby"   ──▶  rule "chat:*": subscribe = authenticated ✓
            ├─ subscribe "user:u_7"     ──▶  rule "user:{{ auth.user_id }}": only u_7 ✓
            ├─ subscribe "resource:orders" ─▶ each change checked against orders' read policy
            └─ publish "chat:lobby"     ──▶  rule "chat:*": publish = authenticated ✓
```

Realtime is for things connected clients should see now.
It is not a queue: a client that is not connected does not receive messages sent meanwhile, except what it can fetch from a channel's recent history.
Work that must happen whether or not anyone is connected belongs in events and flows.


## Where realtime is configured

Realtime is configured per environment in Studio under **Services → Realtime**.

| Section | What it holds |
| --- | --- |
| Channel rules | Each rule's **Pattern**, **Kind**, **Subscribe** and **Publish** policies, **Presence** switch and **History** length |
| Connections | The connections open now, with their user and channels |
| Active channels | Channels with subscribers now, with **Subscribers**, **Present** and **Delivered** counts |

A channel rule has these fields:

| Field | Default | Meaning |
| --- | --- | --- |
| `pattern` | required | The channel names the rule governs: a fixed name, a `*` wildcard, or a template such as `user:{{ auth.user_id }}` |
| `subscribe` | `authenticated` | The policy for joining a matching channel |
| `publish` | `authenticated` | The policy for sending to a matching channel |
| `presence` | on | Whether members can share presence on matching channels |
| `history` | `50` | How many recent messages are kept per channel, up to 1000 |
| `kind` | `public` | A label; `durable` also keeps messages across restarts, for a retention period |

Rules are tried in order, and the first whose pattern matches wins.
A channel no rule matches uses the environment's default policy, which is `authenticated` unless changed.

Whether a resource publishes its changes is not a channel rule.
It is the resource's own **realtime** setting, under **Data**.


## Connecting

You rarely connect yourself.
The first `subscribe()` opens the connection, and the client keeps it open while channels need it.

<CodeGroup>
```typescript TypeScript
const room = pawabase.realtime.channel("chat:lobby");
await room.subscribe();
```

```python Python
# Live channels need AsyncPawabase and pip install "pawabase[realtime]"
room = apb.realtime.channel("chat:lobby")
await room.subscribe()
```

```text WebSocket
# A live channel is a WebSocket, for example with websocat:
websocat "wss://api.example.com/realtime/v1/socket?apikey=$PAWABASE_KEY&token=$TOKEN&environment=production"
{"type": "subscribe", "channel": "chat:lobby", "ref": "1"}
# ← {"type": "ack", "ref": "1", "ok": true}
```
</CodeGroup>

`connect()` opens it explicitly and resolves once the server has welcomed the connection.
`disconnect()` closes it and stops reconnecting.

<CodeGroup>
```typescript TypeScript
await pawabase.realtime.connect();
console.log(pawabase.realtime.connectionId);
pawabase.realtime.disconnect();
```

```python Python
await apb.realtime.connect()
print(apb.realtime.connection_id)
await apb.realtime.close()
```

```text WebSocket
# A live channel is a WebSocket, for example with websocat:
websocat "wss://api.example.com/realtime/v1/socket?apikey=$PAWABASE_KEY&token=$TOKEN&environment=production"
# ← {"type": "welcome", "connection_id": "…"}
```
</CodeGroup>

The connection is a WebSocket to `/realtime/v1/socket` on the gateway, with the API key, the person's access token when signed in, and the environment name in the URL.
The gateway checks the key before the realtime service sees the connection.

### The runtime's WebSocket

Browsers, Deno, Bun and Node 22 and later have a global `WebSocket`, which the client uses.
On Node 20, pass an implementation, such as the `ws` package:

```typescript
import WebSocket from "ws";
import { createClient, type WebSocketConstructor } from "@pawabase/client";

const pawabase = createClient({
  url,
  apiKey,
  environment: "production",
  realtime: { webSocket: WebSocket as unknown as WebSocketConstructor },
});
```

Without one, `connect()` and `subscribe()` throw `ConfigError` with a message saying so.

### Connection status

`realtime.status` is one of five values, and `onStatusChange` reports every change.

| Status | Meaning |
| --- | --- |
| `idle` | No connection has been opened yet |
| `connecting` | Opening for the first time |
| `open` | Connected and welcomed; channels can be joined |
| `reconnecting` | The connection dropped and the client is trying again |
| `closed` | Closed by `disconnect()`, or by the server for a reason reconnecting would not fix |

```typescript
const stop = pawabase.realtime.onStatusChange((status) => {
  banner.hidden = status === "open" || status === "idle";
  banner.textContent = status === "reconnecting" ? "Reconnecting…" : "Offline";
});
```

Show `reconnecting` in your interface.
People forgive a short gap; they do not forgive a screen that silently stopped updating.
