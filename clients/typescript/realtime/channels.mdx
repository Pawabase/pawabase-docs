`realtime.channel(name, options)` returns the channel object for a name.
Asking for the same name again returns the same object, so every part of your app that listens to a channel shares one subscription.

<CodeGroup>
```typescript TypeScript
const room = pawabase.realtime.channel<{ text: string }, { name: string }>("chat:lobby", {
  presence: { name: "Ada" },
  replay: 50,
});
```

```python Python
room = apb.realtime.channel("chat:lobby", presence={"name": "Ada"}, replay=50)
```
</CodeGroup>

| Option | Meaning |
| --- | --- |
| `presence` | Your presence data, shown to others on the channel while you are subscribed |
| `replay` | After a reconnect, fetch up to this many recent messages and deliver the ones you missed |

The two type parameters describe the message payload and the presence data.
They are promises to the compiler; the server does not check payload shapes.

### Channel names

Channel names are short strings of letters, digits and a few separators.
The server accepts names that start with a letter or digit, followed by letters, digits and `: _ . @ = + -`, up to 200 characters.
Event names allow letters, digits and `: _ . -`, up to 100 characters.

| Name | Valid |
| --- | --- |
| `chat:lobby` | Yes |
| `org:acme:announcements` | Yes |
| `user:u_7` | Yes |
| `doc=42.cursor` | Yes |
| `chat/lobby` | No: `/` is not allowed |
| `:lobby` | No: must start with a letter or digit |
| `chat lobby` | No: spaces are not allowed |

A colon is the conventional separator, and rules match on it naturally: `chat:*` governs every chat room.

### Subscribing

`subscribe()` joins the channel, connecting first if needed.
It resolves with the channel once the server has accepted, and it is safe to call twice.

<CodeGroup>
```typescript TypeScript
try {
  await room.subscribe();
} catch (error) {
  if (error instanceof RealtimeError && error.code === "forbidden") showMessage("You cannot join this room.");
  else throw error;
}
```

```python Python
from pawabase import RealtimeError

try:
    await room.subscribe()
except RealtimeError as error:
    if error.code == "forbidden":
        show_message("You cannot join this room.")
    else:
        raise
```

```text WebSocket
{"type": "subscribe", "channel": "chat:staff", "ref": "2"}
# ← {"type": "ack", "ref": "2", "ok": false, "error": "forbidden", "reason": "…"}
```
</CodeGroup>

The server checks the channel's subscribe policy against the connection's identity.
A refusal rejects with `RealtimeError` whose `code` is `forbidden`, and the channel also emits an `error` event.

`room.subscribed` is `true` while the channel is joined on an open connection.

### Receiving messages

`on(event, handler)` listens for one of five channel events, and returns a function that stops listening.

| Event | Handler receives | When |
| --- | --- | --- |
| `message` | A `ChannelMessage` | A message arrived on the channel |
| `presence` | `{ joins, leaves, members }` | Someone joined or left, or presence data changed |
| `subscribed` | nothing | The channel was joined, including after a reconnect |
| `closed` | `{ reason }` | The channel stopped receiving: unsubscribed, or the connection was lost |
| `error` | A `RealtimeError` | The server refused a request on this channel |

<CodeGroup>
```typescript TypeScript
const stopMessages = room.on("message", (message) => {
  appendToChat(message.from, message.payload.text, message.sent_at);
});

const stopTyping = room.onEvent("typing", (message) => showTyping(message.from));
```

```python Python
room.on(None, lambda message: append_to_chat(message["from"], message["payload"]["text"], message["sent_at"]))
room.on("typing", lambda message: show_typing(message["from"]))
# In Python, on(event, handler) filters by the message's event name; None receives every message.
```
</CodeGroup>

`onEvent(name, handler)` is a shortcut that listens only for messages with one event name.

A message has these fields:

| Field | Meaning |
| --- | --- |
| `id` | The message's id, unique on the channel |
| `channel` | The channel name |
| `event` | The event name the sender chose, such as `message` or `typing` |
| `payload` | The data the sender sent |
| `from` | The sender's user id, `"server"` for messages published by the platform or with a secret key, or `null` for an anonymous sender |
| `sent_at` | When the server accepted the message |
| `seq` | A sequence number, present on messages read from history |

Handlers that throw do not break delivery to other handlers.

### Iterating messages

A channel is also an async iterator, which suits code that processes messages in order:

<CodeGroup>
```typescript TypeScript
for await (const message of room) {
  await handle(message);
}
```

```python Python
async for message in room:      # subscribes on first use
    await handle(message)
```
</CodeGroup>

The loop ends when the channel is unsubscribed.
Breaking out of the loop unsubscribes the channel.
Messages that arrive while your loop is busy wait in a queue of up to 1000; beyond that, the oldest are dropped.

### Sending messages

`send(event, payload)` publishes a message on the channel over the socket.
It resolves with the message id once the server has accepted it.

<CodeGroup>
```typescript TypeScript
const { id } = await room.send("message", { text: "Hello" });
```

```python Python
sent = await room.send("message", {"text": "Hello"})
message_id = sent["id"]
```

```text WebSocket
{"type": "publish", "channel": "chat:lobby", "event": "message", "payload": {"text": "Hello"}, "ref": "3"}
# ← {"type": "ack", "ref": "3", "ok": true, "id": "…"}
```
</CodeGroup>

The server checks the channel's publish policy.
A refusal rejects with `RealtimeError` code `forbidden`.
A payload larger than the limit, 64 KiB by default, rejects with `payload_too_large`.

The sender receives its own message on the channel too, like every other subscriber.
Use the returned id to recognize it, for example to replace an optimistic copy.

An environment can turn off publishing from clients altogether, so that only servers publish.
Then every client `send` is refused, and messages come from flows or servers instead.

### Leaving

`unsubscribe()` leaves the channel, clears its presence, ends any iterators, and forgets the channel object.

```typescript
await room.unsubscribe();
```

Unsubscribe when a screen that uses a channel unmounts.
Channels that stay joined keep receiving and keep counting against the connection's limit.


## Channel rules in practice

Rules turn channel names into permissions.
A few patterns cover most applications.

| Pattern | Subscribe | Publish | Use |
| --- | --- | --- | --- |
| `announcements` | `public` | `{ "service": true }` | Messages from servers to everyone, including signed-out visitors |
| `chat:*` | `authenticated` | `authenticated` | Rooms any signed-in person may join |
| `user:{{ auth.user_id }}` | `authenticated` | `{ "service": true }` | A private channel per person, for notifications |
| `org:{{ auth.org }}:*` | `authenticated` | `authenticated` | Channels shared within the caller's current organization |
| `doc:*` | A named policy that checks membership | The same | Collaboration on records with their own sharing |

Templates deserve a closer look.
The pattern `user:{{ auth.user_id }}` governs every channel that starts with `user:`, but permits a caller only the one that matches their own id.
A person who asks for `user:u_8` while signed in as `u_7` is refused by this rule, rather than falling through to a looser default.
A signed-out caller is refused too, because the template cannot be filled.

Policies on channels see the channel's name, its segments, the action, and for publishes the payload:

| Variable | Meaning |
| --- | --- |
| `$channel.name` | The channel, such as `org:acme:general` |
| `$channel.segments` | The name split on `:` and `/`, such as `["org", "acme", "general"]` |
| `$channel.action` | `subscribe`, `publish` or `presence` |
| `$input` | For a publish, the message payload |

```json
{
  "all": [
    { "truthy": "$auth.org" },
    { "eq": ["$channel.segments.1", "$auth.org"] }
  ]
}
```

That condition admits a caller to `org:<slug>:…` channels only for the organization in their token.

### Rules change while people are connected

When an environment's rules change, the server re-checks every open subscription in that environment.
A subscription the new rules no longer allow is closed by the server, which sends a `channel_closed` frame naming the channel and the reason.

The TypeScript client does not yet handle `channel_closed` as a channel event.
It reports the frame through the `onProtocolError` option, as `an unknown frame arrived: channel_closed`, and the channel object still believes it is subscribed.
If your application changes rules while people are connected, pass `onProtocolError` and resubscribe or tear down the affected screens when it reports `channel_closed`.
