Management operations are available on `Pawabase` and `AsyncPawabase` when using a secret key (`pb_sk_...`). They target paths under `/platform/v1/projects/{project}/envs/{environment}/...`. These operations are for trusted servers, scripts, and CI only. Never use secret keys in browsers.

## The mental model

Management methods use `self._manage(suffix)` to build platform paths. Many are reads with `retry=True`. Mutations like `deploy_functions()` are not retried. Some operations return deployment/run information.

## Functions

| Method | HTTP | Path | Notes |
| --- | --- | --- | --- |
| `functions(branch=None)` | `GET` | `/platform/v1/projects/{p}/envs/{e}/functions` | List functions. Retry. |
| `deploy_functions(archive, branch="main", manifest=None, runtime="python3.11", limits=None)` | `POST` | `/platform/v1/projects/{p}/envs/{e}/function-deployments` | Upload base64 tar.gz. Not retried. |
| `deployments(branch=None, limit=50)` | `GET` | `/platform/v1/projects/{p}/envs/{e}/function-deployments` | List deployments. Retry. |
| `deployment(deployment_id)` | `GET` | `/platform/v1/projects/{p}/envs/{e}/function-deployments/{id}` | Get deployment. Retry. |
| `activate_deployment(deployment_id)` | `POST` | `/platform/v1/projects/{p}/envs/{e}/function-deployments/{id}/activate` | Activate/rollback. |
| `remove_deployment(deployment_id)` | `DELETE` | `/platform/v1/projects/{p}/envs/{e}/function-deployments/{id}` | Remove deployment. |
| `function_branches()` | `GET` | `/platform/v1/projects/{p}/envs/{e}/function-branches` | List branches. Retry. |
| `remove_function_branch(branch)` | `DELETE` | `/platform/v1/projects/{p}/envs/{e}/function-branches/{branch}` | Delete branch functions. |
| `function_runs(function=None, branch=None, status=None, after=None, limit=50)` | `GET` | `/platform/v1/projects/{p}/envs/{e}/function-runs` | List runs. Retry. `function_logs` is alias. |
| `function_run(run_id)` | `GET` | `/platform/v1/projects/{p}/envs/{e}/function-runs/{run_id}` | Get run. Retry. |
| `run_function(name, input=None, branch=None, as_user=None)` | `POST` | `/platform/v1/projects/{p}/envs/{e}/functions/{name}/invoke` | Run as operator. Returns `{"status", "result" \| "error"}`. |

### deploy_functions
```python
import base64

with open("bundle.tar.gz", "rb") as f:
    archive = base64.b64encode(f.read()).decode()

res = pb.deploy_functions(archive, branch="main", manifest={"entry": "handler"}, runtime="python3.11")
```

| `emit_event(name, payload=None)` | `POST` | `/platform/v1/projects/{p}/envs/{e}/events` | Publish event. |

| `branches()` | `GET` | `/platform/v1/projects/{p}/envs/{e}/branches` | List branches. Retry. |

## Runtime

| Method | HTTP | Path | Notes |
| --- | --- | --- | --- |
| `runtime_call(method, args=None, kwargs=None, as_user=None, branch=None)` | `POST` | `/platform/v1/projects/{p}/envs/{e}/runtime/call` | Call ctx.runtime method. Needs `runtime:use` scope. |
| `identify(token)` | `POST` | `/platform/v1/projects/{p}/envs/{e}/runtime/identify` | Identify user from token. |
| `runtime_db(op, **fields)` | `POST` | `/platform/v1/projects/{p}/envs/{e}/runtime/db` | Runtime DB operations. |

## Example

```python
from pawabase import Pawabase

with Pawabase(url, "pb_sk_...", project="acme", environment="production") as pb:
    fns = pb.functions()
    res = pb.run_function("process-job", {"job_id": "j1"})
    pb.emit_event("job.completed", {"job_id": "j1"})
    runs = pb.function_runs(function="process-job", limit=10)
```

## Notes

- Use secret keys only on trusted servers
- Some operations not retried (deploy_functions)
- `run_function()` returns `{"status", "result"|"error"}`
- Branch parameters filter to specific branches where applicable


## Deep dive: deploy_functions

```python
import base64
import tarfile
import io

# Create bundle
buf = io.BytesIO()
with tarfile.open(fileobj=buf, mode='w:gz') as tar:
    tar.add('handler.py')
    tar.add('requirements.txt')

archive = base64.b64encode(buf.getvalue()).decode()

result = pb.deploy_functions(
    archive,
    branch="main",
    manifest={"entry": "handler:main", "runtime": "python3.11"},
    runtime="python3.11",
    limits={"memory": "256Mi", "timeout": 60}
)
```

The method is not retried. It uploads a base64-encoded tar.gz bundle.

## Deep dive: run_function

```python
# Run as operator
result = pb.run_function("send-email", {"to": "user@example.com", "subject": "Hi"})
# {"status": "completed", "result": {"sent": true}}

# Run with user impersonation
result = pb.run_function("create-post", {"title": "Hello"}, as_user={"id": "user_123"})

# Run on specific branch
result = pb.run_function("process-job", {"job_id": "j1"}, branch="feature-x")
```

## Deep dive: runtime_call

```python
result = pb.runtime_call("send_email", args=["user@example.com"], kwargs={"subject": "Hi"})
result = pb.runtime_call("get_user", kwargs={"id": "u123"}, as_user={"id": "admin"})
```

Calls methods on `ctx.runtime`. Values are in codec form as per the gateway. Requires `runtime:use` scope.

## Security notes

- All management operations require secret keys
- Never use secret keys in client-side code
- Use environment variables
- Limit key scopes
- Audit management operations
- Use `as_user()` carefully with `run_function` and `run_flow`

## Deep dive: Management API

The management API is under `pb.management` and provides administrative operations for projects, environments, resources, policies, routes, flows, etc. These operations typically require management/administrative credentials.

### Accessing management endpoints

```python
# Management operations
result = pb.management.projects.list()
```

The exact method names depend on the API structure. The management namespace gives access to platform management operations.

### Project and environment management

Management operations can create/update projects, environments, deploy configurations, manage keys, etc. These are typically used by CI/CD systems or admin tools.

### Resource management

You can programmatically manage resources, fields, relations, operations, and policies through the management API.

### Route and flow management

Manage routes, flows, subscriptions, schedules, and other delivery mechanisms.

### Security considerations

- **Never use management keys in client apps** - Management credentials have elevated privileges
- **Rotate keys regularly** - Especially for automation
- **Audit usage** - Track management operations
- **Least privilege** - Use service accounts with minimal needed permissions

### Common patterns

```python
pb = Pawabase(url, management_key, project=project)
# Management operations
```

Management endpoints are under `/platform/v1/...` as noted in the overview.
