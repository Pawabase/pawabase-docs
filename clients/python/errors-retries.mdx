## PawabaseError

```python
from pawabase import PawabaseError
```

### Attributes
| Attribute | Type | Meaning |
| --- | --- | --- |
| `status_code` | `int` | HTTP status code, or `0` if gateway could not be reached. |
| `detail` | `Any` | Parsed JSON body or raw text from response. |
| `code` | `str \| None` | `detail["error"]` if `detail` is a dict and it's a string. |
| `message` | `str` | Extracted message from detail. |
| `problems()` | `list[str]` | Returns problems list from `problems` in body or `detail.detail.problems`. |

`__init__(status_code, detail)` sets attributes and calls `super().__init__(f"Pawabase API returned {status_code}: {self.message}")`. `__str__` returns the exception message.

### Error parsing

`_failure(response)` does:
```python
try:
    detail = response.json()
except ValueError:
    detail = response.text
return PawabaseError(response.status_code, detail)
```

`_message(detail)` extracts messages from various shapes:
- If dict: checks `detail.get("detail", detail.get("message", detail.get("error")))`. If inner is dict, returns `inner.get("message") or str(inner)`. If inner is list, joins list items. Else returns string representation.
- If list: joins
- Else returns string

## Retry policy

### Constants
- `RETRIED_STATUSES = frozenset({502, 503, 504})`
- `MAX_RATE_WAITS = 8`
- `MAX_RATE_WAIT_SECONDS = 20.0`

### Behavior

**Transport errors** (`httpx.TransportError`):
- Caught, converted to `PawabaseError(0, f"Could not reach {self.url}: {error}")`
- Stored as `last`
- Sleep: `min(0.25 * 2**attempt, 2.0)` seconds
- Increment attempt, retry if attempts remain
- After exhaustion, raise `last`

**429 Rate Limited**:
- If `response.status_code == 429 and waits < MAX_RATE_WAITS`:
  - `waits += 1`
  - Sleep `rate_wait(response)`
  - `continue` loop (retry same request)
- `rate_wait(response)`:
  - Check `response.headers.get("retry-after")`
  - If None, try `response.json().get("retry_after")`
  - Convert to float, `min(max(float, 1.0), 20.0)`
  - If parse fails, return `1.0`

**502/503/504**:
- If status in `RETRIED_STATUSES` and `retry=True` and `attempt + 1 < attempts`:
  - Store `_failure(response)` as `last`
  - Sleep exponential backoff
  - Increment attempt, retry
- Else fall through to `_body()` which raises `_failure(response)`

**Other errors**: `_body()` raises `_failure(response)` if `response.is_error`.

### When retry is True
- `request()` sets `retry = method.upper() in ("GET", "HEAD")`
- Many read methods set `retry=True`: `auth_settings()`, `functions()`, `deployments()`, `deployment()`, `function_branches()`, `function_runs()`, `function_run()`, `events()`, `definitions()`, `branches()`
- Mutations do not retry by default

### Attempts
Total attempts = `retries + 1`. With `retries=2`, up to 3 attempts.

## Handling errors

```python
from pawabase import Pawabase, PawabaseError

with Pawabase(url, key, project="acme") as pb:
    try:
        post = pb.get("posts", "bad_id")
    except PawabaseError as e:
        if e.status_code == 0:
            print("Network error")
        elif e.status_code == 404:
            print("Not found")
        elif e.status_code == 429:
            print("Rate limited")
        elif e.status_code == 422:
            print("Validation error:", e.problems())
        else:
            print(f"Error {e.status_code}: {e.message}")
```

## Tips

- Check `status_code == 0` for network failures
- Use `problems()` for validation and deployment errors
- Mutations are not retried; implement idempotency yourself
- `request()` only retries GET/HEAD
- Rate limit waits are capped at 20 seconds
- Max 8 rate limit waits per request


## Deep dive: PawabaseError internals

```python
class PawabaseError(RuntimeError):
    def __init__(self, status_code: int, detail: Any) -> None:
        self.status_code, self.detail = status_code, detail
        self.code = detail.get("error") if isinstance(detail, dict) and isinstance(detail.get("error"), str) else None
        self.message = _message(detail)
        super().__init__(f"Pawabase API returned {status_code}: {self.message}")
    
    @property
    def problems(self) -> list[str]:
        body = self.detail if isinstance(self.detail, dict) else {}
        for holder in (body, body.get("detail") if isinstance(body.get("detail"), dict) else {}):
            if isinstance(holder.get("problems"), list):
                return [str(p) for p in holder["problems"]]
        return []
```

The `problems()` method looks for `problems` in the top-level body or in `detail.detail`. It's used for deployment refusals and validation errors that list multiple problems.

## Deep dive: _message() parsing

```python
def _message(detail: Any) -> str:
    if isinstance(detail, dict):
        inner = detail.get("detail", detail.get("message", detail.get("error")))
        if isinstance(inner, dict):
            return str(inner.get("message") or inner)
        if isinstance(inner, list):
            return "; ".join(str(i.get("msg", i)) if isinstance(i, dict) else str(i) for i in inner)
        return str(inner) if inner is not None else str(detail)
    return str(detail)
```

This handles various error response shapes from different parts of the gateway.

## Deep dive: retry logic flow

```python
def _call(self, method, path, *, json=None, params=None, retry=False):
    last = None
    waits = 0
    attempt = 0
    while attempt < self._attempts(retry):
        try:
            response = self._client.request(method, path, json=json, params=params, headers=self._extra or None)
        except httpx.TransportError as error:
            last = PawabaseError(0, f"Could not reach {self.url}: {error}")
        else:
            if response.status_code == 429 and waits < MAX_RATE_WAITS:
                waits += 1
                time.sleep(rate_wait(response))
                continue
            if response.status_code in RETRIED_STATUSES and retry and attempt + 1 < self._attempts(retry):
                last = _failure(response)
            else:
                return self._body(response)
        time.sleep(min(0.25 * 2**attempt, 2.0))
        attempt += 1
    assert last is not None
    raise last
```

Note: `attempts` is called as `self._attempts(retry)`. The `attempt` counter is incremented after sleep on transport errors and on retried 5xx errors. The `waits` counter is separate and only used for 429.

## Deep dive: rate_wait()

```python
def rate_wait(response: httpx.Response) -> float:
    asked = response.headers.get("retry-after")
    if asked is None:
        try:
            asked = response.json().get("retry_after")
        except (ValueError, AttributeError):
            asked = None
    try:
        return min(max(float(asked), 1.0), MAX_RATE_WAIT_SECONDS)
    except (TypeError, ValueError):
        return 1.0
```

Looks in header first, then in JSON body. Clamps to 1-20 seconds.

## Practical error handling patterns

```python
from pawabase import Pawabase, PawabaseError

pb = Pawabase(url, key, project="acme")

# Handle specific errors
try:
    post = pb.get("posts", "missing")
except PawabaseError as e:
    if e.status_code == 404:
        print("Post not found")
    elif e.status_code == 0:
        print("Network error - check connection")
    elif e.status_code >= 500:
        print("Server error")
    else:
        print(f"Error {e.status_code}: {e.message}")

# Handle deployment errors with problems
try:
    pb.deploy_functions(archive)
except PawabaseError as e:
    for p in e.problems():
        print(f"Problem: {p}")
```

## Retry behavior summary

| Scenario | Retry? | Notes |
| --- | --- | --- |
| Network error/timeout | Yes | Up to retries+1 attempts, exponential backoff |
| 429 | Yes | Up to 8 waits, uses Retry-After, separate counter |
| 502/503/504 + GET/HEAD or retry=True | Yes | Up to retries+1 attempts |
| 502/503/504 + mutation | No | Fails immediately |
| 400/401/403/404/422 | No | Client errors, not retried |
| Other errors | No | Depends on context |

## Async retry behavior

The async client uses `asyncio.sleep()` instead of `time.sleep()`. Otherwise identical logic.

```python
await asyncio.sleep(min(0.25 * 2**attempt, 2.0))
```
