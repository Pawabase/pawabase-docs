## What this SDK is

The Pawabase Python SDK (`pawabase` 0.2.0) is a thin, flat client for the Pawabase REST and management APIs. It runs on Python 3.12+ and uses `httpx` for transport. The surface is intentionally small: one client class (`Pawabase` for synchronous code, `AsyncPawabase` for async code), a per-call user context helper (`as_user()`), direct request/download helpers, and a set of exceptions.

The Python SDK is designed to mirror the mental model of the TypeScript SDK while fitting Python idioms. There is no namespaced client tree (`pb.auth`, `pb.storage`, `pb.realtime`, `pb.admin`, `pb.manage` do not exist). Resources are accessed through the client methods, management endpoints are under `pb.management` namespace, and operations compose.

## Installation

```bash
pip install pawabase
```

Or in a project using the SDK from source in the monorepo, use the environment where it is installed. The package is installed in `/Users/admin/sillo.build/pawabase/.venv/` as `pawabase` 0.2.0.

## Quick start

```python
from pawabase import Pawabase

pb = Pawabase("https://api.example.com", "pb_pk_live_your_key", project="my-project", environment="production")

# Query records
orders = pb.from_("orders")
page = orders.eq("status", "open").order("created_at", "desc").per_page(20).execute()

# Call a route/flow
result = pb.call_route("/parent/dashboard")

# Storage download
data = pb.download("student-photos", "passport.jpg")
```

For async code:

```python
from pawabase import AsyncPawabase

async def main():
    pb = AsyncPawabase("https://api.example.com", "pb_pk_live_your_key", project="my-project")
    result = await pb.from_("orders").eq("status", "open").per_page(10).execute_async()
```

## The flat API model

The Python SDK exposes a flat API where:
- Authentication context is set via `as_user(token, **headers)` which returns a shallow copy with extra headers
- Resource operations use `pb.from_("resource")` returning a query builder
- Routes/flows are invoked via `pb.call_route(path, ...)` or through flow patterns
- Management endpoints are under `pb.management.*`
- Storage operations use `pb.request()` or `pb.download()` directly
- Real-time is accessed via `pb.realtime` if present (though minimal in 0.2.0)

This matches the product model: resources live in Studio under Data, routes/flows in Routes/Flows, storage in Storage, etc. The client is a transport to those surfaces.
