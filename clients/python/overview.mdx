`pawabase` is the official Python client for Pawabase.
It gives scripts, servers, workers and notebooks the same capabilities the TypeScript client gives browsers: records, authentication, storage, flows and routes, realtime, and, with a secret key, environment management and user administration.

This page is the map of the package.
It explains what a client object represents, the difference between the blocking and the `asyncio` client, what each part is for, which key to use where, and how the Python client differs from the TypeScript one.

<Info>
This section documents the `pawabase` package, version 0.3.0, from the `feat/sdk-split` branch of the `Pawabase/pawabase-python` repository.
Every method named here exists in that source.
Where the Python client behaves differently from the TypeScript client, the page says so.
</Info>

## The mental model

A Pawabase client is an HTTP client for **one environment of one project**, reached through **one gateway**, holding **one API key** and, optionally, **one signed-in user**.

The client is not a database driver and not an ORM.
It does not connect to your database, and it does not map rows to classes.
Every call is an HTTP request to the gateway; the gateway checks the key and the services apply your policies; what comes back is plain Python data: dictionaries, lists, strings and numbers.

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";

const pawabase = createClient({ url: "https://api.example.com", apiKey: "pb_pk_…", environment: "production" });

const page = await pawabase.from("orders").eq("status", "open").order("created_at", "desc").perPage(20);
for (const order of page.data) console.log(order.id, order.total_minor);
```

```python Python
from pawabase import Pawabase

pb = Pawabase("https://api.example.com", "pb_pk_…", environment="production")

page = pb.from_("orders").eq("status", "open").order("-created_at").per_page(20).execute()
for order in page:
    print(order["id"], order["total_minor"])
```

```bash cURL
curl -G "https://api.example.com/rest/v1/orders" -H "apikey: pb_pk_…" -H "x-environment: production" \
  --data-urlencode "filter[status]=eq.open" --data-urlencode "sort=-created_at" --data-urlencode "per_page=20"
```
</CodeGroup>

What the client adds on top of `httpx` is the part that is easy to get wrong:

| Concern | What the client does |
| --- | --- |
| Credentials | Sends the key on every request, and the user's access token when someone is signed in |
| Sessions | Keeps the session in a store you choose, and renews the access token before it expires or after a `401` |
| Queries | Builds the filter, sort, select, expand and paging parameters, and refuses queries the server would answer wrongly |
| Failures | Raises one exception hierarchy for every error shape the platform produces |
| Rate limits | Waits for `Retry-After` and repeats rate-limited requests |
| Retries | Repeats reads after network failures and gateway errors |
| Realtime | Publishes and reads over HTTP from any client; keeps live channels over one WebSocket on the async client |


## Two clients, one API

The package has two client classes with the same methods.

| Class | Built on | Methods return | Use in |
| --- | --- | --- | --- |
| `Pawabase` | `httpx.Client` | Values | Scripts, Django, Flask, notebooks, synchronous workers |
| `AsyncPawabase` | `httpx.AsyncClient` | Awaitables | FastAPI, Starlette, Sillo, `asyncio` workers |

<CodeGroup>
```typescript TypeScript
// TypeScript has one client; every call returns a promise.
const page = await pawabase.from("orders").eq("status", "open").perPage(20);
```

```python Python
from pawabase import AsyncPawabase

async with AsyncPawabase("https://api.example.com", "pb_pk_…", environment="production") as pb:
    page = await pb.from_("orders").eq("status", "open").per_page(20).execute()
```
</CodeGroup>

The method names, arguments and results are identical; the async client's methods are awaited.
Code written against one translates to the other by adding or removing `await`.

One capability exists only on the async client: live realtime channels, which need a WebSocket that stays open alongside other work.
Publishing, presence and history over HTTP work on both.

## Installing

```bash
python -m pip install pawabase
```

```bash
python -m pip install "pawabase[realtime]"
```

The package needs Python 3.11 or later and depends only on `httpx`.
The `realtime` extra adds the `websockets` package, which live channels need; publishing, presence and history over HTTP work without it.

With `uv` or Poetry:

```bash
uv add pawabase
poetry add "pawabase[realtime]"
```

The package is typed and ships a `py.typed` marker, so type checkers read its annotations.


## The three things a client needs

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";

const pawabase = createClient({ url: "https://api.example.com", apiKey: "pb_pk_live_…", environment: "production" });
```

```python Python
from pawabase import Pawabase

pb = Pawabase(
    "https://api.example.com",
    "pb_pk_live_…",
    environment="production",
)
```

```bash cURL
curl "https://api.example.com/health/v1" -H "apikey: pb_pk_live_…" -H "x-environment: production"
```
</CodeGroup>

### The gateway URL

The first argument is the origin of your Pawabase gateway, the single public entry point for every service.
The client appends `/rest/v1`, `/auth/v1`, `/storage/v1`, `/realtime/v1`, `/flows/v1` and `/platform/v1` to it.
A trailing slash is removed.

Give the origin only, not a service path.
You find it in Studio under **Access → API keys**, in the **Health check** card.

### The API key

| Key | Prefix | Where it may live | What it can do |
| --- | --- | --- | --- |
| Publishable | `pb_pk_…` | Apps, command-line tools people run, servers acting for people | Acts as the anonymous role or the signed-in user; every policy applies |
| Secret | `pb_sk_…` | Servers, workers, CI | Bypasses policies; required for `pb.manage` and `pb.admin` |

A secret key is a root credential for one environment.
Keep it in your server's secret store, never in a repository or a notebook you share.
The client refuses to put a secret key in a URL, for social sign-in, and refuses share links and user administration to clients without one.

Keys are created in Studio under **Access → API keys**; the full key is shown once.
See [API keys](/studio/api-keys).

### The environment name

`environment` defaults to `"development"`.
That default is convenient on a laptop and dangerous everywhere else, because the Python client uses the name in more places than the TypeScript client does:

| Use | Effect of a wrong name |
| --- | --- |
| The `x-environment` header on every request | A mismatch with the key's environment can be refused |
| Social sign-in URLs | The provider sends people to the wrong environment |
| Public storage URLs from `public_url` and `transform_url` | URLs point at another environment's files |
| Realtime connections | The socket names the wrong environment |
| `pb.manage` and `pb.admin` | Management calls change another environment |

Always pass `environment=` explicitly outside local development, from the same configuration that provides the key.


## How a request travels

```text
your code
  │  pb.from_("orders").eq("status", "open").execute()
  ▼
pawabase (Python)
  │  GET /rest/v1/orders?filter[status]=eq.open
  │  apikey: pb_pk_…            x-environment: production
  │  Authorization: Bearer …     (when a user is signed in, or through as_user)
  │  user-agent: pawabase-python/0.3
  ▼
gateway: key, origin, firewall, rate limit       → 401 / 403 / 429
  ▼
data service: validation, then policy            → 422 / 401 / 403 / 404
  ▼
JSON → a Page(data, page, per_page, total)
```

A `429` from the gateway means the request did nothing, which is why the client waits and repeats it whatever the method.
A record hidden by a read policy answers `404`, not `403`, so `get()` raises `NotFoundError` for "does not exist" and "not yours" alike.
