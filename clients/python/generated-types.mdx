## Overview

The Python SDK works with dictionaries and the built-in types. While the SDK itself doesn't auto-generate Pydantic models in the installed version (0.2.0), you can use your own type definitions for better type safety. For full type generation, patterns align with the TypeScript SDK's generated types workflow.


## Type patterns

When working with the SDK, you typically receive dicts from responses. For type checking, you can use `TypedDict` or Pydantic models.

```python
from typing import TypedDict
from pawabase import Pawabase

class Order(TypedDict):
    id: str
    status: str
    total_minor: int
    created_at: str

pb = Pawabase("https://api.example.com", "pb_pk_key", project="app")
orders = pb.from_("orders")
result = orders.execute()  # list[dict] or paginated result
```

## Working with pagination types

The `execute()` method returns the response body as-is from the API. Based on the API response format, this could be a list or a paginated response object. The client passes through the JSON response body.

## Best practices

- Use TypedDict for API response shapes
- Validate with Pydantic if you need runtime validation
- Keep types in sync with your Studio schema
- Use `as_user()` to test with different auth contexts
