```bash cURL
curl -X POST "$PAWABASE_URL/rest/v1/orders" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" -d '{"customer_id": "c_1", "total_minor": 4200}'
curl -X PATCH "$PAWABASE_URL/rest/v1/orders/$ORDER_ID" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" -d '{"status": "paid"}'
curl -G "$PAWABASE_URL/rest/v1/orders" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" --data-urlencode "filter[status]=eq.open" \
  --data-urlencode "filter[total_minor]=gte.1000" --data-urlencode "sort=-created_at" --data-urlencode "per_page=20"
```
</CodeGroup>

Queries are immutable: each method returns a new query.
`execute()` runs one page; `iterate()`, `all()`, `first()`, `single()`, `count()` and `exists()` are the other ways to run it.
The client refuses three kinds of query the server would answer wrongly: a second filter on the same field, `eq.false` (sent as `is.false` instead), and list values that contain commas.

The session lives in a session store: memory by default, or a file that survives runs with `FileSessionStore`.
The client renews the access token shortly before it expires and once after a `401`.

`pb.manage` and `pb.admin` are attributes of every client, but their calls need a secret key; with a publishable key the server refuses them.


## Choosing a key for each place Python runs

| Where the code runs | Key | Identity |
| --- | --- | --- |
| A web server rendering pages or serving an API for people | Publishable | `pb.as_user(token)` per request |
| A background worker, cron job or queue consumer | Secret | None |
| A webhook receiver for a payment provider | Secret | None, after verifying the provider's signature |
| A command-line tool a person signs in to | Publishable | The person's session, in a `FileSessionStore` |
| A data notebook exploring production data | Secret, read-only through key restrictions | None |
| A CI job that applies definitions | Secret | None |
| A test suite | Publishable for test people, secret for setup | Test users |

A server acting for people should hold a publishable key and use `as_user`.
Then policies protect data on the server exactly as they would in a browser, and a bug in your server cannot reach more than the person could.


## How many clients to create

A client owns an `httpx` connection pool.
Creating one per request throws that pool away.

| Context | Clients |
| --- | --- |
| A web server | One per process, created at startup; `as_user(token)` per request |
| A script | One, used as a context manager so it closes |
| A worker | One per process |
| Tests | One per test, with a fake transport, closed afterwards |

```python
with Pawabase(url, key, environment="production") as pb:
    print(pb.from_("orders").count())
```

`as_user` returns a lightweight view that shares the parent's connection pool.
Closing a view closes nothing; closing the parent closes the pool.


## What comes back

| Call | Returns |
| --- | --- |
| `query.execute()` | A `Page`: `data`, `page`, `per_page`, `total`, and `raw`; iterable and indexable |
| `first()` | The first row, or `None` |
| `single()` | The first row, or raises `NotFoundError` |
| `get(id)`, `create(…)`, `update(…)` | A row as a `dict` |
| `delete(id)` | `None` |
| `pb.auth.get_user()` | The user as a `dict` |
| `bucket.upload(…)` | `{"bucket", "key", "size", "content_type"}` |
| `bucket.download(key)` | `bytes` |
| `pb.flows.invoke(…)` | The flow's response body |
| `pb.manage.*`, `pb.admin.*` | The management plane's JSON |

Field names are the server's, in `snake_case`, exactly as Studio and the API Explorer show them.
Dates arrive as ISO 8601 strings; parse them with `datetime.fromisoformat` where you need `datetime` objects.
When you send `datetime`, `date` or `Decimal` values in a create or update, the client converts them to ISO strings and text.


## How the Python client differs from the TypeScript client

Both clients talk to the same API, and most calls translate directly.
These differences matter when you move code or knowledge between them.

| Area | Python | TypeScript |
| --- | --- | --- |
| Default environment | `"development"` | None; features that need it raise |
| Async model | Two classes: `Pawabase` and `AsyncPawabase` | One class; every call is a promise |
| Running a query | `execute()` | `await query` |
| Typed rows | Plain `dict`; type with generated `TypedDict`s | Generic `Database` type checks names and fields |
| Rate limits | Waits up to 8 times, 1 to 20 seconds each, for any method | Waits within `maxRetryAfterMs`, up to the retry count |
| Network failures | Retried for reads, storage uploads and signing only | Retried for safe methods, including `PUT` and `DELETE` |
| Timeouts | `NetworkError` | `TimeoutError` |
| Validation errors | `ValidationError` with the raw issue list in `detail` | `ValidationError` with `issues`, `fieldError`, `byField` |
| Walking pages with an unknown total | Stops at the first short page | Continues until empty pages |
| Session events | No `INITIAL_SESSION`; listeners get changes only | `INITIAL_SESSION` first |
| Public file URLs | Keyless gateway URLs, with `transform_url` | Object URLs with the publishable key |
| Share links | `create_share_link` on a bucket, with a secret key | Through the management module |
| Live realtime | Async client only; the socket keeps its first token | Any client; refreshed tokens are sent over the socket |
