Each part of the client is a thin, typed layer over one family of gateway paths.
This section explains what each part is for and when you would reach for it, so you can find the right page.

### Records

`pawabase.from("orders")` returns a resource client for the `orders` resource.
It can create, read, update, replace and delete single records, and it can start a query.

<CodeGroup>
```typescript TypeScript
const orders = pawabase.from("orders");

const order = await orders.create({ customer_id: "c_1", total_minor: 4200 });
const same = await orders.get(order.id);
await orders.update(order.id, { status: "paid" });

const open = await orders
  .eq("status", "open")
  .gte("total_minor", 1000)
  .order("created_at", "desc")
  .perPage(20);
```

```python Python
orders = pb.from_("orders")

order = orders.create({"customer_id": "c_1", "total_minor": 4200})
same = orders.get(order["id"])
orders.update(order["id"], {"status": "paid"})

open_orders = orders.eq("status", "open").gte("total_minor", 1000).order("created_at", "desc").per_page(20).execute()
```

```bash cURL
curl -X POST "$PAWABASE_URL/rest/v1/orders" \
  -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" \
  -d '{"customer_id": "c_1", "total_minor": 4200}'

curl "$PAWABASE_URL/rest/v1/orders/$ORDER_ID" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"

curl -X PATCH "$PAWABASE_URL/rest/v1/orders/$ORDER_ID" \
  -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" \
  -d '{"status": "paid"}'

curl -G "$PAWABASE_URL/rest/v1/orders" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  --data-urlencode "filter[status]=eq.open" --data-urlencode "filter[total_minor]=gte.1000" \
  --data-urlencode "sort=-created_at" --data-urlencode "per_page=20"
```
</CodeGroup>

A query is an immutable value.
Each method returns a new query, so a base query can be shared and refined without surprises.
A query is also a promise: `await` runs it and returns one page.

The query builder knows three server behaviors that would otherwise return wrong data silently, and it refuses to send those queries:

| Server behavior | What the client does |
| --- | --- |
| The server keeps only the last filter when a field is filtered twice. | A second filter on the same field throws `InvalidQueryError`. |
| `filter[flag]=eq.false` matches the wrong rows. | `eq(column, false)` is sent as `is.false`. |
| `in` lists are split on commas. | An `in` value that contains a comma throws `InvalidQueryError`. |

The [records page](/data/records/overview) covers every filter, selection, expansion, pagination and bulk method, and what each one sends.

### Authentication

`pawabase.auth` is everything about the person using your application: signing up, signing in by password, magic link or a social provider, multi-factor authentication, sessions on other devices, organizations they belong to, and keys they create for themselves.

<CodeGroup>
```typescript TypeScript
const result = await pawabase.auth.signInWithPassword({ email, password });

if (result.status === "mfa_required") {
  await result.verify(codeFromUser);
}

pawabase.auth.onAuthStateChange((event, session) => {
  console.log(event, session?.user.email);
});
```

```python Python
result = pb.auth.sign_in_with_password(email=email, password=password)

if result.status == "mfa_required":
    result.verify(code_from_user)

pb.auth.on_auth_state_change(lambda event, session: print(event, session and session.user["email"]))
```

```bash cURL
curl -X POST "$PAWABASE_URL/auth/v1/token" -H "apikey: $PAWABASE_KEY" -H "content-type: application/json" \
  -d '{"grant_type": "password", "email": "ada@example.com", "password": "…"}'
# → {"access_token": …, "refresh_token": …, "expires_in": 900, "user": {…}}
# or {"mfa_required": true, "mfa_token": "…", "factors": ["totp"]}, finished with:
curl -X POST "$PAWABASE_URL/auth/v1/token" -H "apikey: $PAWABASE_KEY" -H "content-type: application/json" \
  -d '{"grant_type": "mfa", "mfa_token": "…", "code": "123456"}'
```
</CodeGroup>

The most valuable thing `auth` does is invisible.
Pawabase rotates refresh tokens on every use and treats a refresh token presented twice as theft, which ends the whole session family.
Two requests that both notice an expired token and both refresh would sign the user out.
The client makes every caller in one client share a single refresh, and in browsers it serializes refreshes across tabs with the Web Locks API.
A `401` on any request triggers one refresh and one replay.

The [authentication page](/clients/typescript/authentication/overview) explains the session lifecycle, every sign-in method, MFA, organizations, and how sessions are stored.

### Storage

`pawabase.storage` uploads and downloads files in the environment's buckets.
Each bucket has its own policies for reading, writing, listing and deleting, and its own limits on content types and size.

<CodeGroup>
```typescript TypeScript
const avatars = pawabase.storage.from("avatars");

await avatars.upload(`${userId}/me.png`, file);
const { url } = await avatars.createSignedUrl(`${userId}/me.png`, { expiresIn: 300 });
```

```python Python
avatars = pb.storage.from_("avatars")

avatars.upload(f"{user_id}/me.png", Path("me.png"))
url = avatars.create_signed_url(f"{user_id}/me.png", expires_in=300)["url"]
```

```bash cURL
curl -X PUT "$PAWABASE_URL/storage/v1/object/avatars/$USER_ID/me.png" \
  -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: image/png" \
  --data-binary @me.png

curl -X POST "$PAWABASE_URL/storage/v1/sign/avatars/$USER_ID/me.png" \
  -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" \
  -d '{"method": "GET", "expires_in": 300}'
```
</CodeGroup>

Signed URLs carry their own authority.
A signed upload URL lets a browser send a file straight to storage without ever holding a key that could do anything else.
The [storage page](/clients/typescript/storage/overview) covers uploads, downloads, listings, public URLs and signed URLs.

### Flows and routes

`pawabase.flows.run(name, input)` runs a [flow](/flows/overview) that has an HTTP trigger without a path.
`pawabase.routes.get(path)`, `post`, `put`, `patch` and `delete` call [custom routes](/data/custom-routes/overview) you defined under `/rest/v1`.

<CodeGroup>
```typescript TypeScript
const quote = await pawabase.flows.run<{ total: number }>("price-cart", { cart_id: "cart_9" });
const receipt = await pawabase.routes.post("orders/42/refund", { reason: "damaged" });
```

```python Python
quote = pb.flows.invoke("price-cart", {"cart_id": "cart_9"})
receipt = pb.routes.post("orders/42/refund", {"reason": "damaged"})
```

```bash cURL
curl -X POST "$PAWABASE_URL/flows/v1/price-cart" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"cart_id": "cart_9"}'

curl -X POST "$PAWABASE_URL/rest/v1/orders/42/refund" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"reason": "damaged"}'
```
</CodeGroup>

These are the way an application calls server-side logic that is more than a single record operation.
The [flows and routes page](/clients/typescript/flows-and-routes/overview) explains what each returns and how their errors arrive.

### Realtime

`pawabase.realtime.channel(name)` gives you a channel on the environment's realtime service.
A channel delivers messages, tracks who is present, and keeps recent history.
A resource with realtime turned on publishes its changes on `resource:<name>`, filtered per subscriber by the resource's read policy.

<CodeGroup>
```typescript TypeScript
const changes = pawabase.realtime.channel("resource:orders");
changes.on("message", (message) => console.log(message.event, message.payload));
await changes.subscribe();
```

```python Python
async with AsyncPawabase(url, key, environment="production") as apb:
    changes = apb.realtime.channel("resource:orders")
    changes.on("message", lambda message: print(message["event"], message["payload"]))
    await changes.subscribe()
```

```bash cURL
# Live channels are a WebSocket: wss://<gateway>/realtime/v1/socket?apikey=…&token=…&environment=…
# Recent messages and publishing also work over HTTP:
curl "$PAWABASE_URL/realtime/v1/channels/resource:orders/history?limit=20" \
  -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN"
```
</CodeGroup>

The client keeps one WebSocket for all channels, sends heartbeats, reconnects with backoff, rejoins channels, can replay what was missed, and removes duplicates by message id.
The [realtime page](/clients/typescript/realtime/overview) covers channels, presence, history, rules and reconnection.

### Errors and retries

Every failure the client raises is a `PawabaseError`.
Failures the server answered are `ApiError` subclasses with a `status`, a stable `code`, the `requestId`, and, for validation failures, a list of field issues.

<CodeGroup>
```typescript TypeScript
import { NotFoundError, ValidationError } from "@pawabase/client";

try {
  await pawabase.from("orders").create(input);
} catch (error) {
  if (error instanceof ValidationError) showFieldErrors(error.byField());
  else throw error;
}
```

```python Python
from pawabase import NotFoundError, ValidationError

try:
    pb.from_("orders").create(values)
except ValidationError as error:
    show_field_errors(error.detail)   # the server's list of issues
```

```bash cURL
curl -i -X POST "$PAWABASE_URL/rest/v1/orders" -H "apikey: $PAWABASE_KEY" -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"total_minor": "abc"}'
# HTTP/1.1 422
# x-request-id: req_…
# [{"type": "missing", "loc": ["body", "customer_id"], "msg": "Field required"}, …]
```
</CodeGroup>

The [errors and retries page](/clients/typescript/errors-retries/overview) lists every class, the retry rules, timeouts, cancellation and observability hooks.

### Management and user administration

With a secret key, a server can do anything Studio does.

<CodeGroup>
```typescript TypeScript
import { manage } from "@pawabase/client/manage";
import { admin } from "@pawabase/client/admin";

const m = manage(pawabase);
await m.secrets.set("PAYSTACK_SECRET", process.env.PAYSTACK_SECRET!);

const a = admin(pawabase);
await a.users.update(userId, { disabled: true });
```

```python Python
service = Pawabase(url, "pb_sk_…", environment="production")

service.manage.secrets.set("PAYSTACK_SECRET", os.environ["PAYSTACK_SECRET"])
service.admin.users.update(user_id, disabled=True)
```

```bash cURL
curl -X PUT "$PAWABASE_URL/platform/v1/envs/production/secrets/PAYSTACK_SECRET" \
  -H "apikey: $PAWABASE_SECRET_KEY" -H "content-type: application/json" -d '{"value": "sk_live_…", "description": ""}'

curl -X PATCH "$PAWABASE_URL/platform/v1/envs/production/auth/users/$USER_ID" \
  -H "apikey: $PAWABASE_SECRET_KEY" -H "content-type: application/json" -d '{"disabled": true}'
```
</CodeGroup>

`manage()` covers the environment's definitions and operations.
`admin()` covers the people who sign in to your application.
They are documented on [Environment management](/clients/typescript/management/overview) and [User administration](/clients/typescript/user-administration/overview).
