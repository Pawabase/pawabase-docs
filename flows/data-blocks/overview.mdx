A flow is a graph of **blocks**. [Triggers](/flows/triggers) start a run, [control blocks](/flows/control-flow/overview) decide which path it takes, [resource and platform blocks](/flows/resource-blocks) talk to your database and the rest of the platform — and **data blocks** do the work in between: turning one value into another, checking it against field definitions, computing a number, or reading the current time.

This page covers every block registered under the `data` category in `pawabase_core.flows.blocks.data`, plus two blocks that read and write the database directly — `db.query` and `db.transaction` — because most flow authors reach for them right alongside `math.calculate` and `time.now`. In the block catalogue itself these two are filed under the `resources` category next to [`resource.get`/`resource.list`/…](/flows/resource-blocks), and [`flows/block-reference`](/flows/block-reference) groups them there; this page groups them here because that's how you'll actually use them.

<Note>
Every block on this page is a pure step: given its configuration and the run's current [state](/flows/state/overview), it produces an output and moves on. None of them branch except `validate.schema`, and none of them end the run. If you're looking for `if`/`switch`/`for each`, see [Control flow](/flows/control-flow/overview); if you're looking for `resource.create` or `http.request`, see [Resource blocks](/flows/resource-blocks) and [Platform blocks](/flows/platform-blocks/overview).
</Note>

## Quick reference

| Key | Title | Category | Handles | What it does |
| --- | --- | --- | --- | --- |
| `transform.map` | Transform | `data` | `next` | Applies a [transformer](/data/transformers/overview) |
| `transform.template` | Template | `data` | `next` | Builds a value from a [template](/flows/templates) |
| `transform.pick` | Pick fields | `data` | `next` | Keeps only some keys |
| `transform.rename` | Rename fields | `data` | `next` | Renames fields on objects |
| `transform.unique` | Remove duplicates | `data` | `next` | Keeps the first occurrence of each item or field value |
| `transform.flatten` | Flatten list | `data` | `next` | Flattens nested lists |
| `transform.slice` | Slice list | `data` | `next` | Selects a page or range of list items |
| `validate.schema` | Validate | `data` | `next`, `invalid` | Validates against field definitions |
| `json.parse` | Parse JSON | `data` | `next` | Parses a JSON string |
| `json.stringify` | Stringify JSON | `data` | `next` | Serialises a value as JSON |
| `math.calculate` | Calculate | `data` | `next` | Arithmetic on a list of numbers |
| `transform.summarize` | Summarize list | `data` | `next` | Aggregates a list, optionally by group |
| `util.id` | Generate id | `data` | `next` | UUID4 or random token |
| `crypto.hash` | Hash | `data` | `next` | SHA-256, SHA-512, HMAC-SHA256 |
| `time.now` | Current time | `data` | `next` | UTC time in iso/date/unix |
| `db.query` | SQL query | `resources` | `next` | Read-only SQL statement |
| `db.transaction` | Transaction | `resources` | `next` | Several resource writes, atomically |

<Tip>
Every block's `output` is available to later blocks as `steps.<node id>.output`. That's true for these blocks exactly as it is for resource and platform blocks — a `math.calculate` node named `total` exposes its number as `{{ steps.total.output }}` just like a `resource.get` node exposes its record. See [State](/flows/state/overview) for the full picture.
</Tip>

## `transform.map` — Transform

Applies a [transformer](/data/transformers/overview) to a value: the same mechanism resources use to shape their API responses, available inside a flow on any value at any point.

| Config | Type | Required | Description |
| --- | --- | --- | --- |
| `value` | `json` | yes | The value to transform |
| `transformer` | `json` | yes | A transformer definition (inline) or the name of a stored transformer |

**Output:** the transformed value.

```json
{
  "id": "shape",
  "data": {
    "block": "transform.map",
    "config": {
      "value": "{{ steps.order.output }}",
      "transformer": "order_public"
    }
  }
}
```

An inline transformer works the same way:

```json
{
  "id": "shape",
  "data": {
    "block": "transform.map",
    "config": {
      "value": "{{ steps.order.output }}",
      "transformer": { "fields": ["id", "number", "status", "total_minor", "currency"] }
    }
  }
}
```


## `transform.template` — Template

Builds a JSON value — a string, an object, or a list, at any depth — from a [template](/flows/templates). Unlike most blocks, `transform.template` sets `raw_config = True`: its `template` configuration is **not** pre-rendered by the engine before the block runs. The block renders it itself with `pawabase_core.templating.render`.

| Config | Type | Required | Description |
| --- | --- | --- | --- |
| `template` | `json` | yes | Any JSON value; strings inside it are rendered as templates |

**Output:** the rendered value.

```json
{
  "id": "envelope",
  "data": {
    "block": "transform.template",
    "config": {
      "template": {
        "order_id": "{{ steps.order.output.id }}",
        "customer": { "email": "{{ steps.order.output.email }}", "name": "{{ steps.customer.output.name }}" },
        "lines": "{{ steps.items.output }}",
        "placed_at": "{{ steps.now.output }}"
      }
    }
  }
}
```

<Tip>
In practice you rarely need `transform.template` as its own node: almost every block's `config` values are templates already. Reach for a dedicated `transform.template` node when you want to build a value once and reuse it — for example, an outgoing event payload referenced from both an `event.emit` node and a `log.write` node.
</Tip>


## `transform.pick` — Pick fields

Keeps only the named keys of an object, or of every object in a list.

| Config | Type | Required | Description |
| --- | --- | --- | --- |
| `value` | `json` | yes | An object, or a list of objects |
| `fields` | `array` of `string` | yes | The keys to keep |

**Output:** an object with only those keys (missing keys are simply absent, not `null`), or a list of such objects when `value` is a list.

```json
{
  "id": "public_view",
  "data": {
    "block": "transform.pick",
    "config": {
      "value": "{{ steps.customer.output }}",
      "fields": ["id", "name", "email"]
    }
  }
}
```

Given `{"id": 9, "name": "Ada", "email": "ada@example.com", "password_hash": "…", "notes": "VIP"}`, the output is `{"id": 9, "name": "Ada", "email": "ada@example.com"}` — `password_hash` and `notes` are dropped.

<Warning>
`transform.pick` is a shaping convenience for what a flow **returns** or forwards on — it is not an access control mechanism. It runs after the data has already been read from the database with full, service-level rights. If a caller should not be able to read a field at all, the answer is a [policy](/policies/overview) or a transformer's `read_only`/`write_only` fields on the resource itself.
</Warning>


## List and object transforms

These blocks are common cleanup steps after `resource.list`, an HTTP request, or parsed JSON. All preserve item order.

| Block | Config | Result |
| --- | --- | --- |
| `transform.rename` | `value`, `fields` | Renames top-level object fields. `fields` is an object such as `{"first_name":"given_name"}`. Works on one object or every object in a list. |
| `transform.unique` | `value`, optional `field` | Removes duplicates, keeping the first item. Set `field` to a dotted path such as `customer.email` to deduplicate records by that value. |
| `transform.flatten` | `value`, `depth` | Flattens nested lists one or more levels; `depth` defaults to `1`. |
| `transform.slice` | `value`, `offset`, optional `limit` | Returns a window of a list, useful for pagination and limits. |

```json
[
  {
    "id": "unique_customers",
    "data": {
      "block": "transform.unique",
      "config": { "value": "{{ steps.orders.output.data }}", "field": "customer.email" }
    }
  },
  {
    "id": "first_page",
    "data": {
      "block": "transform.slice",
      "config": { "value": "{{ steps.unique_customers.output }}", "offset": 0, "limit": 20 }
    }
  }
]
```


## `validate.schema` — Validate

Validates a value against a list of [field definitions](/data/transformers/overview) — the same shape resources, functions and custom routes use. This is the one data block that branches.

| Config | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `value` | `json` | yes | — | The value to validate |
| `fields` | `json` | yes | — | A list of field definitions |
| `on_invalid` | `string` (`fail` \| `branch`) | no | `fail` | What to do when validation fails |

**Handles:** `next` (valid), `invalid` (only reachable when `on_invalid` is `branch`).

**Output:** on success, the *cleaned* value — defaults applied, types coerced, unknown keys dropped. On the `invalid` branch, `{"errors": [...]}` with the same shape as the `422` body a resource operation would return.

By default a failed validation **fails the run** with a `422` and the field errors as `details` — useful right after a `trigger.http` node:

```json
{
  "id": "check",
  "data": {
    "block": "validate.schema",
    "config": {
      "value": "{{ input.body }}",
      "fields": [
        { "name": "email", "type": "email", "required": true },
        { "name": "quantity", "type": "integer", "required": true, "minimum": 1, "maximum": 99 }
      ]
    }
  }
}
```

Set `on_invalid` to `branch` when the flow should handle a bad payload itself:

```json
{
  "id": "check",
  "data": {
    "block": "validate.schema",
    "config": {
      "value": "{{ input.body }}",
      "fields": [{ "name": "email", "type": "email", "required": true }],
      "on_invalid": "branch"
    }
  }
}
```

```json
{
  "id": "reply_invalid",
  "data": {
    "block": "response.return",
    "config": { "status": 422, "body": { "ok": false, "errors": "{{ steps.check.output.errors }}" } }
  }
}
```

<Note>
Most of the time you don't need `validate.schema` at all: a `trigger.http` node bound to a route already validates the body, and every `resource.create`/`resource.update` block validates `data`. Reach for `validate.schema` when a flow accepts a shape that isn't already described anywhere — the body of a [webhook trigger](/flows/triggers#trigger-webhook), or a nested object inside a larger payload.
</Note>


## `json.parse` — Parse JSON

Parses a JSON-encoded string. Useful for a webhook body a provider sent as a string field, or for text read back with `storage.read`.

| Config | Type | Required | Description |
| --- | --- | --- | --- |
| `text` | `string` | yes | The JSON text to parse |

**Output:** the parsed value. Invalid JSON fails the run with a `400` and code `bad_json`:

```
FlowError("invalid JSON: Expecting value: line 1 column 1 (char 0)", status=400, code="bad_json")
```
