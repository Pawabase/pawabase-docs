A schedule's time rule is either a **cron expression** or an **interval**. Pick one per trigger node.

## Cron expressions

Five fields, separated by spaces:

```text
┌───────── minute (0–59)
│ ┌───────── hour (0–23)
│ │ ┌───────── day of month (1–31)
│ │ │ ┌───────── month (1–12)
│ │ │ │ ┌───────── day of week (0–6, 0 = Sunday)
│ │ │ │ │
* * * * *
```

Times are UTC. A schedule set for `0 9 * * *` fires at 09:00 UTC, which is a different local hour in different places and changes by an hour where clocks change. If the work is tied to a local time, work out the UTC hour for the season and revisit it when clocks move, or schedule hourly and check the local time in the flow.

### Symbols

| Symbol | Meaning | Example |
| --- | --- | --- |
| `*` | Every value | `* * * * *` every minute |
| `,` | A list | `0 9,17 * * *` at 09:00 and 17:00 |
| `-` | A range | `0 9-17 * * *` every hour from 09:00 to 17:00 |
| `/` | A step | `*/15 * * * *` every 15 minutes |

### Common expressions

| Expression | Fires |
| --- | --- |
| `*/5 * * * *` | Every 5 minutes |
| `0 * * * *` | Every hour, on the hour |
| `0 3 * * *` | 03:00 daily |
| `0 9 * * 1` | 09:00 every Monday |
| `0 9 * * 1-5` | 09:00 on weekdays |
| `0 0 1 * *` | Midnight on the 1st of each month |
| `0 0 * * 0` | Midnight every Sunday |

## Intervals

`every` is a number of seconds:

```json
{ "id": "start", "data": { "block": "trigger.schedule", "config": { "every": 3600 } } }
```

That fires hourly, counted from when the schedule started, not on the hour. Prefer an interval when the work does not care about the clock, such as polling a provider, and cron when it does.

| Want | Use |
| --- | --- |
| "Every 10 minutes" | `every: 600` or `*/10 * * * *` |
| "At 03:00" | cron |
| "On the first of the month" | cron |
| "About once a minute, whenever" | `every: 60` |

## Overlapping runs

If a run is still going when the next is due, the next one is still started. Two runs of the same flow at once can both act on the same records. Make the flow safe to overlap: claim work by marking records before handling them, or keep the interval longer than the longest run. See [idempotent jobs](/jobs/patterns#idempotent-jobs).

## Testing a rule

Run the schedule on demand while you build the flow:

<CodeGroup>
```typescript TypeScript
await m.schedules.run("nightly-rollup");
```

```python Python
pb.manage.schedules.run("nightly-rollup")
```
</CodeGroup>

Then list recent runs for the flow to see the result:

<CodeGroup>
```typescript TypeScript
const runs = await m.flows.runs({ flow: "nightly-rollup", limit: 5 });
```

```python Python
runs = pb.manage.flows.runs(flow="nightly-rollup", limit=5)
```
</CodeGroup>
