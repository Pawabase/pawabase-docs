A schedule's time rule is either a **cron expression** or an **interval**. Pick one per trigger node.

## Cron expressions

Five fields, separated by spaces:

```text
┌───────── minute (0–59)
│ ┌───────── hour (0–23)
│ │ ┌───────── day of month (1–31)
│ │ │ ┌───────── month (1–12)
│ │ │ │ ┌───────── day of week (0–6, 0 = Sunday)
│ │ │ │ │
* * * * *
```

Times are read in the schedule's `timezone`, which defaults to UTC. Set it to the zone your users live in (`Europe/London`, `Africa/Lagos`) and the schedule follows daylight saving changes for you.

### Symbols

| Symbol | Meaning | Example |
| --- | --- | --- |
| `*` | Every value | `* * * * *` every minute |
| `,` | A list | `0 9,17 * * *` at 09:00 and 17:00 |
| `-` | A range | `0 9-17 * * *` every hour from 09:00 to 17:00 |
| `/` | A step | `*/15 * * * *` every 15 minutes |

### Common expressions

| Expression | Fires |
| --- | --- |
| `*/5 * * * *` | Every 5 minutes |
| `0 * * * *` | Every hour, on the hour |
| `0 3 * * *` | 03:00 daily |
| `0 9 * * 1` | 09:00 every Monday |
| `0 9 * * 1-5` | 09:00 on weekdays |
| `0 0 1 * *` | Midnight on the 1st of each month |
| `0 0 * * 0` | Midnight every Sunday |

## Intervals

`interval_seconds` is a number of seconds, 10 or more:

```json
{ "name": "poll-provider", "interval_seconds": 600, "target_type": "flow", "target": "poll" }
```

That runs every 10 minutes, counted from when the schedule started, not on the clock. Prefer an interval when the work does not care about the clock, such as polling a provider, and cron when it does.

| Want | Use |
| --- | --- |
| "Every 10 minutes" | `interval_seconds: 600` or `*/10 * * * *` |
| "At 03:00" | cron |
| "On the first of the month" | cron |
| "About once a minute, whenever" | `interval_seconds: 60` |

## Overlapping runs and missed runs

- **`overlap: "allow"`** (default) starts the next run even if the last is still going. Two runs can act on the same records, so make the flow safe to overlap, or choose `skip`.
- **`overlap: "skip"`** leaves a tick out if the previous run has not finished. Best for sweeps and syncs.
- **`catch_up: true`** runs occurrences that were missed while the system was down. Leave it off for jobs where only the latest run matters, such as a heartbeat.

## Testing a rule

Run the schedule on demand while you build the flow:

<CodeGroup>
```typescript TypeScript
await m.schedules.run("nightly-rollup");
```

```python Python
pb.manage.schedules.run("nightly-rollup")
```
</CodeGroup>

Then list recent runs for the flow to see the result:

<CodeGroup>
```typescript TypeScript
const runs = await m.flows.runs({ flow: "nightly-rollup", limit: 5 });
```

```python Python
runs = pb.manage.flows.runs(flow="nightly-rollup", limit=5)
```
</CodeGroup>
