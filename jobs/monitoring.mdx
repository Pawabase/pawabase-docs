Jobs are easiest to run when you notice a problem early. Two calls cover most of it: the queue summary and the job log.

## Queue depth

<CodeGroup>
```typescript TypeScript
const queues = await m.jobs.queues();
```

```python Python
queues = pb.manage.jobs.queues()
```
</CodeGroup>

The result lists each queue with its depth (jobs waiting) and job counts by status. Take a reading at intervals and compare them. One number tells you little; the trend tells you a lot.

| What you see | What it usually means |
| --- | --- |
| Depth steady and low | Work is arriving no faster than it is done |
| Depth growing steadily | Work arrives faster than it finishes, or every job is slow |
| Depth growing and many `retrying` | A dependency is down or returning errors |
| Depth zero, many `failed` | Jobs fail on the first attempt; read an error |
| One queue deep, others empty | One kind of work is the problem; check its dependency |

## The job log

<CodeGroup>
```typescript TypeScript
const active = await m.jobs.list({ status: "active", queue: "flows", limit: 25 });
const retrying = await m.jobs.list({ status: "retrying" });
```

```python Python
active = pb.manage.jobs.list(status="active", queue="flows", limit=25)
retrying = pb.manage.jobs.list(status="retrying")
```
</CodeGroup>

Use `status` to ask a specific question: what is running now, what is stuck retrying, what succeeded recently.

## Following one dispatch

A `queue.flow` block outputs a `job_id`. Store it where you can find it later, for example on the record the job works on:

```json
{
  "id": "remember_job",
  "data": {
    "block": "resource.update",
    "config": { "resource": "reports", "id": "{{ input.body.report_id }}", "values": { "job_id": "{{ steps.dispatch_report.output.job_id }}" } }
  }
}
```

Your app can then show "preparing" until a read of the job shows `succeeded`.

<CodeGroup>
```typescript TypeScript
const job = await m.jobs.detail(report.job_id);
const ready = job.status === "succeeded";
```

```python Python
job = pb.manage.jobs.detail(report["job_id"])
ready = job["status"] == "succeeded"
```
</CodeGroup>

<Note>
Polling the management client from a browser is not possible, since it needs a secret key. Poll from your server, or have the finishing flow update a record that the browser reads or listens to over [realtime](/realtime/overview).
</Note>

## Alerting on failure

Add a final step to the flow that emits an event when it cannot finish, and subscribe a notification flow to it:

```json
{ "block": "events.emit", "config": { "name": "report.failed", "payload": { "report_id": "{{ input.report_id }}" } } }
```

For a broader view, watch the failure count. A failure count that moves from zero to a handful after a deploy is a regression you want to hear about at once.
