A **schedule** runs a flow by the clock instead of in response to a request or an event. Nightly rollups, hourly syncs, a reminder sweep every morning: you create a schedule with a time rule and point it at a flow, a function or an event.

## Get started

Create a schedule from code with a secret key (or in the dashboard under Schedules). It names a time rule and what to run.

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";
import { manage } from "@pawabase/client/manage";

const pawabase = createClient({
  url: "https://api.example.com",
  apiKey: process.env.PAWABASE_SECRET_KEY!,
  environment: "production",
});
const m = manage(pawabase);

await m.schedules.create({
  name: "nightly-rollup",
  cron: "0 3 * * *",
  timezone: "Africa/Lagos",
  target_type: "flow",
  target: "rollup",
  overlap: "skip",
});

await m.schedules.run("nightly-rollup");     // fire it now, to test
const all = await m.schedules.list();
```

```python Python
import os
from pawabase import Pawabase

pb = Pawabase("https://api.example.com", os.environ["PAWABASE_SECRET_KEY"], environment="production")

pb.manage.schedules.create({
    "name": "nightly-rollup",
    "cron": "0 3 * * *",
    "timezone": "Africa/Lagos",
    "target_type": "flow",
    "target": "rollup",
    "overlap": "skip",
})

pb.manage.schedules.run("nightly-rollup")     # fire it now, to test
all_schedules = pb.manage.schedules.list()
```
</CodeGroup>

## Settings

| Field | Meaning |
| --- | --- |
| `name` | Letters, digits and dashes. Unique |
| `cron` | A five-field [cron expression](/jobs/cron-and-intervals) |
| `interval_seconds` | Run every N seconds instead (10 or more). Use `cron` or this, not both |
| `timezone` | An IANA name such as `Europe/London`. Cron times are read in this zone. Default UTC |
| `target_type` | What to run: `flow`, `function`, or `event` (emit an event) |
| `target` | The flow or function name, or the event name |
| `payload` | Extra data passed to the target |
| `overlap` | `allow` (default) starts a run even if the last is still going; `skip` waits for it to finish |
| `catch_up` | `true` runs missed occurrences after downtime; default `false` |
| `enabled` | `false` pauses it |

When it fires, the target receives `{ "scheduled_at": "2026-10-29T03:00:00Z" }` along with your `payload`. Use `scheduled_at` for time logic, so a run that starts a little late still works on the right window.

## Schedule from inside a flow

A flow can also hold its own schedule as a `trigger.schedule` node:

```json
{ "id": "start", "data": { "block": "trigger.schedule", "config": { "cron": "0 3 * * *" } } }
```

Use the node when the schedule belongs to the flow; use a schedule definition when you want to manage times separately, point at a function, or emit an event.

## A schedule is a job

A fired schedule that runs a flow appears as an ordinary [job](/jobs/overview) on the `flows` queue. That means it has a status, it can [fail and be retried](/jobs/failures-and-replay), and you can find it in the [job log](/jobs/monitoring).

## Changing and stopping

- **Change the time:** `m.schedules.replace(name, {...})` with the whole definition. The new rule takes effect within seconds.
- **Pause:** replace it with `enabled: false`. Nothing fires until you turn it back on.
- **Remove:** `m.schedules.remove(name)`.

## Patterns

### Nightly rollup

```json
{ "id": "start", "data": { "block": "trigger.schedule", "config": { "cron": "0 3 * * *" } } }
```

Use the `time.now` block with `offset_seconds: -86400` to summarise the previous day, whenever the run starts.

### Sweep for due work

Rather than scheduling one delayed job per item, run a short schedule that finds whatever is due:

```json
{ "id": "start", "data": { "block": "trigger.schedule", "config": { "every": 300 } } }
```

The flow reads records whose `due_at` has passed and `notified` is false, handles them, and marks them. A missed run only delays things until the next one.

### Heartbeat

```json
{ "id": "start", "data": { "block": "trigger.schedule", "config": { "every": 60 } } }
```

A flow that checks something every minute and emits an event when it is wrong.
