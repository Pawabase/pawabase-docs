A **table** holds rows. A **resource** is what turns a table into an API your app can use: it records the columns, the access rules and the behaviour. In Studio you create both at once.

## Where

Choose your environment, then **Data → Data** (the table editor). The secondary sidebar lists every table (use **Find a table** to search) with a `resource` tag on those served as an API, and has a **Create table** button at the top.

## Create a table

1. Click **Create table.** A sheet opens with a switch at the top between **Configure** (the form) and the raw definition.
2. Fill the sections from top to bottom. Each is explained below.
3. Click **Save changes.**

Studio creates the resource and the real database table together, so the table is ready to use as soon as you save.

### Details

| Field | Meaning |
| --- | --- |
| **Name** | The resource's name and API path. Lowercase letters, digits and underscores, starting with a letter, up to 63 characters (for example `tasks`, `order_items`). These names are reserved: `docs`, `openapi.json`, `x`, `rpc`, `health`, `internal`, `platform` |
| **Display name** | A friendly label in Studio |
| **Description** | Appears in the API docs |
| **Table** | The database table. Defaults to the name. Set it to serve an existing table under another name |
| **Primary key** | The key column. Default `id` |
| **ID type** | `ulid` (default), `uuid` or `integer`. Fixed after creation. See [Ids and timestamps](/database/ids-and-timestamps) |
| **Tags** | Group endpoints in the API docs |

### Columns

**Add column**, name it, choose a **Column type**, and open the row to set constraints and flags. The full reference is [Columns and types](/database/columns-and-types).

### Access

*Which endpoints exist, and who may call each.* Choose a **Quick access set** or set each of the five actions. See [Access](/database/access).

### Relations

*Include related rows with `?expand=name`.* See [Relations](/database/relations).

### Behaviour

Timestamps, **Owner field**, **Emit events**, **Broadcast changes**, **Capture changes made outside the API**, **Cache responses**, **Rate limit**, **Transformer**, **Time zone**. Each is described in [Table settings](/database/table-settings).

## After you save

Open the table in the sidebar. Its tabs:

| Tab | Use it for |
| --- | --- |
| **Data** | Browse and edit rows ([Table editor](/database/table-editor)) |
| **Columns** | Change columns later |
| **Access** | The five rules |
| **Indexes** | Speed and uniqueness ([Indexes](/database/indexes)) |
| **History** | Schema changes and rollbacks ([Migrations](/database/migrations-and-history)) |
| **Settings** | Everything from Details and Behaviour |

## Change a table later

Edit on the **Columns**, **Access**, **Indexes** or **Settings** tab and save. If the change affects the database (a new column, a new index), Studio shows a **pending migration** with the SQL; review it and apply. Adding a column is safe; changing or removing one is flagged **Needs review**. See [Migrations and history](/database/migrations-and-history).

## Keep tables and definitions in step

A table can drift from its definition: someone adds a column with SQL, or you edit the definition and don't apply it. The table's status tells you:

| Status | Meaning | What to do |
| --- | --- | --- |
| **In sync** | Table and definition agree | Nothing |
| **Not applied** | The definition has changes the table lacks | Apply the pending migration |
| **Needs review** | The change could rewrite or drop things | Read the plan; apply deliberately |
| **Changed outside** | The table has something the definition doesn't | **Acknowledge** it (adopt it) or fix the table |
| **No table yet** | A resource exists with no table | Apply to create it |
| **Table dropped** | The table is gone | Re-create it or remove the resource |

## Bring in an existing table

If a table already exists in the database (made by a migration or with SQL), turn it into a resource instead of retyping it. On the **Data** page choose **Import a table**, pick the table, give it a **Resource name**, and Studio reads its columns and proposes a definition. Tables Pawabase uses internally are hidden and can't be imported. After importing, set the **Access** rules: a new resource is private until you do.

## Create tables for every resource

The **SQL** page has a **Create tables** button: it creates or extends the tables for **every** resource at once. Columns are only ever added; nothing is dropped or retyped. Use it after promoting definitions to a new environment.

## Deleting

- **Remove the resource** (in the table's **Settings**): the API stops serving the table. The table and its rows stay.
- **Drop the table:** do it deliberately in the [SQL editor](/database/sql-editor), after a [backup](/backups/overview). Studio never drops a table for you.
