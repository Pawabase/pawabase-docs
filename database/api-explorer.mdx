The **API Explorer** is Studio's workbench for the API your tables expose. Use it to check that an access rule behaves, to reproduce a bug a user reported, or to learn the request a feature needs.

## In Studio

**Data → API Explorer.** Requests go to the environment you are in (*switch environments from the top bar*).

### Build a request

1. **Pick an endpoint** from the list: every table's list, get, create, update, delete, plus your routes.
2. Fill **Path parameters** (such as the record id), **Query parameters** (filters, `expand`, sort, page) and **Request body**. Documented headers are offered under **Headers**; add your own with a header name and value.
3. Choose **Authorization** (below).
4. **Send.** The **Response** shows the status, headers and body; **Responses** lists what the endpoint can return.

### Make the request as someone

**Application-user authentication** lets you sign in as a real user of your app: enter **User email**, **Password** and, if they have two-step on, an **MFA code**. Studio then sends the request with *that user's* token, so you see exactly what they would. Test the same request signed in as a different user, and as nobody, to check your [access rules](/policies/testing).

**Authorization** can also use a bearer token you paste.

*Studio supplies a scoped API context for live requests. The **API key for cURL** you enter is only included in copied cURL commands.*

### Copy as cURL

Copy the request as a `curl` command (using the key you entered) to reproduce it in a terminal or share it.

## Same thing from your app

Every request in the Explorer has a client equivalent:

| Explorer request | Client |
| --- | --- |
| `GET /rest/v1/tasks?done=false&sort=-created_at` | `pawabase.from("tasks").eq("done", false).order("created_at", "desc")` |
| `GET /rest/v1/tasks/{id}?expand=author` | `pawabase.from("tasks").get(id, { expand: ["author"] })` |
| `POST /rest/v1/tasks` | `pawabase.from("tasks").create({...})` |
| `PATCH /rest/v1/tasks/{id}` | `pawabase.from("tasks").update(id, {...})` |
| `DELETE /rest/v1/tasks/{id}` | `pawabase.from("tasks").delete(id)` |

Use the Explorer to find out what the wire looks like; use the client in your app.

## Debugging with the Explorer

1. A user says "I can't see my orders."
2. Sign in as them in **Application-user authentication** (use a test copy of the account).
3. Send `GET orders`. Empty? The `list` rule filtered everything. `403`? A rule refused. `401`? Not signed in.
4. Open the request in **Activity** to see which rule decided. See [Troubleshooting](/database/troubleshooting).
