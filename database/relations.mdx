Real data links together: a post has an author and comments, an order has line items. Instead of one request for the post and another for the author, ask for both at once with `expand`.

Relations are declared on the table (for example `posts.author` points at `users`). Declare them in the dashboard under **Database** in the table's settings.

## Expand a relation

<CodeGroup>
```typescript TypeScript
const { data: posts } = await pawabase.from("posts").expand("author").order("created_at", "desc");

posts[0].author.name;     // the author's record is inside the post
```

```python Python
posts = pb.from_("posts").expand("author").order("created_at", "desc").execute().data
posts[0]["author"]["name"]
```
</CodeGroup>

`expand` works on lists and on single records:

<CodeGroup>
```typescript TypeScript
const post = await pawabase.from("posts").get(id, { expand: ["author", "comments"] });
```

```python Python
post = pb.from_("posts").get(post_id, expand=["author", "comments"])
```
</CodeGroup>

Expand several relations by listing them: `.expand("author", "comments")`.

## Two kinds of relation

| Kind | Meaning | Result |
| --- | --- | --- |
| `belongs_to` | The record holds the other's id (`post.author_id`) | An object |
| `has_many` | Other records hold this one's id (`comment.post_id`) | An array |

## Filtering by a related record

To find posts by one author, filter on the id column the post holds:

```typescript
const { data } = await pawabase.from("posts").eq("author_id", authorId).expand("author");
```

## Access rules still apply

Each related record is read under *its own* table's rules. If you may read a post but not its author, the author comes back missing. Check for that instead of assuming it is there:

```typescript
const authorName = post.author?.name ?? "Unknown";
```

## When not to expand

Expanding a large `has_many` pulls many records into one response. For long lists, load the parent first and then page through the children with a filter:

```typescript
const comments = await pawabase.from("comments").eq("post_id", post.id).order("created_at").perPage(20);
```
