## Sort

<CodeGroup>
```typescript TypeScript
pawabase.from("posts").order("created_at", "desc");
pawabase.from("posts").order("pinned", "desc").order("created_at", "desc");   // then by
```

```python Python
pb.from_("posts").order("created_at", "desc")
pb.from_("posts").order("pinned", "desc").order("created_at", "desc")
```
</CodeGroup>

Each `order` after the first breaks ties in the earlier ones. Ascending is the default.

## Page size and page number

<CodeGroup>
```typescript TypeScript
const page2 = await pawabase.from("posts").order("created_at", "desc").perPage(25).page(2);
page2.page;      // 2
page2.per_page;  // 25
page2.total;     // matching records, or null
```

```python Python
page2 = pb.from_("posts").order("created_at", "desc").per_page(25).page(2).execute()
page2.page, page2.per_page, page2.total
```
</CodeGroup>

Pages count from 1. The default size is 20, and the server caps it at 200. `limit(n)` asks for at most `n` records.

## Infinite scroll and "Load more"

Keep the page number and add results as it grows. Stop when a page comes back short.

```typescript
async function loadMore(state: { page: number; rows: Post[]; done: boolean }) {
  const next = await pawabase.from("posts").order("created_at", "desc").perPage(20).page(state.page + 1);
  return {
    page: state.page + 1,
    rows: [...state.rows, ...(next.data as Post[])],
    done: next.data.length < 20,
  };
}
```

Because `total` can be `null`, decide "is there more" from the page length, not from `total`.

## Walk through everything

For exports and background work, iterate instead of loading a huge page:

<CodeGroup>
```typescript TypeScript
for await (const page of pawabase.from("orders").eq("status", "paid").pages({ pageSize: 100 })) {
  for (const order of page.data) process(order);
}

const all = await pawabase.from("orders").eq("status", "paid").all({ maxRecords: 5000 });
```

```python Python
for page in pb.from_("orders").eq("status", "paid").pages(page_size=100):
    for order in page:
        process(order)

for order in pb.from_("orders").eq("status", "paid").iterate(page_size=100):
    process(order)

everything = pb.from_("orders").eq("status", "paid").all(max_records=5000)
```
</CodeGroup>

`pages` gives one page at a time, so memory stays flat. Set `maxRecords` as a safety stop.

## Stable pages

If new records arrive while someone is paging, items can shift between pages. Sort by something steady, like `created_at` with `id`, and for feeds prefer "load newer" with a filter (`gt("created_at", lastSeen)`) over page numbers.
