## Sort

<CodeGroup>
```typescript TypeScript
pawabase.from("posts").order("created_at", "desc");
pawabase.from("posts").order("pinned", "desc").order("created_at", "desc");    // then by
```

```python Python
pb.from_("posts").order("created_at", "desc")
pb.from_("posts").order("pinned", "desc").order("created_at", "desc")
```
</CodeGroup>

Each `order` after the first breaks ties in the earlier ones. Ascending is the default. Without any `order`, the order is not guaranteed; always sort lists you show.

## Page size and number

<CodeGroup>
```typescript TypeScript
const page2 = await pawabase.from("posts").order("created_at", "desc").perPage(25).page(2);
page2.page;       // 2
page2.per_page;   // 25
page2.total;      // matching records, or null
```

```python Python
page2 = pb.from_("posts").order("created_at", "desc").per_page(25).page(2).execute()
page2.page, page2.per_page, page2.total
```
</CodeGroup>

Pages count from 1. The default size is 20; the server caps it at 200. `limit(n)` asks for at most `n` records.

## Load more

Keep the page number and add results as it grows. Stop when a page comes back short; don't rely on `total`, which can be `null`.

```typescript
async function loadMore(state: { page: number; rows: Post[]; done: boolean }) {
  const next = await pawabase.from("posts").order("created_at", "desc").perPage(20).page(state.page + 1);
  return {
    page: state.page + 1,
    rows: [...state.rows, ...(next.data as Post[])],
    done: next.data.length < 20,
  };
}
```

## Page controls (when `total` is a number)

```tsx
const pages = page.total == null ? null : Math.ceil(page.total / page.per_page);
// Show "Page 3 of 12" only when `pages` is a number; otherwise show Previous / Next.
```

## Walk through everything

For exports and background work, iterate instead of loading one huge page:

<CodeGroup>
```typescript TypeScript
for await (const page of pawabase.from("orders").eq("status", "paid").pages({ pageSize: 100 })) {
  for (const order of page.data) process(order);
}

const all = await pawabase.from("orders").eq("status", "paid").all({ pageSize: 100, maxRecords: 5000, stopAfterEmptyPages: 1 });
```

```python Python
for page in pb.from_("orders").eq("status", "paid").pages(page_size=100):
    for order in page:
        process(order)

for order in pb.from_("orders").eq("status", "paid").iterate(page_size=100):
    process(order)

everything = pb.from_("orders").eq("status", "paid").all(page_size=100, max_records=5000)
```
</CodeGroup>

| Option | Meaning |
| --- | --- |
| `pageSize` | Rows per request. Default 100; the server maximum is 200 |
| `maxRecords` | Stop after this many rows. A safety stop |
| `stopAfterEmptyPages` | When the server can't count (`total` is `null`), a short or empty page doesn't mean the end. Stop after this many empty pages in a row (default 1) |

`pages` yields one page at a time, so memory stays flat.

## Stable pages

If records arrive while someone is paging, items shift between pages. For feeds:

- Sort by something steady (`created_at`, then `id`).
- Prefer "load newer" with a filter (`gt("created_at", lastSeen)`) over page numbers.
- Let [realtime](/realtime/record-changes) add new records at the top instead of re-reading page 1.

## Keyset-style paging

For very large tables, "give me 20 older than this" is faster than deep page numbers, because the database doesn't count skipped rows:

```typescript
async function olderThan(cursor: string) {
  return pawabase.from("events").lt("created_at", cursor).order("created_at", "desc").limit(50);
}
```

Pass the last item's `created_at` as the next cursor. Make sure `created_at` is [indexed](/database/indexes).
