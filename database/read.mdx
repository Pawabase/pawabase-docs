`pawabase.from("table")` starts a query. Add filters and options, then await it.

## A list

<CodeGroup>
```typescript TypeScript
const page = await pawabase.from("tasks");
page.data;      // the records
page.total;     // how many match (or null, see below)
page.page;      // 1
page.per_page;  // 20
```

```python Python
page = pb.from_("tasks").execute()
page.data       # the records
page.total      # how many match (or None)
for task in page: ...
```
</CodeGroup>

A query returns one **page** of records, 20 by default. See [sort and page](/database/sort-and-page) to change that or walk through all of them.

`total` is `null` when your access rules are per-row: the server cannot count rows you may see without checking each one. Do not build "page 3 of N" UI from `total` in that case; show "Load more" instead.

## One record by id

<CodeGroup>
```typescript TypeScript
const task = await pawabase.from("tasks").get("01J…");         // throws NotFoundError if missing
const maybe = await pawabase.from("tasks").maybeGet("01J…");   // null if missing
```

```python Python
task = pb.from_("tasks").get("01J…")                 # raises NotFoundError if missing
maybe = pb.from_("tasks").maybe_get("01J…")           # None if missing
```
</CodeGroup>

A record that exists but that you may not see is also "not found". The two are the same on purpose.

## The first match, or exactly one

<CodeGroup>
```typescript TypeScript
const latest = await pawabase.from("tasks").order("created_at", "desc").first();   // row or null
const mine = await pawabase.from("profiles").eq("user_id", user.id).single();      // row, or throws
```

```python Python
latest = pb.from_("tasks").order("created_at", "desc").first()
mine = pb.from_("profiles").eq("user_id", user["id"]).single()
```
</CodeGroup>

`first()` gives you the first row or `null`. `single()` expects exactly one row and throws if there are none or several.

## Count and exists

<CodeGroup>
```typescript TypeScript
const open = await pawabase.from("tasks").eq("done", false).count();
const any = await pawabase.from("tasks").eq("done", false).exists();
```

```python Python
open_count = pb.from_("tasks").eq("done", False).count()
any_open = pb.from_("tasks").eq("done", False).exists()
```
</CodeGroup>

## Only some fields

Ask for the fields you need to download less:

<CodeGroup>
```typescript TypeScript
const { data } = await pawabase.from("posts").select("id", "title");
```

```python Python
data = pb.from_("posts").select("id", "title").execute().data
```
</CodeGroup>

## Every record

`all()` follows the pages for you and returns everything that matches. Use it only for results you know are small.

<CodeGroup>
```typescript TypeScript
const everything = await pawabase.from("tags").all();
```

```python Python
everything = pb.from_("tags").all()
```
</CodeGroup>

## Plain-object style

If you prefer one call with options over chaining:

```typescript
const page = await pawabase.from("tasks").list({
  where: { done: false },
  sort: "-created_at",
  select: ["id", "title"],
  perPage: 50,
});
```

In Python: `pb.from_("tasks").list(where={"done": False}, sort="-created_at", select=["id", "title"], per_page=50)`. A `-` before a field means descending.
