`pawabase.from("table")` (`pb.from_("table")` in Python) starts a query on one table. Add filters and options, then run it. Every read is made **as the caller**: the signed-in person, a guest, a machine, or nobody. The table's `list` and `get` [access rules](/database/access) decide what comes back, so the same query safely returns different rows to different people.

<CodeGroup>
```typescript TypeScript
const { data } = await pawabase
  .from("tasks")
  .eq("done", false)
  .order("due_at")
  .limit(20);
```

```python Python
page = (
    pb.from_("tasks")
    .eq("done", False)
    .order("due_at")
    .limit(20)
    .execute()
)
page.data
```
</CodeGroup>

This page covers the ways to read. To narrow results see [Filter](/database/filter), and to order and paginate see [Sort and page](/database/sort-and-page).

## Ways to read

| You want | TypeScript | Python | Returns |
| --- | --- | --- | --- |
| A page of records | `await query` or `query.execute()` | `query.execute()` | a page |
| One record by id | `get(id)` | `get(id)` | the record, or `NotFoundError` |
| One record by id, maybe | `maybeGet(id)` | `maybe_get(id)` | the record or `null` / `None` |
| The first match | `first()` | `first()` | the record or `null` / `None` |
| The first match, required | `single()` | `single()` | the record, or `NotFoundError` |
| How many match | `count()` | `count()` | a number |
| Whether any match | `exists()` | `exists()` | a boolean |
| Every match | `all()` | `all()` | a list |
| Every match, one at a time | `for await (const row of query)` | `for row in query.iterate()` | rows, page after page |
| A page from plain options | `list({...})` | `list(...)` | a page |
| Records closest in meaning | `similar({...})` | `similar(...)` | records with a distance, see [Vector search](/ai/vector-search) |

## A page of records

<CodeGroup>
```typescript TypeScript
const page = await pawabase.from("tasks");
// the same as: await pawabase.from("tasks").execute()

page.data;       // the records
page.total;      // how many match for this caller, or null
page.page;       // 1
page.per_page;   // 20
```

```python Python
page = pb.from_("tasks").execute()

page.data        # list of dicts
page.total       # int or None
page.page        # 1
page.per_page    # 20
page.has_next    # whether another page follows
page.raw         # the response body as received

for task in page: ...        # a page iterates its records
len(page)
page[0]
```
</CodeGroup>

In TypeScript a query is also a promise, so `await` runs it. In Python, call `.execute()`. Nothing is sent until then.

A query returns one **page**, 20 records unless you ask for another size (at most 200). See [Sort and page](/database/sort-and-page).

### What `total` means

`total` is how many records match **for this caller**, across all pages. It is `null` when the table's read rule has to look at each record to decide, because then the database count would include records the caller may not see.

When `total` is `null`:

- a page can hold **fewer** records than `per_page` even though more follow, because records the caller may not see were taken out after the page was read;
- don't build "Page 3 of 12" from it. Use **Load more**, and stop when a page comes back empty;
- `count()` refuses rather than guess (see [Count and exists](#count-and-exists)).

Rules that compare a record's column to a value from the session (`record.owner_id` is `auth.user_id`) are turned into a database filter, so they keep `total` a number. See [How rules are evaluated](/policies/how-rules-are-evaluated).

## One record by id

<CodeGroup>
```typescript TypeScript
const task = await pawabase.from("tasks").get("01J…");            // throws NotFoundError if missing
const maybe = await pawabase.from("tasks").maybeGet("01J…");      // null if missing
const withOwner = await pawabase.from("tasks").get(id, { expand: ["owner"] });
```

```python Python
task = pb.from_("tasks").get("01J…")                    # raises NotFoundError if missing
maybe = pb.from_("tasks").maybe_get("01J…")              # None if missing
with_owner = pb.from_("tasks").get(task_id, expand=["owner"])
```
</CodeGroup>

A record that exists but that the caller's rule hides answers **not found** as well. That is on purpose: a refusal never tells someone a record exists. If a record you know exists comes back not found, check the `get` rule.

`maybeGet` only swallows "not found". Other errors (signed out, server down) still throw.

## The first match

<CodeGroup>
```typescript TypeScript
const latest = await pawabase.from("tasks").order("created_at", "desc").first();   // row or null
const profile = await pawabase.from("profiles").eq("user_id", user.id).single();    // row, or NotFoundError
```

```python Python
latest = pb.from_("tasks").order("created_at", "desc").first()     # dict or None
profile = pb.from_("profiles").eq("user_id", user["id"]).single()  # dict, or NotFoundError
```
</CodeGroup>

Both ask the server for one record. `single()` throws `NotFoundError` when nothing matches. It does **not** check that only one record matches: with several, it returns the first in the query's order. When "exactly one" matters (one profile per user), enforce it with a [unique index](/database/indexes) on the column.

Always add an `order` to `first()`. Without one, "first" is the first by id, which is rarely what you mean.

## Count and exists

<CodeGroup>
```typescript TypeScript
const open = await pawabase.from("tasks").eq("done", false).count();
const anyOpen = await pawabase.from("tasks").eq("done", false).exists();
```

```python Python
open_count = pb.from_("tasks").eq("done", False).count()
any_open = pb.from_("tasks").eq("done", False).exists()
```
</CodeGroup>

Both read one record. `count()` returns the page's `total`, so it counts what **this caller** may see. When the total is unknown (see [What `total` means](#what-total-means)), `count()` throws (`InvalidQueryError` in TypeScript, `QueryError` in Python) instead of returning a wrong number. For those tables, count with `all()` on a small result, or keep a counter column that a [flow](/logic/flows) updates.

`exists()` is always safe to call.

For a number a person shouldn't be able to work out from their own reads (orders across all customers), compute it on a server with a secret key or in a [route](/logic/routes).

## Only some columns

Name the columns you need to download less:

<CodeGroup>
```typescript TypeScript
const { data } = await pawabase.from("posts").select("id", "title", "published_at");
```

```python Python
data = pb.from_("posts").select("id", "title", "published_at").execute().data
```
</CodeGroup>

- The id is always included.
- Columns you leave out are left out of each record. In TypeScript the result type marks them optional.
- An unknown column name is refused.
- `select` saves bandwidth, not database work: the server still reads whole rows, because rules and related records may need columns you didn't ask for.

Columns marked **write only** (a hashed secret, an internal note) are never returned, whatever you select.

## Related records

`expand` adds records from [relations](/database/relations) declared on the table:

<CodeGroup>
```typescript TypeScript
const { data } = await pawabase.from("posts").expand("author", "comments").limit(10);
data[0].author;     // the related user record (belongs to)
data[0].comments;   // a list (has many)

const post = await pawabase.from("posts").get(id, { expand: ["author"] });
```

```python Python
page = pb.from_("posts").expand("author", "comments").limit(10).execute()
page.data[0]["author"]
post = pb.from_("posts").get(post_id, expand=["author"])
```
</CodeGroup>

Related records are read under **their own** table's read rule. A related record the caller may not see is left out, so a post whose author is hidden comes back with no author rather than failing. Repeated names are sent once.

## Everything that matches

`all()` follows the pages for you. Use it when you know the result is bounded, and set `maxRecords` as a safety stop.

<CodeGroup>
```typescript TypeScript
const tags = await pawabase.from("tags").all();
const paid = await pawabase.from("orders").eq("status", "paid").all({ pageSize: 200, maxRecords: 5000 });
```

```python Python
tags = pb.from_("tags").all()
paid = pb.from_("orders").eq("status", "paid").all(page_size=200, max_records=5000)
```
</CodeGroup>

For large results, iterate so memory stays flat:

<CodeGroup>
```typescript TypeScript
for await (const order of pawabase.from("orders").eq("status", "paid")) {
  await sendReceipt(order);
}
```

```python Python
for order in pb.from_("orders").eq("status", "paid").iterate():
    send_receipt(order)

# async client
async for order in apb.from_("orders").eq("status", "paid").iterate():
    await send_receipt(order)
```
</CodeGroup>

See [Walk through everything](/database/sort-and-page#walk-through-everything) for page-by-page loops and their options.

## One call with plain options

If you prefer one call over chaining, or the options come from a URL, use `list`:

<CodeGroup>
```typescript TypeScript
const page = await pawabase.from("tasks").list({
  where: { done: false, priority: { gte: 3 } },
  sort: "-created_at,id",          // a leading - means descending
  select: ["id", "title"],
  expand: ["owner"],
  page: 2,
  perPage: 50,
});
```

```python Python
page = pb.from_("tasks").list(
    where={"done": False, "priority": {"gte": 3}},
    sort="-created_at,id",
    select=["id", "title"],
    expand=["owner"],
    page=2,
    per_page=50,
)
```
</CodeGroup>

`paginate: false` (`paginate=False`) returns every match in one response instead; see [Turn paging off](/database/sort-and-page#turn-paging-off).

## Reusable queries

Queries are **immutable**: every method returns a new query, so you can build a base and branch from it without the branches affecting each other.

<CodeGroup>
```typescript TypeScript
const live = pawabase.from("posts").eq("status", "live");

const [newest, popular] = await Promise.all([
  live.order("published_at", "desc").limit(5),
  live.order("views", "desc").limit(5),
]);
```

```python Python
live = pb.from_("posts").eq("status", "live")

newest = live.order("published_at", "desc").limit(5).execute()
popular = live.order("views", "desc").limit(5).execute()
```
</CodeGroup>

`from("posts").query()` starts an empty query, which is handy for a function that receives a query and adds to it:

```typescript
import type { QueryBuilder } from "@pawabase/client";

function visibleTo(query: QueryBuilder<Post>, teamId: string) {
  return query.eq("team_id", teamId).is("archived_at", null);
}
const page = await visibleTo(pawabase.from("posts").query(), team.id).limit(20);
```

## Typed records (TypeScript)

With a generated `Database` type, `from()` knows each table's columns:

```typescript
import type { Database } from "./pawabase-types";
const pawabase = createClient<Database>({ url, project, apiKey, environment });

const { data } = await pawabase.from("posts").eq("status", "live");   // data: Post[]
pawabase.from("postz");                                               // type error
pawabase.from("posts").eq("statsu", "live");                          // type error
```

Generate the types with `npx pawabase-types`. See [TypeScript types](/database/typescript-types).

Without generated types, type one table by hand:

```typescript
interface Post { id: string; title: string; status: "draft" | "live" }
const posts = pawabase.resource<Post>("posts");
```

## Cancel and time out

<CodeGroup>
```typescript TypeScript
const controller = new AbortController();
const query = pawabase.from("orders").order("created_at", "desc").withOptions({
  signal: controller.signal,
  timeoutMs: 10_000,
});
cancelButton.onclick = () => controller.abort();
const page = await query;            // AbortError when cancelled, TimeoutError after 10 s

await pawabase.from("orders").get(id, { signal: controller.signal });
```

```python Python
# a timeout for every request of the client
pb = Pawabase(url, key, project=project, environment=env, timeout=10.0)

# cancel an async read
task = asyncio.create_task(apb.from_("orders").execute())
task.cancel()
```
</CodeGroup>

Reads are retried automatically after a network failure or a `502`/`503`/`504`, and after a rate limit, before you see an error.

## Reading in a React component

Abort in the effect's cleanup, so a component that unmounts or re-renders doesn't set state from an old query:

```tsx
import { AbortError } from "@pawabase/client";

function useTasks(done: boolean) {
  const [tasks, setTasks] = useState<Task[]>([]);
  const [error, setError] = useState<unknown>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    pawabase.from("tasks").eq("done", done).order("due_at").withOptions({ signal: controller.signal })
      .then((page) => setTasks(page.data as Task[]))
      .catch((e) => { if (!(e instanceof AbortError)) setError(e); })
      .finally(() => setLoading(false));
    return () => controller.abort();
  }, [done]);

  return { tasks, error, loading };
}
```

With TanStack Query, pass its `signal` through:

```tsx
const { data } = useQuery({
  queryKey: ["tasks", { done }],
  queryFn: ({ signal }) => pawabase.from("tasks").eq("done", done).withOptions({ signal }).then((p) => p.data),
});
```

## Reading on a server

On a server that renders pages for many people, read as **each** person, never as one shared signed-in client:

<CodeGroup>
```typescript TypeScript
const pawabase = createClient({ url, project, apiKey: process.env.PAWABASE_KEY!, environment });

export async function GET(req: Request) {
  const db = pawabase.asUser(readAccessToken(req));     // this request's person
  const { data } = await db.from("orders").eq("status", "open");
  return Response.json(data);
}
```

```python Python
pb = Pawabase(url, os.environ["PAWABASE_KEY"], project=project, environment=env)

@app.get("/orders")
def orders(request):
    db = pb.as_user(request.cookies.get("pb_access"))
    return db.from_("orders").eq("status", "open").execute().data
```
</CodeGroup>

A client made with a **secret** key reads every record, ignoring rules. Use it for jobs and reports, never for requests on someone's behalf.

## Advanced

### Read several tables at once

Independent reads don't need to wait for each other:

<CodeGroup>
```typescript TypeScript
const [orders, customers, stats] = await Promise.all([
  pawabase.from("orders").eq("status", "open").limit(10),
  pawabase.from("customers").order("created_at", "desc").limit(5),
  pawabase.from("orders").eq("status", "open").count(),
]);
```

```python Python
orders, customers, open_count = await asyncio.gather(
    apb.from_("orders").eq("status", "open").limit(10).execute(),
    apb.from_("customers").order("created_at", "desc").limit(5).execute(),
    apb.from_("orders").eq("status", "open").count(),
)
```
</CodeGroup>

### Avoid one request per row

Reading related records in a loop sends one request per row. Use `expand`, or collect the ids and read them in one query:

```typescript
// slow: one request per order
for (const order of orders) order.customer = await pawabase.from("customers").get(order.customer_id);

// one request
const ids = [...new Set(orders.map((o) => o.customer_id))];
const { data: customers } = await pawabase.from("customers").in("id", ids).limit(200);
```

An `in` list is sent in the URL, so keep it to a few hundred ids; for more, split it.

### Cached tables

A table with a cache time (the table's **Settings → Cache responses**, up to a day) answers identical list requests from cache until the time runs out or someone writes to the table through the API. Reads right after your own write are never stale, because the write clears the cache. See [Caching and rate limits](/database/caching-and-rate-limits).

### Live results

To keep a list on screen up to date as records change, subscribe to [record changes](/realtime/record-changes) or use a live query, which re-runs the list for you when the table changes.

### Read limits

| Limit | Value |
| --- | --- |
| Records per page | 1 to 200, default 20 |
| Records with paging off | 5000; more answers `400` |
| Search text | 200 characters, 10 words |
| Filters | one per column |

## What can go wrong

| Error (TypeScript / Python) | Status | Meaning |
| --- | --- | --- |
| `AuthenticationError` | 401 | The rule needs a signed-in user, or the session expired |
| `PermissionError` / `ForbiddenError` | 403 | Signed in, but the rule refused the list |
| `NotFoundError` | 404 | No such record, or the rule hides it, on `get` and `single` |
| `ValidationError` | 400, 422 | A filter value the server refused (a bad date), a page size over 200, an unknown column |
| `InvalidQueryError` / `QueryError` | before sending | A query the server would answer wrongly: two filters on one column, a comma in an `in` value, `count()` when the total is unknown |
| `RateLimitError` / `RateLimitedError` | 429 | Still rate limited after the automatic waits |
| `NetworkError`, `TimeoutError` | none | Couldn't reach the server |

```typescript
import { NotFoundError, PermissionError } from "@pawabase/client";

try {
  return await pawabase.from("projects").get(id);
} catch (error) {
  if (error instanceof NotFoundError) return notFoundPage();
  if (error instanceof PermissionError) return askToJoinProject();
  throw error;
}
```

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| A list is empty but Studio shows rows | The `list` rule hides them from this caller | Open **Access rules → Test** and try the caller |
| `get` says not found for a real id | The `get` rule hides it | Same as above |
| `total` is `null` | A per-row rule | See [What `total` means](#what-total-means) |
| `count()` throws "cannot count" | The same | Count with `all()`, or keep a counter |
| Pages are short but more follow | The same | Load more until a page is empty |
| A related record is missing from `expand` | Its own table's rule hides it | Check that table's `get` rule |
| Results are stale | A cache time on the table and writes from outside the API (SQL editor, imports) | Shorten the cache, or write through the API |
| Reads are slow on a big table | No index on the filtered or sorted column | Add an [index](/database/indexes) |
