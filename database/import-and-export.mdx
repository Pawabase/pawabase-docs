## Import in Studio

On a table's **Data** tab choose **Import**. The wizard has three parts.

**1. The file.** *A CSV needs a header row. A JSON file is an array of objects. Up to a few hundred thousand rows works in the browser.* Columns are matched to the table's columns by name.

**2. What to do with a row that already exists.**

| Option | Meaning |
| --- | --- |
| **Add every row as a new record** (`insert`) | Every row becomes a new record. Rows that clash with a unique value fail |
| **Update the existing record, and add the rest** (`upsert`) | Rows are matched by a **key column** you choose; matches are updated, the rest added |

**3. Events.** **Run events, flows and realtime for each row** is *off by default: a bulk import should not send a welcome email for every row.* Turn it on only when you want each row to behave like a normal create.

Use **dry run** first: it validates every row against the column rules and reports a **Row** and **Problem** for each failure without writing anything. Then run it for real. Large files go in chunks, and the report shows how many rows were created, updated and failed.

## Move data between environments

Remember: definitions move with **promote**; data moves only when you export and import it. Never copy real customer data into a development environment without anonymising it.

## Seeding

Keep a seed script in your repository, using `importRecords` with `mode: "upsert"` and a stable `key`. It can be re-run safely: existing rows update instead of duplicating.

## Common problems

| Symptom | Cause |
| --- | --- |
| Rows fail with "must not be empty" | A required column is blank in the file |
| Dates rejected | Use ISO 8601 (`2026-10-01T10:00:00Z`) |
| Duplicates | Use `upsert` with the right key column |
| Booleans become text | In CSV, use `true` / `false` |
| Welcome emails sent to everyone | Events were on; keep them off for imports |
