Add filter methods before you run the query. Several filters are combined with **and**.

## The filters

<CodeGroup>
```typescript TypeScript
pawabase.from("tasks")
  .eq("done", false)               // equal
  .neq("owner_id", user.id)        // not equal
  .gt("priority", 2)               // greater than
  .gte("priority", 3)
  .lt("due_at", new Date())        // less than (dates are accepted)
  .lte("estimate", 8)
  .like("title", "Write%")         // case-sensitive pattern
  .ilike("title", "%docs%")        // case-insensitive pattern
  .in("status", ["open", "blocked"])
  .notIn("status", ["archived"])
  .is("deleted_at", null)          // is null (or true/false)
  .isNot("assignee_id", null);     // is not null
```

```python Python
(pb.from_("tasks")
   .eq("done", False)
   .neq("owner_id", user_id)
   .gt("priority", 2)
   .gte("priority", 3)
   .lt("due_at", now)
   .lte("estimate", 8)
   .like("title", "Write%")
   .ilike("title", "%docs%")
   .in_("status", ["open", "blocked"])
   .not_in("status", ["archived"])
   .is_("deleted_at", None)
   .is_not("assignee_id", None))
```
</CodeGroup>

`%` in `like` and `ilike` matches any run of characters. In Python, `in_` and `is_` have trailing underscores because `in` and `is` are keywords.

To test for null, use `is` and `isNot`. `eq("x", null)` is rejected, since null never equals anything.

## Several conditions as an object

```typescript
const { data } = await pawabase.from("tasks").where({
  done: false,
  priority: { gte: 3 },
  status: { in: ["open", "blocked"] },
  deleted_at: { is: null },
});
```

Python takes keyword arguments or a dict: `pb.from_("tasks").where(done=False, priority={"gte": 3})`.

A plain value means "equal". An object picks an operator: `eq`, `neq`, `gt`, `gte`, `lt`, `lte`, `like`, `ilike`, `in`, `nin`, `is`, `isnot`.

## An empty list matches nothing

`in("id", [])` returns no rows at once, without a request. That is usually what you want when a list of ids is empty.

## Search box

```typescript
function search(term: string) {
  return pawabase.from("posts").ilike("title", `%${term}%`).order("created_at", "desc").perPage(10);
}
```

Debounce the input, so you do not send a query on every key press.

## Filters and access rules

Filters narrow what you ask for; access rules decide what you are allowed to see. A filter can never reveal rows a rule hides. If you ask for `owner_id = someone else`, you simply get nothing.
