You will build a `tasks` table where each person sees only their own tasks. Do the Studio steps first, then use the code.

## 1. Create the table

<Tabs>
  <Tab title="In Studio">
    1. Open **Data** (under **Data**) in the `development` environment.
    2. Click **Create table**. Name it `tasks`.
    3. On the **Columns** tab add:
       - `title`, type **Text (short)**, **Required**.
       - `done`, type **Yes / no**, default **No**.
       - `owner_id`, type **Text (short)** (this will hold the user's id).
    4. Save. Studio shows the change as a **pending migration**; apply it. The table now exists, and appears in the sidebar tagged `resource`.
  </Tab>
  <Tab title="In code">
    ```typescript
    import { createClient } from "@pawabase/client";
    import { manage } from "@pawabase/client/manage";

    const m = manage(createClient({ url, apiKey: process.env.PAWABASE_SECRET_KEY!, environment: "development" }));

    await m.resources.create({
      name: "tasks",
      owner_field: "owner_id",
      fields: [
        { name: "title", type: "string", required: true },
        { name: "done", type: "boolean", default: false },
      ],
      operations: {},
    });
    await m.resources.migrate("tasks");     // create the table
    ```

    ```python
    pb.manage.resources.create({
        "name": "tasks",
        "owner_field": "owner_id",
        "fields": [
            {"name": "title", "type": "string", "required": True},
            {"name": "done", "type": "boolean", "default": False},
        ],
        "operations": {},
    })
    pb.manage.resources.migrate("tasks")
    ```
  </Tab>
</Tabs>

A definition does not create the table by itself; the **migrate** step does. In Studio that is the **pending migration**. See [Migrations and history](/database/migrations-and-history).

## 2. Say who can do what

A new table is private. Open it and choose the **Access** tab.

<Tabs>
  <Tab title="In Studio">
    Under **Quick access set**, choose **Each user sees and changes their own records**. Studio fills in all five actions (list, get, create, update, delete) and warns you if anything is wider than you intended. Save.
  </Tab>
  <Tab title="In code">
    ```typescript
    await m.resources.replace("tasks", {
      name: "tasks",
      owner_field: "owner_id",
      fields: [
        { name: "title", type: "string", required: true },
        { name: "done", type: "boolean", default: false },
      ],
      operations: {
        list:   { enabled: true, policy: "owner" },
        get:    { enabled: true, policy: "owner" },
        create: { enabled: true, policy: "authenticated" },
        update: { enabled: true, policy: "owner" },
        delete: { enabled: true, policy: "owner" },
      },
    });
    ```
  </Tab>
</Tabs>

`owner_field` tells Pawabase which column holds the owner. It is filled with the caller's id when they create a record, and the `owner` rule compares it with the caller on every read and write. See [Access](/database/access).

## 3. Use it from your app

Sign a user in (see [Auth](/auth/overview)), then:

<CodeGroup>
```typescript TypeScript
const created = await pawabase.from("tasks").create({ title: "Write the docs" });
created.owner_id === (await pawabase.auth.getUser()).id;   // true: filled in for you

const { data } = await pawabase.from("tasks").eq("done", false).order("created_at", "desc");

await pawabase.from("tasks").update(created.id, { done: true });
```

```python Python
created = pb.from_("tasks").create(title="Write the docs")

tasks = pb.from_("tasks").eq("done", False).order("created_at", "desc").execute().data

pb.from_("tasks").update(created["id"], done=True)
```
</CodeGroup>

Sign in as a second user and list `tasks`: you get nothing of the first user's. That is the rule working.

## 4. Look at it in Studio

On the table's **Data** tab you see the rows both users created. Studio acts with its own authority, so it sees all rows. Try the **API Explorer** to send the same requests by hand.

## What you have now

- A table, a matching API, and per-user access rules.
- A `development` copy you can change freely. When you are ready, [promote](/environments/overview) the definition to `production`.
