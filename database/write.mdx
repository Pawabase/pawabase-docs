Writes return the saved record, so you can show the server's version (with its `id`, timestamps and defaults) without another read. Every write is checked against the table's `create`, `update` or `delete` [rule](/database/access) and against the columns' rules.

## Create

<CodeGroup>
```typescript TypeScript
const task = await pawabase.from("tasks").create({ title: "Write the docs", done: false });
task.id;           // assigned by the server
task.created_at;
task.owner_id;     // filled in if the table has an owner field
```

```python Python
task = pb.from_("tasks").create(title="Write the docs", done=False)
task["id"], task["created_at"], task["owner_id"]
```
</CodeGroup>

Leave out `id`, `created_at` and `updated_at`. If the table has an [owner field](/database/ids-and-timestamps#the-owner-column), it is filled with the caller's id.

## Update some fields

<CodeGroup>
```typescript TypeScript
const updated = await pawabase.from("tasks").update(task.id, { done: true });
await pawabase.from("tasks").update(task.id, { assignee_id: null });   // null clears a field
```

```python Python
updated = pb.from_("tasks").update(task["id"], done=True)
pb.from_("tasks").update(task["id"], assignee_id=None)
```
</CodeGroup>

`update` changes only the fields you send. Sending `null` clears a field, even one marked required at create time, so validate in your form.

## Replace

`replace` writes the whole record: fields you leave out return to their defaults.

<CodeGroup>
```typescript TypeScript
await pawabase.from("settings").replace(settings.id, { theme: "dark", language: "en" });
```

```python Python
pb.from_("settings").replace(settings["id"], theme="dark", language="en")
```
</CodeGroup>

Prefer `update` unless you mean "this is the complete new record".

## Delete

<CodeGroup>
```typescript TypeScript
await pawabase.from("tasks").delete(task.id);
```

```python Python
pb.from_("tasks").delete(task["id"])
```
</CodeGroup>

Deleting a record that's gone, or one you may not delete, throws `NotFoundError`. There's no recycle bin: for "undo", use a [soft delete](/database/patterns#soft-delete).

## Validation errors

The server checks required columns, types and constraints before your rules run, and tells you which column is wrong:

<CodeGroup>
```typescript TypeScript
try {
  await pawabase.from("tasks").create({ title: "" });
} catch (e) {
  if (e instanceof ValidationError) {
    e.fieldError("title");   // "must not be empty"
    e.byField();             // { title: ["must not be empty"] }
    e.issues;                // [{ field, message }]
  }
}
```

```python Python
try:
    pb.from_("tasks").create(title="")
except ValidationError as e:
    print(e)
```
</CodeGroup>

Show `fieldError("email")` under each input. Define the rules once, in [Columns and types](/database/columns-and-types), and they apply to every client.

A taken unique value (a duplicate username) is a `ConflictError`:

```typescript
catch (e) { if (e instanceof ConflictError) setErrors({ username: ["Taken"] }); }
```

## What each write needs

| Call | Rule checked | Common errors |
| --- | --- | --- |
| `create` | `create` | `ValidationError`, `ConflictError`, `PermissionError` |
| `update`, `replace` | `update` | `NotFoundError` (missing or hidden), `ValidationError`, `ConflictError` |
| `delete` | `delete` | `NotFoundError` |

## Optimistic updates

Update the screen first, confirm with the server, roll back on failure:

```typescript
async function toggle(task: Task) {
  setTasks((all) => all.map((t) => (t.id === task.id ? { ...t, done: !t.done } : t)));
  try {
    await pawabase.from("tasks").update(task.id, { done: !task.done });
  } catch {
    setTasks((all) => all.map((t) => (t.id === task.id ? task : t)));
    toast("Couldn't save that change.");
  }
}
```

## Avoid duplicate creates

A double-click or a retry can create two records. Two defences:

1. A **unique** column on a natural key (`order_number`, or an idempotency key you generate on the client), so the second attempt is a `ConflictError` you can treat as success.
2. Disable the button while the request is in flight.

```typescript
const key = crypto.randomUUID();
try {
  await pawabase.from("orders").create({ idempotency_key: key, ...order });
} catch (e) {
  if (!(e instanceof ConflictError)) throw e;   // already created
}
```

The client doesn't retry a `POST` after a network drop by itself, to avoid exactly this.

## Concurrent edits

Two people editing the same record: the last write wins. To detect it, send the `updated_at` you read and check it on the server (a [route](/logic/routes)), or make fields independent so edits don't collide.

## Realtime echo

If the table broadcasts changes, you receive your own write back as a message. Merge by `id` so you don't add it twice ([Live records](/realtime/record-changes)).
