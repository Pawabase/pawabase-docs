<Note>
  Bringing your own database is in **beta**. It works end to end, but expect rough edges, and try it on a new project before moving a
  production one. Tell us what breaks.
</Note>

A project can use a Postgres database you run yourself: on your own server, in your office, or in your own cloud account. You don't
give Pawabase the database's address or password. Instead you run **pawabase-connector**, a small program, next to the database.

The connector connects **out** to Pawabase, so you open no port and the database stays private. When Pawabase needs the database, it
asks through that one encrypted connection, and the connector logs in itself with the address only it knows. Your tables, flows,
policies, the REST API and Studio then work exactly as they do on Pawabase's own database.

```
 your network                                         Pawabase
┌─────────────────────────────────┐            ┌───────────────────────────┐
│ Postgres ◄── pawabase-connector │  outbound  │ your project's API, flows, │
│ (stays        (holds the        │──────────►│ policies and Studio        │
│  private)      password)        │  encrypted │                            │
└─────────────────────────────────┘            └───────────────────────────┘
```

## What you need

- **Postgres** 12 or newer, reachable from the machine where the connector runs (usually the database server itself).
- **A machine for the connector**: Linux or macOS (x86-64 or ARM), Windows, or anywhere Docker runs.
- **Outbound HTTPS** from that machine to your Pawabase address. Nothing has to reach in.

## Connect a project

<Steps>
  <Step title="Create a role for Pawabase">
    Give Pawabase a role of its own, never a superuser. Pawabase keeps each environment in a schema of its own, so the role needs
    to create schemas in the database:

    ```sql
    CREATE ROLE pawabase LOGIN PASSWORD 'a long random password';
    GRANT CONNECT, CREATE ON DATABASE app TO pawabase;
    ```

    Pawabase can do whatever this role may do in this database, and nothing more.
  </Step>
  <Step title="Make a connector in Studio">
    Open **Settings → Database** and choose **Make a connector**. Studio shows a one-time token (`pbce_…`) and the commands for your
    machine. The token works once, for 24 hours.
  </Step>
  <Step title="Install it next to the database">
    Run the commands Studio shows. They look like this:

    <Tabs>
      <Tab title="macOS and Linux">
        ```bash
        curl -fsSL https://raw.githubusercontent.com/Pawabase/pawabase-connector/main/install.sh | sh
        sudo pawabase-connector enroll --server https://api.your-project.example --token pbce_…
        sudo pawabase-connector service install
        ```
      </Tab>
      <Tab title="Windows">
        ```powershell
        irm https://raw.githubusercontent.com/Pawabase/pawabase-connector/main/install.ps1 | iex
        # then, in a PowerShell window opened as Administrator:
        pawabase-connector enroll --server https://api.your-project.example --token pbce_…
        pawabase-connector service install
        ```
      </Tab>
      <Tab title="Docker">
        ```bash
        docker run -d --name pawabase-connector --restart unless-stopped \
          -v pawabase-connector:/var/lib/pawabase-connector \
          -e PAWABASE_SERVER=https://api.your-project.example \
          -e PAWABASE_CONNECTOR_TOKEN=pbce_… \
          -e DATABASE_URL='postgres://pawabase:password@db:5432/app' \
          ghcr.io/pawabase/pawabase-connector:latest
        ```
      </Tab>
    </Tabs>

    `enroll` asks for your database's address (the input is hidden), checks that it can log in, and swaps the token for the
    connector's own key. `service install` runs it in the background and starts it with the machine: systemd on Linux, launchd on
    macOS, a Windows service on Windows.
  </Step>
  <Step title="Use it">
    When Studio shows the connector as **Connected**, choose **Use this database**. From then on every environment of the project
    reads and writes your database.
  </Step>
</Steps>

<Warning>
  Switching moves no data. Tables already in Pawabase's own database stay there and are not visible through your database. Switch a
  new project, or copy your data across first.
</Warning>

## What Pawabase keeps

| Kept by Pawabase | Kept only on your machine |
| --- | --- |
| The connector's name, status and version | Your database's address |
| What it reports: database name, role name, Postgres version, the machine's name and system | The database password |
| A hash of the connector's key | The connector's key itself |

The installers check every download against the published checksums before installing it.

## When the connector stops

If the connector stops, or its machine loses its connection, requests for the project's data fail with a clear message:

```json
"this project's database cannot be reached: the project's database connector is offline (last seen …): start pawabase-connector next to the database"
```

Nothing is lost. The connector reconnects on its own, and requests work again as soon as it does. To start it by hand:
`pawabase-connector service start`.

## Remove it

In **Settings → Database**, choose **Remove**:

- the connector's key stops working at once, and its connection closes;
- the project goes back to the database it used before;
- your data stays in your database.

On the machine, `pawabase-connector service uninstall` removes the service.

## Commands

| Command | What it does |
| --- | --- |
| `pawabase-connector enroll --server URL --token TOKEN` | Swap the one-time token for the connector's key, and save the database address (asked for, hidden). |
| `pawabase-connector run` | Run in the foreground, logging to the terminal. |
| `pawabase-connector status` | Show what it is set up to do, and check the database, Pawabase and the service. |
| `pawabase-connector service install` / `uninstall` / `start` / `stop` / `restart` | Manage the background service. |
| `pawabase-connector version` | Print its version. |

The configuration (Pawabase's address, the connector's key and your database address) is one file that only its owner can read:
`/etc/pawabase-connector/config.json` on Linux, `/Library/Application Support/pawabase-connector/config.json` on macOS and
`%ProgramData%\pawabase-connector\config.json` on Windows. To keep the address out of the file, set `DATABASE_URL` in the service's
environment instead: it overrides the saved one.

## From the API

The same steps are available with a secret key, on any environment of the project:

| Request | What it does |
| --- | --- |
| `GET /platform/v1/envs/{env}/database/connector` | The connector, its status and whether the project uses it. |
| `POST /platform/v1/envs/{env}/database/connector` | Make one. Returns the one-time token and the install commands. |
| `POST /platform/v1/envs/{env}/database/connector/use` | Switch the project to it. It must be connected. |
| `DELETE /platform/v1/envs/{env}/database/connector` | Remove it and switch the project back. |
