The first `subscribe()` opens a WebSocket for you, and the SDK keeps it healthy: it sends heartbeats, reconnects after a drop and rejoins your channels. You rarely manage it directly, but you can observe and tune it.

## Status

<CodeGroup>
```typescript TypeScript
console.log(pawabase.realtime.status);   // "idle" | "connecting" | "open" | "reconnecting" | "closed"

const stop = pawabase.realtime.onStatusChange((status) => {
  banner.hidden = status === "open";
});
```

```python Python
# Channels report their own state
room.subscribed          # True while joined
room.on("closed", lambda reason: show_offline())
```
</CodeGroup>

Show a small "reconnecting" indicator when the status is not `open`. The SDK resubscribes by itself when it comes back.

## Open and close by hand

<CodeGroup>
```typescript TypeScript
await pawabase.realtime.connect();    // resolves when the server has welcomed you
pawabase.realtime.disconnect();       // close and stop reconnecting
```

```python Python
await pb.realtime.connect()
await pb.realtime.close()
```
</CodeGroup>

Call `disconnect` (or close the Python client with `async with`) when you discard a client, such as on sign-out, so timers stop.

## Options (TypeScript)

Pass `realtime` to `createClient`:

```typescript
const pawabase = createClient({
  url, apiKey,
  realtime: {
    heartbeatSeconds: 25,
    ackTimeoutMs: 10_000,
    connectTimeoutMs: 10_000,
    reconnect: { baseDelayMs: 500, maxDelayMs: 15_000, maxAttempts: 20 },
  },
});
```

| Option | Default | Meaning |
| --- | --- | --- |
| `heartbeatSeconds` | 25 | Ping interval. The connection is recycled after two silent intervals |
| `ackTimeoutMs` | 10000 | How long to wait for the server to accept a request |
| `connectTimeoutMs` | 10000 | How long to wait for the connection to open |
| `reconnect` | on | Backoff settings, or `false` to stay closed after a drop |
| `webSocket` | built-in | A WebSocket class, for older Node: pass `ws` |

In Node versions without a built-in WebSocket, install `ws` and pass it as `webSocket`.

## Signing in and out

The connection follows the user. When the access token refreshes, the SDK keeps the socket alive; when the user signs out, channels that needed a user close. After a new sign-in, subscribe again.

## One-way streams

When you only need to **listen**, such as a dashboard or a server process, use Server-Sent Events over plain HTTP. There is no socket to manage and it passes through strict proxies.

<CodeGroup>
```typescript TypeScript
for await (const frame of pawabase.realtime.stream(["chat:lobby", "order:42"])) {
  if (frame.type === "message") show(frame.payload);
}
```

```python Python
for frame in pb.realtime.sse(["chat:lobby", "order:42"]):     # async for on the async client
    if frame["type"] == "message":
        show(frame["payload"])
```
</CodeGroup>

Frames are `welcome`, `message` and `presence_diff`. A stream holds at most 20 channels. Send with `publish`. Pass an `AbortSignal` (TypeScript) or break out of the loop to stop.

## Errors

| Situation | What you see |
| --- | --- |
| Channel rule refuses you | `subscribe()` or `send()` throws `RealtimeError` |
| Connection lost | Status moves to `reconnecting`; channels emit `closed` then resubscribe |
| Wrong key or project | The connection closes and does not retry |
| Server unreachable | Reconnect attempts back off until `maxAttempts` |
