A channel can keep a short backlog of recent messages. It lets a screen open with context (the last 50 chat messages) and lets a client that lost its connection catch up.

History is turned on per channel by its [rule](/realtime/channel-rules) with `history: <count>`, up to 1000 messages. With no history set, nothing is kept.

## Load recent messages

<CodeGroup>
```typescript TypeScript
const room = pawabase.realtime.channel("chat:lobby");
const recent = await room.history(50);               // oldest first
// or without a channel object
const same = await pawabase.realtime.history("chat:lobby", 50);
```

```python Python
recent = pb.realtime.history("chat:lobby", limit=50)   # oldest first; works on the sync client
# on a live channel
recent = await room.history(50)
```
</CodeGroup>

Each message has a `seq`, increasing along the channel, so you can order them and remember where you stopped.

A good chat screen does this:

1. Subscribe, so new messages start arriving.
2. Load history.
3. Render history first, then live messages, skipping any id you already have.

```typescript
const seen = new Set<string>();
const add = (m) => { if (!seen.has(m.id)) { seen.add(m.id); messages.push(m); } };

room.onEvent("message", add);
await room.subscribe();
(await room.history(50)).forEach(add);
```

## Catch up after a disconnect

Connections drop: a phone goes through a tunnel, a laptop sleeps. The SDK reconnects by itself. Ask it to replay what you missed with `replay`:

<CodeGroup>
```typescript TypeScript
const room = pawabase.realtime.channel("chat:lobby", { replay: 100 });
```

```python Python
room = pb.realtime.channel("chat:lobby", replay=100)
```
</CodeGroup>

After each reconnect, the SDK fetches up to that many recent messages and delivers those you did not already receive. Duplicates are removed by message id, so your handler sees each message once. With `replay` unset, only messages sent while you were connected are delivered.

Replay is bounded by the channel's history size. If someone was away longer than the backlog covers, reload the screen's data from your records instead.

## History and access

History is read with the same rights as subscribing. If you may not join the channel, you cannot read its backlog.

## When not to rely on history

History is a short convenience, not storage. For anything users expect to find tomorrow, such as chat logs, orders and notifications, save a [record](/data/resources/overview) and use the channel to announce it. Then a missed message costs nothing: the app reads the record.
