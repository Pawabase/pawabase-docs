Presence answers "who is here right now?" Each person on a channel can attach small details, such as a name, an avatar or the page they're on, and everyone on the channel sees the list change live. An entry disappears when its connection leaves.

<CodeGroup>
```typescript TypeScript
const doc = pawabase.realtime.channel("doc:abc", { presence: { name: "Ada", color: "#FF6A00" } });

doc.on("presence", ({ joins, leaves, members }) => renderAvatars(members));
await doc.subscribe();
```

```python Python
doc = pb.realtime.channel("doc:abc", presence={"name": "Ada", "color": "#FF6A00"})
doc.on_presence(lambda joins, leaves: render_avatars(doc.presence_state()))
await doc.subscribe()
```
</CodeGroup>

## Turn it on

Presence is **on** for every channel unless its rule turns it off. To check or change it, open **Realtime → Channels**, choose the rule that covers the channel, and set **Presence** (*Track who is on the channel*). The same switch is **Show who is here** for a rule under **Realtime → Settings**.

On a channel whose rule has presence off, details passed when subscribing are ignored, `track` is refused with `forbidden` "presence is off for this channel", and `presenceState()` stays empty.

## Join with details

Pass your details when you get the channel. They are sent when you subscribe, and again after every reconnect:

<CodeGroup>
```typescript TypeScript
const me = (await pawabase.auth.getCachedUser())!;
const room = pawabase.realtime.channel("room:design", {
  presence: { name: me.name, avatar: me.avatar_url, status: "online" },
});
await room.subscribe();
```

```python Python
room = pb.realtime.channel("room:design", presence={"name": user["name"], "status": "online"})
await room.subscribe()
```
</CodeGroup>

Your details are at most **2 KB** of JSON. Keep them to what others need to draw you: a name, an avatar address, a colour, the section you're viewing.

## Who is here

<CodeGroup>
```typescript TypeScript
room.on("presence", ({ joins, leaves, members }) => {
  joins.forEach((m) => toast(`${m.meta.name} joined`));
  leaves.forEach((m) => toast(`${m.meta.name} left`));
  renderAvatars(members);           // everyone present after this change
});

room.presenceState();               // everyone present now
```

```python Python
def on_presence(joins, leaves):
    for member in joins:
        print(member["meta"]["name"], "joined")
    render(room.presence_state())   # everyone present now

room.on_presence(on_presence)
```
</CodeGroup>

When you join, you first get everyone already there (in TypeScript, as one `presence` event whose `joins` is the whole list). After that, each event holds only what changed.

Each member has:

| Field | Meaning |
| --- | --- |
| `presence_ref` | An id for this one connection on this channel |
| `user_id` | The signed-in person's id, or `null` for an anonymous visitor |
| `meta` | The details they attached |
| `online_at` | When they joined |

The server sets `user_id`, so nobody can appear as someone else. `meta` is whatever the person sent, so don't trust it for anything that matters: draw a name from `meta`, but decide permissions from `user_id`.

## One avatar per person

The same person on two devices, or in two tabs, appears **twice**, with different `presence_ref`s. Group by `user_id`:

```typescript
function people(members: PresenceMember<{ name: string; avatar?: string }>[]) {
  const byUser = new Map<string, (typeof members)[number]>();
  for (const m of members) {
    const key = m.user_id ?? m.presence_ref;   // anonymous visitors stay separate
    if (!byUser.has(key)) byUser.set(key, m);
  }
  return [...byUser.values()];
}
```

## Update your details

<CodeGroup>
```typescript TypeScript
await room.track({ name: "Ada", avatar, status: "away" });
```

```python Python
await room.track({"name": "Ada", "status": "away"})
```
</CodeGroup>

Subscribe first. `track` replaces your details (it doesn't merge), and everyone gets a presence change. The new details are also kept for reconnects.

Presence is for details that change slowly. For fast signals, like a cursor or "typing…", send messages instead, which don't rewrite the roster each time:

```typescript
let last = 0;
input.addEventListener("input", () => {
  if (Date.now() - last < 2000) return;   // at most every 2 seconds
  last = Date.now();
  room.send("typing", { on: true });
});
room.onEvent("typing", (m) => showTyping(m.from));
```

## Read the roster without joining

<CodeGroup>
```typescript TypeScript
const members = await pawabase.realtime.presence("doc:abc");
```

```python Python
members = pb.realtime.presence("doc:abc")    # works on the blocking client
```
</CodeGroup>

A normal HTTP request, useful for "3 people viewing" on a list page, or on a server rendering a page before the browser connects. The channel's subscribe rule applies.

## When someone leaves

- **Unsubscribing** or **closing the connection** removes the entry at once.
- A connection that **drops without closing** (a laptop lid, a lost signal) is removed when it stops answering heartbeats, within about 45 seconds.
- After a reconnect, the client joins again with its details, so the person reappears.

Show "away" from your own data (no activity for a few minutes) rather than from presence alone.

## In React

```tsx
function useRoster<M>(channelName: string, me: M) {
  const [members, setMembers] = useState<PresenceMember<M>[]>([]);

  useEffect(() => {
    const channel = pawabase.realtime.channel<unknown, M>(channelName, { presence: me as Record<string, unknown> });
    const off = channel.on("presence", ({ members }) => setMembers(members));
    channel.subscribe();
    return () => { off(); channel.unsubscribe(); };
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [channelName]);

  return members;
}

function Viewers({ docId }: { docId: string }) {
  const me = useMe();
  const members = useRoster(`doc:${docId}`, { name: me.name, avatar: me.avatar_url });
  return <AvatarStack people={people(members)} />;
}
```

## Patterns

- **Who's viewing this record:** a channel per record (`doc:<id>`), presence with name and avatar.
- **Online now in a team:** a channel per organization (`org:{{ auth.org }}` in the rule), presence with a status.
- **Seats in a live session:** the rule's **Subscriber limit** caps how many can join.
- **Support agents available:** presence with `{ available: true }` on `support:agents`, and your routing reads `presence("support:agents")`.

## Limits

| Limit | Value |
| --- | --- |
| Details per member | 2 KB |
| Removal after a dropped connection | about 45 seconds |
| Members on a channel | the rule's **Subscriber limit**, if set |

## See it in Studio

In **Realtime → Playground**, join a channel and watch members appear under **Present**. **Realtime → Connections** shows who is connected and which channels they joined.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| The roster stays empty | Presence is off on the channel's rule | Turn **Presence** on |
| Everyone appears twice | Each tab or device is a member | Group by `user_id` |
| `payload_too_large` on `track` | Details over 2 KB | Send less; keep big data in records |
| People stay "online" after leaving | Their connection dropped without closing | They disappear within about 45 s |
| `forbidden` "subscribe to the channel first" on `track` | Not subscribed yet | `await subscribe()` first |
| `forbidden` "presence is off for this channel" | The rule has presence off | Turn **Presence** on |
