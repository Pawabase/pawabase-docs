---
title: "Record changes"
description: "Keep a list live as records are created, updated and deleted, with each change sent only to people allowed to read that record."
icon: "database"
---

Instead of polling, subscribe to a resource and the list updates itself. When a record is created, updated or deleted, subscribers hear about it on the channel `resource:<name>`.

## Turn it on

Realtime is a setting on the resource: `realtime: true`. Set it when you define the resource, or flip it later in the dashboard on the resource's Realtime switch.

```typescript
await m.resources.create({
  name: "notes",
  realtime: true,
  owner_field: "owner_id",
  fields: [{ name: "text", type: "string", required: true }],
  operations: {
    list: { enabled: true, policy: "owner" },
    get: { enabled: true, policy: "owner" },
    create: { enabled: true, policy: "authenticated" },
  },
});
```

Every change made through the API or a flow publishes a message. Direct edits in the database console do not.

## Listen

<CodeGroup>
```typescript TypeScript
const notes = pawabase.realtime.channel<{ resource: string; change: string; record: Note }>("resource:notes");

notes.on("message", ({ event, payload }) => {
  if (event === "created") list.add(payload.record);
  if (event === "updated") list.replace(payload.record);
  if (event === "deleted") list.remove(payload.record.id);
});

await notes.subscribe();
```

```python Python
notes = pb.realtime.channel("resource:notes")

def on_change(message):
    record = message["payload"]["record"]
    if message["event"] == "created":
        add(record)
    elif message["event"] == "updated":
        replace(record)
    elif message["event"] == "deleted":
        remove(record["id"])

notes.on("message", on_change)
await notes.subscribe()
```
</CodeGroup>

| `event` | When | `payload.record` |
| --- | --- | --- |
| `created` | A record was created | The new record |
| `updated` | A record was changed | The record as it is now |
| `deleted` | A record was removed | The record as it was before |

The payload also carries `resource` (the name) and `change` (same as `event`).

## Who receives what

Subscribing to `resource:notes` does not by itself show anyone anything. For every change and every subscriber, Pawabase checks the resource's **read policy** with that subscriber's identity, twice:

1. against the record in the change, and
2. against the record as it is now, so a record that was just handed to someone else is not sent to someone who could read it a moment ago.

With the `notes` definition above, Ada hears about her notes and Bob about his. Neither learns the other's exist. Fields marked write-only and columns the resource does not declare are removed from the message, the same as in an API response.

You cannot publish on `resource:*` channels. Only the platform does.

## A complete live list

Load, then listen, then reconcile after reconnects:

```typescript
const { data: initial } = await pawabase.from("notes").order("created_at", "desc");
const items = new Map(initial.map((n) => [n.id, n]));

const channel = pawabase.realtime.channel("resource:notes", { replay: 100 });
channel.on("message", ({ event, payload }) => {
  if (event === "deleted") items.delete(payload.record.id);
  else items.set(payload.record.id, payload.record);
  render([...items.values()]);
});
await channel.subscribe();
```

The `replay` option fills in changes made while the connection was down, within the backlog's size. Changes are filtered for you exactly as live ones are.

## Doing something on the server instead

Record changes are for connected clients. To run work when a record changes, such as sending an email, use the resource's [events](/events/overview) with a [flow](/flows/overview).
