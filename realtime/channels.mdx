A channel is a name. Everyone subscribed receives what is sent to it. Use a prefix and an id so rules can match groups: `chat:lobby`, `order:42`, `doc:abc`.

Which channels a person may join, and who may send, is decided by **channel rules** an administrator sets in the dashboard under **Realtime**. By default signed-in users may join and send.

## Subscribe and listen

<CodeGroup>
```typescript TypeScript
const room = pawabase.realtime.channel("chat:lobby");

const stop = room.onEvent("message", (m) => {
  console.log(m.from, m.payload, m.sent_at);
});

await room.subscribe();
// later
stop();                      // stop this listener
await room.unsubscribe();    // leave
```

```python Python
room = pb.realtime.channel("chat:lobby")
room.on("message", lambda m: print(m["from"], m["payload"]))
await room.subscribe()
# later
await room.unsubscribe()
```
</CodeGroup>

Asking for the same channel twice returns the same object, so parts of your app share one subscription. The first `subscribe()` opens the connection.

## What a message holds

| Field | Meaning |
| --- | --- |
| `id` | Unique. The client uses it to drop duplicates |
| `event` | The label it was sent with |
| `payload` | Whatever was sent: any JSON |
| `from` | The sender's user id, or `"server"` for messages from your backend |
| `sent_at` | When it was accepted |

## Send

<CodeGroup>
```typescript TypeScript
await room.send("message", { text: "hello" });
await room.send("typing", { on: true });
```

```python Python
await room.send("message", {"text": "hello"})
```
</CodeGroup>

You also receive your own messages, so render from what the channel delivers instead of adding yours twice.

## Listen to one event or all

```typescript
room.on("message", (m) => log(m.event, m.payload));     // every message
room.onEvent("typing", (m) => showTyping(m.from));       // only "typing"
room.on("subscribed", () => setStatus("live"));
room.on("closed", ({ reason }) => setStatus(reason));
room.on("error", (e) => report(e));
```

Python: `room.on(None, handler)` for every message, `room.on("typing", handler)` for one.

## Read messages as a loop

<CodeGroup>
```typescript TypeScript
for await (const message of room) render(message);
```

```python Python
async for message in room:
    render(message)
```
</CodeGroup>

## Load recent messages

If the channel keeps history, a new screen can start with context:

<CodeGroup>
```typescript TypeScript
const recent = await room.history(50);       // oldest first
```

```python Python
recent = pb.realtime.history("chat:lobby", limit=50)
```
</CodeGroup>

A good chat screen subscribes first, then loads history, and skips ids it has already shown:

```typescript
const seen = new Set<string>();
const add = (m) => { if (!seen.has(m.id)) { seen.add(m.id); messages.push(m); } };
room.onEvent("message", add);
await room.subscribe();
(await room.history(50)).forEach(add);
```

## Catch up after a drop

Ask the channel to replay what you missed on reconnect:

```typescript
const room = pawabase.realtime.channel("chat:lobby", { replay: 100 });
```

After each reconnect the client fetches up to 100 recent messages and delivers the ones you did not get, once each. History is short, so for anything that must not be lost, save it as a record and use the channel to announce it.

## In React

```typescript
useEffect(() => {
  const room = pawabase.realtime.channel(`order:${orderId}`);
  const stop = room.onEvent("status", (m) => setStatus(m.payload.status));
  room.subscribe();
  return () => { stop(); room.unsubscribe(); };
}, [orderId]);
```

## Typed payloads (TypeScript)

```typescript
const room = pawabase.realtime.channel<{ text: string }, { name: string }>("chat:lobby");
room.onEvent("message", (m) => m.payload.text);   // string
```

## Errors

`subscribe()` and `send()` throw a `RealtimeError` when a channel rule refuses you, for example when you are not signed in but the rule needs a user.
