---
title: "Publishing from a server"
description: "Send messages to channels from your backend or a flow, without opening a socket."
icon: "server"
---

Your backend can push to connected clients: "your export is ready", "the order shipped", "maintenance in five minutes". It does not need a live connection to do it.

## Publish from code

<CodeGroup>
```typescript TypeScript
// With a secret key on your server
await pawabase.realtime.publish("user:42", "export.ready", { url, name: "report.pdf" });
```

```python Python
pb.realtime.publish("user:42", "export.ready", {"url": url, "name": "report.pdf"})   # sync client is fine
```
</CodeGroup>

The result gives the message `id`. A message published this way has `from: "server"`.

A secret key bypasses the channel's publish rule. With a publishable key the rule applies, which is how a browser publishes without a socket.

## Publish from a flow

Use the `realtime.publish` block to notify clients as part of automation:

```json
{
  "id": "tell_user",
  "data": {
    "block": "realtime.publish",
    "config": {
      "channel": "user:{{ input.user_id }}",
      "event": "export.ready",
      "payload": { "url": "{{ steps.build.output.url }}" }
    }
  }
}
```

## Pattern: tell one user

1. Each signed-in client subscribes to `user:<their id>`.
2. A [channel rule](/realtime/channel-rules) for `user:*` lets a user join only their own.
3. Your backend or a flow publishes to that channel when something happens.

<CodeGroup>
```typescript TypeScript
const mine = pawabase.realtime.channel(`user:${user.id}`);
mine.onEvent("export.ready", (m) => toast(`Your export is ready: ${m.payload.name}`));
await mine.subscribe();
```

```python Python
mine = pb.realtime.channel(f"user:{user_id}")
mine.on("export.ready", lambda m: toast(m["payload"]["name"]))
await mine.subscribe()
```
</CodeGroup>

## Messages are not storage

A client that is offline when you publish will not receive the message unless the channel keeps [history](/realtime/history) and the client replays it. For anything that must reach the user, save a record (a notification row) and publish a message that tells the app to look.

## Tips

- Keep payloads small: identifiers and a little text, not whole documents.
- Name events by what happened (`order.shipped`), not by what the client should do.
- Publish after the change is saved, not before, so a client reacting to the message can read the data.
