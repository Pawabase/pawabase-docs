A share link opens **one file** for anyone who holds it, until it expires or you revoke it. It works whatever the bucket's read rule says, for that file only. Use it to send a contract to a client or an export to a partner.

Compared with a signed URL ([downloading](/storage/downloading#temporary-signed-link)): a signed URL is for minutes and is made by the app on behalf of a signed-in user; a share link is for hours or days, is recorded, and can be revoked.

## Create, list and revoke

Share links are created with a **secret key**, so do it on a server.

<CodeGroup>
```typescript TypeScript
import { manage } from "@pawabase/client/manage";
const m = manage(serverClient);

const link = await m.buckets.createShare("documents", "7/contract.pdf", {
  expiresIn: 7 * 24 * 3600,
  permissions: "view",
  label: "Contract for Acme",
});
console.log(link.url);

const links = await m.buckets.shares("documents");
await m.buckets.revokeShare("documents", link.id);
```

```python Python
bucket = pb.storage.from_("documents")      # pb uses a secret key

link = bucket.create_share_link("7/contract.pdf", expires_in=7 * 24 * 3600, permissions="view", label="Contract for Acme")
print(link["url"])

links = bucket.list_share_links()
bucket.revoke_share_link(link["id"])
```
</CodeGroup>

| Option | Meaning |
| --- | --- |
| `expiresIn` / `expires_in` | Seconds. Default 3600 (one hour). Between 1 minute and 1 year |
| `permissions` | `view` (shown in the browser, never as a download), `download` (always an attachment), or `both` (default) |
| `label` | A note for you, shown in the list |

The answer includes the link's `id`, `status` (`active`, `expired`, `revoked`), `expires_at`, and the `url` to give out.

## What the link allows

- That one file, in that environment. Not the bucket's listing, not a sibling file.
- Image [resizing](/storage/images) works through a share link, so you can share a thumbnail.
- Replacing the file keeps the link working. Deleting, renaming or moving it revokes the link, so a new file at the same key is never reachable through an old link.

Opening a link needs no key and no sign-in. An expired or revoked link answers `410`, and an unknown token or deleted file answers `404`.

<Warning>
Anyone with the URL can open the file. Treat it like a password: prefer short lifetimes, send it over a private channel, and revoke links you no longer need.
</Warning>

## A typical flow

1. A user clicks "Share" on a document in your app.
2. Your server checks they own the document, then calls `createShare` with a one-day lifetime.
3. You return the URL for them to copy.
4. The document's page lists active links (`shares`) with a "Revoke" button that calls `revokeShare`.

In the dashboard, the same links appear on the file's Sharing tab.
