Storage holds the bytes; your [data](/data/resources/overview) holds the meaning. The usual pattern is to store the file's **key** on a record and build the URL when you need it.

## Store the key, not the URL

A URL can change (a signed link expires, a domain moves). A key does not. Keep the key in a column such as `avatar_key` and build the link on read.

<CodeGroup>
```typescript TypeScript
const key = `${user.id}/avatar-${crypto.randomUUID()}.png`;
await pawabase.storage.from("avatars").upload(key, file);
await pawabase.from("profiles").update(profile.id, { avatar_key: key });

// Later, to display it
const src = pawabase.storage.from("avatars").getPublicUrl(profile.avatar_key);
```

```python Python
key = f"{user_id}/avatar-{uuid.uuid4()}.png"
pb.storage.from_("avatars").upload(key, open("avatar.png", "rb"), content_type="image/png")
pb.from_("profiles").update(profile["id"], avatar_key=key)

# Later, to display it
src = pb.storage.from_("avatars").public_url(profile["avatar_key"])
```
</CodeGroup>

Upload first, then save the key, so a record never points at a file that does not exist.

## Replace a file

Give the new file a new key, update the record, then delete the old key. A fresh key avoids stale caches in browsers and CDNs.

<CodeGroup>
```typescript TypeScript
const old = profile.avatar_key;
await pawabase.storage.from("avatars").upload(newKey, file);
await pawabase.from("profiles").update(profile.id, { avatar_key: newKey });
if (old) await pawabase.storage.from("avatars").remove(old);
```

```python Python
old = profile.get("avatar_key")
bucket = pb.storage.from_("avatars")
bucket.upload(new_key, data)
pb.from_("profiles").update(profile["id"], avatar_key=new_key)
if old:
    bucket.remove(old)
```
</CodeGroup>

## Clean up when a record goes

Deleting a record does not delete its files. Do it yourself, or let a [flow](/flows/overview) do it when the record is deleted, so cleanup happens even if the delete came from somewhere else. List by prefix to remove everything a user owns (see [downloading](/storage/downloading#delete)).

## Attachments with metadata

For several files per record, create a table (`attachments`) with `record_id`, `key`, `name`, `size` and `content_type`. Save the `name` the user chose there; the key itself should be generated.

## Limits and quotas

A bucket's `max_bytes` caps one file. The plan on your project caps total storage; uploads beyond it are refused. Python raises `QuotaExceededError` (a kind of `ForbiddenError`) for that. Check usage in the dashboard's usage view.
