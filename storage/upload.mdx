Set the bucket's rules and limits up first ([Create a bucket](/storage/buckets)). Then `upload(key, body)` stores a file at a key in the bucket. If the key already exists, the file is replaced.

<CodeGroup>
```typescript TypeScript
const documents = pawabase.storage.from("documents");

const stored = await documents.upload(`${user.id}/contract.pdf`, file);
stored.key;            // "7f3…/contract.pdf"
stored.size;           // bytes
stored.content_type;   // "application/pdf", decided from the file's bytes
stored.url;            // its address on the gateway
```

```python Python
documents = pb.storage.from_("documents")

stored = documents.upload(f"{user_id}/contract.pdf", open("contract.pdf", "rb"))
stored["key"], stored["size"], stored["content_type"], stored["url"]
```
</CodeGroup>

The answer describes what was stored:

| Field | Meaning |
| --- | --- |
| `bucket` | The bucket |
| `key` | The key, cleaned (see [Keys](#keys)) |
| `size` | Bytes stored |
| `content_type` | The type Pawabase decided from the file's contents |
| `etag` | Changes whenever the file is replaced |
| `url` | The file's stable address on the gateway, `…/storage/v1/files/<environment>/<bucket>/<key>`. Anyone can open it when the bucket is public; otherwise the read rule applies. See [Links and URLs](/storage/urls-and-links) |

## From a web page

<CodeGroup>
```typescript Input
const input = document.querySelector<HTMLInputElement>("#file")!;
input.addEventListener("change", async () => {
  const file = input.files?.[0];
  if (!file) return;
  const stored = await pawabase.storage.from("documents").upload(`${user.id}/${crypto.randomUUID()}.pdf`, file);
  await pawabase.from("documents").create({ name: file.name, path: stored.key, size: stored.size });
});
```

```tsx React
function Uploader({ userId }: { userId: string }) {
  const [busy, setBusy] = useState(false);
  const [error, setError] = useState<string | null>(null);

  async function onChange(event: React.ChangeEvent<HTMLInputElement>) {
    const file = event.target.files?.[0];
    if (!file) return;
    setBusy(true);
    setError(null);
    try {
      const ext = file.name.split(".").pop();
      await pawabase.storage.from("documents").upload(`${userId}/${crypto.randomUUID()}.${ext}`, file);
    } catch (e) {
      setError(uploadMessage(e));   // see "Handle refusals" below
    } finally {
      setBusy(false);
      event.target.value = "";      // lets the same file be picked again
    }
  }

  return (
    <label>
      <input type="file" accept="application/pdf,image/*" onChange={onChange} disabled={busy} />
      {busy && "Uploading…"} {error}
    </label>
  );
}
```
</CodeGroup>

Keep the original file name in a record, not in the key. See [Files and records](/storage/files-and-records).

## What you can send

| TypeScript | Python |
| --- | --- |
| `File` or `Blob`; its type is used | `bytes`, `bytearray`, `memoryview` |
| `ArrayBuffer`, typed arrays such as `Uint8Array` | An open binary file (`open(path, "rb")`) |
| `string`, stored as UTF-8 text | A `pathlib.Path`; its type is guessed from the name |
| `ReadableStream`: streams without buffering, but is never retried | `str`, stored as UTF-8 text |
| `FormData` with a `file` field | |

### How the type is decided

1. The type you pass: `{ contentType: "image/png" }` in TypeScript, `content_type="image/png"` in Python.
2. Otherwise the file's own: a `Blob`'s `type` in TypeScript; for a `Path`, a guess from its name in Python.
3. Otherwise, in Python, a guess from the key's extension.
4. Otherwise `application/octet-stream`.

That is the **declared** type. Pawabase then reads the start of the file and decides its **real** type from the bytes. The real type is what's stored, what the bucket's **Accepted types** are checked against, and what browsers get. A script renamed to `photo.png` is refused, not stored as an image.

## What the bucket checks

Every setting you made in Studio is enforced on every upload, however it's sent:

| Bucket setting | If broken | TypeScript | Python |
| --- | --- | --- | --- |
| **Who may upload new objects** | `401` signed out, `403` signed in | `AuthenticationError`, `PermissionError` | `AuthenticationError`, `ForbiddenError` |
| **Who may replace objects** (when the key exists) | the same | the same | the same |
| **Accepted types** | `400` "… does not accept …" | `ApiError`, status 400 | `ValidationError` |
| **Largest file** | `400` | `ApiError`, status 400 | `ValidationError` |
| The environment's upload limit (plan) | `413` | `PayloadTooLargeError` | `PawabaseError`, status 413 |
| A key that isn't allowed | `400` | `ApiError`, status 400 | `ValidationError` |
| Storage full for the plan | `403` `quota_exceeded` | `PermissionError` | `QuotaExceededError` |

Sizes are checked **while** the file streams in, not from a size the sender claims, so an oversized upload stops at the limit without the rest being read.

## Keys

A key is the file's path inside the bucket, such as `7f3…/2026/contract.pdf`.

- **Put the owner first.** `<user id>/…` lets one rule say "people manage files under their own id". See [Who can do what](/storage/access).
- **Generate names.** `crypto.randomUUID()` or `uuid.uuid4()` avoids collisions and guessable addresses. Keep the human name in a record.
- **Use `/` for folders.** Studio and listing show prefixes as folders.
- **Not allowed:** an empty key, `.` or `..` parts, control characters, and very long keys. A leading `/` is removed.
- Keys are case-sensitive: `Photo.png` and `photo.png` are two files.

## Replace a file

Uploading to an existing key replaces the file. It's checked by **Who may replace objects**, not **Who may upload new objects**, so you can let people add files but not overwrite them.

- The `etag` changes, so browsers holding the old version see it changed.
- Resized versions of an image made from the old file are dropped.
- The file's address stays the same. Browsers that cached it for the bucket's **Browser cache** time may still show the old one; use a new key when that matters.

Repeating the same upload is harmless, so both SDKs retry an upload after a network failure.

## Large files: signed upload links

For large files, or to send a file straight to storage from a device without your own server in the middle, your **server** creates a short-lived **signed upload link**, and the browser sends the file to it. The link is tied to one key, and optionally to one content type and a size limit.

Buckets issue signed upload links unless that's turned off with the bucket's `signed_uploads` setting, which is set from [infrastructure as code](/tools/iac/buckets) or the [management client](/tools/management-client) rather than in Studio. Then:

<CodeGroup>
```typescript TypeScript
// On your server, as the person (asUser) or with a secret key
const { url, expires_at } = await db.storage.from("videos").createSignedUploadUrl(`${userId}/intro.mp4`, {
  expiresIn: 600,                       // seconds, 1 to 604800 (7 days); default 300
  contentType: "video/mp4",             // the upload must be exactly this type
  maxBytes: 500 * 1024 * 1024,          // and at most this size
});
return Response.json({ url });

// In the browser, with the url your server returned
await pawabase.storage.from("videos").uploadToSignedUrl(url, file);
```

```python Python
bucket = pb.storage.from_("videos")
link = bucket.create_signed_upload_url(
    f"{user_id}/intro.mp4",
    expires_in=600,
    content_type="video/mp4",
    max_bytes=500 * 1024 * 1024,
)
# hand link["url"] to the device, or send the file yourself:
bucket.upload_to_signed_url(link["url"], Path("intro.mp4"), content_type="video/mp4")
```
</CodeGroup>

- The caller creating the link must be allowed to upload that key themselves: you can't grant access you don't have (`403` "you may not grant access you do not have").
- A bucket with `signed_uploads` off answers `403` "this bucket does not issue signed URLs for that".
- The browser sends no API key and no token: the link is the credential. Anyone holding it can upload until it expires.
- A file of another type answers `415` "this URL accepts video/mp4 only"; a larger file answers `413` "the upload is larger than this URL allows".
- The bucket's own **Accepted types** and **Largest file** still apply on top.

### Progress

`fetch` can't report upload progress. For a progress bar, send the signed upload with `XMLHttpRequest`:

```typescript
function uploadWithProgress(url: string, file: File, onProgress: (fraction: number) => void) {
  return new Promise<void>((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open("PUT", url);
    xhr.setRequestHeader("content-type", file.type || "application/octet-stream");
    xhr.upload.onprogress = (e) => e.lengthComputable && onProgress(e.loaded / e.total);
    xhr.onload = () => (xhr.status < 300 ? resolve() : reject(new Error(xhr.responseText)));
    xhr.onerror = () => reject(new Error("network error"));
    xhr.send(file);
  });
}
```

## Cancel and time out

<CodeGroup>
```typescript TypeScript
const controller = new AbortController();
cancelButton.onclick = () => controller.abort();

await documents.upload(key, file, { signal: controller.signal, timeoutMs: 120_000 });
```

```python Python
# a longer timeout for big uploads
pb = Pawabase(url, key, environment=env, timeout=300.0)
```
</CodeGroup>

The default timeout is 30 seconds per attempt, which is short for large files on slow connections. Raise it for uploads, or use a signed upload link.

## Handle refusals

<CodeGroup>
```typescript TypeScript
import { ApiError, AuthenticationError, PermissionError, PayloadTooLargeError } from "@pawabase/client";

function uploadMessage(e: unknown): string {
  if (e instanceof AuthenticationError) return "Sign in to upload.";
  if (e instanceof PermissionError) return e.is("quota_exceeded") ? "Storage is full." : "You can't upload here.";
  if (e instanceof PayloadTooLargeError) return "That file is too large.";
  if (e instanceof ApiError && e.status === 400) return e.message;   // type or size the bucket refused
  throw e;
}
```

```python Python
from pawabase.errors import AuthenticationError, ForbiddenError, QuotaExceededError, ValidationError

try:
    documents.upload(key, data)
except AuthenticationError:
    ...                                 # sign in
except QuotaExceededError:
    ...                                 # storage full
except ForbiddenError:
    ...                                 # the rule refused
except ValidationError as error:
    print(error.message)                # type, size or key refused
```
</CodeGroup>

Check the size and type in the browser first (`accept` on the input, `file.size`) for a quick message, but treat the bucket's checks as the real ones.

## Many files

Upload a few at a time, not hundreds at once:

```typescript
async function uploadAll(files: File[], prefix: string, onDone: (n: number) => void) {
  let done = 0;
  const queue = [...files];
  const worker = async () => {
    for (let file = queue.shift(); file; file = queue.shift()) {
      await pawabase.storage.from("photos").upload(`${prefix}/${crypto.randomUUID()}-${file.name}`, file);
      onDone(++done);
    }
  };
  await Promise.all([worker(), worker(), worker()]);
}
```

## From a server or script

A client with a **secret** key uploads without the bucket's rules (the type and size checks still apply). Use it for imports and generated files:

<CodeGroup>
```typescript TypeScript
import { readFile } from "node:fs/promises";

const admin = createClient({ url, apiKey: process.env.PAWABASE_SECRET_KEY!, environment });
await admin.storage.from("reports").upload("2026/11/summary.pdf", await readFile("summary.pdf"), {
  contentType: "application/pdf",
});
```

```python Python
from pathlib import Path

admin = Pawabase(url, os.environ["PAWABASE_SECRET_KEY"], environment=env)
admin.storage.from_("reports").upload("2026/11/summary.pdf", Path("summary.pdf"))
```
</CodeGroup>

Flows can store files too, including images sent as a data URL, with the **Store file** block and its `encoding` setting. See [Storage and cache blocks](/logic/blocks/storage-cache).

## Advanced

### Upload, then record

When a file belongs to a record (an avatar, an attachment), upload first, then save the record with the key. If saving the record fails, remove the file so it isn't orphaned:

```typescript
const stored = await bucket.upload(key, file);
try {
  await pawabase.from("attachments").create({ task_id: taskId, path: stored.key, name: file.name });
} catch (error) {
  await bucket.remove(stored.key).catch(() => undefined);
  throw error;
}
```

### Images straight from a canvas

```typescript
const blob = await new Promise<Blob>((resolve) => canvas.toBlob((b) => resolve(b!), "image/webp", 0.85));
await pawabase.storage.from("thumbnails").upload(`${user.id}/${id}.webp`, blob);
```

Shrinking images in the browser before upload saves bandwidth. You don't need to make several sizes: [image transforms](/storage/images) resize on request.

### Multipart

Passing a `FormData` sends `multipart/form-data`; the file must be in a field named `file`. Other fields are ignored. Prefer passing the `File` itself.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `400` "… does not accept text/html …" | The file's real type isn't in **Accepted types** | Add the type, or check the file really is what its name says |
| `400` on a file under the size you set | The bucket's **Largest file** is lower than you think | Check the bucket's settings |
| `413` | The environment's upload limit | Raise it on a higher plan, or split the file |
| `403` on an upload that worked before | The key exists, and **Who may replace objects** refuses | Use a new key, or allow replacing |
| `401` | Not signed in | Sign in, or allow guests |
| Uploads time out | 30 s default timeout on a slow connection | Raise `timeoutMs` / `timeout`, or use a signed link |
| The old image still shows after replacing | Browser cache | Use a new key, or add `?v=` to the address |
