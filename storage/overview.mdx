Storage keeps files such as avatars, documents, exports and attachments. Files live in **buckets** (folders with their own rules). Each file has a **key**, its path in the bucket, like `7/avatar.png`.

You **set up** buckets in Studio, and your app **uses** them through `pawabase.storage` (`pb.storage` in Python).

## Where it is in Studio

<Frame caption="Services → Storage with no buckets yet.">

</Frame>

Open your project, choose an environment, then **Services → Storage**. The page lists your buckets; choosing one opens a file browser with folders, uploads and a panel for each file.

## A first taste

<CodeGroup>
```typescript TypeScript
const avatars = pawabase.storage.from("avatars");

await avatars.upload(`${user.id}/avatar.png`, file);                    // a File from <input type="file">
const src = avatars.getPublicUrl(`${user.id}/avatar.png`);              // use in <img src>
```

```python Python
avatars = pb.storage.from_("avatars")

avatars.upload(f"{user_id}/avatar.png", open("avatar.png", "rb"), content_type="image/png")
src = avatars.public_url(f"{user_id}/avatar.png")
```
</CodeGroup>

## The ideas

| Idea | Meaning |
| --- | --- |
| Bucket | A named container with its own rules: who can read, write, list, replace and delete, and which types and sizes it accepts |
| Key | A file's path in its bucket. Slashes act like folders. Uploading to an existing key replaces the file |
| Public bucket | Anyone with a file's address can see it. Good for avatars and product images |
| Private bucket | Reading needs a signed-in person the bucket's rules allow, or a temporary link |
| Signed link | A temporary link to one file, with no sign-in. For minutes |
| Share link | A longer-lived link you can revoke. For days |
