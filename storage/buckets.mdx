A bucket is created once per environment and then used from your app. Creating and changing buckets is an administrator task, so it uses the management client with a **secret key**, from a server or a setup script. You can also do the same in the dashboard under Storage, which is handy for a first bucket.

## Create a bucket

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";
import { manage } from "@pawabase/client/manage";

const pawabase = createClient({
  url: "https://api.example.com",
  apiKey: process.env.PAWABASE_SECRET_KEY!,
  environment: "production",
});
const m = manage(pawabase);

await m.buckets.create({
  name: "avatars",
  public: true,
  accepts: ["image/png", "image/jpeg", "image/webp"],
  max_bytes: 2 * 1024 * 1024,
  write_policy: "authenticated",
});
```

```python Python
import os
from pawabase import Pawabase

pb = Pawabase("https://api.example.com", os.environ["PAWABASE_SECRET_KEY"], environment="production")

pb.manage.buckets.create({
    "name": "avatars",
    "public": True,
    "accepts": ["image/png", "image/jpeg", "image/webp"],
    "max_bytes": 2 * 1024 * 1024,
    "write_policy": "authenticated",
})
```
</CodeGroup>

Bucket names are lowercase letters, digits and hyphens, and unique within the environment. `avatars` in `development` and in `production` are separate buckets with separate files.

## Settings

| Field | Meaning |
| --- | --- |
| `name` | The bucket's name. Required. |
| `public` | `true` lets anyone read a file whose URL they have. Writing, listing and deleting still follow their rules. Default `false`. |
| `accepts` | Allowed content types. Patterns like `image/*` work. Empty means all types. Checked against the file's real contents, not only the header you send. |
| `max_bytes` | Largest file in bytes. `0` uses the environment's own limit. |
| `read_policy` | Who may read. Default `authenticated`. |
| `write_policy` | Who may upload a **new** key. Default `authenticated`. |
| `list_policy` | Who may list. Follows `read_policy` when unset. |
| `update_policy` | Who may replace an existing file. Follows `write_policy`. |
| `delete_policy` | Who may delete. Follows `write_policy`. |
| `cache_max_age` | Seconds browsers may cache a file. `0` revalidates every time. |
| `transforms` | Image resizing limits. See [Images](/storage/images). |

A policy is a short name (`"public"`, `"authenticated"`, `"service"`) or a condition. See [Access rules](/storage/access).

## Common setups

<Tabs>
  <Tab title="Public avatars">
    ```json
    { "name": "avatars", "public": true, "write_policy": "authenticated", "accepts": ["image/*"], "max_bytes": 2097152 }
    ```
    Anyone can show an avatar. Only signed-in users can upload, and only images up to 2 MB.
  </Tab>
  <Tab title="Private documents">
    ```json
    { "name": "documents", "read_policy": "authenticated", "write_policy": "authenticated", "max_bytes": 26214400 }
    ```
    Nothing is readable without signing in. Use signed or share links to give a file to someone else.
  </Tab>
  <Tab title="Server-written exports">
    ```json
    { "name": "exports", "read_policy": "authenticated", "write_policy": { "service": true } }
    ```
    Users can download an export, but only your server (or a flow) can create one.
  </Tab>
</Tabs>

## List, read, change and remove

<CodeGroup>
```typescript TypeScript
const mine = await pawabase.storage.listBuckets();       // [{ name, public, accepts, max_bytes }]

const all = await m.buckets.list();                        // full definitions
const one = await m.buckets.getOne("avatars");
await m.buckets.replace("avatars", { name: "avatars", public: true, max_bytes: 5 * 1024 * 1024 });
await m.buckets.remove("avatars");
```

```python Python
mine = pb.storage.list_buckets()          # [{name, public, accepts, max_bytes}]

all_buckets = pb.manage.buckets.list()    # full definitions
one = pb.manage.buckets.get_one("avatars")
pb.manage.buckets.replace("avatars", {"name": "avatars", "public": True, "max_bytes": 5 * 1024 * 1024})
pb.manage.buckets.remove("avatars")
```
</CodeGroup>

`replace` sends the whole definition, so include every field you want to keep. Removing a bucket removes its settings; clear its files first if you want them gone.

## Work with a bucket's files as an administrator

With a secret key, the management client can read and write any file regardless of the bucket's rules. Use this for back-office tools and migrations, not for your app's normal reads.

<CodeGroup>
```typescript TypeScript
const page = await m.buckets.objects("avatars", { prefix: "7/", limit: 50 });
await m.buckets.putObject("avatars", "7/avatar.png", bytes, "image/png");
await m.buckets.moveObject("avatars", "7/avatar.png", "7/profile.png");
await m.buckets.deleteObject("avatars", "7/profile.png");
```

```python Python
page = pb.manage.buckets.objects("avatars", prefix="7/", limit=50)
pb.manage.buckets.put_object("avatars", "7/avatar.png", data, "image/png")
pb.manage.buckets.move_object("avatars", "7/avatar.png", "7/profile.png")
pb.manage.buckets.delete_object("avatars", "7/profile.png")
```
</CodeGroup>

<Note>
Which storage backend holds the bytes (local disk or S3-compatible) is a property of the environment, not the bucket, and does not change your code. If you need a different backend, change it in the dashboard's environment settings.
</Note>
