Open **Services → Storage**, choose a bucket, then its **settings**. The settings are grouped as follows.

## Details

| Setting | Meaning |
| --- | --- |
| **Name** | The bucket's name. Fixed after creation |
| **Description** | A note for your team |
| **Public bucket** | Anyone with an object's URL may read it. Uploads, listing and deletes still follow the rules |

## Who passes

*What your application's requests may do. Studio administrators can always manage objects, whatever is set here.*

| Setting | Meaning | Default |
| --- | --- | --- |
| **Who may read** | Download or show a file | Signed-in users (everyone if **Public bucket**) |
| **Who may upload new objects** | Upload to a key that doesn't exist yet | Signed-in users |
| **Who may list objects** | List the bucket. *Reading an object does not let someone enumerate the bucket* | Same as read, so a **public** bucket with this unset can be listed by anyone. Set it |
| **Who may replace objects** | Overwrite an existing key | Same as upload |
| **Who may delete objects** | Delete a file | Same as upload |

Each is a [rule picker](/policies/rule-references): built-ins, role/permission shorthands, a named rule, or a custom condition. Rules can read `$object.key` and `$object.segments`; see [Rules on storage](/policies/storage).

## Uploads

| Setting | Meaning |
| --- | --- |
| **Accepted types** | MIME patterns such as `image/*` or `application/pdf`. Empty accepts anything. Checked against the file's real contents, not only the header the client sent |
| **Largest file** | In MB. 0 falls back to the environment's own upload limit, which the plan caps. A file over it is refused with `400` |

## Delivery

| Setting | Meaning |
| --- | --- |
| **Browser cache** | Seconds a browser may reuse a file before asking again. 0 revalidates every time, which is safest when files are replaced |

Files have an `ETag` that changes when a file is replaced, so browsers always revalidate correctly. A longer cache is faster for files that never change (put a version in the key, `avatar-2.png`).

## Image transformations

*Resize, crop and convert images on request, without changing the stored original. Variants are served only to callers who may read the original.*

| Setting | Meaning |
| --- | --- |
| **Enable transformations** | Adds `?width=`, `?height=`, `?fit=`, `?format=`, `?quality=` and `?rotate=` to object URLs |
| **Allowed output formats** | Which formats may be requested: WebP, AVIF, JPEG, PNG |
| **Automatic format** | `?format=auto` picks AVIF or WebP when the browser's Accept header allows it |
| **Largest width / height** | The biggest output a visitor may ask for |
| **Largest source image** | MB. Larger originals aren't transformed |
| **Largest output** | MB of the result |
| **Default quality** | 1 to 100 |
| **Simultaneous transformations** | *Per bucket, per server process.* More wait their turn |
| **Time limit** | Seconds per transformation |

Each number has a platform ceiling a bucket can lower but not raise. See [Images](/storage/images).

## Settings you set from code

A few bucket settings aren't in Studio's form. Set them with [infrastructure as code](/tools/iac/buckets) or the [management client](/tools/management-client):

| Setting | Default | Meaning |
| --- | --- | --- |
| `signed_uploads` | `true` | Whether the bucket issues [signed upload links](/storage/upload#large-files-signed-upload-links) |
| `signed_downloads` | `false` | Whether it issues [signed download links](/storage/urls-and-links#signed-links). Turn it on for private buckets you hand links out of |
| `transforms.fits` | `["contain", "cover", "fill"]` | Which fits a transformation may ask for |
| `transforms.max_input_pixels` | 50,000,000 | The largest original (width × height) that is transformed. The platform's ceiling is 100,000,000 |

```python
from pawabase_iac import Bucket

documents = Bucket(
    "documents",
    read_policy="authenticated",
    write_policy="authenticated",
    signed_downloads=True,
    accepts=["application/pdf"],
    max_bytes=20 * 1024 * 1024,
)
```

A bucket with `signed_downloads` off answers `403` "this bucket does not issue signed URLs for that" when someone asks for a download link.

## What changes immediately

Rule and limit changes affect new requests within seconds. Existing files aren't touched: tightening **Accepted types** doesn't remove files already stored.
