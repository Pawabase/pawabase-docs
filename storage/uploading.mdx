`upload(key, body)` stores a file at a key. If the key already exists, the file is replaced, so repeating an upload is safe. The bucket's rules decide whether you may, and its type and size limits apply to every upload.

## Upload from your app

<CodeGroup>
```typescript TypeScript
const documents = pawabase.storage.from("documents");

// A File from <input type="file">
const stored = await documents.upload(`${user.id}/contract.pdf`, file);
console.log(stored.size, stored.content_type);

// Text or JSON you built yourself
await documents.upload(`${user.id}/notes.json`, JSON.stringify(notes), { contentType: "application/json" });
```

```python Python
documents = pb.storage.from_("documents")

# A file on disk
stored = documents.upload(f"{user_id}/contract.pdf", open("contract.pdf", "rb"))
print(stored["size"], stored["content_type"])

# Text or JSON you built yourself
documents.upload(f"{user_id}/notes.json", json.dumps(notes), content_type="application/json")
```
</CodeGroup>

The result describes what was stored: `bucket`, `key`, `size`, `content_type` and, when available, `etag`.

### What you can pass as the body

| TypeScript | Python |
| --- | --- |
| `Blob` or `File` (content type taken from the file) | `bytes`, `bytearray`, `memoryview` |
| `ArrayBuffer` or typed array | An open binary file |
| `string` (stored as `text/plain`) | A `pathlib.Path` (content type guessed from its name) |
| `ReadableStream` (not retried on failure) | `str` (stored as `text/plain`) |
| `FormData` | |

If you do not pass a content type, the SDK uses the file's own, then guesses from the key's extension, then falls back to `application/octet-stream`. Pass one when the guess would be wrong.

## Choose good keys

- Put the owner first: `<user id>/avatar.png`. It makes per-user [access rules](/storage/access) one line.
- Do not trust the user's file name. Generate the key (`crypto.randomUUID()`, `uuid.uuid4()`) and keep the original name in a record.
- Add a version or a unique id when you must not overwrite: `7/avatar-2.png`.

## Upload straight from the browser, past your server

For large files, or to keep your server out of the data path, your server creates a one-time **signed upload link** and the browser sends the file to it. Nobody needs a key.

<CodeGroup>
```typescript TypeScript
// On your server (any client with permission to write)
const bucket = serverClient.storage.from("videos");
const { url } = await bucket.createSignedUploadUrl(`${user.id}/intro.mp4`, {
  expiresIn: 300,
  contentType: "video/mp4",
  maxBytes: 200 * 1024 * 1024,
});
// Send `url` to the browser, then in the browser:
await pawabase.storage.from("videos").uploadToSignedUrl(url, file);
```

```python Python
# On your server
bucket = pb.storage.from_("videos")
link = bucket.create_signed_upload_url(
    f"{user_id}/intro.mp4", expires_in=300, content_type="video/mp4", max_bytes=200 * 1024 * 1024
)
# Send link["url"] to the client. A Python client uploads with:
bucket.upload_to_signed_url(link["url"], open("intro.mp4", "rb"), content_type="video/mp4")
```
</CodeGroup>

The link is pinned to one key, one content type and one maximum size, and works only until it expires. Anything outside those is refused.

## Cancel, time out and show progress

TypeScript uploads accept an `AbortSignal` and a timeout:

```typescript
const controller = new AbortController();
cancelButton.onclick = () => controller.abort();

await documents.upload("7/report.pdf", file, { signal: controller.signal, timeoutMs: 120_000 });
```

For a progress bar, the browser's `fetch` does not report upload progress. Use a signed upload link and `XMLHttpRequest` for that one upload if you need the percentage.

## When an upload is refused

<CodeGroup>
```typescript TypeScript
import { PermissionError, AuthenticationError, PayloadTooLargeError, ValidationError } from "@pawabase/client";

try {
  await documents.upload(key, file);
} catch (e) {
  if (e instanceof AuthenticationError) showSignIn();
  else if (e instanceof PermissionError) showMessage("You cannot upload here.");
  else if (e instanceof PayloadTooLargeError) showMessage("That file is too large.");
  else if (e instanceof ValidationError) showMessage("That file type is not allowed.");
  else throw e;
}
```

```python Python
from pawabase.errors import AuthenticationError, ForbiddenError, ValidationError

try:
    documents.upload(key, data)
except AuthenticationError:
    ask_to_sign_in()
except ForbiddenError:
    show("You cannot upload here.")
except ValidationError:
    show("That file is too large or not an allowed type.")
```
</CodeGroup>

| Problem | Cause |
| --- | --- |
| Not signed in | The bucket's write rule needs a user and the request had none |
| Forbidden | The rule refused this user for this key |
| Too large | Over the bucket's `max_bytes` |
| Wrong type | Not in `accepts`, judged from the file's contents |

Check the size and type in the browser first to give a friendly message, but treat the bucket's limits as the real enforcement.
