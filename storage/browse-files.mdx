Studio's file browser is the quickest way to see what's in a bucket, upload a test file, fix a mistake or hand someone a link. It acts with **Studio's own authority**, so it ignores your bucket rules, which makes it ideal for back-office work.

## Open it

**Services → Storage**, then click a bucket. A breadcrumb shows where you are; click a part to go up.

## The list

Folders appear first, then files, with **Name, Size, Type, Modified**. Click a folder to open it; click a file to open its panel. If a folder or bucket is empty it says **No objects here.**

### Folders

Storage has no real folders; a "folder" is a shared key prefix. Studio shows them as folders anyway.

- **New folder** asks for a name and creates it.
- To remove a folder it must be **empty**: delete its files first, then the folder.

### Upload

Click **Upload**, choose a file. It's stored at the current folder plus the file name and a toast confirms. Uploading to an existing name replaces that file.

Studio enforces the bucket's **Accepted types** and **Largest file** on uploads too.

## A file's panel

Click a file. The panel has three tabs.

### Overview

| Section | Shows |
| --- | --- |
| **Object** | Key, Size, Type, Last modified |
| **Address** | **Gateway URL** (the address your app uses) and **URL**. Public files can be opened directly |
| **Metadata** | What the storage provider and the platform know about the file (ETag, content type, size) |
| **Actions** | **Download**, **Rename or move**, **Delete** |

- **Rename or move** takes a new key. Because links are tied to the key, renaming or moving a file **revokes** its [share links](/storage/share-links).
- **Delete** asks you to confirm. There is no recycle bin.
- Files too large to preview say *Too large to preview. Download it instead.*

### Sharing

Create and revoke temporary links. See [Share links](/storage/share-links).

### Transform

Try a resize or conversion on an image and copy the resulting address. See [Images](/storage/images#try-it-in-studio).

## Handy uses

- **Check what an app uploaded** and whether the key has the pattern you expect (`<user id>/…`).
- **Fix a bad upload:** replace it by uploading the correct file with the same name.
- **Send a document to a customer:** open it, **Sharing**, create a link.
- **Clean up** test files before launch.
