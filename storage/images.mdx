Add options to an image's address and Pawabase serves that version. The stored original is never changed, so you don't generate thumbnails yourself.

## Turn it on in Studio

1. **Services → Storage**, open the bucket, then its **settings**.
2. Find **Image transformations** and turn on **Enable transformations**.
3. Choose **Allowed output formats** and **Automatic format**, and set the largest sizes, the default quality and the time limit (see [Bucket settings](/storage/bucket-settings#image-transformations)). All three fits are allowed unless the bucket's `transforms.fits` setting, set from code, narrows them.
4. Save.

## Try it in Studio

1. Open an image in the file browser, then the **Transform** tab.
2. Under **Try a transformation** set **Width**, **Height**, **Fit**, **Format**, **Quality** and **Rotate**.
3. The **Result** shows the picture and the exact address to use. Copy it.

*The stored original is never changed. Settings here only build a URL.* Only PNG, JPEG, WebP, GIF, AVIF and BMP images can be transformed; for anything else the tab says so. If transformations are off for the bucket, it tells you to enable them in the bucket's settings.

## Use it in your app

<CodeGroup>
```typescript TypeScript
const thumb = pawabase.storage.from("avatars").fileUrl(`${user.id}/me.png`, {
  width: 96, height: 96, fit: "cover", format: "webp",
});

// or add options to an address you already have, such as an upload's `url`
const { url } = await pawabase.storage.from("avatars").upload(`${user.id}/me.png`, file);
const same = `${url}?width=96&height=96&fit=cover&format=webp`;
```

```python Python
thumb = pb.storage.from_("avatars").transform_url("7/me.png", width=96, height=96, fit="cover", format="webp")
```
</CodeGroup>

```html
<img src="…" width="96" height="96" alt="Ada">
```

Resizing works for public URLs, signed links and share links. The read rule is checked on every request, so a variant is never shown to someone who couldn't read the original.

## Options

| Option | Short | Values | Meaning |
| --- | --- | --- | --- |
| `width`, `height` | `w`, `h` | pixels | Output size. Give one and the other follows the ratio |
| `fit` | | `contain`, `cover`, `fill` | `contain` fits inside and never enlarges; `cover` fills and crops; `fill` stretches |
| `format` | `f` | `webp`, `avif`, `jpeg`, `png`, `auto` | `auto` picks AVIF or WebP when the browser allows |
| `quality` | `q` | 1 to 100 | Compression for lossy formats |
| `rotate` | | -360 to 360 | Degrees clockwise |
| `crop` | | `x,y,width,height` | Crop the original first, in source pixels |

Photo orientation is applied. Animated images use their first frame. SVG is never rasterised.

In TypeScript, `fileUrl(key, options)` takes `width`, `height`, `fit`, `format`, `quality` and `rotate` (`@pawabase/client` 0.6.0). In Python, `transform_url` takes the same (`rotate` from `pawabase` 0.8.0). Add `crop` to the address yourself.

## Limits and refusals

Everything is bounded by the bucket's settings:

| Request | Result |
| --- | --- |
| Larger than **Largest width / height** | `400` |
| A format or fit you didn't allow | `400` |
| Original larger than **Largest source image** | `413` |
| Result larger than **Largest output** | `413` |
| Not an image | `415` |
| Corrupt image | `422` |
| Too many at once (over **Simultaneous transformations**) | `503`, retry |

## Sizes worth reusing

Each variant is generated once and cached, so reuse a few sizes:

| Where | Options |
| --- | --- |
| Avatar in a list | `width=64&height=64&fit=cover&format=webp` |
| Profile picture | `width=256&height=256&fit=cover&format=auto` |
| Card image | `width=480&format=auto` |
| Full-width banner | `width=1600&format=auto&quality=75` |

For sharp pictures on high-density screens:

```html
<img src="…&width=480&format=auto" srcset="…&width=480&format=auto 1x, …&width=960&format=auto 2x">
```

## A helper for your app

```typescript
type Transform = { width?: number; height?: number; fit?: "contain" | "cover" | "fill"; format?: "webp" | "avif" | "jpeg" | "png" | "auto"; quality?: number };

export function imageUrl(address: string, options: Transform) {
  const url = new URL(address);
  for (const [name, value] of Object.entries(options)) if (value !== undefined) url.searchParams.set(name, String(value));
  return url.toString();
}

export function Avatar({ address, size = 48 }: { address: string; size?: number }) {
  return (
    <img
      src={imageUrl(address, { width: size, height: size, fit: "cover", format: "auto" })}
      srcSet={`${imageUrl(address, { width: size * 2, height: size * 2, fit: "cover", format: "auto" })} 2x`}
      width={size}
      height={size}
      alt=""
      loading="lazy"
    />
  );
}
```

`new URL` keeps any query string already there (`apikey`, a signed link's `token`) and adds the options to it.

## Caching

Variants are cached per original and options, and are purged when you replace the original. Responses carry an `ETag`, and `Vary: Accept` when you use `format=auto`, so a CDN keeps the right version for each browser.
