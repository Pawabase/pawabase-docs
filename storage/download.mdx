Reading a file from your app goes through the bucket's **Who may read** rule, as the signed-in person. To show a file in an `<img>` or hand out a link instead, see [Links and URLs](/storage/urls-and-links).

## Read a file

<CodeGroup>
```typescript TypeScript
const documents = pawabase.storage.from("documents");

const blob = await documents.download("7f3…/contract.pdf");           // Blob
const text = await documents.downloadText("7f3…/notes.txt");          // string
const notes = await documents.downloadJson<Notes>("7f3…/notes.json"); // parsed JSON
const stream = await documents.downloadStream("7f3…/backup.zip");     // ReadableStream<Uint8Array>
const response = await documents.downloadResponse("7f3…/contract.pdf");
response.headers.get("etag");
response.headers.get("content-type");
response.headers.get("content-length");
```

```python Python
documents = pb.storage.from_("documents")

data = documents.download("7f3…/contract.pdf")           # bytes
text = documents.download_text("7f3…/notes.txt")         # str, utf-8 by default
notes = documents.download_json("7f3…/notes.json")       # parsed JSON
response = documents.download_response("7f3…/contract.pdf")   # httpx.Response
response.headers["etag"]
```
</CodeGroup>

| TypeScript | Python | Returns |
| --- | --- | --- |
| `download(key)` | `download(key)` | the bytes: a `Blob` / `bytes` |
| `downloadText(key)` | `download_text(key, encoding="utf-8")` | text |
| `downloadJson(key)` | `download_json(key)` | parsed JSON |
| `downloadStream(key)` | `pb.stream("GET", path)` | a stream, for large files |
| `downloadResponse(key)` | `download_response(key)` | the raw response, with headers |

All of them take `{ signal, timeoutMs }` in TypeScript. Reads are retried after a network failure.

### When a read is refused

| Answer | Meaning | TypeScript | Python |
| --- | --- | --- | --- |
| `401` "sign in to read this object" | The read rule needs a signed-in person | `AuthenticationError` | `AuthenticationError` |
| `403` "you may not read this object" | Signed in, but the rule refuses | `PermissionError` | `ForbiddenError` |
| `404` | No file at this key | `NotFoundError` | `NotFoundError` |
| `502` | The storage provider couldn't be reached | `ServerError` | `ServerError` |

## Large files

Stream instead of holding the whole file in memory:

<CodeGroup>
```typescript TypeScript
import { createWriteStream } from "node:fs";
import { Readable } from "node:stream";
import { pipeline } from "node:stream/promises";

const stream = await pawabase.storage.from("backups").downloadStream("2026-11-13.zip");
await pipeline(Readable.fromWeb(stream as any), createWriteStream("backup.zip"));
```

```python Python
with pb.stream("GET", "/storage/v1/object/backups/2026-11-13.zip") as response:
    response.raise_for_status()
    with open("backup.zip", "wb") as out:
        for chunk in response.iter_bytes():
            out.write(chunk)
```
</CodeGroup>

### Part of a file

The server answers a `Range` header with just those bytes (`206`), which lets video players seek and lets you resume a broken download:

```typescript
const { url } = await pawabase.storage.from("videos").createSignedUrl("intro.mp4", { expiresIn: 300 });
const firstMegabyte = await fetch(url, { headers: { range: "bytes=0-1048575" } });   // 206
```

Video and audio elements send ranges for you when you give them a file's address. One range per request is supported; several ranges get the whole file. A range that starts past the end answers `416`. Compressed answers aren't used with ranges.

## Offer a download in a browser

<CodeGroup>
```typescript Save a file
const blob = await documents.download("7f3…/contract.pdf");
const href = URL.createObjectURL(blob);
const a = Object.assign(document.createElement("a"), { href, download: "Contract.pdf" });
a.click();
URL.revokeObjectURL(href);
```

```typescript A link
// a signed link opens without your code, and works in a new tab or an email
const { url } = await documents.createSignedUrl("7f3…/contract.pdf", { expiresIn: 300 });
window.open(`${url}&download=Contract.pdf`);
```
</CodeGroup>

Downloading into a `Blob` holds the file in memory; for big files prefer a signed link.

### Open in the browser, or save

Files are served in a way that keeps your site safe:

- **Images, video and audio of common types** (PNG, JPEG, GIF, WebP, AVIF, MP4, WebM…) open **in the browser**.
- **Everything else**, including HTML, SVG, XML and JavaScript, is always sent **as a download**, so a file someone uploaded can never run script on your domain. PDFs are sent with a strict policy too.
- Add `download` to the address to force a download, or `download=<name>` to choose the saved file's name.

## List files

Needs **Who may list objects**.

<CodeGroup>
```typescript TypeScript
const page = await documents.list({ prefix: "7f3…/", limit: 50 });
page.files;      // [{ key, size, content_type, modified, etag, url }]
page.prefixes;   // the "folders" directly below: ["7f3…/2025/", "7f3…/2026/"]
page.cursor;     // pass back for the next page; "" on the last

for await (const file of documents.listAll({ prefix: "7f3…/" })) {
  console.log(file.key, file.size);
}
```

```python Python
page = documents.list(prefix="7f3…/", limit=50)
page["files"], page["prefixes"], page["cursor"]

for file in documents.list_all(prefix="7f3…/"):
    print(file["key"], file["size"])

# async client
async for file in adocuments.list_all(prefix="7f3…/"):
    ...
```
</CodeGroup>

| Option | Default | Meaning |
| --- | --- | --- |
| `prefix` | `""` (the whole bucket) | Only keys that start with this |
| `limit` | 100 | Files per page, at most 1000 |
| `cursor` | | The previous page's `cursor`, for the next page |
| `pageSize` / `page_size` on `listAll` / `list_all` | the server's default | Files per request while walking |

Each file has `key`, `size`, `content_type`, `modified`, `etag` and `url`. Listing is by **prefix**, so design keys with that in mind: `<user id>/<year>/<file>` lists one person's files, or one year of them, cheaply.

Being allowed to read a file doesn't let someone list the bucket: listing has its own rule, so people can open a link without seeing what else is there.

### A folder view

`prefixes` holds the "folders" directly under the prefix, so you can show one level at a time:

```typescript
async function openFolder(prefix: string) {
  const { files, prefixes, cursor } = await documents.list({ prefix, limit: 100 });
  return {
    folders: prefixes.map((p) => ({ name: p.slice(prefix.length).replace(/\/$/, ""), prefix: p })),
    files: files.map((f) => ({ name: f.key.slice(prefix.length), size: f.size, type: f.content_type, url: f.url })),
    more: cursor,
  };
}
```

Folders aren't real objects: a folder exists while a file's key starts with it. Studio's **New folder** keeps an empty folder by storing a small hidden marker file, which listing never returns.

## Delete

Needs **Who may delete objects**.

<CodeGroup>
```typescript TypeScript
await documents.remove("7f3…/contract.pdf");

// a whole folder
for await (const file of documents.listAll({ prefix: "7f3…/old/" })) {
  await documents.remove(file.key);
}
```

```python Python
documents.remove("7f3…/contract.pdf")

for file in documents.list_all(prefix="7f3…/old/"):
    documents.remove(file["key"])
```
</CodeGroup>

- A missing file answers `404`. A refused delete answers `403`.
- Deleting a file also ends its [share links](/storage/share-links) and drops its resized images.
- There's no recycle bin. To allow undo, mark the related record deleted and remove files later in a [scheduled flow](/automation/schedules). See [Files and records](/storage/files-and-records#clean-up).

## Move and rename

The client has no rename. Upload under the new key, point your record at it, then remove the old one:

<CodeGroup>
```typescript TypeScript
async function move(bucket: string, from: string, to: string) {
  const store = pawabase.storage.from(bucket);
  const blob = await store.download(from);
  await store.upload(to, blob);
  await store.remove(from);
}
```

```python Python
def move(bucket: str, old: str, new: str):
    store = pb.storage.from_(bucket)
    store.upload(new, store.download(old))
    store.remove(old)
```
</CodeGroup>

In Studio, **Rename or move** on a file does it in one step. A script with a secret key can also use the [management client](/tools/management-client)'s `buckets.moveObject`.

## Caching

- Every file has an **ETag** that changes when the file is replaced. A browser or your code can send `If-None-Match` with it, and an unchanged file answers `304` with no body.
- The bucket's **Browser cache** setting (seconds) says how long a browser may reuse a file before asking again. `0`, the default, makes it ask every time, which is cheap thanks to the ETag and safest when files are replaced.
- Files in a public bucket are served as cacheable by anyone (`public`); files behind a read rule are `private`, so shared caches don't keep them.
- Text-like files (plain text, CSV, CSS, Markdown, JSON, XML, NDJSON, JavaScript, SVG) are compressed with gzip when the browser accepts it.

If you replace a file under the same key while browsers may have cached it, use a new key instead, or add a version to the address (`?v=2`).

## Advanced

### Read many files

Read a few at a time; each read is a request:

```typescript
const keys = page.files.map((f) => f.key);
const texts = await Promise.all(keys.slice(0, 10).map((k) => documents.downloadText(k)));
```

### On a server, as a person

Read files on behalf of the person making a request with `asUser`, so the bucket's rules apply to them:

<CodeGroup>
```typescript TypeScript
const db = pawabase.asUser(accessToken);
const pdf = await db.storage.from("invoices").download(`${userId}/2026-11.pdf`);
return new Response(pdf, { headers: { "content-type": "application/pdf" } });
```

```python Python
db = pb.as_user(access_token)
pdf = db.storage.from_("invoices").download(f"{user_id}/2026-11.pdf")
```
</CodeGroup>

A client with a **secret** key reads any file, ignoring the rules.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `401` on a file you uploaded | Not signed in, or the session expired | Sign in again |
| `403` | **Who may read** refuses this person | Check the rule; owner-first keys need the key to start with the person's id |
| `403` on `list` but reads work | Listing has its own rule | Set **Who may list objects** |
| `404` | Wrong key; keys are case-sensitive | List the prefix to see the real key |
| An HTML or SVG file downloads instead of opening | On purpose, for safety | Serve such files from your own site, or use images |
| The old version shows after replacing | Browser cache | New key, or `?v=` |
| Out of memory on big files | `download()` holds the whole file | Stream, or use a signed link |
