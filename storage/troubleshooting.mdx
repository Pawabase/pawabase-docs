## "Upload fails with 401"

The rule needs a signed-in person and the request had none (or the session expired). Check `await pawabase.auth.getSession()`.

## "Upload fails with 403"

You're signed in but **Who may upload new objects** (or **replace**, if the key exists) refuses this key. The usual cause: the key doesn't start with the person's id. In Studio, open the bucket's settings and read the rule; then **Activity** → the request → which rule decided ([Debugging rules](/policies/debugging)).

## "Upload fails with 400"

The answer's message says which check refused it:

- "… does not accept …": the file's real type isn't in **Accepted types**. Browsers can label a file wrongly; the check uses the actual contents. Check the pattern (`image/*`, `application/pdf`).
- A size message: the file is over the bucket's **Largest file**. Raise it in the bucket's settings, or shrink the file before uploading.
- A key message: the key is empty, has `..` parts or characters keys can't hold.

In TypeScript this is an `ApiError` with `status` 400; in Python a `ValidationError`.

## "Upload fails with 413"

The file is over the environment's own upload limit, which the plan caps (`PayloadTooLargeError` in TypeScript). A bucket's **Largest file** can't raise it. Use a higher plan or a smaller file.

## "I uploaded but can't see the file"

- Look in Studio's file browser at the exact key. A different prefix (`7/` vs `07/`) is a different folder.
- The read rule refuses your user: `401` signed out, `403` signed in. Check the rule and the key's first segment.

## "The public URL gives 404"

The key is wrong (keys are case-sensitive), or the file was deleted. A bucket that isn't public answers `401` to an address opened without a session, because its read rule needs a signed-in person; use a signed link for those.

## "Signed link doesn't work"

- Signed downloads are off for the bucket (the default): `403` "this bucket does not issue signed URLs for that". Turn on `signed_downloads` from [infrastructure as code](/tools/iac/buckets) or the [management client](/tools/management-client).
- It expired. Make a new one each time.
- You couldn't read the file yourself when you made it.

## "Share link says expired or revoked"

Check **Sharing** on the file: status and expiry. Renaming or moving a file revokes its links.

## "Image transformation returns an error"

| Status | Cause |
| --- | --- |
| 400 | A size, format or fit outside what the bucket allows |
| 413 | Source or output too large |
| 415 | Not a picture (SVG isn't rasterised) |
| 422 | Corrupt image |
| 503 | Too many at once; retry |

Also check **Enable transformations** is on.

## "Replaced a file but the old one still shows"

Browser cache. Use a new key, or add `?v=2`. Check **Browser cache** in the bucket's settings.

## "Listing returns nothing"

**Who may list objects** refuses you (it follows read, if unset), or the **prefix** doesn't match. Remember keys are case-sensitive.

## "Quota exceeded"

Your plan's storage limit is reached. Check **Project → Usage & plan**; delete files or upgrade.

## Collect this when asking for help

The call, the bucket's settings (screenshot **Who passes**), who was signed in, the error's `status`, `code` and `requestId`.
