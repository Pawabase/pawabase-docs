Every flow starts at a **trigger**. A flow can have more than one trigger block; each is an entry point and the flow runs from the one that fired. The trigger's output is the run's `input`, which later blocks read as `{{ input… }}`.

This page documents **8 blocks**. For how flows work, see [Flows](/logic/flows) and the [flow editor](/automation/flow-editor). Values in settings can use templates such as `{{ input.id }}` and `{{ steps.load.output.email }}`; see [Block reference overview](/logic/blocks/overview).

| Block | What it does |
| --- | --- |
| [Event](#event) | Runs when a matching platform event is published. |
| [HTTP request](#http-request) | Runs when an HTTP request reaches a custom route bound to this flow. |
| [Background job](#background-job) | Runs when the flow is dispatched as a background job. |
| [Manual run](#manual-run) | Runs when started from Studio or the management API. |
| [Realtime message](#realtime-message) | Runs when a client publishes to a realtime channel. |
| [Resource change](#resource-change) | Runs after a resource operation. |
| [Schedule](#schedule) | Runs on a schedule managed in Schedules. |
| [Inbound webhook](#inbound-webhook) | Runs when an inbound webhook is received and verified. |

## Event

**Key:** `trigger.event` · **Starts a flow**

Runs when a matching platform event is published.

**Continues to:** `next`

| Setting | Type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `event` | text | yes |  | Event name or pattern, e.g. order.*  |

## HTTP request

**Key:** `trigger.http` · **Starts a flow**

Runs when an HTTP request reaches a custom route bound to this flow.

**Continues to:** `next`

| Setting | Type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `method` | `GET \| POST \| PUT \| PATCH \| DELETE` |  | `POST` |  |
| `path` | text |  |  | Route path, e.g. /orders/`{id}`/pay |
| `policy` | any JSON |  |  | Who may invoke it directly at /flows/v1/&lt;name> (when no path is set) |
