These blocks read and write your tables, and run a read-only SQL query when you need something the record blocks can't express.

This page documents **8 blocks**. For how flows work, see [Flows](/logic/flows) and the [flow editor](/automation/flow-editor). Values in settings can use templates such as `{{ input.id }}` and `{{ steps.load.output.email }}`; see [Block reference overview](/logic/blocks/overview).

| Block | What it does |
| --- | --- |
| [SQL query](#sql-query) | Runs a parameterised read-only SQL query on the project database. |
| [Transaction](#transaction) | Applies several resource writes atomically. |
| [Create record](#create-record) | Creates a record. |
| [Delete record](#delete-record) | Deletes a record. |
| [Get record](#get-record) | Loads one record; follows `missing` when it does not exist. |
| [List records](#list-records) | Lists records of a resource. |
| [Update record](#update-record) | Updates fields of a record; follows `missing` when it does not exist. |
| [Add to a number](#add-to-a-number) | Adds to number fields of a record in one step; follows `missing` when it does not exist. |

## Add to a number

**Key:** `resource.increment`

Adds to number fields of a record in one step; a negative amount subtracts. Follows `missing` when there is no record with that id.

**Continues to:** `next`, `missing` (follow the one that applies)

| Setting | Type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `resource` | text | yes |  |  |
| `id` | text | yes |  |  |
| `amounts` | any JSON | yes |  | `{field: amount}`, e.g. `{"enrolled": 1}` or `{"stock": -2}` |

Use it for counters: seats taken, items in stock, likes, views. The database does the addition, so runs that happen at the same moment
all count. Reading a record with **Get record**, adding in the flow and saving it with **Update record** loses updates when two runs
overlap: both read the same value, both write value + 1, and one addition is gone.

```json title="Take a seat when someone enrols"
{
  "block": "resource.increment",
  "config": {
    "resource": "sections",
    "id": "{{ input.event.payload.record.section_id }}",
    "amounts": { "enrolled": 1 }
  }
}
```

- Only `integer` and `number` fields can be added to. An `integer` field takes whole amounts only.
- A field that is empty starts from 0.
- The step answers with the record as it is afterwards, and the change is a normal update: `<resource>.updated` events, realtime and
  history all see it.
- Any other check (for example "never go below 0") belongs in a condition before the step, or in a policy.
