A [flow](/logic/flows) is a set of **blocks** joined by arrows. Each block does one thing: read a record, send an email, ask a model, branch on a condition. This reference lists **all 76 blocks** with every setting.

## How a flow runs

1. A **trigger** fires and the run starts. The trigger's data is the run's **input**.
2. The engine follows the arrows from the trigger. Each block runs, produces an **output**, and chooses which **exit** to take.
3. The run ends when there is nothing left to follow, a **Respond** or **Fail** block runs, a **Stop** block runs, or it exceeds the flow's time limit.

A flow has a **timeout** (60 seconds by default, up to 900). A flow can also choose whether to **record runs**, which keeps each run's trace in [Activity](/activity/background-work).

## Exits

A block can have more than one exit. A block that checks something has exits named for the answer: `true` and `false`, `allowed` and `denied`, `hit` and `miss`, `missing`, `anonymous`, `invalid`, `failed`. Most blocks have a single `next` exit.

On the canvas, drag from the exit you want to the next block. If a block takes an exit that has nothing connected to it, that path simply ends.

## Passing values between blocks

Settings accept **templates**: `{{ … }}` placeholders filled in as the block runs.

### What you can read

| Root | What it holds |
| --- | --- |
| `input` | What started the run: the trigger's data (a request, an event's payload, a schedule's `scheduled_at`) |
| `steps.<id>.output` | The output of an earlier block, by the block's id |
| `steps.<id>.handle` | Which exit that block took |
| `vars` | Values set with the **Set variables** block |
| `item`, `index` | Inside a **For each** loop: the current item and its position (from 0) |
| `auth` | Who is calling: `auth.user_id`, roles and more, when a person triggered the run |
| `credential` | The key that made the request, such as `credential.is_service` |
| `env` | The environment's name |
| `run` | The run itself: `run.id`, `run.flow`, `run.trigger`, `run.request_id` |

Reach inside with dots: `{{ steps.load.output.email }}`, `{{ input.body.issue.title }}`, and into lists by position: `{{ input.items.0.name }}`.

### Whole value or text

- A setting that is **exactly one template** gives you the value itself, not its text. `"{{ input.items }}"` passes the list along unchanged, and `"{{ input.total }}"` stays a number.
- A template **inside other text** is turned into text: `"Order {{ input.id }} is ready"`. Objects and lists inside text become JSON. A missing value becomes empty.

### Filters

Add filters after a `|`. Some take an argument after a colon, and filters can be chained.

| Filter | What it does |
| --- | --- |
| `default:value` | Use the value when the lookup is empty, for example `{{ input.name \| default:"friend" }}` |
| `upper`, `lower` | Change the case of text |
| `length` | The number of items or characters |
| `first`, `last` | The first or last item of a list |
| `keys` | The keys of an object, as a list |
| `int`, `float`, `str`, `bool` | Convert the value |
| `json` | Turn the value into JSON text |

An unknown filter name makes the block fail with a clear message. Templates are a **lookup**, not a programming language: for calculations use the **Calculate** block, and for logic use **If** and **Switch**.

### Secrets

Never put a key in a flow. Write `secret://STRIPE_API_KEY` where the value goes, or read one with the **Read secret** block. See [Secrets](/secrets/overview).

## When a block fails

A failing block ends the run as **failed** unless you handled it. Blocks that can fail expectedly, such as an HTTP call, have a `failed` exit you can connect. Wrap anything flaky in a **Retry** block, and use **Fail** to stop with your own status and message when something is wrong. The run's trace in [Flow runs](/activity/background-work#flow-runs) shows every block, its input and its output.

## Testing
