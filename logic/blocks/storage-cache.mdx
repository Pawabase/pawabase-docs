File blocks work on [buckets](/storage/overview). Cache blocks keep short-lived values, so slow work isn't repeated.

This page documents **8 blocks**. For how flows work, see [Flows](/logic/flows) and the [flow editor](/automation/flow-editor). Values in settings can use templates such as `{{ input.id }}` and `{{ steps.load.output.email }}`; see [Block reference overview](/logic/blocks/overview).

| Block | What it does |
| --- | --- |
| [Cache delete](#cache-delete) | Removes a key from the cache. |
| [Cache get](#cache-get) | Reads the cache; follows `hit` or `miss`. |
| [Cache invalidate tags](#cache-invalidate-tags) | Invalidates every cached entry carrying any of the tags. |
| [Cache set](#cache-set) | Writes a value to the cache. |
| [Delete file](#delete-file) | Deletes an object from a bucket. |
| [Store file](#store-file) | Writes text or JSON to a bucket. |
| [Read file](#read-file) | Reads a (small) file from a bucket as text. |
| [Signed URL](#signed-url) | Creates a signed URL for downloading or uploading one object. |

## Store file

**Key:** `storage.put`

Writes a file to a bucket: text or JSON, or a binary file such as an image, sent as base64 or a data URL.

**Continues to:** `next`

| Setting | Type | Required | Default | Notes |
| --- | --- | --- | --- | --- |
| `bucket` | text | yes |  |  |
| `key` | text | yes |  |  |
| `content` | any JSON | yes |  | Text or JSON with `text`; a base64 string with `base64`; a `data:<type>;base64,...` string with `data_url` |
| `content_type` | text |  | `text/plain` for text | With `data_url`, the type comes from the data URL unless you set one |
| `encoding` | text |  | `text` | `text`, `base64` or `data_url` |

The output is `{ bucket, key, size, content_type, url }`. `url` is the file's address on the gateway, `/storage/v1/files/<environment>/<bucket>/<key>`, which anyone can open when the bucket is public. Save that URL in your table rather than the file itself.

The bucket's rules still apply. Pawabase checks the file's real type from its bytes, so a script sent as `image/png` is refused. A type the bucket doesn't accept, or a file over its size limit, stops the flow with a `422` (`file_refused`).

```json
{
  "block": "storage.put",
  "config": {
    "bucket": "media",
    "key": "logos/{{ auth.user_id }}/{{ steps.id.output }}",
    "content": "{{ input.body.logo }}",
    "encoding": "data_url"
  }
}
```
