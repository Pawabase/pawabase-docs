Use these when a flow serves a signed-in person: require sign-in, load their profile, or check an [access rule](/policies/overview) and branch on the answer.

This page documents **4 blocks**. For how flows work, see [Flows](/logic/flows) and the [flow editor](/automation/flow-editor). Values in settings can use templates such as `{{ input.id }}` and `{{ steps.load.output.email }}`; see [Block reference overview](/logic/blocks/overview).

| Block | What it does |
| --- | --- |
| [Look up user](#look-up-user) | Loads any user of this project from the sign-in system by id. |
| [Require sign-in](#require-sign-in) | Fails with 401 unless the caller is signed in (optionally with a role). |
| [Current user](#current-user) | Loads the calling user's full profile from the sign-in system. |
| [Check policy](#check-policy) | Evaluates a policy and follows `allowed` or `denied`. |
