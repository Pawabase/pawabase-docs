A **function** is code you wrote and deployed with your project. Your app calls it by name and gets back whatever it returned.

There are two ways to call a function. Use `invoke` for the common case (send input, get a result), and `fetch` (TypeScript) or `request` (Python) when the function is an HTTP handler and you need control over the method, path, headers and response.

## Invoke

`invoke` sends your input as JSON in a `POST` and returns the function's result.

<CodeGroup>
```typescript TypeScript
const result = await pawabase.functions.invoke("orders.create", { sku: "A1", quantity: 2 });
```

```python Python
result = pb.functions.invoke("orders.create", sku="A1", quantity=2)
```
</CodeGroup>

- The name is exactly what the function is registered as. Names can contain dots to group related functions (`orders.create`, `orders.refund`).
- In Python, your input is passed as keyword arguments. In TypeScript, it is one object.
- With no input, call `invoke("name")`.
- The return value is the function's return value. If the function returns nothing, you get `undefined` (`None` in Python).

### Type the result (TypeScript)

Pass the type you expect. It is a promise to the compiler, not a check at runtime, so validate anything you do not control.

```typescript
type Receipt = { id: string; total: number; currency: string };

const receipt = await pawabase.functions.invoke<Receipt>("orders.create", { sku: "A1", quantity: 2 });
receipt.total;   // number
```

### Who may call it

Every function has an **access rule**, like a table does. It might be "any signed-in user", "users with the `admin` role" or "service callers only". The rule runs before your code does. Your API key also needs permission to invoke functions: a normal publishable key has it unless the project restricted its scopes.

A refused call throws `AuthenticationError` (not signed in) or `PermissionError` (`ForbiddenError` in Python).

## Call options

Every call accepts options as a last argument.

<CodeGroup>
```typescript TypeScript
const controller = new AbortController();

await pawabase.functions.invoke("reports.build", { month: "2026-09" }, {
  signal: controller.signal,      // cancel from your UI
  timeoutMs: 60_000,              // give up after a minute
  headers: { "x-request-source": "dashboard" },
  idempotent: false,
});
```

```python Python
pb.functions.invoke(
    "reports.build",
    month="2026-09",
    headers={"x-request-source": "dashboard"},
)
```
</CodeGroup>

| Option | Meaning |
| --- | --- |
| `signal` | An `AbortSignal`. Aborting rejects the promise with `AbortError` |
| `timeoutMs` | Per-attempt timeout in milliseconds. The default comes from the client, 30 seconds |
| `headers` | Extra request headers |
| `idempotent` | Allow the client to retry a `POST` after a network failure. Leave it off unless running the function twice is harmless |

### Retries and double-running

The client retries *safe* failures by itself: rate limits, `502`, `503`, `504`, and network errors on requests that are safe to repeat. A `POST` is **not** repeated after a network failure unless you set `idempotent: true`, because the first attempt may have succeeded. If your function charges a card or sends an email, make it idempotent on the server (accept a unique key) before you set the flag.

```typescript
await pawabase.functions.invoke("payments.charge", { orderId, key: crypto.randomUUID() }, { idempotent: true });
```

## HTTP functions: `fetch` and `request`

Some functions are full HTTP handlers with their own paths and methods. Use `fetch` to call one with any method, path, query and body and receive the raw `Response`.

<CodeGroup>
```typescript TypeScript
const res = await pawabase.functions.fetch("orders", "/42/items", {
  method: "POST",
  body: { sku: "A1" },
  query: { notify: "true" },
});

if (res.ok) {
  const item = await res.json();
} else {
  console.log(res.status, await res.text());
}
```

```python Python
response = pb.functions.request(
    "orders",
    "/42/items",
    method="POST",
    json={"sku": "A1"},
    params={"notify": "true"},
)
if response.is_success:
    item = response.json()
```
</CodeGroup>

Differences from `invoke`:

- You choose the **method** and **path**. The path is appended to the function's name: `orders` + `/42/items` calls `/functions/v1/orders/42/items`.
- You get the **response itself**: status, headers and a streaming body. An error status is returned to you, not thrown, so you can read the function's own error body.
- A body that is an object is sent as JSON. Strings, `Blob`, `FormData`, buffers and streams are sent as they are, which makes file upload and streaming possible.
- The API key and the signed-in user's token are attached as for every call.

| `fetch` option | Meaning |
| --- | --- |
| `method` | Defaults to `GET`, or `POST` when you pass a `body` |
| `query` | Query-string values. Arrays repeat the key |
| `body` | The request body |
| `headers`, `signal`, `timeoutMs` | As above |
| `branch` | Run the version deployed on another branch. Used for previews and testing |

### Stream a response

```typescript
const res = await pawabase.functions.fetch("reports", "/export.csv");
const reader = res.body!.getReader();
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  append(new TextDecoder().decode(value));
}
```

### Upload a file to a function

```typescript
const form = new FormData();
form.append("file", file);

const res = await pawabase.functions.fetch("imports", "/csv", { method: "POST", body: form });
```

For large files, upload to [storage](/storage/upload) with a signed link and pass the key to the function instead.

## Test a branch before it ships

When your team deploys a function to a feature branch, call that version with `branch`:

```typescript
await pawabase.functions.fetch("orders", "/preview", { branch: "feature-x" });
```

In Python: `pb.functions.invoke("orders.create", branch="feature-x", sku="A1")`. Leave `branch` out to use the main deployment.

## Handle errors

<CodeGroup>
```typescript TypeScript
import { ApiError, AuthenticationError, PermissionError, ValidationError, RateLimitError } from "@pawabase/client";

try {
  await pawabase.functions.invoke("orders.create", { sku: "A1" });
} catch (e) {
  if (e instanceof AuthenticationError) redirectToSignIn();
  else if (e instanceof PermissionError) show("You can't do that.");
  else if (e instanceof ValidationError) showFieldErrors(e.byField());
  else if (e instanceof RateLimitError) show(`Try again in ${e.retryAfter ?? 5}s`);
  else if (e instanceof ApiError && e.code === "out_of_stock") show("Sold out");
  else throw e;
}
```

```python Python
from pawabase import AuthenticationError, ForbiddenError, ValidationError, PawabaseError

try:
    pb.functions.invoke("orders.create", sku="A1")
except AuthenticationError: ...
except ForbiddenError: ...
except ValidationError as e: print(e)
except PawabaseError as e: print(e)
```
</CodeGroup>

When your function raises its own error with a code (for example `out_of_stock`), the client surfaces it as an `ApiError` with that `code`, so the app can show a precise message. Design codes as part of your function's contract.

## Checklist for a good function API

1. Name by what happens (`orders.create`, `invoices.send`), grouped with dots.
2. Accept one object of named inputs. Avoid positional meaning.
3. Return a small object with the ids and facts the screen needs next.
4. Validate input on the server. Never rely on the client.
5. Raise errors with stable codes the app can switch on.
6. Make functions with side effects safe to repeat, using a key from the caller.
