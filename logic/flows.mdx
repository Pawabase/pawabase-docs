A **flow** is an automation made of steps: read a record, branch on a value, send an email, publish to a channel, call a function, return a response. You build flows visually in the dashboard, and anyone on your team can read and change them without a deploy.

Your app starts a flow that has an **HTTP trigger** by calling it by name.

## Run a flow

<CodeGroup>
```typescript TypeScript
const response = await pawabase.flows.run("send-welcome", { name: "Ada", plan: "pro" });
```

```python Python
response = pb.flows.invoke("send-welcome", name="Ada", plan="pro")
```
</CodeGroup>

Your input arrives in the flow as `input`. The call waits for the flow to finish and returns its response.

`run` and `invoke` are the same method (Python also accepts `run`).

## What comes back

A flow's response is whatever its `response.return` block sends. If the flow has no such block, you get its result wrapped as `{ "data": … }`.

```typescript
type Quote = { total: number; currency: string };

const quote = await pawabase.flows.run<Quote>("price-quote", { sku: "A1", quantity: 3 });
quote.total;
```

Design flows the way you design a function: take one object, return a small object.

## Who may run it

The flow's HTTP trigger has an access rule: public, any signed-in user, a role, and so on. It runs before the first step. A refused call throws `AuthenticationError` or `PermissionError` / `ForbiddenError`.

Steps inside the flow run with the authority you configured for the flow, which can be more than the caller has. That is the point: a flow can write to a table the user cannot write to directly, after checking that this specific action is allowed. Keep that in mind when you design the first step: **validate who is asking and what they ask for**.

## Flows with a path are routes

A flow whose HTTP trigger has a **path and method** (for example `POST /orders/{id}/pay`) is reached as a [route](/logic/routes), not through `flows.run`. `flows.run` is for flows with a name only.

## Call options

<CodeGroup>
```typescript TypeScript
await pawabase.flows.run("export-report", { month: "2026-09" }, {
  timeoutMs: 120_000,
  signal: controller.signal,
  headers: { "x-source": "admin" },
});
```

```python Python
pb.flows.invoke("export-report", headers={"x-source": "admin"}, month="2026-09")
```
</CodeGroup>

The options are the same as for [functions](/logic/functions#call-options): `signal`, `timeoutMs`, `headers`, and `idempotent` to allow retrying a `POST` after a network failure when running twice is harmless.

## Waiting for a long flow

A call waits for the flow, and a browser request should not wait minutes. For anything slow, split the work:

1. The flow you call **starts** the work in the background (a queued job) and returns at once with an id.
2. The background work finishes later and records its result, or publishes to a channel.
3. Your app watches the record or the channel.

```typescript
const { reportId } = await pawabase.flows.run("start-report", { month: "2026-09" });

const channel = pawabase.realtime.channel(`report:${reportId}`);
channel.onEvent("ready", (m) => window.open(m.payload.url));
await channel.subscribe();
```

See [patterns](/logic/patterns#long-running-work).

## Errors from inside a flow

A flow can stop and return an error on purpose, with a status and a code. Your app sees it as the matching error type, with the code available as `error.code` and any details in `error.details`.

```typescript
try {
  await pawabase.flows.run("apply-coupon", { code });
} catch (e) {
  if (e instanceof ApiError && e.code === "coupon_expired") show("That coupon has expired.");
  else if (e instanceof ValidationError) show(e.fieldError("code") ?? "Check the code.");
  else throw e;
}
```

Agree the codes with whoever builds the flow and treat them as part of the API.

## Test a flow

While you build a flow, run it from a script with a secret key and the management client, which can run a flow with any input and as any user, and shows the step-by-step trace. From your app's tests, call `flows.run` against a development environment.

```typescript
import { manage } from "@pawabase/client/manage";

const m = manage(serverClient);   // secret key
const result = await m.flows.run("apply-coupon", { code: "SAVE10" }, { asUser: { id: "usr_1" } });
```
