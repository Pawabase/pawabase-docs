## Emit from code

<CodeGroup>
```typescript TypeScript
await m.events.emit("order.paid", { order_id: "o_42", total: 1999 });
```

```python Python
pb.manage.events.emit("order.paid", {"order_id": "o_42", "total": 1999})
```
</CodeGroup>

This needs a secret key, so emit from your server. The call returns once the event is accepted; reactions run afterwards.

## Emit from a flow

Use the `event.emit` block:

```json
{
  "id": "announce_payment",
  "data": {
    "block": "event.emit",
    "config": {
      "event": "order.paid",
      "payload": {
        "order_id": "{{ steps.load_order.output.id }}",
        "total": "{{ steps.load_order.output.total }}"
      }
    }
  }
}
```

The block outputs `{ "event": "order.paid", "id": "<event id>" }`. The flow carries on straight away without waiting for anything to react. A path that does not exist in the payload expression becomes `null`.

## Events Pawabase emits for you

You do not emit these; they appear on their own.

- **Records:** every resource emits `<name>.created`, `<name>.updated` and `<name>.deleted` after a write succeeds. The payload is the record. Set `events: false` on a resource to turn this off, which suits high-volume tables that never drive automation.
- **Authentication:** `user.signed_up`, `user.signed_in`, `user.signed_out`, `user.email_verified`, `user.password_changed`, `user.mfa_enabled`, `user.mfa_reset`.

A record event only fires for writes made through the API or a flow. To announce edits made some other way, set `capture: true` on the resource.

## Choose names

Use `domain.action`, lowercase, in the past tense: `order.paid`, `invoice.overdue`, `cart.abandoned`. A name says what happened, not what to do about it.

- Avoid the prefixes `user.` and your resource names for custom events, so you never collide with platform events.
- Keep the set small and stable. Subscribers depend on names.

## Choose payloads

Put in what a reaction needs to start work: the record id and the facts that may change. Leave out large objects and secrets.

```typescript
// Good: identifiers and a little context
await m.events.emit("order.paid", { order_id: "o_42", customer_id: "c_9", total: 1999 });

// Avoid: the whole order with every line item and address
```

A reaction can read the current record by id. That is better than trusting a snapshot that may be out of date by the time the reaction runs.

## Make reactions safe to repeat

Delivery is at least once, so keep a marker of events already handled. In a flow, check the event `id` first:

```json
{ "id": "seen", "data": { "block": "cache.get", "config": { "key": "evt:{{ input.event.id }}" } } }
```

Stop if it is set; do the work; then set it. Set the marker after the work succeeds, so a crash in between means the event is retried, not lost.
