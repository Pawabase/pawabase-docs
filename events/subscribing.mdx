A **subscription** connects an event name to something that should run. Create as many as you like for the same event.

## Create a subscription

<CodeGroup>
```typescript TypeScript
await m.subscriptions.create({
  name: "reserve-stock",
  event: "orders.created",
  target_type: "flow",
  target: "reserve-inventory",
});

await m.subscriptions.create({
  name: "big-orders",
  event: "orders.created",
  target_type: "flow",
  target: "notify-sales",
  condition: { gt: ["$input.event.payload.record.total", 100000] },
});

await m.subscriptions.create({
  name: "live-orders",
  event: "orders.created",
  target_type: "realtime",
  target: "orders:live",
});
```

```python Python
pb.manage.subscriptions.create({
    "name": "reserve-stock",
    "event": "orders.created",
    "target_type": "flow",
    "target": "reserve-inventory",
})

pb.manage.subscriptions.create({
    "name": "big-orders",
    "event": "orders.created",
    "target_type": "flow",
    "target": "notify-sales",
    "condition": {"gt": ["$input.event.payload.record.total", 100000]},
})
```
</CodeGroup>

| Field | Meaning |
| --- | --- |
| `name` | Letters, digits and dashes. Unique |
| `event` | The event name or a pattern |
| `target_type` | `flow`, `function`, or `realtime` |
| `target` | The flow or function name, or the channel to publish to |
| `condition` | Optional. Only matching events run the target |
| `enabled` | Set `false` to pause without deleting |

Outbound webhooks are separate: see [webhooks](/webhooks/outbound).

## Subscribe from inside a flow

The same thing can be done by giving a flow a `trigger.event` node, with the event name and an optional condition. The flow then starts on each matching event with the event as `input.event`:

```text
input.event.name              "orders.created"
input.event.payload.record    the new record
input.event.id                use for duplicates
input.event.occurred_at       "2026-09-30T14:02:11.342Z"
```

Use a subscription when the reaction is a function or a channel, or when you manage reactions in code. Use `trigger.event` when the flow should own its own trigger.

## Match with wildcards

`*` stands for any run of characters, **including dots**.

| Pattern | Matches |
| --- | --- |
| `orders.created` | Only that event |
| `orders.*` | `orders.created`, `orders.updated`, `orders.line.added` |
| `*.created` | `orders.created`, `users.created` |
| `*` | Every event |

Matching is case-sensitive. There is no one-segment wildcard; check `input.event.name` in the flow when you need to be exact.

## Filter with a condition

A condition runs against the event before anything starts, so a non-matching event costs nothing. It uses the same language as [policies](/policies/conditions): `eq`, `ne`, `gt`, `in`, combined with `all`, `any`, `not`. Operands read the event as `$input.event.…`.

## List, change and remove

<CodeGroup>
```typescript TypeScript
const subs = await m.subscriptions.list();
await m.subscriptions.replace("big-orders", { name: "big-orders", event: "orders.created", target_type: "flow", target: "notify-sales", enabled: false });
await m.subscriptions.remove("big-orders");
```

```python Python
subs = pb.manage.subscriptions.list()
pb.manage.subscriptions.remove("big-orders")
```
</CodeGroup>

`replace` sends the whole definition.

## What happens when a reaction fails

A flow started by an event gets one attempt unless you add a `control.retry` step around the part that can fail. A failed run shows up in the [job log](/jobs/failures-and-replay), where you can retry it. Other reactions are unaffected.

## Troubleshooting

<AccordionGroup>
  <Accordion title="The flow never starts">
    Check the event name matches exactly, including case; the flow is enabled; and the condition is not filtering the event out. Open the event in [Inspecting](/events/inspecting) to see which subscriptions it reached.
  </Accordion>
  <Accordion title="A reaction ran twice">
    Delivery is at least once. Make the reaction safe to repeat using the event id.
  </Accordion>
  <Accordion title="A subscription added today missed yesterday's event">
    Subscriptions apply to events from the moment they exist. Past events are not replayed to new subscribers.
  </Accordion>
</AccordionGroup>
