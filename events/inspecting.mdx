When something does not happen, the first question is whether the event fired and what it reached.

## List and open events

<CodeGroup>
```typescript TypeScript
const recent = await m.events.list({ name: "order.paid", limit: 20 });
const one = await m.events.detail(recent[0].id);
```

```python Python
recent = pb.manage.events.list(name="order.paid", limit=20)
one = pb.manage.events.detail(recent[0]["id"])
```
</CodeGroup>

`list` filters by `name`, takes `limit`, and pages with `after`. An event's detail has its full envelope and the reactions that were started for it, with each one's outcome.

## See how events connect

<CodeGroup>
```typescript TypeScript
const graph = await m.events.graph();
```

```python Python
graph = pb.manage.events.graph()
```
</CodeGroup>

The graph shows which events exist and which flows, functions, channels and webhooks listen to them. It is the quickest way to find an event no one listens to, or one with an unexpected listener.

## Follow a chain

Every event carries the `request_id` of the request that caused it. The same id appears on the flow run and the webhook delivery that follow, so one id ties a user action to everything it set off.

## Check the reactions

- Flow runs: `m.flows.runs({ flow: "send-receipt", limit: 5 })`.
- Background jobs: [job log](/jobs/monitoring).
- Webhook deliveries: [outbound deliveries](/webhooks/outbound#delivery-history).

The dashboard's Events view shows the same information as a table, with filters by name and time, if you prefer to click through.
