The client already stores and refreshes the session. In React you only need to **mirror it into state** and **guard routes**.

## A context

```tsx
// src/auth.tsx
import { createContext, useContext, useEffect, useState, type ReactNode } from "react";
import type { Session, User } from "@pawabase/client";
import { pawabase } from "./pawabase";

type AuthState = { user: User | null; session: Session | null; loading: boolean };

const AuthContext = createContext<AuthState>({ user: null, session: null, loading: true });

export function AuthProvider({ children }: { children: ReactNode }) {
  const [state, setState] = useState<AuthState>({ user: null, session: null, loading: true });

  useEffect(() => {
    const { unsubscribe } = pawabase.auth.onAuthStateChange((_event, session) => {
      setState({ user: session?.user ?? null, session, loading: false });
    });
    return unsubscribe;
  }, []);

  return <AuthContext.Provider value={state}>{children}</AuthContext.Provider>;
}

export const useAuth = () => useContext(AuthContext);
```

Wrap your app once: `<AuthProvider><App /></AuthProvider>`.

`loading` is true until the first event arrives, which happens right away with the stored session. Don't redirect while it is true, or signed-in people see the sign-in page flash.

## Guard a route

```tsx
import { Navigate, useLocation } from "react-router-dom";
import { useAuth } from "./auth";

export function RequireAuth({ children }: { children: JSX.Element }) {
  const { user, loading } = useAuth();
  const location = useLocation();
  if (loading) return null;
  return user ? children : <Navigate to="/sign-in" state={{ from: location }} replace />;
}
```

## Guard by role

```tsx
export function RequireRole({ role, children }: { role: string; children: JSX.Element }) {
  const { user } = useAuth();
  return user?.roles.includes(role) ? children : <p>You don't have access to this page.</p>;
}
```

This only decides what to *show*. The [access rules](/policies/overview) protect the data.

## Sign-in page

```tsx
async function signIn(email: string, password: string) {
  const result = await pawabase.auth.signInWithPassword({ email, password });
  if (result.status === "mfa_required") return { needsCode: true as const, verify: result.verify };
  return { needsCode: false as const };
}
```

After a successful call, `onAuthStateChange` fires and `useAuth` updates. Navigate in an effect that watches `user`:

```tsx
const { user } = useAuth();
const navigate = useNavigate();
useEffect(() => { if (user) navigate(location.state?.from?.pathname ?? "/"); }, [user]);
```

## Show only the methods that are on

```tsx
function useAuthSettings() {
  const [settings, setSettings] = useState<Awaited<ReturnType<typeof pawabase.auth.settings>> | null>(null);
  useEffect(() => { pawabase.auth.settings().then(setSettings); }, []);
  return settings;
}
```

Use `passkeys_enabled`, `magic_link_enabled`, `email_code_enabled` and `signup_enabled` to render the right buttons.

## Social sign-in return

On the page that receives the redirect, do nothing special: the client reads the session itself. To show errors, call `getSessionFromUrl()` once in an effect (see [social sign-in](/auth/social-sign-in#finish-on-return)).

## Account page

```tsx
function Account() {
  const { user } = useAuth();
  const [name, setName] = useState(user?.name ?? "");

  return (
    <form onSubmit={async (e) => { e.preventDefault(); await pawabase.auth.updateUser({ name }); }}>
      <input value={name} onChange={(e) => setName(e.target.value)} />
      <button>Save</button>
      <button type="button" onClick={() => pawabase.auth.signOut()}>Sign out</button>
    </form>
  );
}
```

## Server-rendered React (Next.js and similar)

Server code can't read `localStorage`. Two approaches:

- Keep Pawabase calls in the browser, behind the guard above.
- On the server, create a client per request with the user's token: `createClient({ url, apiKey, accessToken })`. See [Node.js](/quickstarts/node#acting-for-one-user).
