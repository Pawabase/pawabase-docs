### Sign-up first

`POST /auth/v1/signup` creates the account and, unless verification is required, signs the user straight in:

```python
@r.post("/signup", request_model=SignUp, middleware=limits, summary="Create an account")
async def signup(ctx: HttpContext, body: SignUp):
    config = await config_for(akountz, ctx)
    if not config.signup_enabled:
        raise HTTPException(status_code=403, detail="sign-up is disabled")
    if body.redirect_to and not config.redirect_allowed(body.redirect_to):
        raise HTTPException(status_code=400, detail="redirect_to is not an allowed URL")
    user = await create_account(
        config,
        email=body.email,
        password=body.password,
        username=body.username,
        name=body.name,
        user_metadata=body.data,
    )
    await akountz.emit(
        config.project,
        config.env,
        "user.created",
        {"user_id": str(user.id), "email": user.email, "method": "password"},
        actor=str(user.id),
    )
    if config.require_email_verification:
        token = await links.issue(akountz, config, "verify", user=user)
        await emails.send(
            akountz,
            config,
            "verify",
            user.email,
            link=links.link(config, "verify", token, body.redirect_to),
        )
        return created(
            {"user": await user_view(user), "session": None, "verification_required": True}
        )
    session = await start_session(akountz, config, user, method="password", ctx=ctx)
    return created({**session, "verification_required": False})
```

Two shapes come back, and a client must handle both:

```json
{ "user": { "…": "…" }, "session": null, "verification_required": true }
```

```json
{ "access_token": "…", "refresh_token": "…", "…": "…", "verification_required": false }
```

<Warning>
The `session` key is **`null`** when verification is required. A client that reads `response.session.access_token` unconditionally will throw on the verification path. Branch on `verification_required`, or on `session === null`.
</Warning>

The sign-up body:

```python
class SignUp(BaseModel):
    email: str = Field(max_length=255)
    password: str = Field(min_length=1, max_length=1024)
    username: str | None = Field(default=None, max_length=150)
    name: str = Field(default="", max_length=200)
    data: dict[str, Any] = Field(default_factory=dict, description="Initial user_metadata")
    redirect_to: str | None = None
```

`data` becomes `user_metadata`, which the user can later edit themselves — so never use it for an entitlement. See [`meta` versus `app`](/auth/auth-in-policies/meta-versus-app#meta-versus-app).

### What sign-in can refuse, and how

The order of checks in the `password` grant determines which error you get:

```python
email = normalise_email(body.email)
user = await find_by_email(config.project, config.env, email)
refusal = HTTPException(status_code=400, detail="invalid email or password")
if user is None:
    await log_event(..., reason="unknown email", ctx=ctx)
    raise refusal
if is_locked(user):
    await log_event(..., reason="locked", ctx=ctx)
    raise HTTPException(status_code=429, detail="too many failed attempts; try again later")
if not user.check_password(body.password):
    await record_failure(
        user, akountz.settings.lockout_threshold, akountz.settings.lockout_minutes
    )
    await log_event(..., reason="wrong password", ctx=ctx)
    raise refusal
if user.is_disabled:
    await log_event(..., reason="disabled", ctx=ctx)
    raise HTTPException(status_code=403, detail="this account is disabled")
if config.require_email_verification and user.email_verified_at is None:
    raise HTTPException(status_code=403, detail="confirm your email address first")
```

| Status | Detail | What the client should do |
| --- | --- | --- |
| `400` | `invalid email or password` | Wrong credentials — the same message for an unknown email and a wrong password, deliberately |
| `422` | `a valid email address is required` | The email failed normalisation; a client bug, not a user error |
| `429` | `too many failed attempts; try again later` | Locked out. Back off; do not retry in a loop |
| `403` | `this account is disabled` | Show the message, offer support |
| `403` | `confirm your email address first` | Send them to the verification flow |
| `200` | `{ "mfa_required": true, … }` | Not an error — continue to the MFA branch |

<Note>
An unknown email and a wrong password produce the **identical** `400 invalid email or password`. That is correct: a different response for "no such account" is an account-enumeration oracle.
</Note>

### The MFA branch

If the user has MFA enabled and the environment allows it, a successful password check returns a challenge instead of a token pair:

```python
if user.mfa_enabled and config.mfa_enabled:
    await require_membership(config, user, body.org)
    challenge = await links.issue(
        akountz, config, "mfa", user=user, data={"method": "password", "org": body.org}
    )
    await log_event(config.project, config.env, "mfa_challenge", user=user, ctx=ctx)
    return {
        "mfa_required": True,
        "mfa_token": challenge,
        "factors": ["totp", "recovery_code"],
    }
```

Complete it with the `mfa` grant:

```json
{ "grant_type": "mfa", "mfa_token": "…", "code": "123456" }
```

```python
async def _complete_mfa(ctx: HttpContext, config: AuthConfig, body: TokenRequest):
    if not body.mfa_token or not body.code:
        raise HTTPException(status_code=400, detail="mfa_token and code are required")
    row = await links.consume(akountz, config, "mfa", body.mfa_token, peek=True)
    user = row.user
    if user is None or user.is_disabled:
        raise HTTPException(status_code=400, detail="the challenge is no longer valid")
    used = await mfa.verify(akountz, user, body.code)
    if used is None:
        await record_failure(
            user, akountz.settings.lockout_threshold, akountz.settings.lockout_minutes
        )
        await log_event(..., kind="mfa_verify", reason="wrong code", success=False, ctx=ctx)
        raise HTTPException(status_code=400, detail="the code is not valid")
    ...
    session = await start_session(
        akountz, config, user, method=method, ctx=ctx, aal="aal2", org=org
    )
    session["mfa_method"] = used
    return session
```

Three things a client must know:

1. **`mfa_token` is single-use and expires in five minutes** — `LIFETIMES["mfa"] = 300`. A wrong code does *not* consume it, so the user keeps their remaining attempts; a successful one does, so a retry after success returns `400 the challenge is no longer valid`.
2. **A wrong MFA code counts toward account lockout** — `record_failure` is called, the same counter as a wrong password.
3. **The success response has an extra `mfa_method`**, either `"totp"` or `"recovery_code"`.

```json
{
  "access_token": "…",
  "refresh_token": "…",
  "aal": "…",
  "mfa_method": "totp",
  "org": null,
  "org_role": null
}
```
