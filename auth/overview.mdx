Auth gives your app **users**. A person signs up once, signs in whenever they return, and from then on every request your app makes is made *as that person*. Your [database](/database/overview), [storage](/storage/overview) and [realtime](/realtime/overview) rules read that identity to decide what the person may see and change.

This section teaches Auth from both sides at once. For every feature you will see:

- **What it is and when to use it.**
- **In Studio:** where to click, and what each setting means.
- **In your app:** the client calls that use it.

## A first taste

<CodeGroup>
```typescript TypeScript
const { user } = await pawabase.auth.signUp({ email: "ada@example.com", password: "a long passphrase" });

pawabase.auth.onAuthStateChange((event, session) => {
  console.log(event, session?.user.email);     // SIGNED_IN, SIGNED_OUT, TOKEN_REFRESHED …
});

await pawabase.auth.signOut();
```

```python Python
result = pb.auth.sign_up(email="ada@example.com", password="a long passphrase")

pb.auth.on_auth_state_change(lambda event, session: print(event))

pb.auth.sign_out()
```
</CodeGroup>
