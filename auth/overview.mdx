Auth gives your app **users**. A user signs up once, signs in whenever they come back, and from then on every request your app makes is made *as that person*. Your [database](/database/overview) and [storage](/storage/overview) rules use that identity to decide what they can see and change.

## How it works

1. Your app calls a sign-in method, like `signInWithPassword`.
2. Pawabase returns a **session**: a short-lived access token and a long-lived refresh token.
3. The client library stores the session, attaches the token to every request, and refreshes it before it expires.

You never handle tokens yourself. You call methods and listen for changes.

<CodeGroup>
```typescript TypeScript
const { user } = await pawabase.auth.signUp({ email: "ada@example.com", password: "a long passphrase" });

pawabase.auth.onAuthStateChange((event, session) => {
  console.log(event, session?.user.email);     // SIGNED_IN, SIGNED_OUT, TOKEN_REFRESHED …
});

const current = await pawabase.auth.getUser();
await pawabase.auth.signOut();
```

```python Python
result = pb.auth.sign_up(email="ada@example.com", password="a long passphrase")

pb.auth.on_auth_state_change(lambda event, session: print(event))

current = pb.auth.get_user()
pb.auth.sign_out()
```
</CodeGroup>

## Which methods are on

Each sign-in method is switched on in the dashboard under **Authentication**. To adapt your UI, ask the project what it allows:

<CodeGroup>
```typescript TypeScript
const settings = await pawabase.auth.settings();
if (settings.passkeys_enabled) showPasskeyButton();
if (settings.magic_link_enabled) showMagicLink();
```

```python Python
settings = pb.auth.settings()
if settings["passkeys_enabled"]:
    show_passkey_button()
```
</CodeGroup>

The settings also say whether sign-up is open and whether new accounts must confirm their email.

## The user object

Every sign-in returns a `user`:

| Field | Meaning |
| --- | --- |
| `id` | A stable id. Use it as the owner of records |
| `email`, `email_verified` | The address and whether it is confirmed |
| `name`, `username`, `avatar_url` | Profile fields the person can edit |
| `user_metadata` | Anything else you want to store about them. They can edit it, so never trust it for permissions |
| `app_metadata`, `roles` | Set by you or an administrator. Safe for permissions |
| `mfa_enabled` | Whether two-factor is on |
| `identities` | Linked social accounts |
