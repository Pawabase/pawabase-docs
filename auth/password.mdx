## Sign up

<CodeGroup>
```typescript TypeScript
const { user, session, verificationRequired } = await pawabase.auth.signUp({
  email: "ada@example.com",
  password: "a long passphrase",
  name: "Ada",
  data: { plan: "free" },                       // stored in user_metadata
  redirectTo: "https://myapp.com/welcome",     // where the confirmation link sends them
});
```

```python Python
result = pb.auth.sign_up(
    email="ada@example.com",
    password="a long passphrase",
    name="Ada",
    data={"plan": "free"},
    redirect_to="https://myapp.com/welcome",
)
result.user, result.session, result.verification_required
```
</CodeGroup>

Two things can happen:

- **They are signed in at once.** `session` is set and the client stores it.
- **They must confirm their email first.** `verificationRequired` is `true` and `session` is `null`. Show a "check your inbox" message. When they click the link, they land on your `redirectTo` page already signed in.

Whether confirmation is required is a project setting. The `redirectTo` address must be on your project's list of allowed redirect URLs, which you set in the dashboard.

## Sign in

<CodeGroup>
```typescript TypeScript
const result = await pawabase.auth.signInWithPassword({ email, password });

if (result.status === "mfa_required") {
  // The account has two-factor on. Ask for the code, then finish:
  await result.verify(codeFromUser);
}
```

```python Python
result = pb.auth.sign_in_with_password(email=email, password=password)

if result.status == "mfa_required":
    result.verify(code_from_user)
```
</CodeGroup>

After this, `pawabase.auth.getUser()` returns the person and every request is made as them. See [Two-factor](/auth/two-factor) for the full flow.

## Handle errors

A wrong password and an unknown email give the same error on purpose, so nobody can discover which addresses have accounts.

<CodeGroup>
```typescript TypeScript
import { AuthenticationError, ValidationError, RateLimitError } from "@pawabase/client";

try {
  await pawabase.auth.signInWithPassword({ email, password });
} catch (e) {
  if (e instanceof AuthenticationError) setMessage("Wrong email or password.");
  else if (e instanceof ValidationError) setMessage(e.fieldError("email") ?? "Check your details.");
  else if (e instanceof RateLimitError) setMessage("Too many tries. Wait a moment.");
  else throw e;
}
```

```python Python
from pawabase import AuthenticationError, ValidationError, RateLimitedError

try:
    pb.auth.sign_in_with_password(email=email, password=password)
except AuthenticationError:
    message = "Wrong email or password."
except ValidationError as e:
    message = "Check your details."
except RateLimitedError:
    message = "Too many tries. Wait a moment."
```
</CodeGroup>

Repeated failed sign-ins temporarily lock the account, and sign-up and sign-in share a rate limit, so do not retry in a loop.

## Change the password

A signed-in user changes their password with their current one:

<CodeGroup>
```typescript TypeScript
await pawabase.auth.updateUser({ current_password: "old", password: "a new long passphrase" });
```

```python Python
pb.auth.update_user(current_password="old", password="a new long passphrase")
```
</CodeGroup>

For a forgotten password, see [verification and resets](/auth/verification-and-resets#reset-a-forgotten-password).

## Good practice

- Ask for a long password (the project enforces a minimum) instead of complicated rules, and allow paste so password managers work.
- Put `autocomplete="email"` and `autocomplete="current-password"` on your inputs.
- Offer [passkeys](/auth/passkeys) or [email codes](/auth/email-codes-and-magic-links) alongside passwords. Fewer passwords means fewer resets.
