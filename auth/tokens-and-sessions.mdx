After any sign-in the SDK holds a **session**: a short-lived access token that proves who the user is, and a refresh token used to get the next one. For a browser or mobile app you rarely touch either. The client stores the session, sends the access token on every request, renews it shortly before it expires, and tells you when the user becomes signed in or out. This page explains each of those behaviours, how to change them, and how to use sessions correctly on a server, where there is no single "current user".

## What a session holds

<CodeGroup>
```typescript TypeScript
const session = await pawabase.auth.getSession();

session?.access_token;      // sent as Authorization: Bearer …
session?.refresh_token;
session?.expires_at;        // Unix seconds
session?.user.email;
session?.org;               // organization slug, or null
```

```python Python
session = pb.auth.session

session.access_token
session.refresh_token
session.expires_at          # epoch seconds
session.user["email"]
session.org                 # organization slug, or None
```
</CodeGroup>

`getSession()` resolves `null` when nobody is signed in. In Python `pb.auth.session` is `None`.

| Property | Notes |
| --- | --- |
| `access_token` | A signed token, valid for **15 minutes**. Every request carries it. |
| `refresh_token` | Exchanged **once** for a new access and refresh token. |
| `expires_in` / `expires_at` | Lifetime in seconds as issued; the Unix time it ends. |
| `session_id` | The identifier of this sign-in. Shown in the session list. |
| `org` / `org_role` | The organization the tokens were issued for, and the user's role there. |
| `user` | The [user object](/auth/overview#the-user). |

Shorthand accessors exist for the common reads:

<CodeGroup>
```typescript TypeScript
const token = await pawabase.auth.getAccessToken();   // null when signed out
const user = await pawabase.auth.getCachedUser();     // the session's copy, no network
const fresh = await pawabase.auth.getUser();          // from the server, and re-cached
```

```python Python
token = pb.auth.access_token                          # None when signed out
user = pb.auth.user                                   # the session's copy, no network
fresh = pb.auth.get_user()                            # from the server, and re-cached
```
</CodeGroup>

## Inside the access token

The access token is a JWT. You do not need to decode it to use Pawabase, but its claims are useful to know when you read it yourself, for example to show a role in the UI:

| Claim | Meaning |
| --- | --- |
| `sub` | The user's id. |
| `email` | The user's email at issue time. |
| `aud` | `authenticated` for a signed-in user. |
| `env` | The environment the token belongs to. A token is not valid in another environment. |
| `sid` | The session id. |
| `iat`, `exp` | Issued at, and expiry (Unix seconds). |
| `typ` | `access`. |
| `aal` | Assurance level: `aal1` (one factor) or `aal2` (a second factor was used). |
| `roles`, `perms` | Roles and permissions at the moment the token was issued. |
| `org`, `org_role` | The active organization and the user's role in it, or `null`. |

<Warning>
Roles and permissions are read when a token is **issued**. If you change a user's roles, a token they already hold keeps the old ones until it is renewed (within 15 minutes) or they sign in again. Call `refreshSession()` to pick up the change immediately.
</Warning>

Treat decoded claims as a convenience for display, never as proof on your own server. A browser can edit anything it holds. To know who is calling, [verify on the server](#use-sessions-on-a-server).

## Where the session is stored

| Environment | Default |
| --- | --- |
| TypeScript in a browser | `localStorage`, so the user stays signed in between page loads and across tabs. |
| TypeScript on a server, React Native, tests | In memory. Pass a storage for anything else. |
| Python | In memory. Pass a `session_store` to survive restarts. |

<CodeGroup>
```typescript TypeScript
import { createClient, MemoryStorage } from "@pawabase/client";

// keep nothing between page loads
const ephemeral = createClient({ url, apiKey, auth: { persistSession: false } });

// bring your own storage (React Native's AsyncStorage, a cookie jar, …)
const custom = createClient({
  url,
  apiKey,
  auth: {
    storage: {
      getItem: (key) => AsyncStorage.getItem(key),
      setItem: (key, value) => AsyncStorage.setItem(key, value),
      removeItem: (key) => AsyncStorage.removeItem(key),
    },
    storageKey: "myapp.session",
  },
});
```

```python Python
from pawabase import FileSessionStore, Pawabase

# a command-line tool or desktop app: stay signed in between runs
pb = Pawabase(url, key, session_store=FileSessionStore("~/.myapp/session.json"))
```
</CodeGroup>

Storage options for the TypeScript `auth` block:

| Option | Default | Effect |
| --- | --- | --- |
| `storage` | `localStorage` in browsers, memory elsewhere | An object with `getItem`, `setItem` and `removeItem`. Each may return a promise. |
| `storageKey` | Derived from the URL and key | The key the session is saved under. Set it if one page hosts two clients. |
| `persistSession` | `true` | `false` keeps the session in memory only. |
| `autoRefreshToken` | `true` | Renew the access token before it expires. |
| `refreshMarginSeconds` | `60` | How early, in seconds, a token counts as expiring. |
| `detectSessionInUrl` | `true` in browsers | Pick up the tokens a social sign-in leaves in the page URL. |

A Python `SessionStore` is any object with `get()` and `set(session)`, so you can keep sessions in a database or a secrets manager. `FileSessionStore` writes a file readable only by its owner (mode 600), and `MemorySessionStore` is the default.

<Warning>
A session in storage is a credential. Anything that can read the file or `localStorage` can act as the user until the refresh token is revoked. Keep `FileSessionStore` files out of version control and shared folders.
</Warning>

### Several tabs, one session

In a browser, tabs share the stored session. When one tab renews the tokens or signs out, the others see the change in storage and update, instead of renewing again. You get this without code, and listeners in the other tabs are told.

## Renewal

The access token lives 15 minutes, so the SDK renews it for you:

- **Before a request**, if the token is within the margin of expiring (60 seconds by default).
- **After a 401**, once: the request is repeated with the new token.
- **On a timer**, in the TypeScript client, shortly before expiry, so a page left open stays signed in.

Renewal is serialized. Refresh tokens are single-use: using one twice fails, and a replayed token can end the session as a precaution. Two requests, or two tabs, that both notice an expired token must not both try. The TypeScript client makes concurrent callers share one renewal, and uses the Web Locks API across tabs where the browser has it. The async Python client serializes renewal with a lock.

If renewal fails because the refresh token is no longer good (revoked, expired, or already used), the session ends: the stored session is removed and `SIGNED_OUT` is emitted. A temporary network failure does not end it; the next call tries again.

You can also renew by hand, for example to pick up changed roles or switch organization:

<CodeGroup>
```typescript TypeScript
const session = await pawabase.auth.refreshSession();
const inAcme = await pawabase.auth.refreshSession({ org: "acme" });   // or switchOrg("acme")
```

```python Python
session = pb.auth.refresh_session()
in_acme = pb.auth.refresh_session(org="acme")                         # or switch_org("acme")
```
</CodeGroup>

Turn automatic renewal off with `auth: { autoRefreshToken: false }` in TypeScript or `auto_refresh=False` in Python when something else owns the session, such as a framework that keeps it in a cookie. Then call `refreshSession()` yourself.

## React to sign-in and sign-out

<CodeGroup>
```typescript TypeScript
const { unsubscribe } = pawabase.auth.onAuthStateChange((event, session) => {
  if (event === "SIGNED_OUT") router.push("/login");
  if (event === "TOKEN_REFRESHED") cacheToken(session!.access_token);
});

// later
unsubscribe();
```

```python Python
def on_change(event, session):
    if event == "SIGNED_OUT":
        show_login()

unsubscribe = pb.auth.on_auth_state_change(on_change)

# later
unsubscribe()
```
</CodeGroup>

| Event | Fires when |
| --- | --- |
| `INITIAL_SESSION` | TypeScript only. Once, after the stored session has been read: the session or `null`. Use it to decide the first screen. |
| `SIGNED_IN` | A sign-in, sign-up, magic link, code, passkey, social return or `setSession` produced a session. |
| `SIGNED_OUT` | The user signed out, or the session ended because renewal failed. |
| `TOKEN_REFRESHED` | The tokens were renewed. |
| `USER_UPDATED` | The profile changed (`updateUser`, `upgradeAnonymous`). |

<Note>
The TypeScript client reads storage asynchronously, so `getSession()` waits until storage has loaded before answering. Use `INITIAL_SESSION` or `await pawabase.auth.initialized()` to avoid flashing a login screen at someone who is already signed in.
</Note>

When you are done with a client that will not be used again, for instance in a test, call `pawabase.dispose()` so its timers and listeners stop.

## Adopt tokens you already have

If the tokens come from somewhere else, such as a cookie your server set, a redirect, or another process, hand them to the SDK:

<CodeGroup>
```typescript TypeScript
const session = await pawabase.auth.setSession({ access_token, refresh_token });
```

```python Python
session = pb.auth.set_session(access_token, refresh_token)
```
</CodeGroup>

The user is loaded from the server, the session is stored, and `SIGNED_IN` fires.

For a TypeScript app that returns from a social sign-in, tokens in the page address are read automatically. To do it by hand, for instance with `detectSessionInUrl: false`, call `getSessionFromUrl()`. It answers one of `signed_in`, `mfa_required`, `linked`, `error` or `none`; see [Social login](/auth/social-login).

## Sign out and revoke

`signOut` ends sessions on the server and forgets the local one:

<CodeGroup>
```typescript TypeScript
await pawabase.auth.signOut();                        // this device
await pawabase.auth.signOut({ scope: "others" });     // every other device
await pawabase.auth.signOut({ scope: "global" });     // every device, including this one
```

```python Python
pb.auth.sign_out()                                    # this device
pb.auth.sign_out(scope="others")                      # every other device
pb.auth.sign_out(scope="global")                      # every device, including this one
```
</CodeGroup>

| `scope` | Effect |
| --- | --- |
| `local` (default) | Ends this session. |
| `others` | Ends all of the user's other sessions and keeps this one. |
| `global` | Ends every session. |

The local session is forgotten even if the request fails, so a flaky network never leaves a "signed-out" user holding a working session. An access token that was already issued stays valid until it expires, up to 15 minutes: signing out stops renewal, and it does not recall tokens in flight. For anything that must stop immediately, such as a stolen device, also revoke the user's sessions or [disable the account](/auth/managing-users).

## Manage a user's sessions

A user can see where they are signed in and end any of those sessions, which is the "log out of other devices" screen:

<CodeGroup>
```typescript TypeScript
const sessions = await pawabase.auth.sessions.list();
// [{ id, method, aal, ip, user_agent, created_at, last_refreshed_at, current }]

await pawabase.auth.sessions.revoke(sessions.find((s) => !s.current)!.id);

const history = await pawabase.auth.sessions.history();
// [{ kind, method, success, reason, ip, user_agent, at }]
```

```python Python
sessions = pb.auth.sessions.list()
# [{"id", "method", "aal", "ip", "user_agent", "created_at", "last_refreshed_at", "current"}]

other = next(s for s in sessions if not s["current"])
pb.auth.sessions.revoke(other["id"])

history = pb.auth.sessions.history()
# [{"kind", "method", "success", "reason", "ip", "user_agent", "at"}]
```
</CodeGroup>

| Field | Meaning |
| --- | --- |
| `method` | How the person signed in, for example `password`, `email_code`, `passkey`, `anonymous`, or the name of a provider. |
| `aal` | The assurance level of that session. |
| `current` | `true` for the session making this request. |
| `history[].kind` | A sign-in event such as `sign_in`, `recovery_requested` or a failure. `success` and `reason` explain the outcome. |

`history()` is the account's recent activity, including failed attempts. Showing it lets people notice sign-ins they do not recognize.

Two related lists live under `auth`: `auth.devices` (`list`, `forget`) shows browsers and apps the user has signed in from, and `auth.apiKeys` (`list`, `create`, `revoke`) manages keys a user makes for themselves to call the API as themselves.

## Use sessions on a server

A server answers many users at once, so it must never share one client-wide session. Create one client for the process and give each request its own view that carries that user's token.

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";

export async function handler(request: Request) {
  const token = request.headers.get("authorization")?.replace(/^Bearer /, "") ?? null;

  const pawabase = createClient({
    url: process.env.PAWABASE_URL!,
    apiKey: process.env.PAWABASE_PUBLISHABLE_KEY!,
    accessToken: token ?? undefined,
  });

  const user = await pawabase.auth.getUser();          // 401 if the token is not valid
  const { data: orders } = await pawabase.from("orders");
  pawabase.dispose();
  return Response.json({ user, orders });
}
```

```python Python
# one client for the process
pb = Pawabase(os.environ["PAWABASE_URL"], os.environ["PAWABASE_PUBLISHABLE_KEY"])

def handler(request):
    token = request.headers.get("authorization", "").removeprefix("Bearer ") or None
    with pb.as_user(token) as user_client:             # same connection pool, this user's token
        user = user_client.auth.get_user()             # 401 if the token is not valid
        orders = user_client.from_("orders").execute()
    return {"user": user, "orders": orders}
```
</CodeGroup>

With `accessToken` (TypeScript) or `as_user` (Python) the client keeps no session, never renews, and sends exactly that token. Because Pawabase checks the token on every call, your handler acts with that user's permissions and your [policies](/policies/overview) apply as they would in the browser. `accessToken` can also be a function returning a token, for frameworks that own the session.

### Know who is calling

To authenticate a request on your server, ask Pawabase. Do not trust what you decode yourself:

- Call `getUser()` with the caller's token. A valid token answers with the user; anything else is a 401.
- Or make the call you wanted anyway. A policy that requires a signed-in user refuses an invalid token for you.

User access tokens are signed by the project, not by a key you hold, so there is no public key to verify them offline. If another service needs to trust your users without calling Pawabase, issue it an [integration token](/auth/passkeys-and-codes#integration-tokens) instead, which that service can verify against published keys.

### Cookie-based apps

Server-rendered frameworks usually keep the tokens in an HTTP-only cookie. On each request, read the access token from the cookie and use `accessToken`/`as_user` as above. When it expires, call `refreshSession()` once with the refresh token from the cookie (use `setSession` to adopt both), then write the new pair back to the cookie. Do this in one place, such as middleware, because refresh tokens are single-use: two simultaneous requests both refreshing with the same token will log the user out.

## Failure behaviour

| Situation | What you see |
| --- | --- |
| Access token expired | Handled for you: renewed, request repeated. |
| Refresh token revoked or already used | The session ends; `SIGNED_OUT` fires; the next call asks the user to sign in. |
| Session revoked from another device | The next renewal fails and ends the session the same way. |
| Network down during renewal | The session is kept; the request fails with a network error and a later call retries. |
| `getUser()` with an invalid token | `AuthenticationError` (401). |
| Calling `refreshSession()` with no session | An error: there is nothing to renew. Sign in first. |

## Recipes

### Guard a page until the session is known

In a single-page app, wait for `INITIAL_SESSION` before deciding between the app and the login screen, otherwise a signed-in user briefly sees the login page.

```typescript
import { useEffect, useState } from "react";
import type { Session } from "@pawabase/client";

export function useSession() {
  const [state, setState] = useState<{ ready: boolean; session: Session | null }>({ ready: false, session: null });

  useEffect(() => {
    const { unsubscribe } = pawabase.auth.onAuthStateChange((event, session) => {
      setState({ ready: true, session });
    });
    return unsubscribe;
  }, []);

  return state;
}

export function Protected({ children }: { children: React.ReactNode }) {
  const { ready, session } = useSession();
  if (!ready) return null;                       // still reading storage
  return session ? children : <Navigate to="/login" />;
}
```

`INITIAL_SESSION` is delivered to a new listener once storage has been read, so this hook is ready on the first answer. More patterns, including a provider component, are in [Client integration](/auth/client-integration).

### Call your own backend as the user

Send the access token to a backend you run, and have it ask Pawabase who the caller is (see [know who is calling](#know-who-is-calling)). Read a fresh token each time rather than caching one: the client renews it for you.

<CodeGroup>
```typescript TypeScript
const token = await pawabase.auth.getAccessToken();

const response = await fetch("https://api.example.com/reports", {
  headers: { authorization: `Bearer ${token}` },
});
```

```python Python
token = pb.auth.access_token

response = requests.get("https://api.example.com/reports", headers={"authorization": f"Bearer {token}"})
```
</CodeGroup>

If the call comes back 401 because the token expired between reading it and the request arriving, read the token again and retry once. The Pawabase client does this itself for Pawabase calls; for your own backend you do it.

### Build a "your devices" screen

<CodeGroup>
```typescript TypeScript
const sessions = await pawabase.auth.sessions.list();

const rows = sessions.map((s) => ({
  id: s.id,
  label: `${s.method} · ${s.user_agent ?? "unknown device"}`,
  lastSeen: s.last_refreshed_at ?? s.created_at,
  isThisDevice: s.current,
}));

async function signOutDevice(id: string) {
  await pawabase.auth.sessions.revoke(id);
}
```

```python Python
rows = [
    {
        "id": s["id"],
        "label": f'{s["method"]} · {s["user_agent"] or "unknown device"}',
        "last_seen": s["last_refreshed_at"] or s["created_at"],
        "is_this_device": s["current"],
    }
    for s in pb.auth.sessions.list()
]


def sign_out_device(session_id: str):
    pb.auth.sessions.revoke(session_id)
```
</CodeGroup>

Mark the current device clearly and do not offer to revoke it from this list: use `signOut` for that. After a revoke, the other device is signed out the next time it renews, within 15 minutes.

### Sign out when the session expires everywhere

Listen for `SIGNED_OUT` once, at the root of your app, and clear any cached data there. It fires for a deliberate sign-out, for a revoked session and for a failed renewal, so one handler covers all three.

```typescript
pawabase.auth.onAuthStateChange((event) => {
  if (event === "SIGNED_OUT") {
    queryClient.clear();
    router.replace("/login");
  }
});
```

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| The user is signed out after a page reload | Storage is not persisting (`persistSession: false`, or a browser that blocks storage). | Check `localStorage` is available, or supply your own `storage`. |
| Signed in on one tab, signed out on another | Two clients use different `storageKey`s, or storage is blocked in one tab. | Use one client per page, with the same key. |
| Intermittent sign-outs on a server | Two requests refreshed with the same refresh token. | Refresh in one place, once per user, then store the new pair. |
| `getUser()` fails with 401 after a long idle period | The refresh token expired or the session was revoked. | Sign in again. |
| The roles in the token are stale | Roles are read when the token is issued. | Call `refreshSession()`. |
| A decoded token shows another environment | The client is configured for a different environment. | Check `url`, `apiKey` and `environment`. |
| The session list is empty | The call was made with no signed-in user. | Sign in first; the list needs a user token. |
| `INITIAL_SESSION` never arrives (Python) | It is a TypeScript-only event. | Read `pb.auth.session` after creating the client. |

## Terms

| Term | Meaning |
| --- | --- |
| Session | One sign-in on one device: a pair of tokens, with an id you can list and revoke. |
| Access token | The short-lived credential sent on every request. |
| Refresh token | The single-use credential that gets the next pair. |
| Assurance level (`aal`) | `aal1` means one factor was used; `aal2` means a second factor, or a passkey. |
| Revoke | End a session on the server so it can no longer be renewed. |
| Scope (of sign-out) | Which of the user's sessions to end: this one, the others, or all. |
| Publishable key | The key your app ships with; it identifies the environment and carries no user. |
| Secret key | A server-only key that bypasses user checks; never used to sign people in. |
