Two-factor authentication (2FA) asks for a second proof after the password: a six-digit code from an authenticator app such as 1Password or Google Authenticator. Even if a password leaks, the account stays safe.

Turn it on in the dashboard under **Authentication** (`mfa_enabled` in `auth.settings()`).

## Let a user turn it on

<Steps>
  <Step title="Start enrolment">
    The server makes a secret. Show it as a QR code and as text.
  </Step>
  <Step title="Confirm with a code">
    The person scans the QR code, then types the code their app shows. Pawabase checks it and switches 2FA on.
  </Step>
  <Step title="Save recovery codes">
    You receive one-time recovery codes once. Make the person save them.
  </Step>
</Steps>

<CodeGroup>
```typescript TypeScript
const { otpauth_uri, secret } = await pawabase.auth.mfa.enroll();
// Render otpauth_uri as a QR code (any QR library). Show `secret` for manual entry.

const { enabled, recovery_codes } = await pawabase.auth.mfa.verifyEnrollment(codeFromUser);
showOnce(recovery_codes);
```

```python Python
enrollment = pb.auth.mfa.enroll()          # {"factor_id", "secret", "otpauth_uri"}
result = pb.auth.mfa.verify_enrollment(code_from_user)
show_once(result["recovery_codes"])
```
</CodeGroup>

Recovery codes are shown only once. Tell people to store them somewhere safe; each works one time if they lose their phone.

## Sign in with a second factor

When an account has 2FA, `signInWithPassword` does not finish. It returns `mfa_required` with a `verify` function:

<CodeGroup>
```typescript TypeScript
const result = await pawabase.auth.signInWithPassword({ email, password });

if (result.status === "mfa_required") {
  const session = await result.verify(codeFromUser);   // an authenticator code or a recovery code
}
```

```python Python
result = pb.auth.sign_in_with_password(email=email, password=password)

if result.status == "mfa_required":
    session = result.verify(code_from_user)
```
</CodeGroup>

Passwordless methods, social sign-in and passkeys can return the same `mfa_required` result, so handle it in one place. `getSessionFromUrl` and `verifyEmailCode` both return it.

The wrong code gives an `AuthenticationError`. Allow a few retries, and offer "use a recovery code".

## Check, turn off, and get new recovery codes

<CodeGroup>
```typescript TypeScript
const status = await pawabase.auth.mfa.status();     // { enabled, aal, recovery_codes_remaining }

await pawabase.auth.mfa.disable(currentCode);
const { recovery_codes } = await pawabase.auth.mfa.regenerateRecoveryCodes(currentCode);
```

```python Python
status = pb.auth.mfa.status()
pb.auth.mfa.disable(current_code)
codes = pb.auth.mfa.regenerate_recovery_codes(current_code)["recovery_codes"]
```
</CodeGroup>

Disabling and regenerating both ask for a current code, so someone using a stolen, signed-in browser cannot weaken the account. `aal` in the status tells you the strength of this session: `aal1` is a password alone, `aal2` includes the second factor.

## Remember this device

You can let people skip the second factor on devices they trust. Use `remember_device` (Python) when signing in, and list or forget trusted devices:

<CodeGroup>
```typescript TypeScript
const devices = await pawabase.auth.devices.list();
await pawabase.auth.devices.forget(devices[0].id);
```

```python Python
pb.auth.sign_in_with_password(email=email, password=password, remember_device=True)
devices = pb.auth.devices.list()
pb.auth.devices.forget(devices[0]["id"])
```
</CodeGroup>
