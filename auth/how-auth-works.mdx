Every Auth feature is built from the same few parts. Learn them once and the rest of the section reads easily.

## Users

A **user** is a person who can sign in to your app. Each user has:

| Part | Meaning |
| --- | --- |
| `id` | A stable identifier. Use it as the owner of records. It never changes |
| `email` and `email_verified` | The address and whether the person has proved they own it |
| `username`, `name`, `avatar_url` | Profile fields the person can edit |
| `user_metadata` | Free-form data the person can see and edit |
| `app_metadata` | Free-form data only your server can change. Safe to base permissions on |
| `roles` | Named groups of permissions you assign. See [Roles](/auth/roles) |
| `mfa_enabled` | Whether a second step is turned on |
| `identities` | Linked sign-in methods, such as a Google account |
| `created_at`, `last_sign_in_at` | When the account was made and last used |

Users belong to an **environment**. A user in `production` does not exist in `development`, so test accounts never mix with real ones.

## Identities

An **identity** is one way a user proves who they are: a password, a Google account, a company login. One user can have several, so the same person can sign in with a password today and Google tomorrow and end up in the same account. See [Linked accounts](/auth/linked-accounts).

## Sessions

When someone signs in, Pawabase creates a **session**: one signed-in browser or device. A session consists of two tokens:

| Token | Lives | Used for |
| --- | --- | --- |
| **Access token** | 15 minutes by default | Sent with every request to prove who is calling |
| **Refresh token** | 30 days by default | Traded for a fresh access token before the old one expires |

The client library stores both, attaches the access token to requests and refreshes it quietly in the background. Your code never touches them.

Two safety rules are built in:

- A refresh token works **once**. Using it returns a new refresh token and invalidates the old one. If an old token is ever used again, Pawabase assumes it was stolen and ends the whole session. The auth webhook for this is `session.reuse_detected`.
- The client shares one refresh between requests and, in browsers, between tabs, so normal use never trips this rule.

Lifetimes and the number of devices per person are settings. See [Sessions](/auth/sessions).

## What an access token says

The access token is a signed document that lists facts about the caller. Your access rules read these facts:

| Fact | Meaning |
| --- | --- |
| user id | Who the caller is |
| roles and permissions | What they are allowed to do |
| organization and organization role | Which organization the session is acting in |
| `aal` | Assurance level: `aal1` after a password, `aal2` after a second step |
| email | The user's address |

Because the token is signed, the server trusts it without a database lookup. Because it is short-lived, a change you make (a new role, a disabled account) takes effect within minutes, or immediately if you end the person's sessions.

## Assurance levels

`aal1` means the person proved one thing, like a password. `aal2` means they also completed a second step. An [access rule](/policies/overview) can require `aal2` for sensitive actions, so a stolen password alone is not enough. See [Two-step verification](/auth/two-step-verification).

## Keys: who is calling Pawabase

Separate from users, every request carries an **API key** that identifies your *project*:

- A **publishable key** (`pb_pk_…`) goes in client code. On its own it can do only what your public rules allow; once a user signs in, requests are made as that user.
- A **secret key** (`pb_sk_…`) belongs on a trusted server and bypasses all rules. Never ship it.

See [Keys and security](/reference/keys-and-security).

## The session in your app

The client keeps the session for you. What it does, and the knobs you have:

<CodeGroup>
```typescript TypeScript
const session = await pawabase.auth.getSession();     // refreshed first if about to expire; null when signed out
const token = await pawabase.auth.getAccessToken();   // string | null
const user = await pawabase.auth.getCachedUser();     // as of sign-in or the last refresh, no request
await pawabase.auth.initialized();                    // the stored session has been read
```

```python Python
pb.auth.session        # Session | None
pb.auth.access_token   # str | None
pb.auth.user           # dict | None, no request
pb.auth.expiring()     # True within 60 seconds of expiry
pb.auth.can_refresh()  # a refresh token is held
```
</CodeGroup>

A session holds `access_token`, `refresh_token`, `expires_at` (Unix seconds), `session_id`, the organization it's scoped to (`org`, `org_role`) and the `user`.

### Where it's kept

| | TypeScript | Python |
| --- | --- | --- |
| Default | `localStorage` in a browser, memory elsewhere | Memory |
| Keep it between runs | The default in a browser | `session_store=FileSessionStore(path)`; the file is created readable by you only |
| Your own store | `auth: { storage }` with `getItem`, `setItem`, `removeItem`, sync or async (React Native's AsyncStorage fits) | Any object with `get()` and `set(session_or_None)` |
| Memory only | `auth: { persistSession: false }` | The default |

<CodeGroup>
```typescript React Native
import AsyncStorage from "@react-native-async-storage/async-storage";

export const pawabase = createClient({
  url, apiKey, environment,
  auth: { storage: AsyncStorage, detectSessionInUrl: false },
});
```

```python A command-line tool
from pathlib import Path
from pawabase import Pawabase
from pawabase.auth import FileSessionStore

pb = Pawabase(url, key, environment=env,
              session_store=FileSessionStore(Path.home() / ".mytool" / "session.json"))
```
</CodeGroup>

TypeScript's other auth options:

| Option | Default | Meaning |
| --- | --- | --- |
| `autoRefreshToken` | `true` | Refresh on a timer before expiry |
| `refreshMarginSeconds` | `60` | How long before expiry a token counts as expiring |
| `detectSessionInUrl` | `true` in browsers | Pick up a social sign-in's tokens from the address on load |
| `storageKey` | from the URL and key | Change it to run two clients for one environment side by side |

### Refreshing

- **Before expiry:** TypeScript refreshes on a timer `refreshMarginSeconds` before the token expires; Python refreshes before a request when the token is within 60 seconds of expiry.
- **After a `401`:** both refresh once and send the request again.
- **When a tab comes back** to the foreground with an expiring token (browsers).
- **One at a time:** concurrent requests share one refresh, and in a browser tabs take turns through the Web Locks API, so a refresh token is never used twice.

A refresh the server refuses (`400`, `401` or `403`) signs the person out. A refresh that fails for a passing reason (offline, a server error) keeps the session, and TypeScript tries again 10 seconds later.

Refresh by hand when you need new facts in the token at once, such as after an admin changed someone's roles: `await pawabase.auth.refreshSession()` / `pb.auth.refresh_session()`.

### Events

<CodeGroup>
```typescript TypeScript
const { unsubscribe } = pawabase.auth.onAuthStateChange((event, session) => {
  if (event === "SIGNED_OUT") router.push("/login");
  else setUser(session?.user ?? null);
});
```

```python Python
unsubscribe = pb.auth.on_auth_state_change(lambda event, session: print(event))
```
</CodeGroup>

| Event | When |
| --- | --- |
| `INITIAL_SESSION` | TypeScript, once per listener, after the stored session was read: end your loading state here |
| `SIGNED_IN` | Any sign-in, an adopted session, a session found in the address, another tab signing in |
| `SIGNED_OUT` | Sign-out, a refused refresh, another tab signing out |
| `TOKEN_REFRESHED` | A refresh here or in another tab, or switching organization |
| `USER_UPDATED` | Profile, picture or guest upgrade changes |

Tabs stay in step through the browser's `storage` event. A listener that throws never breaks auth.

### Adopt a session you already have

`setSession` stores tokens you got elsewhere (cookies from a server-rendered page, a deep link). It fetches the user with them first, so bad tokens fail here.

<CodeGroup>
```typescript TypeScript
await pawabase.auth.setSession({ access_token, refresh_token });
```

```python Python
pb.auth.set_session(access_token, refresh_token)
```
</CodeGroup>

## On a server

A server that renders pages for many people must never hold one signed-in session: it would belong to whoever signed in last. Keep one client for the process and act as each request's person:

<CodeGroup>
```typescript TypeScript
const pawabase = createClient({ url, apiKey: process.env.PAWABASE_KEY!, environment });

export async function handler(req: Request) {
  const db = pawabase.asUser(readCookie(req, "pb_access"));   // no session kept, never refreshes
  const { data } = await db.from("orders").eq("status", "open");
  return Response.json(data);
}
```

```python Python
pb = Pawabase(url, os.environ["PAWABASE_KEY"], environment=env)

def handler(request):
    db = pb.as_user(request.cookies.get("pb_access"))         # shares the connection pool
    return db.from_("orders").eq("status", "open").execute().data
```
</CodeGroup>

Keep the tokens in HTTP-only cookies set by a route of yours, and refresh there when the access token is close to expiry. Services and AI agents that act as themselves use [machines](/auth/machines) and `asMachine`.

## Putting it together

1. Your app calls `signInWithPassword`.
2. Pawabase checks the password against the user's password identity, applies the lockout and device rules, and creates a session.
3. The client stores the session and fires `SIGNED_IN`.
4. Each later request carries the access token. Your rules see `$auth.user_id`, `$auth.roles` and the rest.
5. Before 15 minutes pass, the client refreshes the token.
6. `signOut()` ends the session on the server and forgets it locally.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Signed out in every tab at once | A refresh token was used twice, which counts as theft | Don't copy sessions between clients or processes |
| Signed out after the laptop sleeps | The refresh failed while offline, then the token expired | Expected; the next sign-in fixes it. Keep `autoRefreshToken` on |
| Requests on a server act as the wrong person | One shared signed-in client | `asUser` / `as_user` per request |
| A new role doesn't apply | The access token still carries the old facts | `refreshSession()` |
| `INITIAL_SESSION` never fires in Python | It's TypeScript only | Read `pb.auth.session` after creating the client |
