[Attack protection](/auth/attack-protection) locks an account after too many wrong passwords. **Bot protection** works before that: it asks a request to prove it comes from a person's browser or app, so a script cannot create accounts in bulk, try stolen password lists, or make your project send email to strangers.

It is off until you turn it on. Your app needs no changes for the built-in check: the SDK solves it by itself.

## What it protects

| Action | Stops |
| --- | --- |
| Creating an account | Fake accounts in bulk |
| Signing in with a password | Password guessing and stolen-password lists |
| Asking for a sign-in link | Your project sending email to strangers |
| Asking for a sign-in code | The same |
| Asking for a password reset | Reset emails sent in bulk |
| Asking for the confirmation email again | Confirmation emails sent in bulk |
| Starting a guest session | Guest accounts made in bulk |

Never checked: refreshing a session, the second step of a sign-in, and anything your servers do with a secret key.

To protect your own forms (contact, newsletter, checkout), see [Protect your forms](/auth/protect-your-forms).

## In Studio

**Users & auth → Bot protection.** The page has four tabs: **Overview** and **Activity** to watch what it does, **Settings** to change it, and **Add to your site** for your own forms.

### When to check

| Choice | What happens |
| --- | --- |
| **Off** | Nobody is ever checked |
| **Only when it looks like an attack** | People sign in as usual. A check appears for an address that keeps failing, tries many accounts or creates many |
| **Every time** | Every protected request is checked first |

Each action can differ from this under **What to protect**: *Same as above*, *Every time*, *When suspicious* or *Never*. A common setup is *only when it looks like an attack* for everything, and *every time* for creating an account.

### How to check

| Check | For |
| --- | --- |
| **Built in** | Nothing to set up and nothing for people to click: their browser does a short piece of work. Works in mobile apps and scripts too |
| **Cloudflare Turnstile** | Usually invisible. Needs a free Cloudflare account |
| **hCaptcha** | A checkbox, sometimes a picture puzzle |
| **Google reCAPTCHA** | A score with no interaction (v3), or a checkbox (v2) |

A hosted provider needs its **Site key** (public; your sign-in page uses it to show the check) and **Secret key** (kept encrypted and never shown again). **Check the keys** asks the provider whether it accepts the secret. For reCAPTCHA v3, **Lowest score to accept** is 0 (certainly a bot) to 1 (certainly a person); 0.5 is the usual choice.

**Effort** (built in only) decides how much work a browser does: *Light*, *Normal* or *Heavy*. Heavier costs a bot more and a slow phone about a second.

### If the provider cannot be reached

| Choice | During an outage |
| --- | --- |
| **Use the built-in check instead** (recommended) | People are still checked, without the provider |
| **Let people through** | Nobody is locked out, and nobody is checked until it is back |
| **Refuse until it is back** | Nothing gets through unchecked. People cannot sign in |

After three failures to reach the provider in a minute, Pawabase stops asking it for a minute and your choice applies, so a provider outage does not slow every sign-in down.

### Your sites

A check solved on any site not in this list is refused. `*.example.com` covers every subdomain. Empty accepts any site.

### Suspicion and blocking

**How quickly to become suspicious** applies to *only when it looks like an attack*:

| Choice | Asks for a check |
| --- | --- |
| **Relaxed** | Only at clear signs of abuse. Fewest checks |
| **Balanced** (recommended) | After a handful of failures |
| **Strict** | At the first signs. More people will see one |

An address that keeps going after being checked is refused for **Block an address for (minutes)**. **After a passed check, do not ask again for (minutes)** lets someone who solved a check sign in again without another (0 asks every time). **Addresses that are never checked** takes your office or your servers, as `203.0.113.7` or `10.0.0.0/8`.

## How suspicion is worked out

Each request gets a score from 0 to 100, from what its address and the account it names have done in the last minutes:

| Signal | Adds up to |
| --- | --- |
| Failed sign-ins from this address | 45 |
| Different accounts this address has tried | 40 |
| Failed sign-ins on this account, from anywhere | 35 |
| Accounts created from this address | 40 |
| Checks this address failed | 30 |
| Checks this address was shown and never solved | 30 |
| Emails this address asked to be sent | 30 |
| A client that says it is a script, or sends no user agent | 15 |

A check is asked for from the *Balanced* threshold (35); the address is blocked at 90. The built-in check also gets harder as the score rises. IPv6 addresses are counted by their `/64`, since one subscriber holds the whole block.

With several server processes and Redis, every process shares these counts. Without Redis they are counted per process, and the Overview tab says so.

## What your app sees

### With the SDK

The built-in check is handled for you: when a request is refused with `captcha_required`, the SDK solves the check and sends the request again. A solved check earns a **clearance** that the SDK keeps and sends with later requests, so people are rarely asked twice.

With a hosted provider, give the client a way to show its widget. It is called with the provider and its site key, and returns the token the widget gives:

<CodeGroup>
```typescript TypeScript
import { createClient } from "@pawabase/client";

const pawabase = createClient({
  url: "https://api.example.com",
  project: "01JC4…",
  apiKey: "pb_pk_…",
  auth: {
    captcha: {
      // Only needed for Turnstile, hCaptcha or reCAPTCHA.
      getToken: (check) => showTurnstile(check.site_key, check.provider_action ?? check.action),
      // Optional: say "Checking…" while the built-in check runs.
      onSolving: (solving) => setChecking(solving),
    },
  },
});

await pawabase.auth.signInWithPassword({ email, password });   // checked only when needed
```

```python Python
from pawabase import Pawabase

pb = Pawabase("https://api.example.com", "pb_pk_…", project="01JC4…")

# A script or an app signing people in earns a pass for the action, then sends it.
granted = pb.captcha.protect("signin")
pb.auth.sign_in_with_password(email=email, password=password, captcha_token=granted["pass"])
```
</CodeGroup>

`protect` solves the built-in check itself. For a hosted provider, pass `get_token=` (Python) to show its widget.

To show a provider's widget before the person presses the button, rather than after a refusal, ask ahead:

<CodeGroup>
```typescript TypeScript
const ahead = await pawabase.auth.captchaChallenge("signup", email);
if (ahead.required && ahead.captcha?.provider !== "pawabase") showWidget(ahead.captcha);
```

```python Python
ahead = pb.captcha.prepare("signup")
if ahead["required"]:
    ...
```
</CodeGroup>

Already showing a widget yourself? Send its token with the call (`captchaToken` in TypeScript, `captcha_token` in Python) or as the `x-captcha-token` header.

### Errors

| Error | Means | Do |
| --- | --- | --- |
| `captcha_required` (403) | A check is needed. `details.captcha` says which | The SDK solves the built-in one; show the provider's widget |
| `captcha_failed` (403) | The check sent was wrong, used or expired. `details.captcha` is a fresh one | Solve the fresh one |
| `too_many_attempts` (429) | The address is blocked for a while. `retry_after` is in seconds | Wait; say "Too many attempts. Try again later." |
| `captcha_unavailable` (503) | The provider is down and the setting is *Refuse until it is back* | Try again in a minute |

<CodeGroup>
```typescript TypeScript
import { isCaptchaError, captchaChallengeOf } from "@pawabase/client";

try {
  await pawabase.auth.requestPasswordReset({ email });
} catch (error) {
  if (isCaptchaError(error)) showWidget(captchaChallengeOf(error));
  else throw error;
}
```

```python Python
from pawabase import PawabaseError
from pawabase.captcha import challenge_of

try:
    pb.auth.request_password_reset(email=email)
except PawabaseError as error:
    check = challenge_of(error)
    if check is None:
        raise
```
</CodeGroup>

## Watching it

- **Overview:** checks asked, passed, failed and blocked over the last 24 hours or 7 days, by hour and by action, and your forms.
- **Activity:** the addresses blocked right now, with **Unblock** (which also forgets what the address did), and the latest refusals. Refusals also appear in [sign-in activity](/auth/sign-in-activity), at most once a minute per address.

## Privacy

The built-in check sets no cookies and sends nothing to anyone else. A hosted provider sees your visitors' addresses: mention it in your privacy notice.

## Limits

The built-in check makes abuse expensive, and stops casual scripts outright. It cannot tell a person from a determined attacker running a real browser and paying for the work. For a target worth that much, use a hosted provider, and keep *Use the built-in check instead* for outages.
