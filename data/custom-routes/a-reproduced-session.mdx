This is the sequence that produced the facts above, in order, on a clean API. It is worth following once with your own flow.

<Steps>
  <Step title="Create a flow and a route">
    A flow, `echo`, with a `trigger.http` and a `response.return` that returns the payload's `params`, `query` and `body`. A route `POST /echo/{id}` with policy `authenticated` and one required string field `reason` with `max_length` 10.
  </Step>
  <Step title="Call it correctly">
    `POST /rest/v1/echo/7?x=1&y=two` with `{"reason": "because"}` as a signed-in user answered `200`: `{"params": {"id": "7"}, "query": {"x": "1", "y": "two"}, "body": {"reason": "because"}}`. The values are text.
  </Step>
  <Step title="Call it without a credential">
    The same call with no token answered `401`, `Authentication required`.
  </Step>
  <Step title="Break the body four ways">
    A reason that is too long, an empty object, an extra key and no body at all each answered `422` with a bare list, naming `string_too_long`, `missing`, `extra_forbidden` and `json_invalid`.
  </Step>
  <Step title="Check the order of the checks">
    A signed-out caller with an **invalid** body got the `422`. With a **valid** body, the `401`. Validation runs first.
  </Step>
  <Step title="Return a 202 and an error">
    One route's flow ended with `response.return` (`status: 202`, header `x-custom: yes`) and answered `202` with the header. Another ended in `error.raise` (`status: 404`, code `thing_missing`) and answered `404` with `{"error": "thing_missing", "message": "no such thing"}`.
  </Step>
  <Step title="Rate-limit and disable">
    A route with a limit of 2 per 60 seconds refused its third call with `429` and `retry-after: 30`. A disabled route answered the router's `404`.
  </Step>
  <Step title="Cache a summary and write underneath it">
    A cached `GET` route over a resource's list returned one item. A record was added through the API. The same caller's same query still returned one item, while another query and another user saw two.
  </Step>
  <Step title="Call a function through a route">
    A function registered in the code directory answered through a route with the merged `{"n": 3, "id": "7"}`, and with `{}` answered `422`, `invalid function input`. A function that raised returned a plain `500`, one that slept past its timeout `504`, and one with the policy `deny` returned its result through a public route.
  </Step>
  <Step title="Save a route at a resource's path">
    `GET /later` was saved as a route, then a `later` resource was created. The resource won, and the Overview listed `route GET /later: shadows a resource route`.
  </Step>
</Steps>


## Troubleshooting

| What you see | Cause | Fix |
| --- | --- | --- |
| `404` with `{"status": 404, "error": "Not Found", ...}` | The route is disabled, deleted, or its method or path is different | Check **Enabled**, the method and the exact path |
| `404` with the plain text `Not found` | The path reached a **resource**, and the record does not exist | A route may be shadowed by a resource. Check the Overview |
| `401` on a route you thought was public | The policy is `authenticated` (the default) | Set `public` explicitly |
| `403`, `This API key lacks the 'routes:invoke' scope` | The key was created without that scope | Issue a key with it |
| `403`, `policy '<name>' refused` | The policy refused a signed-in caller | Check the condition against the caller and the body |
| `403` on a `GET` route whose policy mentions `$input` | A `GET` has no body, so the comparison is false | Move the check to the query, or use a `POST` |
| `422` with a list | Body validation. Read the `loc` and `msg` | Fix the body |
| `422` with `invalid function input` | The merged input failed the function's own `input_fields` | Check path parameters and body together |
| `422` with `validation failed` | A `validate.schema` block in the flow | Fix the body for that schema |
| `200` with `total: null` for a missing required field | The route uses `input_schema`, which does not enforce `required` | Use `input_fields` or check in the flow |
| `500`, `missing_flow` | The route names a flow that does not exist | Create the flow, or fix the name |
| `404`, `no function '<name>'` | The function is not registered (not deployed, wrong name, import error) | Check the project's code directory and the API's logs |
| `500`, `Internal Server Error` from a function route | The function raised | Read the function's logs. The message is not returned |
| `504`, `timeout` | The function ran past its `timeout` | Do less, or raise the timeout |
| `429` | Over the route's limit | Wait for `retry-after`, or raise the limit |
| An answer that does not reflect a write | A cached `GET` route | Shorten `cache_ttl`, or accept the staleness |
| A route's body is `null` | A `GET` or `DELETE` route, or an unparseable JSON body with no input model | Use `POST`, or fix the JSON |
| The `id` is text where you expected a number | Path parameters are always text | Convert in the flow or function |
| The response has fields it should not | The flow returns more than it should, and `response_schema` does not trim | Build the body, or use a transformer with `pick` |
| Changes to a function do not appear | The code is loaded once per project when it is first used | Restart the API, or reload the project's code |


## Questions that come up

<AccordionGroup>
  <Accordion title="Is a custom route public by default?">
    No. With no policy it is `authenticated`. To make it public, set the `public` policy.
  </Accordion>
  <Accordion title="Can a route return a status other than 200?">
    From a flow, yes: `response.return` sets the status and headers, and `error.raise` sets an error status. From a function, no: it returns `200`, unless it fails.
  </Accordion>
  <Accordion title="Are path parameters numbers?">
    No. They are always text. A flow or function converts them.
  </Accordion>
  <Accordion title="Why did my `GET` route ignore the body?">
    `GET` and `DELETE` routes never read a body. Use `POST`, or put the data in the query string.
  </Accordion>
  <Accordion title="Why does my route accept any JSON?">
    Without `input_fields` or `input_schema` the body is unvalidated. Declare a shape.
  </Accordion>
  <Accordion title="Why is `required` ignored with `input_schema`?">
    A referenced schema compiles with every field optional, so constraints are enforced and required is not. Use `input_fields` for required fields.
  </Accordion>
  <Accordion title="Can I see request headers in a flow?">
    No. A route's flow gets `params`, `query` and `body`. For header-based authentication of callbacks, use an inbound hook.
  </Accordion>
  <Accordion title="Can a route call another route?">
    A flow can call another flow, and a function can call flows, functions and resources through its runtime. Routing a call back out through HTTP to the same environment is not something to build on: call the flow or function directly.
  </Accordion>
  <Accordion title="Does a route have its own events?">
    No. A route runs a flow, and the resource blocks inside it publish the resource events they normally do. See [Resource events](/data/resource-events/overview).
  </Accordion>
  <Accordion title="Can two routes share a path?">
    Yes, with different methods. The same method and path is refused with a `409`.
  </Accordion>
  <Accordion title="Can I use a route to replace a resource operation?">
    Not at the resource's own path. Disable the operation on the resource, and serve your own behavior at a sub-path.
  </Accordion>
  <Accordion title="What happens to a route when I delete its resource?">
    Nothing. The route is independent. If it used the resource's table through SQL, it will fail at run time.
  </Accordion>
  <Accordion title="How do I change a route without downtime?">
    Save it. It takes effect on the next request. For a breaking change, add a new path and migrate clients.
  </Accordion>
</AccordionGroup>


## Before you publish a route

1. **Is the path outside resource space,** and does the Overview report no problems?
2. **Is the policy named,** and does it fail closed?
3. **Is the body declared** with `input_fields` (or checked in the flow)?
4. **Does the handler exist** in this environment: the flow promoted, or the function deployed?
5. **Does the response contain only what the caller may see?**
6. **Does every error have a status and a code** a client can switch on?
7. **Is there a rate limit** where the route costs something?
8. **Is the cache time, if any, short,** and the policy about the caller only?
9. **Do keys have `routes:invoke`** only where they should?
10. **Do the other doors** (`/flows/v1`, `/functions/v1`) have the policies you intend?
11. **Is there a test** for who may, what is accepted and what happens?


## What to remember

- **A route is an endpoint under `/rest/v1`, answered by a flow or a function.**
- **No policy means `authenticated`.** Public must be written.
- **Validation runs before the policy.**
- **Path parameters and query values are text.**
- **Without an input model, the body is unvalidated.** `GET` and `DELETE` bodies are ignored.
- **`input_fields` enforce required. `input_schema` does not.**
- **`response_schema` is documentation.** It does not trim or default.
- **A flow chooses its status and headers. A function cannot.**
- **A function's own policy is not applied through a route.**
- **A route's cache is not cleared by writes.**
- **A route cannot sit at a resource's path.** One created later is silently shadowed, and the Overview says so.
- **A route names its handler without checking it.** Promote flows with routes.


## Terms

| Term | Meaning |
| --- | --- |
| **Route** | A stored endpoint under `/rest/v1` with a method, a path, a policy and a handler |
| **Handler** | The flow or function a route runs |
| **Payload** | The `params`, `query` and `body` handed to the handler |
| **Input model** | `input_fields` or `input_schema`, which validate the body |
| **Plan-time policy** | The part of a policy decided before the body is read |
| **`$input`** | The validated body, as a policy condition sees it |
| **`routes:invoke`** | The API key scope a route needs |
| **Direct door** | `/flows/v1/<name>` and `/functions/v1/<name>`, which run a flow or function without a route |
| **Shadowed** | A route that a resource's own path hides |
| **Function** | A registered Python function that takes a context and returns JSON |
